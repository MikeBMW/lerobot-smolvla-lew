## 根因（一条设计错误，两个文件都犯）
1. **横移高度按"目标点 z + 180mm"算**，不按"当前位置 + 安全抬升量"算：
   - `tools/register_ready_skill.py`：`TRAVERSE_DZ = 180`（写死）
   - `tools/register_approach_skill.py`：`--traverse-dz` 默认 `180`
   ⇒ 臂先被抬到 z≈0.549（比出发现场高 **217mm**、比准备点高 180mm）再横移 194mm。
   ⇒ 违反现场铁律「不要升高超过 10cm」；这一高度已在横梁/夹具风险区。
2. **"包络校验通过"被当成"净空安全"**：`env_model` 的包络由**历史运动/示教数据**拟合 ⇒ 它只知道
   "臂曾经到过哪里"，**不知道障碍物在哪**。日志「✅ 包络内 z=0.5491」是必要而非充分条件。
3. （衍生）**大角度姿态在横移中顺便完成**：准备点→侧面点1 含 93.71° 转身，工具本体扫掠半径大，
   在夹具/模块附近等于一段不可预知的碰撞路径。

## 教训（长期生效，已写进技能 `real-arm-motion-control`）
1. **转移抬升量 = 相对当前高度，且 ≤ 100mm（现场规矩），默认取 50mm**；
   **横移高度 = max(起点 z, 目标点 z) + 抬升量**，永远不要写成"目标点 z + 180"这种与起点无关的绝对量。
2. **包络校验 ≠ 净空校验**。任何"抬到某高度再横移"的计划，必须另外回答"这个绝对高度在车间里对应什么？
   顶上有没有横梁/线槽/夹具？"——**没有实测净空数字时，抬升量取最小值（50mm）并请老倪目视确认**。
3. **大角度姿态变化（≥30°）不在工件/夹具附近完成**：要么在已确认的开阔位（如准备点）先转好，
   要么拆成小幅多步 + 老倪盯着。
4. **计划里必须同时给"相对当前的高度变化"和"绝对高度"**，并标出与现场 10cm 规矩的关系；
   只给绝对 z 值老倪无法在十几秒内判断。
5. **一有"要碰撞/注意"信号：立刻跑 `tools/agent_all_stop.py`**（杀执行器 = 断我方唯一下发路径；
   停 GPU 重活让给安全层；保留只读采集/安全层），然后只读报位姿，等老倪处理。

## 修复（本次落地）
1. 两个注册器改为**有界相对抬升**：`横移高度 = max(起点z, 目标z) + min(climb, 100mm)`，`climb` 默认 50mm；
   删掉 `TRAVERSE_DZ=180` 这类绝对量。
2. 执行器增加**爬升闸**：一条计划里相对**计划起点**的抬升 > `climb_limit_mm`（默认 100）⇒ 拒发，
   除非请求显式带 `allow_climb_mm` 确认。
3. 已注册的旧技能（`L2.goto_ready`/`L2.approach_surface_pt1`/`L2.goto_surface_pt*`/号位等）按新规则重算并重注册；
   重注册前一律 `arm=0` 演练 + 打印每段"相对当前高度变化"给老倪目视。
4. `tools/agent_all_stop.py`（现场"注意/要碰撞"时一键：杀执行器 + 让 GPU + 复查剩余进程）。
