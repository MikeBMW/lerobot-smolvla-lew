# feature.dbc — 能力数据库方案 (参考 Vector CANoe DBC)

> 版本: v1.0 · 2026-08-19 · 设计: 静静 (系统工程模块化)
> 参考: Vector CANoe 产品的 DBC 数据库文件 (CAN Database)

---

## 一、为什么参考 DBC

Vector CANoe 用 **DBC 文件**统一描述总线上所有节点/消息/信号：
- 一份 DBC，多个 ECU 节点共享同一套信号定义
- 换节点不改总线结构，改配置即可
- 第三方设备按 DBC 对齐信号，即插即用

我们的问题同构：**多个模型（相当于 ECU 节点）要在一个平台/容器里配置接入**。
因此设计 **feature.dbc** —— 能力数据库文件：

| CANoe 概念 | feature.dbc 对应 | 说明 |
|---|---|---|
| Node (ECU) | 模型节点 (BU_) | 平台内可配置的模型 / 第三方接入点 |
| Message (BO_) | 能力 (BO_) | 每条能力 = 一条消息，含接口与信号 |
| Signal (SG_) | 输入/输出信号 (SG_) | 能力的数据接口契约 |
| 节点信号映射 | 模型能力组合 (CM_) | 每个模型选用哪些能力 |
| DBC 共享 | 平台统一读取 | 同一文件驱动所有模型配置 |

## 二、文件格式规范 (feature.dbc)

```
VERSION "1.0"

// 模型节点 BU_: 平台内可配置的模型 / 第三方接入点
BU_: STATE_SPACE ACT SMOLVLA VLA_TOUCH YOLO

// 数据流形态 FLOW_: 形态名 "形态说明" "特征" 适用节点...
FLOW_: STATE_VECTOR "状态向量流" "决策=运动规律建模" STATE_SPACE
FLOW_: IMAGE_ACTION "图像+状态→动作流" "完整作业执行" ACT SMOLVLA

// 能力 BO_ <ID> <名称>: <接口> <类别>
BO_ A1 目标识别定位: IN 感知
 SG_ 输入_现场图像 : 24 "RGB图像 640x480, 约30fps"
 SG_ 输出_目标清单 : 64 "类别/置信度/位置框"

// 模型能力组合 CM_ <节点>: <能力ID...>
CM_ STATE_SPACE: A1 A2 A3 A4 B3 B4 C1 C2 C3 C4 D1 D2 E1 E2 F1 F2 G1 G2 G3 H1 H3
CM_ ACT: A1 A2 A4 B1 C1 C3 C4 D1 D2 E1 E2 E3 F1 F2 G1 G2 G3 H1 H3
```

### 关键字
| 关键字 | 含义 | 语法 |
|---|---|---|
| `VERSION` | 数据库版本 | `VERSION "1.0"` |
| `BU_` | 模型节点清单 | `BU_: A B C` |
| `FLOW_` | 数据流形态定义 | `FLOW_: ID "名称" "说明" 节点...` |
| `BO_` | 能力定义 (消息) | `BO_ ID 名称: 接口 类别` |
| `SG_` | 能力信号 (输入/输出) | `SG_ 信号名 : 位宽 "说明"` (缩进在 BO_ 下) |
| `CM_` | 模型能力组合 | `CM_ 节点: 能力ID...` |
| `//` | 注释 | |

### 接口取值
`IN` 输入观测 · `OUT` 动作输出 · `CFG` 参数配置 · `TRAIN` 训练接入 ·
`DEPLOY` 部署接入 · `EVAL` 评估接入 · `MON` 监控上报 · `SCHED` 调度接入

## 三、平台集成 (同一个平台/容器配置不同模型)

```
┌─────────────────────────────────────────────┐
│  Z-MAX 平台 / 容器                          │
│                                             │
│  feature.dbc ──→ 解析器(feature_dbc.py)     │
│      │                                       │
│      ├─→ 能力库总览 (数据字典树)             │
│      ├─→ 模型节点配置 (切换模型=按 CM_ 加载) │
│      └─→ 接口契约 (SG_ 信号对接)             │
│                                             │
│  模型节点: STATE_SPACE / ACT / 第三方...     │
└─────────────────────────────────────────────┘
```

### 第三方模型接入流程 (三步)
1. **登记节点**: feature.dbc `BU_` 增加节点名 (如 `EXT_PI0`)
2. **声明能力**: `CM_ EXT_PI0: A1 A2 B1 ...` (从能力库勾选)
3. **对齐信号**: 按所选能力的 `SG_` 信号契约实现适配 → 平台同流程运行
   (训练/评估/部署/监控无需改平台代码)

## 四、与能力库 (model_feature.py) 的关系
- **单一数据源**: model_feature.py 能力库 ↔ feature.dbc 双向同步
  (提供 `export_dbc()` 生成 / `parse_dbc()` 读取)
- **文件即配置**: 平台运行时以 feature.dbc 为配置事实，改文件即改配置
- **版本管理**: feature.dbc 入库 (git)，能力演进可追溯

## 五、交付物
- `feature.dbc` — 能力数据库文件 (仓库根)
- `tools/gui/feature_dbc.py` — 解析器/生成器/树构建
- 本文档 — 方案说明
