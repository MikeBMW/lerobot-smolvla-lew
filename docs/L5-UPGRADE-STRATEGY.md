# 大模型层（L5）升级优化策略

> 老倪 2026-09-24：「大模型层给出升级优化策略」
> 依据：本仓库实测数据（延迟/显存/精度）+ 已完成的统一主干改造经验

---

## 一、L5 现状（实测基线）

| 项 | 现状 | 问题 |
|---|---|---|
| 规划模型 | DeepSeek Vision（云端）| **单次 61s** → 已做异步旁路 |
| 兜底模型 | smolvlm2-500m（本地）| 能力弱，仅兜底 |
| 冷启动 | **6.7s** | 每次调用都付 → 必须常驻（已改常驻，稳态 101ms/10Hz）|
| 输出 | 阶段序列（7 阶段）| 无结构化 schema 校验 |
| 视觉编码 | 独立（与 L4 不共享）| **重复编码、显存浪费、表征不统一** |

**核心矛盾**：L5 要「定方向」，但云端大模型**慢且贵**，本地小模型**弱**；而 L4 已经有一个**训好的 86.4M 预训练视觉主干**（SigLIP 768d）在空转 —— 两份视觉编码在跑同一画面。

---

## 二、升级策略（四条，按投入产出排序）

### 策略 1 ⭐ **视觉表征收口**：L5 复用 L4 的 SigLIP 主干（零新增训练）
```
现状: L5(独立 VLM 编码) + L4(SigLIP 编码) → **同一帧编码两次**
改为: L4 的 SigLIP 768d 特征 → 共享给 L5（特征总线）
      L5 只做"规划头"（轻量, 几百万参数）

收益（可量化）:
  · 显存: 省掉一份视觉塔（L5 侧 ~0.35GB fp32 / 0.18GB fp16）
  · 延迟: 免二次编码（单帧 ~30ms @ batch16, 实测 SigLIP batch16 = 29ms）
  · 表征统一: L5 的"看到"与 L4 的"想到"同一空间 → 规划与预测一致
风险: L5 规划任务需要语义级理解（SigLIP 是视觉特征, 不含语言）
      → 缓解: SigLIP 特征 + 语言 token 一起进轻量 cross-attention 规划头
```

### 策略 2 ⭐ **分级调用**（治 61s 延迟，不牺牲质量）
```
高频(每帧/每 N 帧): 本地 smolvlm2-500m 或规则规划器  → **<200ms**
低频(任务切换/异常时): 云端 DeepSeek Vision          → 61s 但只在必要时
路由判据（客观）:
  · 阶段序列未变 + 无异常 → 走高频
  · 阶段切换 / L2 报异常 / 位姿偏差超阈 → 触发低频重规划
实测支撑: L5 冒烟已跑通异步旁路（不阻塞闭环），当前就是"低频触发"形态
   → 本策略 = 把它**规范化**: 明确触发条件 + 高频路径的能力下限
```

### 策略 3 **结构化输出 + 合法性校验**（治"规划不可执行"）
```
现状: L5 自由文本 → 解析成阶段序列 → 无校验
改为: 强制 schema（JSON）+ **三条硬校验**:
  ① 阶段顺序合法（接近→对位→下降→抓取→抬起→转移→插入 不得跳反）
  ② 依赖满足（插入前必须已抓取；抓取前必须已下降）
  ③ 与当前观测一致（若 L4 预测"已在插入阶段", 不得规划"回到接近"）
不合法 → 拒绝并回退到规则规划器（安全兜底）
收益: 消除"LLM 幻觉出不可执行序列"这类故障（安全层已要求上层只给意图）
```

### 策略 4 **规划质量与 L4 世界模型联动**（治"规划与预测脱节"）
```
现状: L5 规划与 L4 预测**各算各的**（前者文本推理, 后者视觉潜空间）
改为: L5 规划时**查询 L4 的认知预测**（"若执行该序列, L4 预测观测如何演化"）
      → 用预测结果对候选规划**打分排序**（模型预测控制 MPC 思路）
实现: L5 产出 K 个候选序列 → L4 对每个做 rollout 预测 → 选预测代价最低的
成本: K 次 L4 前向（K=3 → ~400ms @ 10Hz 可接受）
理论依据: 符合"上层只给意图/条件, 执行由下层收口"的架构原则
```

## 三、不建议做的（有依据）

```
✗ **把 L5 换成更大的本地 VLM**（如 Qwen2.5-VL-7B）
   → 8GB 显存装不下（实测: SmolVLA+LEW 7.08G 已 OOM）; 端侧(Orin/Mac)更不可能
✗ **L5 端到端微调**（让规划器自己学策略）
   → 规划数据极少（阶段序列几十条级）→ 必过拟合;
     且 L5 的价值在"通用推理", 端到端微调会把通用能力磨掉（灾难性遗忘）
✗ **每条指令都调云端大模型**
   → 61s × 每步 = 闭环不可用; 成本也撑不住
```

## 四、落地路径（可执行）

| 阶段 | 动作 | 判据 | 预估 |
|---|---|---|---|
| P0 | 现状固化：L5 常驻 + 异步旁路（**已完成**）| 稳态 101ms | ✅ |
| P1 | 策略 3（schema + 三校验） | 非法序列拒绝率 100% | 1-2h |
| P2 | 策略 2（分级调用规范化） | 高频路径 <200ms 占比 >90% | 2-3h |
| P3 | 策略 1（复用 SigLIP 特征） | 省显存 + 免二次编码，规划质量不回退 | 半天 |
| P4 | 策略 4（MPC 式规划-预测联动） | 闭环成功率提升（A/B）| 1天 |

**优先级**：P1 → P2 → P3 → P4（先便宜的安全/延迟，再贵的表征统一/联动）

---

## 五、与全系统 pipeline 的关系

```
L5 在 pipeline 中的位置: L5 定方向 → L4 认知 → L3 调度 → L2 反馈
本次升级后:
  · L5 与 L4 **共享视觉表征**（策略1）→ 两层从"串联"变"共享总线"
  · L5 的规划**可被 L4 预测打分**（策略4）→ 两层形成**闭环协商**（非单向）
  · 均已在 tools/multi_layer_pipeline.py 的 Layer 契约内（换实现不改上下游）
⇒ 符合"模块化 / 管道化 / 可复制 / 可运维"要求
```
