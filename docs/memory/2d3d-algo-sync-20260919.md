## 一、深度算法 (depth_align.py, 620a5be0)：代码自检通过 ≠ 真机可用

| 项 | 飞书汇总 | 本机实测 (2026-09-18 晚) |
|---|---|---|
| 深度来源 | 「框 + 深度 0.42m → 3D [0.0017,0.0014,0.42]」 | 在役 `/realsense/depth/image_rect_raw` (16UC1 640×480) **全帧只有 2.0~5.0m**：2.00–3.00m 205204 px · 3.00–5.00m 58957 px · **<1.3m 共 0 px**；光模块框 [250,8,304,168] 内读到 median 2.926m |
| 对齐外参 | 由 `orin_d405_factory_calib.py` 取 | 该脚本在 Orin 上**取不到**：设备被在役驱动占用，`query_sensors()` 只回 `Stereo Module`，profile/extrinsics 读不出 → 外参目前是合成值 |
| 自检性质 | 5/5 全绿 | 自检是**合成场景**（第 184-185 行 ext 用 identity + 平移 10px 造图）→ 证的是函数自洽，不证真机可用 |

**结论**：`depth_align.py` 作为纯函数没问题，但**不能在真机链路上启用**（会把光模块报成 ~2.9m）。
要启用必须先解决：① 这条深度话题到底对着哪里（相机安装/朝向/是否被别的流占用）② 真正的 depth→color 外参。
在此之前，真机 3D 走「彩色内参 K + 机器人 FK 自监督手眼」这条路（已实测可用，见下）。

## 二、手眼 T_base_cam：从「只能报相机系」到「可自监督解出」

飞书汇总：「T_base_cam / plane_z 仍未标定 → 真机 3D 只能报相机系」。现状更新：

1. **彩色内参 K 已拿到（白拿，不需要标定设备）**：`/realsense/color/camera_info` 给出 D405 出厂标定
   fx=394.06 fy=393.47 cx=318.44 cy=238.66 @640×480（⚠️ 不是仿真那套 fx=610）。
   已落 `models/real_cam_calib.json`（`tools/calib_fetch_realsense_intrinsics.py`，只订阅零发布）。
2. **手眼可以不靠棋盘格解**：有 K 后未知量只剩 手眼(R,t) + 夹持偏移 off + 夹持歪斜 R_rel，
   由「YOLO 框 + 机器人自身 TCP 位姿（编码器）」自监督拟合（`Box3DSolver`，米制锚定）。
   实测（合成留出 40 帧，真值只打分）：
   - K 已知 + 解 手眼/off/R_rel → 3D 边界框中心 **3.71mm** · 8 角点 **3.98mm** · 姿态 3.1° · 反投影 IoU 0.93
   - 不估 R_rel → 中心偏 **77mm**（歪斜被 off 吸收）| 尺寸与 off 联合解（无 K）→ 偏 **65mm**（退化）
3. **彩排（走现场同一套函数 + 真机 K）**：正例 rms 0.86px、前提自证 IoU 0.874 → 落盘 → 留出 40 帧 8 角点 **5.23mm**；
   反例（模块没被夹、台面静放）→ IoU 0.226 → **拒绝落盘**。
4. **现场只差一个动作**：拖动模式下把模块（在爪上）走 ≥10 个不同位姿 → 自动拟合 → `models/box3d_state.json`。
   哨兵 cron `3cae27b292b6`（每 15min）已保活采集进程并在标定落盘时只报一次。
   落地后真机 3D **报 base 系**，不是相机系。
   （平面 plane_z 仍缺：模块躺台面时才需要，用工装高度量一次或夹爪示教即可。）
