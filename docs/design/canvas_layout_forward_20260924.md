文件: `flows/state_space_obs.json`（83 节点 · 132 连线 · 16 行带）· 工具: `tools/relayout_canvas_v2.py`

## 二、算法（v2 相对 v1 的改进）

1. 断环 → DAG（反馈线优先被断，主链受保护）→ `rank` = 最长路径层级；
2. 行带保持语义不动；**行内顺序**作为搜索变量：重心排序（前驱/后继双向扫）+ **相邻交换局部搜索**；
3. 参数网格 (PITCH 540/700 × 排法 pack/grid × 行间距) 取交叉最小；
4. 每轮 `repair` 保证 DAG 边严格左→右；`kill_overlaps` 清零重叠；`vspace` 纵向留白；
5. 写入前硬断言：前向违规 0 · 重叠 0 · 节点/连线数不变 · 端点全在 → 才落盘（自动备份）。

**被实测否决的方案**: 行带按"因果序"重排（数据源→L2感知→L3→L4→L2收口→执行）——
交叉反而 639/649（> 571），因为感知层上移后，它到下方记忆/收口层的连边变成更长的跨层线。**保留原行序**。

## 三、为什么交叉只从 551 降到 571：几何已到极限，真瓶颈是"线本身"

交叉数是**拓扑量**（由连边端点的相对左右顺序决定），加宽画布 / 拉开间距**不改变**它。
单条线交叉数 top（现布局）：总装记忆中枢→Feature 清单 33 · YOLO→L4 环境渲染图像源 32 ·
流形专家预测器→通用算子A 30 · 肌肉记忆技能库→动作调制器 28 · 传感器融合→INTACT 22。

**132 条线里有 53 条是"传递冗余候选"**（A→C 同时存在 A→…→C 的绕行路径）。实测删除投影：

| 删除条数 | 交叉数（快算口径，基线 479） |
|---|---|
| 删 5 条 | ≈ 331 (-31%) |
| **删 10 条** | **≈ 265 (-45%)** |
| 删 15 条 | ≈ 202 (-58%) |
| 删 30 条 | ≈ 103 (-78%) |

单条降幅最大: 🧭能力档位→⚡前馈加速器 (-37) · 🧠总装记忆中枢→🧩Feature清单 (-33) ·
🎯YOLO→🧪L4环境渲染图像源 (-32) · 💪肌肉记忆技能库→🧭动作调制器 (-28) · 📡传感器融合→🎯INTACT (-25)。

→ **删线是语义改动，等老倪点头**（候选清单见 `reports/` 脚本输出；我的建议：只删"绕行链已承载同一语义"
的那批，并在 desc 里注明"经 X→Y→Z 链路传递"）。

## 四、复现 / 运维

```bash
python3 tools/relayout_canvas_v2.py --measure                 # 纯体检(不改)
python3 tools/relayout_canvas_v2.py --band-order keep --x-mode grid --pitch 700 --gap 300 --vgap 100   # dry-run
python3 tools/relayout_canvas_v2.py --apply --x-mode grid --pitch 700 --gap 300 --vgap 100            # 写入(自动备份)
```
