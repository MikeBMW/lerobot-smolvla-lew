## 4. 两个根因 (都定位到代码行)

### 4.1 场权写死太低 (记忆层"在场但不使劲")
`src/lerobot/memory/potential_field.py::blend_action` 旧式 `w = w_max·max(conf, w_floor)`,
桥调用 `w_max=0.5, w_floor=0.2`, 现场 `conf ≡ 0` (离最近轨迹管 207mm) ⇒ **w̄ 恒 0.1**。

**修法 (增益调度, 可测):**
```
far = clip((d_perp − d_near)/(d_far − d_near), 0, 1)
w   = max(w_max·max(conf, w_floor),  w_far·far)        # 默认 w_far=0.85, d_near=30mm, d_far=150mm
```
在管内 (d_perp < 30mm) 维持原公式 → **不回退**; 远场 (模型跑飞) 让记忆场主导 → 才有"救援"能力。
`far` / `w_far_gain` 写进每步诊断, 便于同口径对比。

### 4.2 模型动作塌缩 (这条路的天花板)
`IntentActionActor` 输入 = 潜槽 `[z_t, m_t, z_t·m_t]` + 上一动作嵌入 (**无本体/几何输入**);
`grep observation train.py jepa.py module.py` **零命中** —— 数据集 `optical_insert_v4.h5` 里明明有 39D `observation`,
**却从来没人消费**。224²/patch14 的潜空间补不出亚毫米几何 ⇒ 动作头预测条件均值 ⇒
预测幅度只有教师 **7~22%** (v3/v4/v5 全如此) ⇒ 判闸输给常数基线 (0.0424 vs 0.0368)。

→ 这正是"记忆层势场"要补的东西; 但模型侧也有明确改进路径 (见 §5 v6)。
