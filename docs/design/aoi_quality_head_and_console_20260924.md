# 外观质量检测 · 质量检测任务头 + 汇总终端窗口 方案 (2026-09-24)

> 需求原话 (老倪): 「外观质量检测节点，要进行光模块的金手指缺陷检测，以及外观划伤检测；仿照 YOLO 目标检测节点
> 右键打开新窗口的功能，在外观质量检测节点上右键打开一个新窗口，能够将光模块金手指检查技能、图像定位、拉伸等技能，
> 以及光模块外观检测、外观图像的显示、缺陷显示、框选，以及当视频里看到新缺陷的时候，能够马上标定，进行在线的
> YOLO 训练，可以参考之前的 YOLO 目标检测的标定和训练过程。这个节点是 YOLO 模型的一个新的**质量检测任务头**
> ——你来设计任务头训练方案，并增加 UI 窗口的技能交互方式；即这个窗口是**质量检测的汇总终端窗口**」

## 0. 设计要点 (三句话)
1. **一个任务头, 两个角色**: 「质量检测任务头」= YOLO 检测头 + **AOI 类别 schema** —— 定位类框给 **ROI**(图像定位/拉伸),
   缺陷类框给 **缺陷**(金手指划痕/污染/氧化/崩缺 + 外观划伤/变形/污渍)。同一个头既做定位又做缺陷, 不新增第二网络。
2. **两级级联推理**: 全帧先跑定位类 → 取金手指/本体 ROI → **裁剪拉伸到判据分辨率** → ROI 内跑缺陷类
   (小缺陷在高分辨率下才可见; 全帧直接跑大分辨率既慢又漏)。
3. **在线闭环**: 窗口里看到新缺陷 → **立刻框选标定** → 追加标注库 → **增量微调**(基座=在役质量检测权重) →
   真推理验证 → 人工确认后才软链在役 (老倪门槛: 有提升非仅不回退)。

## 2. 质量检测任务头

### 2.1 类别 schema (单一真源, 与 DET-AOI-01~04 对齐)
| 组 | 类名 | 对应 | 用途 |
|---|---|---|---|
| **定位** loc | `module_body` | 光模块本体 | 外观 ROI |
| | `gold_finger` | 金手指区域 | **金手指检查 ROI** (DET-AOI-01) |
| | `optical_port` | 光口/端面 | 端面清洁度 ROI (DET-AOI-02) |
| **缺陷** defect | `gf_scratch` / `gf_contam` / `gf_oxide` / `gf_chip` | 金手指划痕 / 污染 / 氧化·镀层缺损 / 崩缺 | 金手指缺陷检测 |
| | `app_scratch` / `app_deform` / `app_stain` | 外观划伤 / 变形·毛刺 / 污渍 | 外观划伤检测 |

- **为什么用检测框而不是分类**: 缺陷要**位置** (供 AOI 复检/复焦/剔除引导), 且一张图可多缺陷 → 检测头天然支持。
- 与现有启发式的关系: 启发式 (Canny+霍夫/斑点/灰度偏移) 给**可解释数值**并映射到 `DET-AOI-0x` 判据;
  学习头给**位置 + 类别 + 置信度**。两者**同表对照**, 学习头未证明提升前不替代启发式 (老倪门槛)。

### 2.2 两级级联 (图像定位 → 拉伸 → 缺陷)
```
全帧 ──(定位类)──→ gold_finger / optical_port / module_body 框
        │
        ├─ ROI 裁剪 + pad → 拉伸到 640² (可选 2× 超采样)   ← 「图像定位/拉伸」技能
        │
        └─(缺陷类)──→ 缺陷框 (回到全帧坐标 = 逆变换) ──→ 判决表 (DET-AOI-01~04)
```
- **坐标口径**: 框一律存**原始帧像素坐标** (与现有标定层一致); ROI 拉伸只用于推理, 结果逆变换回原帧。
- **超采样**: 金手指占画幅比例小 (实测 2448×2048 全帧, 金手指通常 <8%) → 直推 640 会丢小缺陷;
  拉伸到 640 并把阈值/最小框面积按放大倍率换算 (放大 k 倍 → 最小缺陷像素阈缩小 k²)。
- **兜底**: 无权重/无检出 → 回落启发式 (`AOIQualityChecker`), 判决表标注 `source=heuristic` (不假装是模型)。

### 2.3 训练方案
| 项 | 设定 | 依据 |
|---|---|---|
| 数据源 | `data/yolo_aoi_annot` (新增数据根; 真机 ‖ 仿真分开) | 与目标检测数据物理隔离, 防类别语义打架 |
| 类别表 | `classes.txt` = 上表顺序 (定位类在前, 缺陷类在后) | 行号=class id; 顺序进 schema 版本, 改动=大版本 |
| 基座 | `--base auto` → **在役质量检测权重** (首次 = `yolo_peg_live.pt` 域适应微调); 无则 `yolov8n.pt` | 复用域内特征, 小样本友好 |
| 训练 | `yolo_annot_train.py --root data/yolo_aoi_annot --epochs 100 --imgsz 640 --batch 8 --cos-lr` | 体检不过不训 (退出 2) |
| 小样本 | <8 张时 val 复用 train 并**显式标注** `val_overlap_train=true` (mAP 不可信) | 已有机制 |
| 判据 | 定位类 mAP@0.5 ≥ 0.98 · 缺陷类 mAP@0.5 ≥ 0.90 · 现场留出集逐类召回 ≥ 0.85 · 与启发式同口径对照**不回退** | DET 目标 + 老倪门槛 |
| 上线 | 训练完 → 真推理验证 → **人工点「切到在役」** → 软链 `models/yolo_aoi_live.pt` | 不自动切换 (在役链路零意外) |
| 在线增量 | 窗口内「马上标定」→ 追加样本 → 后台增量微调 (基座=当前在役) → 日志实时回显 | 缺陷样本稀有 → 增量比全量重训快 |

### 3.2 技能交互 (每个按钮 = 一个真函数, 不是占位)
| 技能 | 行为 | 实现 |
|---|---|---|
| 🔍 金手指检查 | 定位 `gold_finger` → 拉伸 → 缺陷检测 + 启发式数值 → 判决表 | `AoiQualityHead.inspect(frame, roi="gold_finger")` |
| 🪞 外观划伤 | 定位 `module_body` → 同上 (类含 `app_scratch`) | 同上 `roi="module_body"` |
| 🔘 光口端面 | 定位 `optical_port` → 端面清洁度 (划痕/污染/端面破损) | 同上 `roi="optical_port"` |
| 🖼 全帧扫描 | 不做 ROI, 直接全帧推理 (快速普查) | `roi=None` |
| 图像定位/拉伸 | ROI 框 + 手动拉伸倍率 (1×/2×/4×) → 画面与推理同步 | `crop_stretch()` |
| ✏️ 标定模式 | 画面上拖框 → 选类别 (定位/缺陷) → 💾 保存 (原始帧坐标) | `yad.save_sample()` |
| 🚀 在线训练 | 后台增量微调 (基座=在役) → 日志实时回显 → 完成真推理验证 | `yolo_annot_train.py` 子进程 + 日志轮询 |
| ⬆ 切到在役 | 人工确认后软链 `models/yolo_aoi_live.pt` + 记录旧链 (可回滚) | 软链 + 备份 |

### 3.3 快捷键 (复用现有口径, 输入框有焦点不抢键)
`Enter` 保存标注 · `N` 保存并下一帧 · `F` 冻结 · `1-9` 选类别 · `Del` 删选中 · `Ctrl+Z` 撤销 ·
`S` 换技能 · `G` 开/关金手指 ROI 高亮

## 4. 数据流 (窗口 ↔ 数据层 ↔ 训练)
```
真机帧(Orin srv→Docker→本地) / 仿真帧(metaworld corner2)
   → 窗口画面 (帧龄校验, 负帧龄拒用)
   → 推理: AoiQualityHead (定位→ROI→拉伸→缺陷) ‖ 启发式 AOIQualityChecker
   → 判决表 (DET-AOI-01~04 + 数值 + 阈值 + 结论)  → 导出 JSON/Excel
   → 标注: yad.save_sample(原始帧坐标) → data/yolo_aoi_annot/sessions/<会话>/…
   → 构建: yad.build_dataset() → dataset/{images,labels}/{train,val} + data.yaml + stats.json
   → 训练: yolo_annot_train.py --root data/yolo_aoi_annot (后台, 日志回显窗口)
   → 验证: val 抽样真推理 + 与启发式同口径对照 → 人工「切到在役」
```

## 6. 风险与红线
- ❌ **不自动切在役**: 训练完只提示, 切换必须人工点 (在役链路零意外)
- ❌ 学习头未证明提升前**不替代**启发式 (同表对照, 数值可解释); 无权重时必须明标 `source=heuristic`
- ❌ 不做"拿旧图冒充实时": 帧龄校验 (负帧龄/超龄拒用并如实标)
- ❌ 数据不进代码库 (`data/` 已 .gitignore); 类别顺序 = schema 版本, 改动需同步 `detection_targets.json`
- ✅ 所有技能按钮 = 真函数 (禁止占位按钮); 判决与缺陷一律带数值/阈值/来源
