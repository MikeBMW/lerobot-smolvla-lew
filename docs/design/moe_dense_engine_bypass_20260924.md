# MOE / 统一主干 · 引擎闭环只读旁路 + 同源三方对照 — 2026-09-24

**结论一句话**: 两个模型都能**每帧真调、零回退、延迟合格**; 但**认知头打不过最朴素的持久基线**
(同源 3.3×/5.2×, 引擎流 29×/40×) → 按交付门槛(有提升非仅不回退)**都不具备接管条件**。
真因不是"模型坏了", 是**任务定错了**: "预测下一帧观测"在 10Hz 平滑轨迹上几乎无信息量。

## 一、每帧真调 (只读旁路 · 动作不参与下发)

工具: `tools/moe_engine_bypass.py --model {moe,dense}` (同一套旁路框架, 两模型同口径可比)

| 项 | 阶段专家 MOE (①-2③) | 统一主干四头 dense (①-3) |
|---|---|---|
| 真调帧数 (10 seed × 600 步, 含对照) | **52,212 帧 · 0 失败** | **52,212 帧 · 0 失败** |
| 单帧延迟 (mean / p50 / p95) | 9.67 / 9.53 / 10.36 ms | 9.47 / 9.35 / 10.22 ms |
| 引擎控制周期 100ms (DT_ENV=0.1) → 占预算 | **9.7%** (上限 ~103Hz) | **9.5%** (上限 ~106Hz) |
| 渲染取证成本 (仪表, 不计入模型) | 0.95 ms/帧 | 0.99 ms/帧 |
| 零回退 (同 seed 对照 vs 旁路) | **10/10 dist 逐位相同 (max 差 0.0mm)** | **10/10 逐位相同** |
| 任务结果 (done) | 旁路 5/10 = 对照 5/10 | 旁路 5/10 = 对照 5/10 |

挂点: `sim.env.step` (引擎 `run()` 里唯一每步一调的物理推进点) → 计数必须 == 步数, 实测成立。
口径核对 (与训练逐项对齐): obs = `sim._obs39()` == `env._get_obs()[:39]` (与 h5 `observation` 同源);
px = `env.render()` → 224×224; MOE 侧仅 `/255` (同 `stage_moe_backbone` 训练), dense 侧 `to_img()` = `/255` + `(x-0.5)/0.5` (同 `joint_unified_backbone` 训练); mem = `zeros(13)` (训练侧即 `torch.zeros(B,13)`)。

## 四、跨域缺口的机理 (不是玄学, 是尺子不同)

工具: `tools/obs_step_delta.py` → `reports/obs_step_delta_engine_vs_h5.json`

| 域 | 帧间 \|Δobs\| 均值 | p50 | p95 |
|---|---|---|---|
| 引擎 (seed104, 60 步) | **0.000298** | 0.000246 | 0.000541 |
| 采集集 (h5) | **0.002966** | 0.001058 | 0.010884 |

→ 采集帧间位移 ≈ 引擎每步的 **10×** (均值) ⇒ "预测下一帧"这个任务在两边的**难度本身就不同源**,
持久基线在引擎上天然近乎完美。**"跨集比对必先验逐维"这条老铁律第三次应验**。

## 五、判决与下一步 (按交付门槛)

- **判决**: MOE / dense 均**不接管**任何段 (保持只读旁路姿态, 默认档零改动)。
- **真问题**: 认知头的训练目标是"预测下一帧观测" —— 无信息量。改法是**换靶子**, 不是加大模型:
  1. 预测**多步** (K=5/10) 或**事件级**量 (接触发生/阶段切换/残余插入深度) —— 与持久基线天然拉开差距;
  2. 一律**带持久基线 + 平凡基线**同表对照 (评估铁律);
  3. 若仍要跨域用, 需**引擎域同源数据**重训/微调后再评。
- 旁路框架已就位 (`moe_engine_bypass.py`), 换靶子后**同一套脚本**直接量"H 步/事件级"指标, 不用重建链路。
