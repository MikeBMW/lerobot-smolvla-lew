## 一、架构 (四流形 + 李群结构)

| 对象 | 流形 | 表征 | 在本工程里的落地 |
|---|---|---|---|
| INTACT 旋转意图 | SU(2) | ω = log(ΔU) ∈ su(2)≅R³ | Φ_su2: 意图 Δz(192) → ω (腕/绕插拔轴) |
| INTACT 刚体意图 | SE(3) | ξ = (ω, v) ∈ se(3)≅R⁶ | Φ_se3: 意图 Δz → ξ = log(T_ee(t+1)T_ee(t)⁻¹) |
| 动作流形 A | 平移 twist 部分 | u = (v_x,v_y,v_z,grip) | 引擎动作 (旋转走 yaw 通道, 另有 SU(2) 路) |
| 接触流形 C | SE(3) 上的 twist | e = log(T_hole⁻¹·T_peg) | **孔系表达**的接触误差 (位置+姿态同一 twist) |
| 性能流形 P | 以 C 为底空间 | F_P(6) | 只作条件不注入 (插拔次要) |
| L2 执行 | 肌肉记忆/解析伺服 | 唯一出口 | 幅度包络 (每层只能收窄) |

数据流:
```
INTACT 预测潜空间 Δz
   ├─Φ_su2→ ω(3) ──┐
   ├─Φ_se3→ ξ(6) ──┴→ ① DiT 几何 token [δ(192) ⊕ ξ(6) ⊕ ω(3)] = 201 维
                      ② 导航方向参考 u_dir = unit(ξ_v)·‖u_ff_L2‖  (幅度按 L2 包络收窄)
                           ↓
                      🎚 切空间增益融合: u = (1−K_nav)·u_L2 + K_nav·u_dir (+K_flow·u_DiT)
                           ↓ 方向/幅度闸 (cos≥0.9, ≤1.5×) → 否决则交回 L2
                           ↓ L2 收口 (sched.decide + safety.saturate, 唯一出口)
```

## 二、数学 (实现见 `src/lerobot/manifold/lie_intent.py`, 纯 numpy)

- SU(2): 四元数乘法/共轭, log/exp, **双覆盖消歧 w≥0**, SLERP 测地线插值
- SE(3): so3_exp/log (含 180° 分支), se3_exp/log 闭式 (V 矩阵), 群合成
- 接触丛: `e = log(T_hole⁻¹·T_peg)` —— 与旧欧氏 F_C(6) 的差别: 姿态误差与位置误差同 twist,
  且**坐标系固定在孔上** ⇒ 同一物理误差在不同世界位姿下数值一致 (可跨场景比)
- 增益融合在**切空间**做: ξ_fuse = (1−K)ξ_L2 + K·ξ_nav, 含旋转时即群上测地线插值
  (K=0 逐位等于 L2 = 零回退; K=1 恰好 nav; 中间 = 测地线中点, 不越出流形)
- Φ 标定: PCA(32) + ridge + LOO 交叉验证, 闸 R²_loso ≥ 0.30 且 null < 0.10 (同仓既有口径)

## 四、诚实边界 (本轮没做完的)

   "整体更新模型" 在这一轮 = 新增两路几何映射与条件 token, **不是**重训网络。

### ② yaw/姿态通道并进唯一出口 — ⚠️ 接线完成, 本轮**失败证据** (不许说成通过)

先纠正一个前提: **引擎动作里没有旋转维** (u = dx,dy,dz,grip; 姿态走 `env._grip_yaw`), 全仓 `_grip_yaw`
只被演示链 (gen_l4_demo_video / 探针) 使用 ⇒ "让 SU(2) 参与控制"的唯一真实出口 = 演示链的 yaw 段。

做了什么: 新增 Arm C (`_align_yaw_su2`) + 夹持后几何闭环 (`align_yaw_su2_loop`), 几何量 =
`yaw_from_twist(contact_twist(T_peg, T_hole))` (孔系绕轴残差, 直读 MuJoCo `site_xmat`), 与脚本参考在
切空间按增益 K 融合 (一维李代数凸组合, K 来自同一套事件→Q 增益)。

三臂实测 (seed 0, yaw 段):

| 臂 | 收尾 φ | 几何需求 Δφ | K 均 | 说明 |
|---|---|---|---|---|
| script (现状) | 89.38° | +90.28° | — | 脚本开环 90° |
| mani (Arm B) | **−45.33°** | +90.28° | — | 流形/试抓头决策, 与几何需求差 135° |
| su2 (Arm C) | **90.00°** | +90.28° | **0.0** | K=0 → 逐位退回脚本参考 (熟场景不抬增益) ✓ |

失败证据 (插入段 2 臂, 全链跑):

| 臂 | 结果 |
|---|---|
| `SS_L4_LIE_YAW=0` | ⑤ 插入**成功**: 真物理推入深度 **49.4mm** (目标 50mm, 到位) |
| `SS_L4_LIE_YAW=1` | **夹持验证失败**: 模块随动 Δz=0.7mm / 指令 12mm (yaw=90.0°) → 未夹住, 根本没走到插入 |

根因 (诚实): Arm C 的 yaw **指令**在 K=0 时等于脚本 (90.00° vs 89.38°), 但**步数不同** (54 步 vs 脚本
~100+ 步) → ② 段的治具/闭夹物理时序被推移 → 抓取姿态失效。也就是说"指令等价"不等于"轨迹等价",
② 段对时序敏感。
另外发现: **② 段(t空夹爪)的 twist 由转台决定, 夹爪转不动它** ⇒ 那里 Δφ_L4 不是可控目标 (所以才 K=0);
SU(2) 残差**真正可控的段是夹持之后** (插入前对准) —— 已在那里接了几何闭环 `align_yaw_su2_loop`
(残差 → <0.5° 才放行, 否则后面的姿态预检会拦), 但本轮因为上游抓取失败**没跑到**, 未验证。

下一步 (②): (a) 让 Arm C 与脚本臂**同步数与同停止条件**(同一 slew 与收敛判据) 再 A/B;
(b) SU(2) 对准只在夹持后段参与 (预抓取段让位脚本); (c) 用 `yaw_grasp_probe.py` 的物理判据
(抬升 Δz>0.08m) 做成功率同口径对照。
