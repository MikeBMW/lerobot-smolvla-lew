# 动作可学性剖面 + 直驱闭环失败判别 (2026-09-13 实测, 光模块插拔新场景适配)

场景: 用 INTACT 现有架构/权重, 只换新数据 (光模块插拔/引擎真链路轨迹), 微调后直驱开引擎,
目标 = 出"INTACT 成功插拔"视频。**结果: 未达成** —— 本文记录的是"怎么在 2 小时内判死这条路",
而不是成功配方 (避免以后重复烧算力)。

## 1. 时间线 (哪一步花了多久, 结论在哪一步出现)

| 步 | 内容 | 实测 |
|---|---|---|
| 0 | 引擎真链路冒烟 (既有采集器, 不改代码) | 8 seed 70s, 成功 4/8; 帧 std 55-56 (真图) |
| 1 | v3 数据集: 600 长回合 (cap=l4 自主恢复) → 成功 531, 切 50 步"插入段末尾"窗口 | 2124 窗口 / 106,200 帧 / 4.9GB h5, 35min |
| 2 | 微调 (官方 pusht 权重初始化, 只新增 config) | 1 epoch ≈ 33min (4181 step @2.1 it/s), batch32 OOM→16 |
| 3 | **离线判闸 (epoch1)** | 模型 xyz MAE 0.0203 vs 常数基线 0.0189 ⇒ **不如常数**; 预测std/教师std = 0.0026/0.055 ≈ 1/21 ⇒ 塌缩 |
| 4 | **闭环直驱 (同轮带解析链对照)** | 解析链 seed0/1 done=True 插入 65.1/65.4mm; 直驱 3/3 seed done=False 插入 658.8/289.2mm (**过冲**), 每步真推理 700 次 |
| 5 | 剖面定位根因 | 见下 §2 |

## 2. 剖面数字 (决定性的那几行)

v3 数据 (env 级动作列 = `env.step(act)` 收到的动作) 逐维统计:

```
全量   mean [-0.0935 -0.0007 -0.0067 0.600]   std [0.0519 0.0038 0.0158 0.0000]
回合内 std 中位 [0.0218 0.0046 0.0131 0.0000]   ← grip 恒 0.6, dy 近乎恒定
回合内 std<0.005 的回合占比: dx 0% · dy 100% · dz 49% · grip 100%
抽样轨迹 (50 步窗口): dx 从 -0.1206 缓慢爬到 -0.0963 (有结构但幅度小); dy/dz/grip 基本不动
```

同一轮引擎内部信号 (tr 键) 逐帧 std:

```
u_sat_vec/u_exec_vec/u_fuse_vec [0.082, 0.072, 0.057, 0.474]   ← 有信息量
u_fb_vec                        [0.001, 0.001, 0.001, 0.000]   ← 反馈项几乎为 0
residual_vec                    [0.003, 0.003, 0.002, 0.168]
```

⇒ 结论: ① env 级动作在插入段就是**饱和速度指令**, 智能在"相位时序 + metaworld 物理";
② 只有插入段的窗口把这条列的方差吃掉了 (dy/grip std → 0), 换成全相位窗口才有相位间方差;
③ 观测上"引擎自己的解析链"能靠同一条饱和指令插进去, 模型直驱不行 —— 因为模型没有阶段/时序先验。

## 3. 数据口径修正 (下一步该这么采, 未验证闭环结果)

- 窗口: `--coverage all` 按 stride 铺满整回合 (接近/对位/下降/抓取/抬起/转移/插入), 不再只取插入段。
- 动作列: `--action-key u` 记 `sim._u_vec` (引擎实际控制向量)。冒烟实测 std 从
  `[0.052,0.004,0.016,0.000]` → `[0.103,0.019,0.055,0.477]`。
- 口径: 成功回合 only (= 官方 `*_single_expert` 语义) + `cap=l4` (引擎自主恢复档, 成功率 36% → 88%)。
- ⚠️ 这套只是把"可学性"往上抬, **闭环成没成仍未验证**; 交付前必须跑 §4 的闭环判据。

## 4. 交付判据 (不许把"链路跑通"说成"成功插拔")

1. 离线判闸: 模型 MAE **显著**低于常数基线 + 预测std/教师std 同量级 (>0.5)。
2. 闭环: 同进程同 seed 同轮, 直驱 `done=True` 且插入深度 ≈ 解析链对照的 65mm 量级 (不是 658mm 过冲)。
3. 视频: 真渲染帧 (逐帧 std>5) + 真推理次数 > 0 + 动作真下发 (无解析兜底)。

## 5. 本次踩到的工程坑 (与结论无关但会再遇到)

| 坑 | 症状 | 修法 |
|---|---|---|
| INTACT runtime 选择 | 判闸/闭环报 `InstantiationException: Error locating target 'module.IntentActionActor'` | 根 `train.py` 训出来的 ckpt 必须 `INTACT_RUNTIME=root` (paper_runtime 里是同名 `module.py` 的另一个类) |
| 训练数据名 | `Cannot resolve 'optical_insert_v3': not a local path or HF repo id` | train.py 走 `load_dataset→_resolve_dataset`, 按字面文件名在 `<LOCAL_DATASET_DIR>/datasets` 找 → **名字必须带 `.h5`** (带扩展名后若再被 `HDF5Dataset` 加一次会变成 `.h5.h5`, 两条路径口径不同, 别互相套用) |
| 8GB 卡 | batch32 `CUDA out of memory` (峰值 7.6/7.62GiB) | batch 16 |
| 采集脚本相对路径 | bridge/引擎脚本内部 `os.chdir()` 后相对 `--status/--spool` 失效 (`FileNotFoundError ... status.json.tmp`) | 传**绝对路径** |
| 逐帧信号日志 | 只有最后一帧的 status.json 覆盖式写入 → 无法"看任意帧信号" | 每步追加 `status.jsonl` (一行一帧: step/action/frame_std/done/model_calls), 运行开始时清空 |
