# 专家混合架构（MoE）设计与路由诊断

## When to Use
- 一个密集头要同时拟合**性质不同的子任务**（例：视觉认知 vs 接触动力学），怀疑互相干扰
- 任务有**已知的离散分段/阶段**（工序阶段、技能、任务类型）→ 天然适合"一阶段一专家"
- 想在**几乎不增参数量**的前提下增加模型容量（稀疏激活）
- 已有 MoE 模型但**怀疑退化成单头**（门控不分化）→ 需要诊断
- 判断"这个场景该不该上 MoE"（见末节反例）

## 核心设计：先验路由 + 稀疏专家（小数据可用）

```
共享编码(冻结主干) → h
                       ↓
门控 g = softmax( stage_onehot @ P  +  MLP(h, stage) )
                  └─ P: 可学习先验矩阵(eye×strength)  └─ 残差修正项
                       ↓
[E0..Ek] k 个专家（每个 = 小头, 只学自己的子任务）
                       ↓
out = Σ gᵢ·Eᵢ(h)    训练: top-1 硬路由 + STE（前向硬/反向软）
```

**为什么用"先验路由"而不是端到端学路由**（小数据关键）：
- 学出来的路由在几万~十几万样本上**极易崩塌**到 1-2 个专家（赢家通吃）
- 已知阶段先验 = 免费的正则，把路由初始化到"正确"位置，MLP 只做微调 → 训练稳定
- 先验强度 `prior_strength`（实测 4.0）是唯一需要调的旋钮：太大 → 僵化；太小 → 崩塌

**参数量几乎不涨**（实测）：主干 86.4M 冻结 + **7 专家共 1.42M 可训**，而密集单头版是 1.13M。
⇒ 只要每个专家是**小头**（实测 expert_hidden=192），7 个专家也只比 1 个大 25%。
⇒ 别在**冻结的预训练主干里**插专家（会破坏预训练表征且显存暴涨）—— 只在**头上**做。

## ⚠️ 路由信号必须真的存在（第一道门）

MoE 改造**先确认数据里带路由信号**，否则门控拿不到 stage → 退化成均匀先验 → 白做。

```python
# 先探数据字段，别假设
import h5py, numpy as np
f = h5py.File("data.h5", "r")
print([k for k in f])                      # 找 stage/skill_ctx/phase 之类
sk = np.asarray(f["skill_ctx"][:2000])     # 实测: dim13:20 = 7 阶段概率
s7 = sk[:, 13:20]
print("行和", s7.sum(1).min(), s7.sum(1).max())    # ≈1 → 概率分布(路由信号)
print("argmax 分布", np.bincount(s7.argmax(1), minlength=7))   # 各阶段样本量(看有没有阶段饿死)
```
**踩过**：合成数据（L5 造的数据）**没有** `skill_ctx` 字段 → DataLoader 直接
`KeyError: object 'skill_ctx' doesn't exist`。多数据集混训时，**每个** h5 都要有该字段。
备选：让生成器补写该字段，或让 MoE 的 stage 从引擎 `sched.stage()` 在线注入。

## 路由分化诊断（这是"MoE 是否成立"的唯一判据）

**必须跑**，不能只看 loss —— 门控不分化 = 退化成单头，MoE 白加。

四条指标（脚本形态见 `scripts/moe_gate_diagnose.py` 思路）：
| 指标 | 含义 | 通过判据 |
|---|---|---|
| ① **阶段→专家混淆矩阵** | 每个阶段主要路由到哪个专家 | 看主导占比 |
| ② **路由熵** | 平均 −Σg·log g（越低越专一）| 明显低于 log(k) |
| ③ **有效专家数** | 真被用到的专家数 | = k（否则有专家**饿死**）|
| ④ **阶段-专家一一对应率** | 主导占比 >50% 的阶段数 / 总阶段 | ≥ (k−1)/k |

**实测结果（7 阶段机器人任务，VLM 主干 + 7 专家）**：
```
② 路由熵 0.259（上界 log7=1.946）→ 很专一
③ 有效专家 7/7 ✅
④ 一一对应 6/7 ✅ 分化成立
矩阵关键行: 下降→E2(42.5%) · 抓取→E3(73.3%) · 插入→E6(69.3%)   ← 三个"接触段"各自独立
            接近/对位/抬起/转移 → 共用 E0   ← 视觉/行为相似段没强行拆开
⇒ 分工**符合物理直觉**: 该分的分了(接触动力学差异大), 不必分的合了(视觉相似)
```
这种"部分分化"才是**健康**结果 —— 若强行要求 k/k 一一对应，说明先验强度过大（僵化）。

## 训练配置要点

- **两阶段配方同样适用**：阶段1 加几何/域增强（练表征）→ 阶段2 关增强短程微调（回精度）。
  机理：增强改表征、微调只动输出头，二者不冲突。见 `edge-finetune-automation` §07b。
- **判据照旧**：留出集 + **平凡基线**（观测恒均 / 动作恒均），训练 loss 不作证据。
- 阶段先验做路由时，**留出集的先验要用同一套编码**（同一 `stage_from_ctx`），否则离线与在线口径不一致。
- 兼容**单样本与批量**：`stage_from_ctx` 要能处理 `(24,)` 与 `(N,24)`，否则 DataLoader 单条取样就报
  `IndexError: too many indices for array`（踩过）。

## 反例：这些情况别上 MoE

```
✗ 数据量小到每专家分不到样本（实测 108k 帧 ÷ 8 专家 ≈ 13.5k/专家 = 边界;
  再少就饿死 —— 通用 MoE 动辄 B 级 token）
✗ 为"参数量大"而 MoE：端侧(Orin/Mac/消费卡)显存是硬约束, 且稀疏专家对
  推理框架(TensorRT/端侧)支持差, 省不了显存
✗ 在冻结的预训练主干里插 MoE（破坏预训练表征 + 显存暴涨）→ 只在头上做
✗ 路由信号不存在且无法在线注入 → 先补信号再谈 MoE
✗ 任务无天然分段（连续单一技能）→ 专家没有分工依据, 退化成集成
```

## 关键提醒：MoE 收益必须闭环验证，别只看离线

离线指标提升（留出 MAE 下降）**不等于**任务收益。实测教训：统一主干离线
0.008（vs 旧架构崩到 45），但闭环 A/B（n=10 逐 seed 对齐）**成功率完全相同（7/10 vs 7/10）**，
失败点同源。⇒ 上 MoE 前先想清楚"哪个下游指标该变"，并准备**逐 seed 对齐**的闭环 A/B。
详见 `zmax-joint-training-deploy` 的闭环 A/B 章节（含宿主融合权重稀释、
内存累积导致的长跑 OOM 与单局模式绕法）。
