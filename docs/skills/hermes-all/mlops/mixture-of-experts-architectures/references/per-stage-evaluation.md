# 按阶段拆解评测（2026-09-24 实测 · MoE 价值只有拆开才看得见）

> 与 SKILL.md「路由分化诊断」、`references/gate-collapse-and-metric-false-positives.md` 同读。
> 前者判"门控有没有真的分工"；本文件判**"分工到底有没有用、用在哪"**。

---

## 1. 问题：全局 MAE 会同时掩盖和误导

三个模型，同一份数据（v6_sub25k）、同 2500 步、同几何增强、同留出集：

| 模型 | 门控单射性 | **全局** 观测 / 动作 |
|---|---|---|
| 密集单头（基线） | — | 0.0124 / 0.0502 |
| MoE `soft`（门控**坍缩**成 1 专家） | 1/k ❌ | **0.0092** / 0.0510 ← 全局最好 |
| MoE `prior`（硬先验路由，**真分工**） | **k/k** ✅ | 0.0109 / **0.0497** |

**只看全局**会得出错误结论：
- 会以为"MoE 有效"（0.0092 最好）→ 但那是**坍缩版**，靠的是参数容量，不是分工；
- 会以为"真分工版更差"（0.0109 > 0.0092）→ 于是把唯一真正分工的版本淘汰掉。

⇒ **全局均值把"分工"和"容量"两种机制混在一个数字里**。必须拆开看。

## 2. 拆法：按阶段（尤其**接触段**）分别算误差

```python
y = stage_p.argmax(1)                       # 每样本的真实阶段(来自路由信号)
CONTACT = [2, 3, 6]                         # 本任务: 下降/抓取/插入 = 接触段
# 对每个模型、每个阶段算 MAE，再汇总接触段
for s in range(k):
    m = (y == s)
    print(STAGES[s], eo[m].mean(), ea[m].mean())      # 观测 / 动作
print("接触段", eo[np.isin(y, CONTACT)].mean(), ea[np.isin(y, CONTACT)].mean())
```

**实测结果（同上三模型）——接触段动作误差**：

| 模型 | 下降 | 抓取 | 插入(n=254) | **接触段均值** |
|---|---|---|---|---|
| 密集单头 | 0.1244 | 0.1350 | 0.0271 | 0.0955 |
| MoE `soft`（容量版） | 0.1281 | 0.1786 | 0.0405 | **0.1157 最差** |
| MoE `prior`（真分工） | **0.1242** | **0.1248** | **0.0225** | **0.0905 最优** |

```
⇒ 分工版在接触段 0.0905 < 密集 0.0955 < 容量版 0.1157
   最可靠的插入段(n=254): 分工版优于密集 17% · 优于容量版 44%
⇒ 而容量版在接触段是**最差**的（虽然全局观测最好）
```

## 3. 结论（可直接复用的两条判断）

1. **不同机制在不同指标上收益**，别用一个数字下结论：
   - **容量堆叠** → 改善"非接触段 / 全局观测预测"
   - **阶段分工** → 改善"**接触段动作预测**"（力控相位这类子任务）
2. **事先指定"该变的下游指标"**：若假设是"分工能治接触段"，那判据就必须是
   **接触段动作误差**（或接触段闭环成功率），而不是全局 MAE。
   全局 MAE 既看不见它、又会把坍缩版的容量红利误当成成功。

## 4. 评测纪律（照抄进任何 MoE A/B）

```
□ 三件套同口径：同数据 / 同步数 / 同增强 / 同留出集
□ 必带**容量对照**（同结构但门控坍缩版）→ 用来区分"容量收益"与"分工收益"
□ 拆阶段 + 汇总接触段（或本任务的关键子段）
□ 小样本阶段（实测抓取段仅 n=15）标注样本量, 不据此下结论
□ 结论句式: "增益来自 X 机制, 体现在 Y 指标上" —— 不许只说"MoE 更好"
```

## 5. 相关坑

- 诊断/部署的 `route` 模式必须与**训练时**一致，否则测的不是真实行为（踩过）。
- 阶段标签来自与训练同一套编码函数（同一 `stage_from_ctx`），否则离线与在线口径不一致；
  合成数据若缺该字段，`KeyError: object 'skill_ctx' doesn't exist`。
- 生成器补字段后要**回查分布**：实测补完 `skill_ctx` 后 5000 帧**全落在阶段 0**
  （引擎 trace 的逐步 stage 未按预期提供）→ 这种"字段在但退化"的情况，
  分布 `np.bincount(argmax)` 一眼可见，务必打印。
