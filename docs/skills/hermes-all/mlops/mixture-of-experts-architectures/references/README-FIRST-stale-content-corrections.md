## 更正 1：门控公式 —— 正文教的正是会坍缩的那版

**SKILL.md「核心设计」代码块**写的是：

```python
g = softmax( stage_onehot @ P + MLP(h, stage) )     # ← 这版实测会坍缩
          └─ 可学习先验矩阵        └─ 自由学习残差项
```

**事实**：训练后期"自由学习项"的 logits 量级淹没固定的先验项 → 全部样本倒向 E0。
实测两条这种配置，单射性分别只有 **4/k** 与 **1/k**，**都坍缩**（后者 E0 独占：
插入 100% / 转移 96.8% / 接近 94.4%）。正文那句"先验=免费正则 → 训练稳定"**不成立**。

**正确的默认实现（硬先验路由，结构性不可能坍缩）**：

```python
if route == "prior":                       # ★ 默认
    g = stage_p / stage_p.sum(1, keepdim=True).clamp_min(1e-6)
    g = torch.where(g.sum(1, keepdim=True) > 0.5, g,
                    torch.full_like(g, 1.0 / n_experts))
else:                                      # 仅当没有现成 stage 先验时才用
    g = torch.softmax(stage_p @ gate_prior + gate_mlp(cat([h, stage_p], 1)), dim=1)
    # ↑ 必须加约束(KL 到先验 / 负载均衡 loss), 否则坍缩
```

⚠️ **诊断/部署的 route 模式必须与训练时一致**，否则测的不是真实行为。

## 更正 2：判据 ④ 是假阳性来源 —— 决定性判据是 ⑤ 单射性

`scripts/moe_gate_diagnose_template.py` 现在**只有 ④**，并把它当通过判据：

```python
④ 阶段-专家一一对应率 ≥ (k-1)/k（实测 6/7 为健康；要求 k/k 说明先验过强）
判据: 对应率 ≥(k-1)/k 且 有效专家=k → MoE 分工成立
注意: 「部分分化」是健康的; 若强行 k/k 全对应, 通常是先验强度过大(僵化)
```

**这段结论已撤回。** 因为 ④ = "每行 argmax 是否达标"，若一个专家吃掉**全部**阶段，
每行 argmax 都是它 → ④ 自动 = k/k **全通过**，而模型其实已退化成单头。
实测更刺眼：**④ 越漂亮（7/7）的那一次，坍缩越严重（单射性 = 1）** —— 弱判据给**反向**信号。

**必须补上并在脚本里打印 ⑤**：

```python
tops = []
for s in range(k):
    m = (y == s)
    if m.sum() == 0: continue
    tops.append(int(np.bincount(routes[m], minlength=k).argmax()))
n_inj = len(set(tops))          # ⑤ 单射性 = 各阶段主导专家去重后的个数
# 判据: n_inj >= k-1  且  有效专家 >= k-1   → 分工成立
```

**口诀：任何只在"某专家独占"时才失效的指标，等于没有指标。**

另注：`references/gate-collapse-and-metric-false-positives.md` 里写"模板已加 ⑤"，
但模板**实际没有** —— 按本节补上才算兑现。

## 更正 3：硬路由版实测结果（正文的"实测结果"块是坍缩版的数据）

正文"实测结果"块展示的 `有效专家 7/7 · ④ 6/7 ✅ 分化成立` 属于**软门控（已坍缩）**的跑，

```
route="prior"（硬先验路由）实测: 单射性 **7/7**（结构性成立）
```

## 附带：三种机制的收益落在不同指标上（选型时别只看全局）

同数据 / 同步数 / 同增强 / 同留出：

| 模型 | 单射性 | 全局 观测/动作 | **接触段动作** |
|---|---|---|---|
| 密集单头 | — | 0.0124 / 0.0502 | 0.0955 |
| MoE `soft`（坍缩=纯容量） | 1/k ❌ | **0.0092** / 0.0510 ← 全局最好 | **0.1157 最差** |
| MoE `prior`（真分工） | **7/7** ✅ | 0.0109 / 0.0497 | **0.0905 最优** |

```
· 容量堆叠 → 改善"非接触段 / 全局观测预测"
· 阶段分工 → 改善"接触段动作预测"（插入段: 优密集 17% · 优容量版 44%）
⇒ 事先指定"该变的下游指标"，否则全局 MAE 既看不见分工收益,
  又会把坍缩版的容量红利误判成"MoE 成功"。细节见 references/per-stage-evaluation.md。
```
