# eye-in-hand 解算器工程学 — 单位/初值/自检盲区 (2026-09-19 现场, 合成数据可复现)

> 触发信号: 手眼数据"看着没问题"(**角度一致性自检中位 0.3° 通过**) 而解算连崩
> (重投影 55~2753px、平移算出 47m / 米级荒谬值)。
> 本文**更正** `references/eye-in-hand-calibration-verified-2026-09-19.md` ⑤ 第 3 步:
> 该节写的 **Park-Martin 闭式解初值在本实现里不可用**(合成理想数据上就错 ~7°), 以本文为准。
> 其余各节(板型/检测/采集纪律/自检/落盘闸门)仍有效。

## ① 单位必须统一成米 (第一杀手, 先查它)
- 症状: 重投影 200~2753px、平移解出米级荒谬值、**多起点也救不回来**。
- 根因: 物点用 mm(`spacing=20`) 而机器人位姿/变换矩阵用 m ——
  `T_b2c = inv(TA @ X) @ T_bb` 里旋转平移是米, 物点却还是"毫米数字" ⇒ 投影整体错位, 模型本身无解。
- 修法: `obj_points(grid, spacing / 1000.0)`; 所有 4×4 与物点统一 m。
- ⚠️ **测试数据生成器也要统一**: 测试若与实现共享同一个单位 bug, 测试通过/失败都不说明任何问题
  (本案为此多烧一整轮: "测试也失败"被误读成"解算器坏")。
- 自查: 板距相机应是 **0.2~0.3 量级(米)**; 若打印出 300+ 或 47 ⇒ 先查单位, 再查姿态解析。

## ② Park-Martin 闭式解不可靠 → "交替优化 + 多起点 LS" (已验证)
- 证据: 在**真值残差 0.000000px** 的合成理想数据上, `park_martin(...)` 复原旋转误差 **7.06°**;
  拿它当唯一初值 → LM 进沟(2753px)。
- ✅ 已验证可用的流程 (repo `tools/handeye_solve_ls.py`, 合成数据 0.00mm/0.000°/0.0000px):
  1. 每视图 `solvePnP`(20 物点↔像素, 物点单位米) → `T_board2cam`;
  2. **交替优化**: ①给定 X → 每视图推一个"板在基座下"位姿 → **SVD 极分解平均**(平移取均值);
     ②给定板位姿 → 每视图推一个 X → 同样平均; 迭代 ~6 次, 收敛判据平移 <1e-5 m;
  3. **多起点**: 单位阵 + 几种小旋转 × 几种 z 平移(10/15/20cm) + 10 组随机 → 各跑一遍,
     取**重投影最小**者(命中 <0.5px 可提前退出);
  4. `scipy.optimize.least_squares(..., method="lm")` 在 12 维参数(X 6 + 板在基座 6)上精修;
  5. **逐视图残差 + 自动剔除**(> max(3×中位, 0.8px) 且保留 ≥4 视图 → 重解取更优者)
     + **留一法**重解给平移 σ/极差(诚实不确定度)。
- 行/列顺序歧义: 原序与转置都解, 取重投影更优者, 并把采用哪种写进结果。

## ③ 自检的盲区 (为什么"角度自检通过"解算仍能崩)
| 自检 | 能查出 | **查不出** |
|---|---|---|
| |工具相对转角| ≡ |板在相机系相对转角| | 位姿源是否活性、板型是否对、配对是否错 | **A/B 取逆方向**、**四元数分量顺序**、**手/靶标是否刚性同体** |

三者都等价于"固定共轭或置换", **相对转角大小不变** ⇒ 自检通过只是"数据/约定自洽"的**必要**条件,
**不是**解算可信的充分条件。解算还要靠: ①单位 ②算法 ③**合成数据自证**。

## ④ 合成数据自证: 必须物理成立 (板在**相机前方**)
- 踩坑: 我第一版合成测试由模型反推生成场景, 把板放在相机**背后**(`t_z = −0.29m`, 没查符号) →
  `solvePnP` **合理**返回镜像解(t 符号翻转) → 表象酷似"解算器坏了", 实为测试场景非物理, 又烧一轮。
- 正确造法: 板放台面(z 向上, 如 `T_b2base.t = [0.45, 0, 0.10]`); 相机在板上方 ~30cm 且**光轴朝下**
  (`R = Rodrigues([π,0,0]) @ 小随机旋转`); 工具位姿 `T_t2b = T_c2b @ inv(X_true)`;
  **断言 `T_b2c[2,3] > 0`**(板必须在相机前方)。
- 判定(解算器可信的门槛): 真值处残差 ≈1e-6 px; 解出 X 与真值差 **<2mm / <0.5° / 重投影 <0.5px**。
- 可重跑脚本: `scripts/handeye_selftest_synth.py`(确定性, 无图像/无机器人依赖)。

## ⑤ 真机首轮结果 —— **尚未达标, 待续 (不要当成已验证流程)**
- 数据: 5 个干净视图(位姿直读源头, 3 读极差 0.00mm, 板 20 点) →
  解出 `T_cam2tool` 平移 `[62.7, −18.3, −209.6] mm`(模长 220mm)/旋转 19.0°;
  板在基座 `[0.5315, −0.0903, 0.3763] m` —— **量级物理合理**, 说明链路已通。
- 但重投影 **中位 24px, 逐视图 15.2~47.5px(五个视图都大) = 系统性误差** ⇒
  落盘闸门(≤1.5px)**正确地拒算**(不落盘、不粉饰)。
- 归因待验证: 手拖示教下报位姿的保真度(柔顺/回差) · 样本数不足 · 板在画面偏小(点间距 46~59px)。
- 下一步: 采到 **≥15 视图** + **相机离板更近(8~15cm, 板占画面更大)** + 姿态更散(≥20~30°);
  重解后**按真机实测如实报精度**(若中位只能 3~5px, 就说 3~5px ≈ 2~4mm, **不为过判据去改判据**)。

## ⑥ 通用教训
- 数值解法连崩时按 **单位 → 初值/算法 → 数据/约定** 顺序排除, 每步都用**可复现自证**
  (合成数据 / 真值处残差), 而不是调参、不是换更多数据先试试。
- **测试与被测共享 bug ⇒ 测试无效**: 写自证脚本前先确认"真值处残差 ≈0"这一条独立成立。
- 拒算文案要写清"哪一步不合格 + 下一步怎么做", 现场操作员才会继续配合而不是白拖。
