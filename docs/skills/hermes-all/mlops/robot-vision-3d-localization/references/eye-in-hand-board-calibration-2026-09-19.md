# eye-in-hand 标定 (相机在臂上 + 固定标定板) — 2026-09-19 现场实录

现场条件: **相机固定在协作臂上 (eye-in-hand)**, 镜头朝下对着**固定标定板** ~50cm;
操作员**只能手动拖动机械臂, 不能控制夹爪开合** (夹爪无遥操作入口)。

## ① 最重要的坑 — 固定相机自监督路径在 eye-in-hand 下是**假标定**
`Box3DSolver` 的自监督拟合假设「**相机固定 + 目标随工具运动**」(中心 = TCP + R(q)·off)。
相机在臂上时, **相机运动会被误当成目标运动** → 拟合参数漂亮但物理全错 (角度/偏移把相机位移吸收掉)。

更糟的是提示语曾**无条件打印** `✅ 自监督标定成功 → models/box3d_state.json`, 而**文件根本没落盘**
(只判 `fit()` 返回 ok, 不校验落盘) → 现场会以为"标定好了"。**教训两条**:
- 相机在臂上时, 那条路径必须**物理前提闸门直接拒算** (`SS_CAMERA_MOUNT=eye_in_hand`, 已在
  `tools/calib_copilot.py` 内置), 并打印"正路是 handeye_collect"。
- 任何"成功"文案必须**回读落盘文件**再打印 (存在性 + 关键字段), 否则就是假成功。

## ② 正路 — 固定板 + 移动相机 (经典 AX=XB), 不需要夹爪
1. `tools/handeye_collect.py` 采 (帧图, 同刻编码器 TCP+四元数) 对, **逐位姿判"板在不在画面"**;
2. `tools/board_handeye_solve.py` 每帧 `findChessboardCorners` → `solvePnP` 得板在相机系位姿 →
   `cv2.calibrateHandEye(..., CALIB_HAND_EYE_TSAI)` → **T_cam2tool**;
   再做**重投影留出复核 (中位 ≤1.5px)** 才落盘 `models/handeye_state.json` (含 per_view 误差);
   同时回算**板在基座系** (tray reference, 插拔可当参考面)。
判据: 可用视图 **<8 直接拒算**(宁缺勿假), 建议 **≥15**。

## ③ 板规格识别 — "5×4 20mm" 有三种解读, 必须全试
现场板 = **CGB-020 5×4 20mm Version B** = **5×4 方格** → **内角点 (5-1)×(4-1) = 4×3 = 12 个**。
探测代码要同时试: `findChessboardCorners(5,4)`(当成角点数) / `(4,3)`(当成方格数→角点) /
`findCirclesGrid(5,4)`(圆点板) / `(4,5)`。
**踩坑**: 只试大格 (9×6 / 11×8 / 8×6 / 7×5 / 6×4) → 小规格板一律"未检出" → 误判"画面里没有标定板"。
→ 先问用户板的型号规格, 再按规格枚举; 工具: `tools/board_probe_cgb.py`。

## ④ 视野极窄 — 相机随臂动, 位姿稍变板就出画
实测同一台设备: TCP z≈0.2621 与 z≈0.3452 **能看到板 (12 角点)**, 而 z≈0.2883 **看不到**。
→ 必须先找到一个**"能看到板"的参考位姿**, 再绕它做变化 (远近/左右/偏航/俯仰);
采集器**逐位姿报板状态**, 否则操作员白拖 16 次。

## ⑤ 采集器纪律 (v1 现场卡死的三条根因, 必须内建)
| 症状 | 根因 | 修法 |
|---|---|---|
| 拖了 3 次一个样本都没存 | "停稳"判据写 **抖动 ≤1mm** — 人手拖停稳后仍有几毫米微抖 → 永远"未停稳" | 停稳阈值放到**人手量级 (≤25mm)** |
| "距上次位移"恒为 0 | 与**运动中不断更新的当前点**比较 → 参照点跟着一起动 | 只与**上一次已保存**的位姿比较 (首次直接存) |
| 卡住也看不出来 (静默) | 只在保存时打印 | **每 5s 心跳**: TCP / 停稳or抖动 / 距上次保存 / 累计 / 上次板状态 |

附加: 机器人"没动"要先证伪再归因 — 连续读编码器 TCP 看是否变化 + 对比 state 文件尾行时间戳与
本机时钟 (差 ~0.1s = 数据流是活的), **别先怀疑操作员**。
