# eye-in-hand 标定: 四元数顺序更正 + 现场采集三条闸门 (2026-09-19 现场实测)

> **本文更正 `references/eye-in-hand-calibration-verified-2026-09-19.md` 的 ② 节**:
> 该节写"现场 `tcp_quat` 首分量最大 ⇒ 顺序 (w,x,y,z)"是**错的**; 正确顺序是 **(x, y, z, w)**。
> 其余各节 (板型/检测/采集纪律/自检/自实现解算) 与本文一致, 仍然有效。

## ① 四元数分量顺序 = (x, y, z, w) — 现场逐位确证
```
ros2 topic echo --once /robot/tcp_pose    # Orin, ROS_DOMAIN_ID=0
  orientation: x 0.8531257  y 0.2125999  z 0.4670121  w -0.0942202
state 日志同一拍:  tcp_quat = [0.853, 0.213, 0.467, -0.094]     → 逐位对应 (x,y,z,w) ✓
```
- **❌ "首分量最大 ⇒ w 在前" 的启发式必须废弃**。本案姿态接近 180° 转 (x=0.853 最大), 该启发式判反
  → 旋转矩阵全错 → 手眼解出**荒谬平移 (实测 47 米)**、重投影 55px, 白烧三次解算。
- **唯一可靠确证法 = 读源头话题逐位比对**(或查驱动文档)。别用统计启发式, 别写死猜测。
- **⚠️ 角度一致性自检查不出顺序错**: 分量顺序错等价于固定正交变换共轭, **相对转角不变**
  (实测: 换顺序前后两两 |Δangle| 数值一模一样) ⇒ 自检"通过"不代表顺序对。
- 代码写法: `default="xyzw"` + 环境变量覆盖 (如 `SS_QUAT_ORDER`) + 在结果里打印"顺序来源"。

## ② 采集闸门: "动过没有"必须含姿态
纯转手腕时 **TCP 位置不变** —— 这是 TCP 的定义, 不是机器人没动。
只比位置的采集器会把"转动了 30°"判成"停稳 1083s", **一个样本都不存**, 还让操作员以为白干了。
- 停稳判据: 位置抖动 ≤ 人手量级 (≈25mm) **且** 姿态角抖 ≤ ~1°;
- 位移判据: 位置位移 ≥8mm **或** 姿态变化 ≥5° 都算"新位姿";
- 心跳里同时打 **位置 + 姿态角**, 一眼看出是"没动"还是"只转了"。

## ③ 采集闸门: 先查机器人和话题, 别先怀疑操作员
| 现象 | 先查什么 | 判据 |
|---|---|---|
| 操作员说动了, 编码器位置+姿态全不动 | `operation_state` | **`idle` 时手推无效**(被刹住) → 必须 `drag` 才能手拖; `has_error=false` 要一起看 |
| 同上 | `ros2 topic hz /robot/tcp_pose` | 应 ~50Hz; 若停发则 tap 在重复最后一个值(表象=机器人静止) |
| 图不跟着动 | 让操作员**遮住法兰上那台相机** 5s | 我的图**不变** ⇒ 数据来自**另一台固定相机**(现场常有多台: 法兰 D405 / 产线 UVC) ⇒ 靶标必须随工具动, 换方案 |

## ④ 慢相机 (~0.53fps) 的配对纪律 (时间判据全被证伪, 用内容判据)
1. 图像 **md5 必须变化** (同一张图配新 TCP = 数据自相矛盾);
2. **场景静止硬证据**: 连续两帧 md5 相同 ⇒ 画面确实静止 ⇒ 该帧内容 = 当前位姿所见
   (文件 mtime ≠ 拍摄时间, "帧落盘晚于停稳"这条也被实测证伪);
3. 机器人连续停稳 **≥6s**; 现场作业卡写明"**停稳 8 秒再说话**";
4. 每次保存把 `board_ok / board_points / frame_age_s` 落进 poses.jsonl, 逐位姿即时回报操作员
   (`✅20点 / ⚠️板不在画面`), 不合格样本**不入解算**, 让操作员当场重做而不是事后返工。

## ⑤ 目标与判据 (不变)
≥15 个合格位姿 + **姿态多样性 ≥20~30°** (手眼只吃旋转激励, 光平移不够);
解算落盘闸门: 视图 ≥8 且**重投影中位 ≤1.5px** + 留一法散布, 否则**拒算并说明下一步**。
