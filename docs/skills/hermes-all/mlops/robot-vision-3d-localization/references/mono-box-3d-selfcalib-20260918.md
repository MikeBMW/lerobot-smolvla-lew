# 单目 2D框→3D 自监督标定 + 坐标系选择 (2026-09-18 实测记录)

场景: Z-MAX 光模块插拔。**只有机器人有位姿真值(编码器 50Hz), 工件没有任何位姿传感器**。
目标: 不量尺寸、不量偏移、不做手眼标定、不装深度相机, 只用 **YOLO 的 2D 框 + 机器人自身位姿**
把 3D 反出来, 并要求**仿真模式下也不许作弊**(不能用仿真白送的内参/外参/深度)。

## 一、算法 (唯一先验 + 一个自监督拟合)

```
先验: 工件被夹爪刚性夹持 ⇒ 工件中心 = TCP + R(q)·off   (off 常数, 未知)
观测: 每帧 YOLO 框的**四条边** (x1,y1,x2,y2)  ≡ 中心 + 宽 + 高
未知: 投影矩阵 P(11) [+ 附着偏移 off(3)]
目标: 让"用 P 投影 (TCP + R·off) 得到的框"同时对上观测框的中心与宽高
      → 纯自监督: 不需要任何人工测量; 机器人给位姿, 相机给框
出 3D: ① predict_held(tcp,quad) = TCP + R·off (工件被夹着时, 最准)
       ② predict_mono(box)      = 由框的像素跨度反推距离(自标定 span×dist 常数) → 视线求交
                                  (工件不在手上时用, 精度明显低于 ①)
```

实现: `models/box3d_solver.py` → `src/lerobot/policies/yolo_3d/box3d_solver.py` (`Box3DSolver`)
· LM(Gauss-Newton+阻尼) 优化, 数值雅可比, 15 个参数 (P 12 项归一 + off 3)
· `add(box, tcp, quat)` 带质量门: 框太小(<8px)/贴边出画/长宽比异常/无位姿 → 拒收并说明原因
· `diversity()` 位姿体检: 帧数≥10 · 平面性 σ3/σ1 ≥0.15 · 姿态散布 ≥10° → 不合格**拒绝拟合**
· `fit()` 自动留出 (默认 20%) 报 `rms_px` 与 `holdout_rms_px`; `degenerate` 标记跑飞
· `fix_off=(0,0,0)` 模式 = 工具零点已示教 → **只解 P(11)**
· `save/load` JSON (`models/box3d_state.json`), 存 P/off/size/位姿多样性/残差

**C. 坐标系/未知量选择** (`tools/frame_choice_experiment.py`)

| 方案 | 拟合rms | 留出rms | off误差 | 留出3D | 留出框IoU |
|---|---|---|---|---|---|
| A 偏移未知 (解 P+off=14 个) | 1.452px | 1.370px | 6.91mm | 6.91mm | 0.835 |
| B **零点已示教 off≡0 (只解 P=11 个)** | 1.472px | 1.412px | — | **0.00mm** | 0.831 |
| C 零点给错 (真 90mm 按 0) | 2.639px | 2.783px | — | 90.00mm | 0.584 |

⇒ 相机侧质量三者相当(~1.4px), 差别**全在工件 3D 从哪来**: 工具零点示教对了就由 FK 直接给(零误差),
估计不出来就带 6.9mm 偏, 零点错了整体偏 90mm。

**D. 像素→3D 只需 P + 已知平面**: `pixel_to_plane(P, uv, z0)` —— 相机中心取 P 最小奇异向量,
视线取 P 两行平面交线, 与 z=z0 求交; 平面上 12 个随机点 → 投影 → 反算, 误差 **0.0000mm**。
(只有 P 时无法分离 K, 所以"沿光轴深度 z"这个语义要用平面给, 不能用 K 反推。)

**E. 浅景深硬边界**: 反投影残差 1.2px 的 P 里 **fx 只有 175 (真值 610)** → 从 P 反解内参不可辨识。
2D 标注(3D→像素)完全可用; **像素→米**必须单独标 K。

## 三、探针/采集设计规则 (S0) 与闸门

`tools/real_probe_plan.py` 生成 13 位姿计划并自检(**不连机器人**): 3×3 栅格(±40mm) +
3 个深度(+55/+110mm) + 姿态 ±16°; 断言 = 非共面 · 步距 ≤80mm · 全在安全盒内。
S0→S1 配对 (`tools/real_autolabel.py`):
- 运动域取**全部连通域面积加权质心**(=两帧中点); "最大连通域"是旧实现, 偏 15~30px
- 3D 点 = 两帧 **TCP 中点** + R(**四元数 slerp 中点**)·实测工件偏移
- 运动必须**收口到工件 ROI**(每帧独立给, 相邻两帧取并集, pad 6px); 不收口 → 标签 IoU 0
- 落盘前**可辨识性预检**(planarity ≥0.15), 不合格拒绝写 P; rms >2px 也不要拿去出标签
- 验证位姿盲测是唯一能抓出"自洽吸收"的手段 (拟合 rms 1.64px vs 盲测 35px)

自动标注闸门 (S2): 抓取门 = 夹爪真值优先, 无发布者时用"**工件预测位置** ±半径内是否有随动";
没夹住/不在视野一律不发标签; 自动标签**永不进 val**。
ROI 来源: `tools/make_roi_from_yolo.py` (在役权重出框, conf≥0.5 + 剔贴边框 + 缺帧留空不补)。

## 四、节点改造 (画布「📐 2D→3D 解算」不许作弊)

- 旧实现 = `aligner.align(obs39, det3d)` 转发上游 `detect_3d` → 仿真白送内参/外参/深度 = 作弊;
  真机缺这三样就一个 3D 都没有(实测 2D 检出 2 框 conf 0.93, 3D 点 0, gaps=无深度/无内参)。
- 新实现 (`tools/gui/node_logic.py::node_yolo_align`): 只吃 `_YOLO_CACHE["det2d"]` 的**框** +
  机器人**自身**位姿(真机=编码器落盘 / 仿真=env 末端状态, 等价 FK) → `Box3DSolver` → 写 39D 的
  光模块段 `[4:7]`/`[22:25]`; 仿真真值只允许事后打分写日志, 缓存里留
  `used_env_module_truth: False / used_sim_geometry: False` 作凭证。
- 开关: `SS_BOX3D_FIX_OFF_MM="0,0,0"`(工具零点已示教 → 只解 P) · `SS_BOX3D_SIZE_MM="40,16,12"`。
- 坑: `node_logic.py` 的 `_REPO_ROOT` 定义在文件后半段 → 在它之前插的模块级代码引用它会
  `NameError` 崩 import; 必须惰性求值 (try/except NameError + 按 `__file__` 推)。
- 坑: `estimate_3d` 在"无内参"处曾**直接 return**, 把已检出的 2D 框一起丢掉 → 下游打"检出=0",
  看起来像模型看不见。修法 = 该分支回传 `meta["boxes_2d"]`(只作 2D 用, 绝不进 3D 槽)。
- 画布/长驻进程改码后**必须重启** (`systemctl --user restart zmax-studio`) 才生效。

## 六、反馈控制: "越近越准" 的定量律 + 反解投影模型 (2026-09-18 晚, `tools/box3d_servo_selftest.py`)

用户要求: 「单独用 YOLO 框直接做 2D→3D 肯定有误差, 所以是反馈控制, 随着距离接近应该越来越准。」
→ 把这条直觉**测出来**, 数字 (同一模块放不同距离, 框从渲染图像抠轮廓+0.5px 噪声, 真值只打分):

| 距离 | 框跨度 | 估计距离 | 3D误差 | σ估算 | σ/距离² |
|---|---|---|---|---|---|
| 0.30m | 87.2px | 0.307m | **1.6mm** | 1.73mm | 0.02 |
| 0.50m | 50.8px | 0.523m | 14.4mm | 5.09mm | 0.02 |
| 0.70m | 33.4px | 0.792m | 83.0mm | 11.75mm | 0.02 |
| 0.90m | 25.5px | 1.035m | 126.4mm | 20.16mm | 0.02 |

- 实测 **σ ∝ 距离^2.20** (理论 2.0): 绝对距离误差随距离**平方**增长 → 0.9m 126mm vs 0.3m 1.6mm = **81×**。
- 横向误差 ∝ 距离 (1 次方) —— 同样 1px 抖动, 距离减半横向误差减半。两个方向都支持"越近越准"。
- 融合 (1/σ² 逆方差加权): 0.80/0.55/0.35m 三测 → σ 2.18mm < 最好单次 2.36mm。
- **关键修正**: 只用"框跨度×距离=常数"的标量尺寸模型有 **~15% 系统偏差** (0.70m 估成 0.806m),
  因为"哪个面朝相机"随姿态变。必须 `predict_box_model(box, quat)`: 沿视线**二分求根**, 找一个
  距离使"该姿态模块在 d 处投影出的 AABB 跨度"=观测跨度 (用已拟合的 P) → 无偏 (上表即修正后);
  σ 由灵敏度给 σ_dist = σ_span/|∂span/∂dist|。**2D→3D 必须带姿态** (姿态从机器人 FK 来)。
  无姿态时退回标量模型并把 σ×2 (诚实降级)。

`Box3DServo(solver, tol_m, max_step_m, min_step_m, sigma_span_px, keep)`:
`observe(box_px, quat=None)` → `{X, dist_m, sigma_m, span_px}`; `plan()` → `{err_m, X_fused, sigma_m, next_step_m, done}`。
`fuse(measurements)` = 按 1/σ² 加权。

**融合合法性 (必须遵守)**: 只有**同一静态目标**的多次观测能融合。目标被夹持随手移动后再融合 = 混了
不同位置 → 结果无意义。夹持件直接用 FK 给的位置(零误差), 不要融合。

**相机安装方式决定公式 (现场必须确认, 未定)**:
- 相机**固定在工装**在 W 里刚体 → 现 `Box3DSolver` 的单 P 公式正确; "越近越准"作用在
  "工件↔孔口相对量"上。仿真里必须"目标固定 + 相机靠近", 不能"相机固定 + 目标移动"(融合会非法)。
- 相机**装在腕上**随 TCP 动 → 相机外参每帧 = FK(q)·T_tool→cam, 未知量多一个 6 自由度手眼;
  用单 P (固定相机) 去解移动相机的帧 = 系统性错误 (本人仿真踩过: 末步误差 60~140mm 抖动不收敛,
  根因就是拿"固定相机标定的 P"去解"已经挪走的相机")。腕上必须改成工具系固连公式。

## 七、2D 框 → **3D 边界框** (2026-09-18 晚): 可辨识性铁律 + 真机内参白拿

老倪: 「镜头里已经有一个光模块, YOLO 也检测出来了。完善策略: 如何根据当前的 2D 检测推算 3D 边界框。」
3D 边界框 = 中心(3) + 姿态 R(3) + 尺寸(3) + **8 角点**。真代码路径 = `Box3DSolver.predict_box3d`
(5 档: held / mono_pose / mono_scalar / **fk_only 诚实降级** / no_3d 拒绝), 现场工具 `tools/box3d_live_box.py`。

**可辨识性实验** (`tools/box3d_identifiability_experiment.py`, 合成 160 训练/40 留出, 框从渲染图像抠轮廓;
真值 off (0,−90,0)mm · 夹持歪斜 12° · 尺寸 40×16×12):

| 臂 | 解算器已知 → 要解 | off 误差 | R_rel 误差 | 3D 框中心 | **8 角点** | 姿态误差 | IoU |
|---|---|---|---|---|---|---|---|
| A | — → P,off | 75.6mm | (没估) | 76.8mm | 76.9mm | 14.2° | 0.819 |
| B | — → P,off,R_rel | 8.6mm | 5.7° | 10.4mm | **10.6mm** | 5.7° | 0.929 |
| C | — → P,off,R_rel,**尺寸** | 64.4mm | 47.7° | 65.8mm | 67.8mm | 49.8° | 0.884 |
| E | 尺寸错+15% → P,off,R_rel | 34.2mm | 11.6° | 43.8mm | 44.2mm | 11.9° | 0.867 |
| F | off≡0(实际不是0) → P,R_rel | 90mm | 29.4° | 90.0mm | 91.1mm | 42.5° | 0.669 |
| **G** | **K 已知** → 手眼+off+R_rel | 3.9mm | 4.9° | 4.29mm | 4.74mm | 5.2° | 0.918 |
| **H** | **K 已知** → 手眼+off+R_rel+尺寸 | 3.7mm | 3.0° | **3.71mm** | **3.98mm** | 3.1° | 0.927 |
| I | K 已知 → 手眼+off (不估 R_rel) | 4.5mm | (没估) | 6.18mm | 7.4mm | 14.2° | 0.811 |

铁律 (都是实测, 不是推的):
1. **真机内参 K 是白拿的** —— `/realsense/color/camera_info` 直接给**出厂标定** (实测 fx=394.06,
   fy=393.47, cx=318.44, cy=238.66 @640×480; ⚠️ **不是仿真那套 610**)。有 K 后**只解手眼 (rvec3+t3)**,
   尺度被米制锚定 → 3D 框精度 **4mm**, 尺寸也能解 (1.6mm)。
   `tools/calib_fetch_realsense_intrinsics.py` 一条命令落 `models/real_cam_calib.json` (只订阅零发布)。
2. **夹持歪斜 R_rel 必须联合估**: 不估它, off 会把歪斜"吸收"掉 → 中心偏 **77mm**, 姿态 14° 起。
3. **尺寸别和 off/R_rel 一起解** (无 K 时): 像素残差能做到 1.1px 却 3D 偏 65mm —— 存在"像素等价、
   3D 不等价"的退化方向。尺寸必须来自图纸/一次量测 (有 K 后即可解)。
4. **尺寸误差线性传到中心** (±15% 尺寸错 → 中心 34~44mm), 所以要么量一次, 要么有 K。
5. **off≡0 只有真示教到模块参考点才成立** (不然偏 90mm, 这是最贵的错误)。
6. 前提自证 = 唯一的"夹持假设成立吗"判据: 用 FK(TCP⊕off) 反投影框 vs 检测框 IoU ≥0.45;
   拟合留出残差 0.7~1.9px 只可能在这个前提下达到 → **残差就是前提的检验**, 不用额外传感器。

实机链路 (`tools/box3d_live_box.py`): 同一行旁路真值 (tcp+quat+image.path) 取**同刻**配对 →
在役权重 `models/yolo_peg_live.pt` (单类 peg) → predict_box3d → JSON + 终端报告;
`--collect` 边干边攒 (框,TCP位姿), ≥10 帧不同位姿自动拟合 + 前提自证 + 落 `models/box3d_state.json`。
⚠️ 机器人静止时 (drag 停住) 攒 1800 帧也是**同一个位姿** → diversity 不过 → 正确地拒绝拟合 (别怪算法)。
⚠️ 真机 `/realsense/depth/image_rect_raw` 在役**测不出口的深度**: 全帧只有 2.0~3.0m (跨域/朝向不匹配,
   与工作区 0.3m 量级冲突) → 在确认相机安装与对齐前**不要**把它当 3D 依据 (别拿它冒充深度)。

⚠️ **现场动作前必须彩排** (`tools/box3d_fitpath_rehearsal.py`, 走的就是现场同一套函数
`try_fit`/`save`/`load`/`predict_box3d`, 状态写 `~/zmax_data/rehearsal/` 不碰现场文件):
① 正例 (真夹持, 120 帧, 真机 K)：rms 0.86px · off 差 3.5mm · 前提自证 IoU 0.874 → 落盘 →
   重载后留出 40 帧全 `held`、**8 角点 5.23mm**、IoU 0.875;
② 反例 (模块静放台面 + 机器人空手走位)：rms 7.67px · 前提自证 IoU 0.226 → **拒绝落盘**。
反例这条是保险: 现场录到的若不是"夹在爪上的模块", 链路必须自己拒绝, 否则假标定会污染之后每一帧。

## 五、诚实边界 (未解决/需现场确认)

1 真机探针未跑(采集时 Orin 不在线), 上面全是合成/离线证据。
2 归档真机帧与 TCP 真值**时间未对齐**(实测 ΔTCP=0mm 而画面移动 ~100px) → 采集必须同刻配对,
  否则配对数据本身是废的; 这条不解决, 精度天花板在采样器不在算法。
3 夹持重复性(松开重夹的微动)是物理下限, 不受坐标系选择影响, 需实测一次。
4 工件相对工具的固定转角 R_rel(夹持歪斜)影响 AABB 框宽窄, 需一次确认或由数据估。
5 工件若含柔性段(光纤), 参考点要选刚性段。
