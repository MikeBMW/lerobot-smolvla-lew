## 2. ⚠️ 零回退工具铁律: 按 (源, 目标, 标签) 三元组比对

`tools/verify_l4_zero_regression.py` 的"连线拓扑"检查比的是 **f/t/label 三元组**，因此:
- **任何 label 改动都会被判成"丢线"**：初版让布局脚本给反向边自动加 `↩` → 实测报"丢失 8 条"，去掉那些 ↩ 又被报"丢失 4 条"。
  **结论：布局脚本永不改 label，只统计反向边数量**；要标 ↩ 就得与基线同改并在报告里说明。
- **有意重接 = 亏损+新增**：把 `帧→👁` 改成 `帧→🧿` 就是 3 条"丢失" + 3 条"新增"（工具眼里），
  **必须在报告里写明是用户要求的 UI 变更**，不要伪称零回退。
- **回路外新增节点会进 L2/L3 执行集**：工具判定"L2/L3 集合必须逐项相同"→ 新增一个 `cap=0`(行名不含 L 标记) 的节点即 ❌。
  这是**有意增量**；可以提议把"回路外新增"与 L4 同等放行（工具归飞书端维护，别单方面改他们的检查器）。
- 报告写法（实测被接受）: 档位归属无变化 ✅ · 原有 N 条连线**丢失 0** ✅ · 新增 M 条（=本次整合的边）· 唯一 ❌ = 新节点计入 L2/L3（有意增量，已提案）。

## 3. 画布加载口径 (断言别写错)

- 加载后 **node id 会重生** (`n1789…`) → 一切断言**按节点名**统计入/出线。
- `len(m.links)` 可能比 JSON 少几条 = 历史重复 (f,t) 被内部去重，**不是加载丢线**（本次 JSON 156 / 画布 152，差 4 条重复）。
- 节点端口要真实存在（`inputs=["in1".."in5"]`），否则线条画不出来；补线脚本要顺手把 `t_port` 加进目标 `inputs`。
- 幂等生成器四件套: `gen_llm_layer_topology.py`(补节点/边) · `gen_global_dataflow.py`(全局整合) ·
  `gen_deepseek_node.py`(provider 节点 + 有意重接) · `gen_ss_obs_layout2.py`(按层级定列重排)。
  每个脚本跑前断言"老节点/老连线逐条未变"，跑后打印 悬空数/反向数/节点数。
