场景: 老倪「技能编排器怎么没有输入呢? 环境数据要输入给技能编排层的大语言模型啊, 而且其它节点怎么都是悬浮在那呢?
你要设计好连接拓扑关系。修复大语言层的连线。」+「怎么又出现了右侧的输出连接到左侧的输入? 保持左上是源头, 右下是输出」。

## 1. 先量, 再改: 悬空/入度为 0 的节点必须逐个点名

```python
import json; d=json.load(open("flows/state_space_obs.json",encoding="utf-8"))
nodes={n["id"]:n for n in d["nodes"]}
din={i:0 for i in nodes}; dout={i:0 for i in nodes}
for l in d["links"]:
    dout[l["f"]]+=1; din[l["t"]]+=1
float_both=[i for i,n in nodes.items() if n.get("type")!="row_bg" and din[i]==0 and dout[i]==0]
no_in=[i for i,n in nodes.items() if n.get("type")!="row_bg" and din[i]==0 and dout[i]>0]
```
实测: 完全悬空 8 个 (训练/推理 · 标定层 · 潜空-流形 · 能力档位 · 意图丛 · 技能词典 · 记忆图谱 · 意图直读),
入度 0 但出度>0 的 3 个 (数据源/技能编排器/总装记忆中枢) —— **技能编排器正是老倪点名的那个**。
判据: 改完必须 `完全悬空 == 0`, 且"无入线"的只剩**真源节点** (数据源/工程记忆这类文件或环境来源)。

## 3. 「不许右→左」的正确做法: x 由数据流层级决定, 不是手摆, 也不是等距网格

```python
# ① DFS 分类边: 回边=反馈边(环闭合, 物理必然反向); 去掉回边得 DAG
#    别用 SCC 缩合! 控制闭环会让 SCC 把整环压成一个点 → 层级全塌 (实测判出 42 条"反馈边", 层级只剩 0..1)
# ② 拓扑序 = DFS finish 的**逆序** (写成正序会让层级全塌成 0..1, 实测踩过)
# ③ 最长路 level[v] = max(level[v], level[u]+1) → x = BASE_X + level*COL_W
#    ⇒ 所有非反馈边 ax < bx 自动成立 (图论保证, 不靠调参)
```
- 行 (y) 仍按语义链路排 (数据源→大模型层→L4→L3→L2→执行→验证→可视化): **行序不影响反向线** (反向只由 x 决定),
  所以可以自由选"人读着顺"的行序。
- 行内同层节点: 最多竖排 `SLOT_CAP` 档 (实测 2~3 合适), 超出的**向右挪列**; 行高按 `130 + slots*124` **自适应**
  (固定行高会把节点挤进下一行 → 实测碎成 38 个 y 档, 行背景全部包不住)。
- 残余反向: 用"定点修补"把非反馈边的目标节点右移, 迭代 8 轮收敛 (实测残余 2 条 → 0 条)。
- **自动标 ↩**: 布局后凡 `x_f >= x_t` 的边 label 前加 `↩` (画布既有约定), 复查时按 label 就能数出双向边。
- 迭代收敛写法会发散: "每行一个偏移量 + 反复互推" 实测跑到 `6.8e27` —— 别用无上界的互推, 要用**层级定列**。

|---|---|---|---|---|
| 基线 (改前) | 7 | 0 | 47 | 208 |
| 首版 (等距网格) | 40 ❌ | 0 | 59 | 357 |
| **按层级定列** | **13** (全为真双向) | 0 | **25** | **202** |

## 4. 双向关系会让"反馈边"必然存在 —— 要如实解释, 不要硬消

记忆层就是双向: `ss_mem_share → ss_mem_l2/l3/l4` (总装下发) 与 `ss_mem_l2/l3/l4 → ss_mem_share` (三层上报)。
两条都该在图上 → 必有一条是 `↩`。同理: 编排器↔规划器 (新技能注册 / 规划需求),
校正器→状态机, 物理世界→环境渲染 (渲染回流)。**交付时逐条列出这 13 条并说明为什么**, 而不是把边删掉凑指标。

## 5. 两个隐蔽坑 (都实测踩过)

| 坑 | 症状 | 修法 |
|---|---|---|
| **同名函数覆盖** | `node_ss_skill` 被定义两次 (技能编排器 + 原子技能) → 直接按名字调用拿到的是**后一个**; 测试里调 `node_ss_skill()` 跑出了"原子技能 无引擎轨迹" | 原子技能改名 `node_ss_atomic`, 同步 `_reg(...)` 与 `show_details` 分派器 (`sssk*`)。注册表因导入时按名取值**恰好**没错, 但这是隐患 |
| **行背景名决定档位** | `verify_l4_zero_regression.py::cap_of()` 按行背景名含不含 `L2/L3/L4` 推断节点档位 → 重排时改了行背景名就被判"档位回退 ❌" | L 档行名**必须保留 L 标记**; 非分级行 (数据源/大模型/验证/可视化) 名字里不要出现 L2/L3/L4 |
| 布局脚本写盘前 | 行背景宽度在"定点修补"之前算 → 修补把节点右移后行背景包不住 | 定点修补**必须放在行背景定尺之前** |
