# 画布卫生清单 (2026-09-19 现场, 老倪三次纠正)

## 1. 节点"消失"= 被布局按图深度顶飞 (不是被删)
布局按**图依赖深度(lv)** 算列号: `x = BASE_X + lv*COL_W`。
**新增一个节点/边会让下游层 lv 暴涨** → 整行被推到最右, 表现为"某节点不见了"。
- 实锤: 给 L2 行加了「📐板坐标系定位」后, "🧠大模型层"整行 `x` 从 **470 → 7400**(lv22),
  用户以为 🧿 DeepSeek-VL 节点被删了 ✗ (其实还在, 只是跑到视野外)。
- 修法(固化): 布局跑完必跑 **后处理脚本**(如 `tools/gui/post_layout_fix.py`)把关键行**锚定回原坐标**,
  以后每次改布局都执行 → 不再反复。

## 2. 画布左上角的"残字"
停用带只从 ROWS 里去掉**不够** —— 它仍会被停在 `(0, BASE_Y-300)` = 画布原点上方,
渲染成一串孤立文字(用户看到"L4专家自主功能"挂在左上角 ✗)。
- 修法: 停用带**直接从 nodes 里删掉**, 并从 `ids` 集合里同步剔除(否则"节点数对账"断言会挂)。

## 3. 不要右→左连线 (用户明确要求)
要求: 画布**不许出现"右侧输出连回左侧输入"**的线(看着乱)。
- 做法: 布局后**剔除**所有 `x[f] >= x[t]` 的连线, 把语义存盘留证
  (`docs/design/feedback-edges-*.json`), 画布只画左→右; 验收数字: **右→左 0 条**。
- 注意副作用: 剔除后可能有**功能节点变孤立** ✗ → 必须补回正向边或把该节点移到其上游右侧;
  验收: **功能孤立 0**(行背景带/分区标题的"孤立"是设计如此, 不算)。

## 4. 新节点必须带 `icon` + `color` (+ 合法 `type`)
**画布会静默过滤缺字段的节点** ⇒ 流程 JSON 有 N 个节点、画布只装 N-1 个,
对账用例会报"画布 82 / 流程 83" ✗ (看起来像功能坏了, 其实是字段缺)。
- 最省事的做法: 照抄一个同类节点的字段集 (`icon`/`color`/`type`/`w`/`h`) 再改内容。

## 5. 连线/字段的既有口径
- 连线键名是 **`f` / `t` / `f_port` / `t_port` / `label` / `id`** (不是 from/to);
  新增连线要自己生成唯一 `id`(如 `lkl2m1`)。
- 改完流程 JSON 要**重新加载画布**才看得到(重启控制台会打断用户会话 ⇒ 让用户点一次「状态空间」即可;
  **用户正在用控制台时不要重启**)。

## 6. 改完必跑的验证 (缺一不可)
1. 画布装载数 == 流程节点数 (对数法, 别硬写数字)
2. 右→左连线 **0** 条
3. 功能孤立 **0** 个
4. 关键新节点的入/出边数量符合设计 (如"板坐标系定位: 入3 出3")
5. 功能清单↔用例矩阵跑一遍(层标也要跟着架构更正同步)
