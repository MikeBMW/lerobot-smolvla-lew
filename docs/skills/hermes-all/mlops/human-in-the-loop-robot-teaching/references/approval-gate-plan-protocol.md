# 人机在环抓取: "先出计划待批准" 协议 (老倪 2026-09-21 原话)

> 「我现在不告诉你实际的光模块的位置，你要自己通过 YOLO 来检测，用 deepseek 来理解，INTACT 意图动作，
> 用 SmolVLA 来规划流程，用 L2 功能来抓取光模块。我先放到拖动模式，防止你误操作。
> **你先把你的计划，动作想好，给我结果，我来批准你的计划。**」

⇒ **真机动作类任务的默认交付物是"待批准的计划"，不是执行**。零指令状态下先产出计划 + 决策点，
等一句批准再逐段执行。

## 一、计划必须包含的五块

1. **感知/几何现状表** (每条都挂实测证据): 相机是否出帧(帧龄/std)、内参 K、手眼标定与精度、
   示教点及其重复性、检测结果、模型各层状态(含**真水平**, 不夸大)。缺项写"❗未定/待验", 不猜。
2. **分段动作序列**, 每段写齐: 用哪个**已注册技能**、参数、**到位判据**(真值+阈值)、**中止条件**。
3. **免费真值**: 每步能用什么独立物理量交叉验证(夹爪开度 空夹≈21/夹住模块≈185、TCP 到位偏差、
   力值)——不要只靠图像。
4. **安全闸门** (见下第三节)。
5. **决策点清单** (3~5 条, 每条一句话, 只要求用户回字母/数字)——把要用户拍板的事显式问出来, 别替他决定。

## 二、分层职责的写法 (上层给意图, 执行由 L2 收口)

- L1 大模型(VLM): 场景理解 → `data/scene_state.json`(目标/位置/朝向/是否在夹爪上/画面质量)
- L4 INTACT: 意图/方向 (若本域成功率低, **明说它只作参考意图, 不承担运动**)
- L3(SmolVLA/VLM 规划): 技能序列 + 参数, 交用户过目
- L2: **唯一执行者** — 只用注册表里的技能名, 守卫/限幅/真值等到位都在执行器里
- 每个感知结论都要带来源标签与帧龄(用户会把画面当结果)

## 三、安全闸门 (逐条, 越界即停)

1. `operation_state=drag`(拖动模式) ⇒ **一条指令都不发**(驱动也会拒); 这是用户设的防误操作闸门
2. 每条真指令前**逐条请示**; 只用 L2 注册表技能名
3. 绝不碰 `/hmi/command`、`/execute_external_task`、`/state_machine/*`、`/move_*`; **不改产线原有代码**
4. 单步最小步长; 每段独立中止条件; **判完成只看真值**(踩过 `success=False / ROBOT_IDLE_TIMEOUT` 假失败 → 别重发)
5. 判据不达标 → 报"不确定", **不擅自加力/加距离**
6. 只在**绝对必要时**、并拿到用户授权后, 才在产线机上起进程; 起也只起**只读那一个节点**
   (例: 只起 `camera/realsense_source` + 原参数, **不启 `/motion` 等控制栈** —— 起整条 launch 会让状态机自己跑流程 = 真机运动)
7. 收尾交代: 你手工起的进程, 用户要起整条产线程序前必须先停它(否则抢设备)

## 四、L2→L1 融合 (拿"看到目标"的最短可靠路径)

通用 VLM 在小目标/远景上会答"目标可见=false"; 而我们自己的 YOLO 在同一帧能检出 →
**用检测框裁剪放大再送 VLM**, 判读结果并入同一个 `scene_state.json` 键(追加式, 不动其它键):
```
L2 检出框(conf) → 带边距裁剪 → 放大(双三次) → L1 判读({"是光模块":true/false,"置信":...,"外观":...})
                 → 落盘对照图 + 并入 scene_state.json
```
实测(产线 RealSense 帧): 整帧判读"两个带绿色拉环的光模块(SFP类)" ✓; 框裁剪判读"是光模块=true(置信中),
顶部绿色拉环/金属外壳/白色标签面" ✓ —— 两层互为证据, 比任何单层都可信。

## 五、开工前的对账项 (缺一个就别谈"精确抓取")

- 位姿来源: 到底哪个话题是真值(`/robot/tcp_pose` 可能 0 发布者) —— **对账/闭环都依赖它**
- 手眼精度 vs 目标尺寸: 例 平移 RMSE 2.5mm 对 10~20mm 的光模块 ⇒ 视觉只够判"哪个槽位",
  毫米级对准要靠示教点重复性(实测 0.4µm) + 接触力
- 深度通道: 有发布者 ≠ 收得到(常见需 BEST_EFFORT QoS); 先验可用性再写进计划
