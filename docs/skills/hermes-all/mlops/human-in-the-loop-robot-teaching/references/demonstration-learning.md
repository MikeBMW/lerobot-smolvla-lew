# 「你看着，学习」= 演示学习流水线 (2026-09-19 首次跑通)

操作员说「我可以让机器人正常工作，你看着，学习，可以不？」时的**交付物**是:
录制真值流 → 切段 → 固化成 L2 技能 JSON → 慢速回放校验。**不是"看着"就完事**。

实测规模: 291s 录制 / 位姿 50Hz(14363 样本) / 夹爪开度 6430 样本 / 画面每 5s 一帧 23 张；
作业窗口只有 t≈200~242s 的 42 秒，其余是待机。

## 1. 录制 (只读, 不在机器人侧留文件)

```bash
# 位姿 50Hz —— 本机落盘, 机器人侧零自研进程
ssh orin 'source /opt/ros/humble/setup.bash; for ws in /home/*/0810/*/install/setup.bash; do [ -f "$ws" ] && source "$ws" && break; done; \
  export ROS_DOMAIN_ID=0; timeout 900 ros2 topic echo /robot/tcp_pose' > ~/zmax_data/demo_pose_<ts>.txt
# 夹爪开度: 同法收 std_msgs/msg/Float32 的开度话题
# 画面上下文: 本机循环 cp 一帧(每 5s) → ~/zmax_data/demo_frames/
```
- 长命令/内含引号/`$()` 的写法常被硬拦 ⇒ **本地写脚本 + `ssh host 'bash -s' < /tmp/x.sh`** 最稳，
  而且不会往对方机器写文件 (红线: 机器人侧零自研进程、零自启)。
- 帧录制脚本要用**解释器绝对路径**启动 (相对路径在别的 cwd 下会 `No such file or directory` 静默失败)。
- 结束要用**不会匹配到自己命令行**的写法停录制 (`pkill -f "rec_[a]\.sh"`)，否则会把自己所在的 shell 杀掉。

## 2. 切段 (停稳段 → 路点)

- 判据: 相邻样本速度 **<2mm/s 且持续 ≥0.3~0.4s** (50Hz ≈ 20 样本) → 取该段均值当路点 (µm 级稳定)。
- 解析 echo 流: 按 `---` 分块, 正则取 `sec/nanosec` + `position(x,y,z)` + `orientation(x,y,z,w)`。
- **路点必须存姿态四元数** —— 只存 xyz 会在回放时 `KeyError: 'quat'`。
  (本次就是漏了姿态崩掉的; 侥幸崩在"发指令之前", 机械臂没动。)
- 演示末尾常混入"事后又挪几下"的尾段 (dwell 十几秒以上) ⇒ **按 dwell/时间裁掉**, 只固化演示循环本身。
- 两个低位点即两个工位: 取料点 z≈0.109 / 放料点 z≈0.147 (本示例)，中段是操作员的搬运路径风格，原样保留。

## 3. 固化 (L2 技能 JSON + contact_guard)

- 位置: `data/skills/l2_muscle/<工件>_<动作>_演示学习_v1.json`；结构 = `id/layer/points{pos,quat}/steps/params/notes`。
- **演示的低位点(z 最小那几个)是"贴底/接触"位** ⇒ 直接回放会硬压。
  技能里必须带 `contact_guard`: 低位点抬高 3~5mm · 下降分两级(先 z+5mm 停 2s) · 到位即停禁下压 · 全程人工在旁。
  理由: 位姿复现精度是 **0.2µm** 级(见下)，所以"压到底是技能定义的问题"，不是控制的精度问题。
- 夹爪的开/合事件与路点**按流内比例对齐只是近似**(开度流没有时间戳) ⇒ 要精确必须同时录时间戳；
  否则把夹爪事件写成"步骤"时标"近似"。
- `data/` 常被 .gitignore ⇒ 技能/点位同时在 `docs/teach/` 放一份入库。

## 4. 回放校验 (验收口径)

- 逐步: 三闸门(`power_state=on` / `operation_state=idle` / `has_error=false`) → 下发 → 读真值 → 与演示值比对(mm) 逐点报。
- 实测: 目标 `(0.64735, 0.29875, 0.10941)` → 实到偏差 **~0.2µm** ⇒ **位姿复现不是瓶颈**。
- 低速走长距离会 `success=False + ROBOT_IDLE_TIMEOUT` (驱动 `wait_until_idle` 上限 30s) 而**动作仍在跑**:
  **轮询 `/robot/tcp_pose` 到位为止, 绝不重发**(重发把 50mm 叠成 100mm)。
- 回放/自动循环的**失败当场如实报**: 本次自主跑"张爪→抬→降→夹紧→抬"5 步, 夹紧那步 `开度=5.0` = **空爪顶死**
  ⇒ 证明示教的"槽位 z"其实在模块**上方**, 两指从空中穿过。
  判据: 夹住应停 ~185~311；停在 ~5~21 = 空 ✗。`success=True` + 开度对了才算抓住。

## 5. 链路落地 (L2 技能 → ROS2 → 机器人)

```
data/skills/l2_muscle/*.json  (L2 肌肉记忆)
   → 本地转发器: 逐条把步骤翻成机器人服务的调用 (bash -s / ros2 service call, 逐步取证)
   → 也可挂到控制台"真机视"面板按钮: 二次确认后起子进程 (解释器用绝对路径, 别用 sys.executable)
```
- 分层口径 (操作员 2026-09-19 更正): **大模型层 = 理解场景** · **L4 = 工作安全 + 物理世界导航** ·
  **L3 = 长程序列规划** · **L2 = 肌肉记忆操作**; 落档 `docs/design/architecture_layers_v511.md`。
- 画布挂节点注意: **node `type` 必须是画布认识的类型**(`model`/`condition`…), 写 `process` 之类未知类型会被
  **静默丢弃** → 表现为"流程 83 / 画布 82 节点数对不上"，排查半天。新节点还缺 `icon`/`color` 也可能被过滤。

## 6. 夹爪"完全不动"的排查梯度 (本状态现场未解决, 只是排除顺序)

症状: srv 调用**返回无错**，但开度恒定不动(本次 579)，开/合/中间值四档(0/150/300/1000)全试过 ✗。
1. 读开度话题是否**持续在发** → 有消息 = 控制器通电并在汇报(排除"断电")。
2. **反向动作测试**(开↔合) → 双向都不动 ⇒ 不是方向性阻塞。
3. **请操作员用示教器按钮开合一次**(决定性对照): 能合 ⇒ 问题在 ROS 驱动/服务侧；也合不动 ⇒
   夹爪控制盒报警/供电/卡死 ⇒ 断电重启控制盒。
4. 机械臂侧三查保持干净再重试。
