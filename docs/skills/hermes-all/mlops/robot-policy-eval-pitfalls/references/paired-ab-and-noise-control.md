# 同 seed 配对 A/B + 噪声对照 (2026-09-12, L4 六层引擎参数寻优实测定稿)

## 触发
- 要用"扫参数/换权重/换信号源"来提升一个**闭环控制器**的成功率, 并要**敢于声称有提升**。
- 看到"某个候选单轮成功率 17%→33%, ✅提升"这类结论, 需要判断它到底是信号还是噪声。
- 老倪红线: 交付门槛是**有提升**(不回退不够用), 但**不夸大** — 两者同时对, 所以口径必须硬。

## ① 为什么单臂平均不可靠 (实锤)
同一份默认参数、同一套 seed、同一进程协议, 重跑就会变:
```
默认参数当候选, 与自身配对 16 对 → 0胜0负16平, 0.250 → 0.250   (测试台自洽, 零假阳性)
另一轮同 seed 集单臂跑        → 基线 0.250 / 0.312 两组数字都出现过
```
⇒ 单轮 6 seed 的"单臂平均"能测到的差异被 ±1 对的抖动吃掉;
**凡只有单轮、单臂结果的正向差异, 只能写「疑似/待配对复验」, 不得写成"有提升"**。

## ② 配对协议 (可复用)
```
每个 seed 内: base 臂跑完 → 立刻在**同进程内**跑候选臂 (背靠背, 消除冷/热启动与布局漂移)
判定: 候选胜 = cand.done and not base.done; 基线胜 = 反之; 其余 = 同分
裁决: 净胜 = 胜 − 负; 净胜 ≥ 2 **且** 大样本复验通过 才算"有提升"
同口径必须一致: 同 seed 集 / 同 reps / 同 max_steps / 同进程内交替 (冷启动偏差是真实存在的混杂)
```
注意**顺序混杂**: 若 base 永远先跑 = 冷启动, 候选永远后跑 = 热启动 → 系统性偏袒候选。
要么背靠背交替, 要么两臂都预热。曾因此整批扫描结论作废。
工具形态: `tools/l4_tune.py --mode paired --set K=V --mod-set NAME=V --seeds ... --reps N`。
- **实例属性 vs 模块常量要分开**: 调度器参数走 `_apply_params` (且 `self.sched` 是在 `_reset()` 里建的,
  不是 `__init__` → 直接取会 AttributeError, 要包 `_reset` 在它建好之后写参);
  模块级常量 (`INSERT_STALL_FRAMES`/`GRIP_CLOSE` 类) 走 `setattr(module, ...)`。
- **未知参数名必须抛错**, 不许静默忽略 (否则"扫了个不存在的参数"会得出假结论)。

## ③ 复验要换 seed 批次, 而且要够大 (本测最贵的教训)
同一候选 `align_xy_fine=0.04` 对默认, 三批同口径:
```
批次1 seeds 0-7  ×2rep : 4胜 0负 12平   0.250 → 0.500   ← 当初据此判"✅有提升"
批次2 seeds 8-23 ×1rep : 1胜 0负 15平   0.375 → 0.438
批次3 seeds 24-55×1rep : 0胜 0负 32平   0.406 → 0.406   ← 32 对完全零差异
合计 n=64: 5胜 0负 59平 · 35.9% → 43.8%  ⇒ **未复现, 不能声称提升**
```
⇒ 教训: (a) 效应量可能全由**第一批**贡献, 别用第一批定论;
(b) "全胜但样本小"(5-0-64) 仍是噪声级证据 — 要看**最大批次**是否复现;
(c) 批次越大越接近真相, 换 seed 复验前不要动默认档。

## ④ 失败根因先分类, 再决定杠杆 (别急着扫参数)
同口径 6 回合实测的阶段-步数分布 + 事件计数:
```
seed1 ❌ 停[插入·接触] 回撤21 遇阻18 重抓5   seed4 ❌ 停[对位] 滑脱6   seed12 ❌ 停[下降] 滑脱6
seed2 ✅ 完成 364步 回撤2 滑脱4 (成功也滑脱, 但能恢复)
汇总: 回撤39 · 遇阻30 · 滑脱20 · 重抓17
```
⇒ 失败是**闭环死循环** (回撤→重对孔→同样偏差再顶住), 不是某个阈值不对。
**结论: 阈值类参数 (align/k_fb/veto/contact/grasp/th 或 遇阻判据帧数) 无法打断死循环** —
实测 10 个候选 (k_fb / align_xy_fine / v_cap_scale / veto_th / contact_th / align_th +
grasp_th / INSERT_STALL_FRAMES / INSERT_JIGGLE_FRAMES / 组合) **全部落在噪声内**。
该关线就关线 (止损), 把算力移到结构性改动 (加恢复策略/换感知通道/换模型侧信号),
并在报告里写"参数线已关闭 (N/N 无差异)"而不是无限扫下去。

## ⑤ 上报口径 (飞书/群报的硬约束)
进度哨兵类 cron 的 prompt 里必须显式写入噪声水平, 否则下一轮报告会把第一批的好看数字当成绩:
```
【已知噪声水平 (必须写进结论, 防夸大)】
同 seed 配对 16 对可探测的最小效应 ≈ 2 对; 默认参数重跑基线也会在 0.250~0.312 之间抖。
→ 只有单轮/单臂结果、未做配对复验的正向差异, 一律写「疑似/待配对复验」, 不得写成"有提升";
  样本外 R² 为负/近零的, 直接写"无信号"。
```

## 可复用判据速查
| 问题 | 判据 |
|---|---|
| 这个候选算有提升么? | 同 seed 背靠背配对, 净胜 ≥2, **且换 seed 批次复验通过** |
| 测试台可信么? | 拿默认值当候选跑一遍: 必须 0胜0负全平 (出现胜负 = 协议有偏) |
| 单轮好看能写进报告么? | 只能写「疑似/待配对复验」 |
| 该继续扫参数么? | 先看失败是"阈值不对"还是"闭环死循环"; 后者扫参数无效 |
