# 训练进展汇报的真实性铁律 (2026-09-10 实锤, 老倪会当场核对)

## 触发
用户问"模型训练有没有进展/突破", 或你要把训练进展汇报给群里/飞书。

## 铁律 1 — 用统计量, 不许挑瞬时值
逐 batch 的 loss 是噪声: 实测同一训练 run 最近 200 条 action_loss = min 0.0116 / max 1.346 /
均值 0.2817 / 中位 0.2448。挑一条低的 (0.0181) 和一条高的 (0.5639) 拼成
"0.5639 → 0.0181 ↓ 持续下降" = 夸大 (真实降幅 ~16%)。
**报趋势用「最近 N 条均值/中位」+ 与早期 N 条对比**; 瞬时极值只能作为范围说明 (min/max)。

## 铁律 2 — 数字与训练日志/配置实况核对
实测翻车: 汇报写"续训覆盖 30000 步", 而训练日志是 `2783/20000`; config 里的 steps=30000 是
旧值未生效。汇报前 grep 日志进度行 + 看实际启动命令, 别抄 config 或作业单。

## 铁律 3 — 分开"引擎/评估修复成绩"与"模型能力突破"
- 引擎/评估管道修复带来的成功率 (如插入成功率 32.1%→46.4%, 28 seed) **不是模型突破** —
  表里必须标类型 ("✅ 引擎修复"), 不能混进模型成果。
- 训练中 loss 下降 ≠ 任务能力; 消融指标优势 (如 Mamba 预测 zRMSE 低 10%) ≠ 抓取/插入能力。
- **突破判定要等训完 rollout 实测** (成功率 / gripper 误差等任务指标)。训练中只能报"进展"。

## 铁律 4 — 汇报格式 (给群/飞书可直接用)
```
📊 训练进展(N/M 步 · x%, ETA ~h)
- 指标1: 近N条均值 a → 早期 b (降 x%) [统计口径]
- 指标2: 均值/中位 + 范围
- 消融/评估: 数值 + 是否模型侧
- 结论: 是"进展"还是"突破" + 待验证项
```
禁止把 "0.56→0.018 持续下降" 这类无统计支撑的戏剧性曲线写进汇报。
