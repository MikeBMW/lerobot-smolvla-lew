# 评测口径假 0%: harness 自拼 batch ≠ 引擎真实调用 (2026-09-26 实测)

## 症状
同一颗策略 (state_space, `outputs/train/state_space_mw5w/checkpoints/030000`):
- 独立评测脚本 `tools/rollout_peg_check.py` (自己拼 batch: 裸 env obs + `select_action`) → **0/5 插入成功**
- 引擎自己的 L3 闭环 (`state_space_sim_real.py` SS_L3=1) → **done=true · 末端 0.9mm · 阶段走到「完成」· 378 步**

⇒ 前者是**假 0%**。策略真实能力 = 后者口径下的数字。

## 铁律
1. **评测必须复用被评对象自己的调用路径** (`_l3_pre` / `post` 处理器 / 引擎的 obs 构造 / 图像尺寸 / task 串)。
   独立脚本自己拼 batch = **必然不同源** → 0% 是脚本的结论, 不是模型的结论。
2. **带正对照**: 同一 harness 里同时跑一颗**已知能用**的权重 (引擎文档标注过 insert N 步完成的那个)。
   正对照失败**不等于** harness 失效 (它可能只是需要更多步: 本例文档口径 insert 341 步 / full 865 步, 420 步内跑不完);
   有效性证据用**引擎自报实际加载的 ckpt** (`🏆 L3 真执行接入: … 模型 ckpt = <path>`) 逐档可核。
3. **换 ckpt 必须清类级缓存**: 引擎把 policy/pre/post 缓存在**类属性** (`RealStateSpaceSim._L3_CACHE`),
   不清就会出现"两档数字逐位相同"的假 A/B。
4. **报 n 和分布**: 同口径下单种子得 1/1(100%), 5 种子得 **1/5(20%)**, 各 seed 最小末端 [1.0,1.3,5.2,1.4,2.4]mm。
   单种子点值会把自己骗了 —— 必须多种子/K 折 + 注明 n。
5. 失败指纹速查: **首层维度不收 (43 vs 39) / 输出被压到 [-1,1] 而真值量级差几个数量级 / 两档逐位相同** =
   口径问题, 不是能力问题。

## 相关: 同源数据量会伪装成"能力不足"
同一颗事件级认知头, 只换**同源训练数据量**与**判据口径**:
- 单次 80/20 划分, reach_z_H10 = 0.7825 (未过 0.79 门槛) → 看上去"能力不够"
- 同数据 5 折 CV: 均值 0.7999 / 最低折 0.7589 / std 0.030 → "勉强达标"
- 同源数据 30 段 → **300 段** (66,000 帧, 引擎自己的 tr): 最低折 **0.69/0.72 → 0.93**, 均值 0.95+ → 门槛稳固通过
⇒ 判据用 **K 折均值 + 最低折 + std**; 数据不足要补同源数据, 不要先加模型容量 (容量 256 vs 128 反而更差)。

## 跨分布不可假定
同一颗头: 造数据管线产物 (l5_gen_v6) 训 → 引擎闭环 AUC **0.238** (低于随机); 引擎 tr 同源训 → 闭环 AUC **0.997~1.000**;
同源头在另一个生成分布 (l5_gen_v5) 上 **0/6**。⇒ 训练域必须与**运行流**同源; 迁移能力不能假定 (同管线内可迁移, 跨管线不行)。
