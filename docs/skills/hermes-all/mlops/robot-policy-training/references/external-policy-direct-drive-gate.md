# 外部预训练策略: 离线回放闸 + 直驱闭环 + 微调预算 (2026-09-12 实测)

场景: 把 INTACT-JEPA (pusht/cube 训的论文权重) 接进本工程六层引擎 (metaworld insert), 让它
**自己的动作直接驱动机器人** (老倪口径: "不改任何逻辑, 直接复制原项目")。
同轮工作的建模/桥接侧见 skill `cross-venv-model-canvas-node` (§8.5/8.6); 本文只记
**判决闸 + 直驱 + 训练预算** 三件事, 全是实测数字。

## 1. 离线回放闸 (原项目自己的评法, 闭环前必做)

原项目 eval 就是: 数据集真帧喂模型 → 输出 action → 与数据集 action 列比。本工程同口径实现
(`tools/<name>_replay_check.py`): 抽 N 帧 → 节点 step → `chunk[0, slot*4:(slot+1)*4]` →
逆归一化 → 与教师 action 逐维比 MAE / pearson / spearman / std。

**判据 (缺一不可)**:
- 模型 xyz MAE **显著优于常数基线** (常数基线 = 永远输出教师均值; 不比 MAE 直接看相关系数会被均值主导骗过)
- 逐维 |ρ| 有量 (实测 |ρ|≤0.27 = 无信号)
- 预测 std 与教师 std **同量级** (塌缩的模型 std 小 10~25 倍)

实测 (微调 8 epoch / 36 回合, 20 万级参数量级策略):

| 量 | 模型 | 教师 / 常数基线 |
|---|---|---|
| xyz MAE | 0.0919 | 常数基线 0.0860 (d**不如常数**) |
| dx / dy / dz pearson | +0.11 / −0.18 / −0.06 | — |
| 预测 std (dx/dy/dz) | 0.0145 / 0.0028 / 0.0383 | 教师 0.172 / 0.081 / 0.113 |

⇒ 动作头**塌缩到均值**。slot 0 与 slot 1 分别测, 结论一致 → 排除"读错槽位"。

## 2. 直驱闭环 (模型动作 → env.step, 中间无控制器)

- 每步真推理一次 (`--infer-every 1`), 把 `chunk[0,0:4]` 逆归一化后**直接**当 env 级动作:
  `a_raw = z·std + mean` (std/mean 取自训练数据集同口径 `get_column_stats`: finite 行 + ddof=1),
  `clip(±1)` → `env.step`。这是训练归一化的逆运算, 不是新增映射 (原项目 eval 同样做逆变换)。
- 引擎侧钩子默认关闭 (`_direct_act=None` → 既有解析链/MLP 路径零改变); 直驱时**夹爪也跳过阈值化**
  和重夹窗口, 否则连续动作被压成两态。
- 阶段状态机保留 (只取阶段标签做记录), 其解析指令被丢弃 —— 这样 KPI (`done`/步数/阶段分布)
  与基线**同口径可比**。
- 实测结果: 直驱 0/4, 同轮解析链 1/4; 每回合 600 次真推理**无报错**, 但下发动作 std 只有教师的
  1/20 (x 0.0072 / y 0.0025 / z 0.0082) → 物理上推不动, 阶段一直停在 接近/对位。
  失败根因 = 上表的动作头塌缩, **不是接线**。

## 3. 训练预算 (先算再跑)

- `steps/epoch ≈ len(dataset)/batch`, 而 `len()` 是**滑窗数** ≈ 原始帧数 (num_steps=8, frameskip=2):
  每 epoch 实际过 7~8× 原始帧。
- 8GB 卡: batch 24 → `torch.OutOfMemoryError` (总容量 7.62 GiB); **batch 16 + num_workers=12** 稳。
  32 核机: 4 workers 0.77 s/步 → 12 workers 实测 **2.1 it/s** (吞吐翻倍; 数据加载曾是瓶颈)。
- 实测 15 万帧 + batch16 ≈ 8,278 步/epoch ≈ **66 min/epoch**; 30 epoch ≈ 50 小时 (不可接受) → 砍到 3。
- **每个 epoch 落独立 ckpt** → 训练跑着就能逐个过离线闸, 过闸即提前上闭环, 不等满轮次。

## 4. 数据侧必踩的两个坑 (域内微调数据)

1. **一次性 concat 会 OOM 且什么都不落盘**: 300 回合 × ~500 帧 = 15 万帧 ≈ 22GB 内存,
   采集循环跑完 1095s 后在落盘处被 OOM 杀 (日志无 ✅ 行 = 最隐蔽的症状)。
   修法 = **分块落盘**: 每攒 N 帧 (实测 2 万帧/块 ≈ 1GB npz) 写一个 part npz (每 part 自包含
   `ep_len/ep_offset`, 带**帧std 校验**与 `done_rate`), 再由流式合并工具逐 part 追加进 h5
   (`create_dataset(maxshape=(None,...))` + `resize` + gzip chunks, 峰值内存 = 一个 part)。
2. **合并后自检不要用裸名**: `swm.data.load_dataset("zmax_insert_v2")` (无 `.h5`) 会
   `FileNotFoundError: not a local path or HF repo id` —— 因为解析器把名字当目录
   (`<cache>/datasets/<name>`) 找。**带扩展名** `zmax_insert_v2.h5` 才对。
   这个报错曾让"采集→合并→训练"接力脚本 `|| exit` 静默断链 (训练根本没起来)。
   最后一定用**官方加载器**读回来验 (样本数/action_dim/pixels std 三个数)。

## 5. 汇报纪律

- 离线闸不过就说"动作头没学会", 不要用"已接通/管线已通"顶替效果结论。
- 直驱成绩必须与**同轮同口径**解析链对照 (实测 0/4 vs 1/4), 不跨轮次比。
- 说清"实际在跑什么": 真推理次数、动作 std、阶段分布都要给, 别只给成功率。
