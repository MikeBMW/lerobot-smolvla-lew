# 画布"层带归属 / 断头 / 右→左线" 判定口径 (2026-09-23 老倪三问实锤)

起因(原话): 「L3 长程序列规划器节点, 为什么在大模型层?」「L2 肌肉记忆技能库, 为什么在 L4 记忆层?」
「状态校正器节点, 为什么没有输出信号连接?」——三问都要**用真画布几何取证**, 不能读 json 推算。

## 1. 「节点在哪一层」= y 落进哪条 row_bg 带
- 带矩形是**整行宽**(实测 x≈-126…9380), 所以只需判 y: 大模型层带 y=932..1350 · L4记忆行 y=1400..1694 ·
  L3 高级自动功能带 y=2556..2850 · L2记忆行 y=2900..3194 · L2 分段控制小模型带 y=4056..4350。
- ⚠️ **真场景坐标 ≠ json 坐标**: 加载时 `_relayout_row_gaps(min_gap=56)` 把同一 y 桶内的节点依次右推
  (普通节点还被撑到 w≥280)。实测 状态校正器 json x=2456 → 真画布 x=2798 ⇒ 判定一律用真画布几何。
- 取证命令:
```bash
QT_QPA_PLATFORM=offscreen gui-venv311/bin/python tools/canvas_node_audit.py \
  flows/state_space_obs.json 状态校正器 肌肉记忆技能库 长程序列规划器
```

## 2. 「画布位置 ≠ 权威归属」——别自己挪节点
- 归属真源 = `src/lerobot/verification/capability_levels.py`:
  L3-B02「任务规划: 任务指令→技能序列(任务规划器/技能编排, 规则+LLM 可插拔)」= **L3 档**;
  L2-A08 原子技能 = L2 档。
- 画布那条 `🧠 大模型层 · 任务/编排/记忆中枢 (回路外慢决策)` 是按**功能**分组(把 L3 规划器/编排器
  与 VLM/DeepSeek 场景理解摆同一行), 坐标被 `tools/gui/post_layout_fix.py` 的 **PIN 表**钉死
  (`{"ssllm": (1460,952), "ssskill": (6080,952)}`) → 与 capability_levels 及 2026-09-19 定稿
  (「LLM 层=场景理解, L3=长程序列规划」) 冲突。
- 处置口径: 报"布局遗留(谁钉的、哪一行)+ 两种修法"(移进真 L3 行 / 改带名·标注), 让老倪决定;
  不要自己挪 —— 挪了会牵动多条边的方向判定与 relayout。
- 同类: 💪 L2 肌肉记忆技能库 被放在 (800,1400) = L4 记忆行(2026-09-19 落技能时直接给的坐标),
  且**悬空**(出1入0, desc 自称"由 L3 序列调用"却没有入边)。属 L2 档, 正确位置 = L2 记忆行 y≈2900。

## 3. 🐛 「某节点没有输出连线」→ 先查 post_layout_fix 的 purge/RESTORE 顺序
- 现象: 状态校正器 真画布 入3/出0 = 断头; 但 🧭动作调制器 的 `in8` 端口标签至今写着
  「contact+残差 (状态校正器)」= 端口还在等这条线(语义端口已备, 边没了)。
- 根因: `tools/gui/post_layout_fix.py` 为实现"画布不许右侧输出连左侧输入", 剔除**所有 `f.x >= t.x`**
  的边并 dump 到 `docs/design/feedback-edges-v510.json`。当时 校正器 x=5750 > 调制器 x=3520 →
  被判右→左删掉。而脚本顺序是 **RESTORE → purge** → 恢复的语义边下一轮又被剔除, 且 dump 是**覆盖写**
  → 上一次的记录被冲掉 = **语义记录永久丢失**(现存 feedback-edges-v510.json 只剩 3 条)。
- 定位手法(逐提交查该边存亡):
```bash
for c in $(git log --format=%h -30 -- flows/state_space_obs.json); do
  git show $c:flows/state_space_obs.json | python3 -c "
import json,sys; d=json.load(sys.stdin)
print('$c', any(l['f']=='ssinnov' and l['t']=='ssched' for l in d['links']))"
done
```
  → 该边最后存在于 `adc464b7`; 在 `13632919`(「剔除22条右→左连线(存feedback-edges)」) 消失。
- 修法(已实测, 复跑不丢): ①补回边 `状态校正器(out1) → 动作调制器(in8)`
  ②把 RESTORE 移到 purge **之后**(脚本复跑会打印「↩ 复跑保边: ssinnov → sssched」)
  ③label 加 `↩ 反馈 · ` 前缀(标明语义回流, 不是前向数据流) ④如实报告右→左线计数代价 18→19。
  新增辅助脚本: `tools/fix_canvas_ssinnov_edge.py`(带备份 + 幂等)。
- 通用教训: **"剔除 + 恢复"型脚本, RESTORE 必须放在剔除之后; 存档必须追加/带时间戳, 禁止覆盖写**。
  否则语义边被静默清除, 事后连证据都查不到。

## 4. 断头 / 孤立 / 悬空 的判定口径
- 工具: `tools/canvas_node_audit.py` = offscreen 真画布加载 + 逐节点 真位置/所在带/入出线数/判定
  + 全画布反向线清单 + 断头(有入无出)/孤立/悬空(有出无入)列表 + 端口 slot 顺序。
- 判定: 显示/终端节点(3D视图 · 波形 · 前馈直方图 · 操作视频 · Test用例 · Feature清单)**天生有入无出
  = 合法终端**, 不算断头; 真可疑的是"包"节点(🧠意图丛 / 🧬技能词典 / 🔗跨层连接)与能力节点。
- 实测基线(2026-09-23, state_space_obs.json): 节点 83 · 画布渲染连线 128(JSON 132: 4 对同名重复边被
  画布按名去重) · 反向线 19 · 断头 13(其中约 10 个是合法终端) · 孤立 0 · 悬空 11。
- ⚠️ 画布加载会**重映射 node id** → 断言/查找一律按**节点名**。
- 改完 flow JSON / 布局脚本 → 重开画布即生效(画布是加载时读 JSON)。
