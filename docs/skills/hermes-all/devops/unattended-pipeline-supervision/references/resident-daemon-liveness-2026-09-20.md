# 常驻执行器 daemon: 自启 / 存活判据 / 热替换 (2026-09-20 实战)

现场症状: 机器重启后, 依赖常驻执行器的界面与技能**静默失能**(界面只显示「执行器未跑」,
按钮点了没反应), 而同机其它有 `@reboot` 的守护照常起来 —— 没人察觉, 直到用户现场点按钮才发现。

| 铁律 | 反面(实踩) | 定式 |
|---|---|---|
| **① 必须自启** | 常驻执行器(本项目 `tools/l2_daemon.py`)只在终端手工起过 → 一次重启永久失能(既不在 crontab `@reboot`, 也不在 systemd) | `~/.hermes/scripts/<name>_keepalive.sh` + cron `@reboot sleep 25 && bash …` 与 `*/5 * * * * bash …`; 脚本**在跑就静默 exit 0**, 未在跑才拉起并打一行日志(与同机 `auto_loop` 守护同款) |
| **② 改代码后必须真重启验证** | 给 daemon 加"注册表热加载"却漏定义 `REG_PATH` → `NameError` **启动即崩**; 而崩之前那一晚技能还能用(内存里跑的是改动前的旧代码) → 只有重启才暴露 | `py_compile` 过 ≠ 能起来(运行时 NameError 语法检查抓不到); 改完 **停旧进程 → 由保活脚本拉起 → 看启动日志第一行**("常驻执行器启动 · FIFO=… · 原子技能 N 个") |
| **③ 存活判据要精确匹配 argv** | `pgrep -f <name>` / `/proc/*/cmdline` **子串**搜索: 脚本名会出现在 grep / 编辑器 / Hermes 包装 shell 的命令行里 → 真死了也报"在线", 保活形同虚设(静默假信号) | `argv = open(p,'rb').read().decode('utf-8','ignore').split('\0')`; `'python' in argv[0] and any(a.endswith('tools/l2_daemon.py') for a in argv[1:])`。实测: 放一个命令行含该文件名的诱饵进程, 旧判据命中 3 / 新判据命中 1 |
| **④ 热替换先停旧实例** | 新实例 `unlink+mkfifo` 重建 FIFO, 而旧实例每轮按**路径**重新 `open(FIFO)` → 两个实例读同一个新 FIFO ⇒ **每条指令执行两次**(相对运动类会真走两倍距离) | 先停旧 pid 再拉新; 起完复核**实例数 = 1** |

自查: 保活脚本"已在跑"分支必须**静默**且不重复拉起; 拉起分支必须留一行日志
(否则"没说话"无法区分"没事"与"没接线")。二进制响应(图像/视频)不要 `decode('utf-8','ignore')`
灌进日志 —— 落盘 + 量化输出, 见 `camera-frame-forensics` 技能。
