工具 `tools/selfcal_kinematic.py`；监督信号 = 编码器 q + 控制器 `endInRef`；对比对象 = URDF `FK(q)` (tool1)。

| 项 | 实测 |
|---|---|
| 采集 | 24 构型 (J1~J3 ±3°, **J4~J6 ±12°**), 关节运动 `speed=8` |
| 基线残差 | **2.519 mm** (均值/中位/最大 2.519/2.519/2.520) |
| 残差向量 | 均值 `[-1.0848, 0.2552, 2.2594] mm` · std `[1.5e-4, 1.9e-4, 1.6e-4]` ⇒ **逐构型完全相同** |
| 自拟合(基座+工具偏移) | 修正后 **0.000 mm** |
| 可辨识性 | 设计矩阵条件数 **3.885e6** (±2° 与 ±12° 两轮都不可分离) |
| 结论 | **纯固定偏移** ⇒ 运动学无零位/杆长误差; 采用常量基座偏移模型 |
| 产物 | `data/selfcal/kinematic_correction.json` |

## 2. AOI 相机 (工控机 10082) 二维重复定位取证 —— 判"不可用"
| 判据 | 实测 | 判定 |
|---|---|---|
| 取图新鲜度 | 每次拍都验 `/last_result.origin` 文件名变化 → 12/12 真新拍 | ✅ 不是旧图问题 |
| 同姿态内曝光 | 连拍 3 帧 std 81.8/81.8/81.8 (另几次 30.1/30.0/30.0 · 53.6/53.5/53.6) | 稳定 |
| 跨姿态曝光 | 81.8 → 28.6 → 53.5 (差 **64.5%**) | ❌ 自动曝光 + 光照随位姿变 |
| 强度差分+差异簇 | 全幅变化 70%+; CLAHE 归一后 0.5% 但**簇乱跳** (位移翻倍 562→103px) | ❌ |
| NCC 模板匹配 | 12/12 NCC ≈ **0.84**(泛匹配地板) · `corr(TCP.x,u)=+0.034` · `corr(TCP.y,v)=+0.038` | ❌ 匹配到噪声 |
| 更早一版判据 (已纠正) | 用 Canny(60,160) 判"无新边缘" —— 位姿 1/2 是**暗帧**(std 34/饱和 0%) → 暗部结构被漏 | 判据本身失效 |

**结论表述法**: "臂确实在视野内（0.5% 局部差异簇证明），但本相机逐帧自动曝光 + 场景纹理贫乏
⇒ 二维观测不可重复 ⇒ (图像, TCP) 配对在现有条件下不可得"。附三条量化判据 + 需要的条件（固定曝光/增益 或 标记物）。

接口字段实测: `POST /capture_detect` = **异步受理**（只回 `{"code":200,"msg":...}`，不出图）；
图在 `GET /picture?kind=origin`（2448×2048, ~5MB）；判决在 `GET /last_result`（`count/defects/detect_type/ms/origin`）。

## 3. 失权中止事件 (安全案例)
```
我上次读到:   q=[1.90, 30.15, -125.47, 3.46, 129.37, 42.39]°  TCP=(597.3, 142.2, 641.6)mm
执行中 11 次: q=[15.50, -26.91, -158.05, 132.5, 15.78, -79.94]°  TCP=(526.8, -29.4, 291.6)mm
              ⇒ ΔJ2 57° · ΔJ4 129° · Δz -350mm(接近台面) · Δy -171mm
我的 12 次 /move_joint 指令: 12/12 读数逐位相同 ⇒ **未生效 / 控制权不在我**
旁证: 产线 motion 节点在跑 (pid 7076) · 控制器日志有 "已请求机器人停止：上位机紧急停止" / "INFO_CODE_EVENT 全部停止 E-0001"
当前瞬时: 速度全 0 · power=on · operation_state=idle · has_error=false
处置: 立即停手, 不做任何写入, 只读核查后上报 (含上述全部数字) + 建议现场确认
```
教训: 闸门"瞬时通过"（idle/静止/上电）**不等于**我有控制权 —— 必须叠加
①产线进程检查 ②指令生效性验证（读数是否变化）③位姿是否被我驱动改变。

## 4. 其他可复用事实
- 单轴精度: J6 相对 +1° (0.017453 rad) → 实测 ΔJ6 = 0.0174193 rad（误差 34 µrad, 0.998°）· TCP 弧长 0.4184mm vs 理论 0.4224mm（0.95%）。
- `/move_pose` 精度: 下 x+10mm → 实测 ΔTCP (10.000, 0.000, 0.000)mm; 回位与起始差 0.000mm。
- SDK 桥 `/status` 字段: `powerState`/`operateMode`/`jointVel`/`jointTorque`/`endInRef`/`flangeInBase`；**无 `operation_state`**。
- `CartesianPosition` 对象不可迭代 → TCP 要按属性取; 长消息被截断时 `json.loads` 会失败 → 改纯字符串查找。
