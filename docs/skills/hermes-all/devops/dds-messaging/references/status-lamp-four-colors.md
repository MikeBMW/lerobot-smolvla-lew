# 状态灯 (四色语义) —— 实现与坑 (2026-09-29)

老倪要求: 「所有 topic 数据都是系统状态的反馈或输入/输出信号; 每个模块要有个状态灯;
绿=正常 · 红=故障 · 黄=报警 · 黑=无信号」。

## 唯一口径放包里, UI 不许自己判

`src/lerobot/dataspace/lamps.py`(纯函数, 零依赖):
`topic_state(key, rec, designed_hz, allowed, now)` · `module_state(node_id, signals, topic_states)` ·
`tally()` · `worst()`。探针把结果写进 `live.json`(`lamp` / `lamp_reason` / `lamp_tally`),
控制台/网页只读 —— 否则“到底算不算故障”会在 N 个地方各判一次。

## 判定顺序很重要(错了就会带错现场判断)

1. 不在档位白名单 → 黑「本档位不发」(量产 prod=0 话题是**预期**, 不是故障)
2. 窗口内 0 条 / 无记录 → 黑
3. **数据龄 > max(5s, 3/设计周期) → 黑「无信号: 最后一条 Xs 前」**
4. 规则 violation/veto → 红; 告警级规则 → 黄
5. 实测 Hz < 设计 ×60% → 黄; 配对 0 → 黄
6. 其余 → 绿

第 3 条最容易漏: 数据停了以后旧样点还在观察窗里, 只按“频率偏低”判会**一直挂黄灯**,
永远不到“无信号”。必须先看数据龄。

**取值前先 dump 一次真实落盘 JSON 的键名, 不要照上游内存变量名写**: 探针落盘的是 `age_s`,
而上游内存里那个变量叫 `last_ts` —— 照内存名字读 ⇒ 该分支永远不生效(实测: 数据停了 63s
仍报黄灯)。取值函数写成两种键都认(`age_s` 优先, 退 `now - last_ts`)。
改完分支后用**一条真实落盘记录直调该函数**验证命中(打印返回的 reason), 不要只看总览计数——
总览只告诉你“有几盏红”, 不告诉你“这盏红是怎么判出来的”。

## 模块灯 = 输出信号的聚合

任一红→红; 否则任一黄→黄; 否则全黑→黑; 否则有黑有绿→黄(部分信号无); 否则绿。
零输入/输出的模块 → 黑「无输入/输出信号」。
**容错取灯**: 总线库里信号带全名 `zmax/xxx`, live.json 里是短键 `xxx` —— 取灯函数必须
两种都认, 否则模块灯恒黑(实测踩过: 回灌全绿时 74 个模块灯还是黑)。

## 实测灯语转换(可用来验证实现)

| 场景 | 模块灯 |
|---|---|
| 无节点间数据流 | 全黑 74 |
| 工程回灌运行中 | **全绿 74** |
| 回灌刚停 | 黄(数据变稀=报警) → 窗口过期后转黑 |

真故障实例: `ss_calib` 红 `valid_flag: valid=0`(标定文件无效); 真报警实例: `hw_state` 黄
`hz_tol: 实测 0.21Hz vs 设计 0.33Hz`。

## UI 坑(控制台)

* 黑灯在深色底上必须加描边(否则看不见), 黄灯用 #f1c40f。
* 深色主题要在 Tab 顶层 widget 上套 QSS(表/树/文本/输入/表头), 否则 PyQt 默认白底 +
  深色主题字色 = “看起来没字”(实测纯白像素 62~79% → 套 QSS 后 0.0%)。
* 空表要有“计数行 + 空态提示”(如“暂无报文 —— 先看状态灯是哪一盏黑/红”), 否则专家无法判断
  是没数据还是界面坏了。
