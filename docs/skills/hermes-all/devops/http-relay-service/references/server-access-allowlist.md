# ECS/服务器「只允许指定机器访问主页」白名单实施（2026-09-25 实测）

## 需求形态
> 「除了 A 机器和 B 机器，谁都访问不了 ECS 主页」

即：**按来源 IP 白名单**限制访问，且**指定的机器必须仍能正常用**（包括数据中转链路）。

## 分层：应用层 + 网络层都要做
```
① nginx allow/deny  → 应用层（HTTP 403）
② 云安全组/防火墙   → 网络层（连不上）
★ 只做①，别人仍能绕过 nginx 之外的面板端口/直连后端 → 要"谁都访问不了"就得两层都做
```

## ① nginx 白名单（宝塔面板环境注意点）

```nginx
# 在站点 vhost 里（宝塔: /www/server/panel/vhost/nginx/<域名>.conf）
location = / {                      # ★ 只锁主页（见下方"关键坑"）
    allow <机器A的公网出口IP>;
    allow <机器B的公网出口IP>;
    deny all;
}
# 需要锁整站时用 location / { ... }  ← 慎用, 见"关键坑"
```

### 关键坑：**锁"主页"和锁"整站"是两件事**
```
需求说的是"主页"（`location = /`）。但/下面常有 API/中转端点（relay/upload 等）。
若顺手写成 `location / { allow...; deny all; }` 把整站锁上：
  → **会切断数据中转链** —— 现场设备（如机器人上位机/边缘盒）的上网出口 IP
    通常**不在**白名单里 → 它上传数据的通道直接被 403 掐断。
⇒ 默认只锁主页; 锁整站必须是**显式选择**且先核对所有依赖该域名的出口 IP。
```

### 落地脚本必须自带的三个保护（少一个都可能把站点搞挂）
```bash
# 1) 改前备份 vhost
cp "$CONF" "$CONF.bak.$(date +%s)"
# 2) 写入后**语法校验**, 不过就回滚
#    宝塔环境的 nginx 是自带二进制, 不是 systemd 那个:
/www/server/nginx/sbin/nginx -t
[ $? -ne 0 ] && { cp "$BAK" "$CONF"; /www/server/nginx/sbin/nginx -s reload; exit 1; }
# 3) reload 后从**本机**自动复验（白名单内的机器应仍 200; 若把自己也锁外面立刻回滚）
curl -s -o /dev/null -w '%{http_code}' "https://<域名>/"
```

### 取"机器公网**出口** IP"（不是内网 IP）
让每台机器自报，多源交叉验证（NAT/多出口时会不一致）：
```bash
for u in https://ifconfig.me https://api.ipify.org https://ipinfo.io/ip; do curl -s "$u"; echo; done
```
⚠️ **出口 IP 会变**（家宽/运营商 NAT/换网）→ 白名单是"会过期的配置"：
留一个更新入口（脚本接收新 IP 参数重跑），别把 IP 硬编码进一堆地方。

## ② 云安全组（网络层）
控制台/API 里把 80/443 的入方向**只放行**这些 IP；其余拒绝。
> 这一步通常在云控制台做（或需 API 凭据）—— **先确认谁有权限**，别承诺"两层都配好了"
> 而只做了一半。对外表述时明确"①已做/②待做"。

## 无法自行实施时要如实说清
实测场景：能 SSH 才有权限改配置，而**SSH 免密不通且没有密码环境变量** →
**不要猜测/试用凭据**。直接把状态与所需输入一次讲清：
```
现状: 域名首页返回 200（说明 web 层在）, 但 relay 端点 502（后端服务已死）
阻塞: SSH 无免密、无密码环境变量 → 我无法自行恢复
需要: ①机器B的公网出口IP  ②服务器 SSH 密码（或你自行执行恢复命令）
脚本已就绪: <脚本路径>, 拿到输入后一条命令执行
```

## 自检清单
```
□ 备份了 vhost 且知道回滚命令
□ nginx -t 通过（用的是面板自带二进制, 不是 systemd 的 nginx）
□ 白名单内机器实测仍 200（自己别被锁在外面）
□ 白名单外机器实测 403/超时（**真的验一下**, 别只配了就算）
□ 明确是"只锁主页"还是"锁整站", 且整站时已核对所有依赖出口 IP
□ 安全组那一层单独交代状态（做了/没做/需谁做）
```
