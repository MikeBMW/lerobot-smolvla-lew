# 远端检测服务的"判决"与"输入几何"取证 (2026-09-24 产线 AOI 实测)

> 适用: 相机/检测服务在**远端主机**, 本机只能通过 HTTP 触发+取图, 判决不直接返回。
> 三条现场追问, 每条都栽过一次: 「为什么恒回 success?」「现在调用模型了么?」「模型检测的是裁减后的图么?」

## 1. `{"code":200,"msg":"success"}` 往往不是判决

程序流程 (Flask): `ensure_camera` → 抓图存盘 → 写"最近照片"(+时间戳) → **投递检测队列** → **立即 return 200**。
源码注释即「已拍照, 投递检测队列 (**不阻塞动作**)」⇒ **恒 success 与有无缺陷无关**。

- 真判决只有两条路: ① `GET /last_result`(verdict / count / defects / n / ms) ② 远端主机终端 stdout
- **别拿 200 当 OK/NG 对外报**; 对外表述要写清"触发成功 ≠ 检测通过"
- 现场症状「应该有缺陷啊, 为什么反馈成功」= 这个语义被误读, 直接给流程图即可解释

## 2. "模型吃的是哪张图" —— 用三条证据回答, 不靠猜

1. **调用点**: 搜远端程序里 `detect(...)` / `enqueue_detect(...)` 的实参 (实测只有 `topview`=裁减图被投递, 原图只是存档)
2. **文件名链**: `/last_result` 里那张图的名字 == `/crop_info` 里 `crop_file` 的名字 → 同一文件
   (⚠️ 比对时先 `os.path.basename` + 反斜杠归一, 远端回的是 `.\dir\X.png`, 直接字符串比会假 False)
3. **尺寸口径**: `/crop_info.canonical` == 模型 `imgsz` ⇒ 无 letterbox/上采样, **裁减质量直接=检测质量**
   (`/crop_info.score` 是它自家对齐分: 实测 0.29 / 0.4378 / v4 模板法 0.95+; score 低 ⇒ 召回不可信)

## 3. 几何/拉长口径: 先问"要多少倍", 别默认拉满

现场定稿: **只把短边拉 k 倍, 长边保持原样** (k=2) —— 例 条 1623×135 → **1623×270**;
反例是"把条映成方图"(纵向十几倍) 被现场否掉: 观感"太长了"、且焊盘边缘被放大成密集纹理, 后续判据全失真。

- 实现要点: 拉长只作用于**短边** (`stretch_short(img, k)`); 保留"显式传 out 尺寸=旧方图口径"的兼容分支
- **裁过曝/裁边界必须行+列都做**: 只做行裁会留下 **100% 饱和的边列** (实测最右 10 列全白)
- 我们的判据图与远端模型的口径**可以不同**, 但**要拿两者做对比/训练就必须先统一几何口径**, 否则白训

## 4. 两套方法结论相反时: 不能直接采信任一

实测: 同一张模型输入图 → 远端 YOLO 判 `OK(count=0)` ‖ 我们启发式判 `FAIL 3 项`(划痕 376 / 污染 263 / 氧化 41.87)。
原因: 我们的阈值不是在"拉伸后的图"口径下调的, 焊盘边缘被放大成密集边缘/斑点 → **假阳性**极常见;
反之也**不能凭它否定远端 OK**。定论只有两条路: ① 人眼在**原图**上核对 ② **同口径留出集**分别量漏检/误报。
证据包建议落 `reports/compare_<ts>/`: 原图 + 模型输入图 + 两套结论 json + 双方指标。
**措辞纪律**: 写"两套结论不一致, 待同口径定论", 不要写"模型漏检"。

## 5. 采集红线 (实测事故): 自动刷新/自动抓拍会连拍产线

曾因窗口「自动刷新·真拍」默认开着 → **每 5s 真拍一次产线台** (审计流水 132 条)。
- 规则: 默认档一律**只读不采集**; "真拍"需**显式勾选**且间隔**强制 ≥10s**
- 所有"实时/推送/监听"类功能: 用**内容标识变化**轮询 (如远端 `/last_result` 的文件名变了才动作),
  **只消费, 不产生** —— 绝不为了推送/刷新去反复触发采集
- 审计: 每次真采集写 `reports/*_capture_log.jsonl` (谁/何时/哪台/耗时/HTTP), 事后能举证"没乱拍"

## 6. 对方"圈选/选源"这类人工输入, 用数字回读而不是截图

界面侧把用户的选择落盘 (选区坐标 + 倍数 + 来源 + 输出尺寸 + 框内指标) → agent 读 json 核对;
实测用户圈的框比目标区域偏 541px, 直接用**框内饱和/死白行/边缘能量**三组数字反馈, 比争论有效。
(agent 无截图通道、不读图; 数字可断言。)
