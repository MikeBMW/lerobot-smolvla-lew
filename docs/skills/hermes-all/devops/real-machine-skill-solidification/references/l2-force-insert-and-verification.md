# 力控插入 · 插到底验收 · 技能写入卫生

从“示教一次”到“下次一条命令重跑”的可复用技能里, 插入这一类最容易在**验收口径**上出错。

## 一、里萨如力控插入的调用口径

`L2.lissa_insert` 三阶段:

| 阶段 | 动作 | 关键参数 |
|---|---|---|
| 1 | 沿**工具 Z** 退 60mm 到插槽口 | `local_mm:[0,0,-60]`(对应产线 `PoseTranslateLocalOffset [0,0,-0.06]`), `needs_unlock:true` |
| 2 | 直线推进到示教点 `insert_pose` | 容差 `tol_mm` 小(0.5mm) |
| 3 | 调 `/lissajous_force_search` | 见下 |

服务参数(抄产线配方, 不猜): `frame_type=3`(工具系) · `plane=0`(XY) ·
`cartesian_desired_force=[0,0,6,0,0,0]`(6N 沿工具 Z) · `amplify_one=6.0/frequency_one=3.0` +
`amplify_two=4.0/frequency_two=2.0`(李萨如 6mm@3Hz + 4mm@2Hz) · `search_box=±0.01m` ·
`search_box_timeout_sec=8` · `use_current_pose_as_box_origin=true` · `calibrate_force_sensor=true`。

要点:
- **盒原点 = 当前位姿** ⇒ 进搜索前必须已在插槽口。前两阶段合起来就是把臂摆到盒原点的手段。
  从别处(如一号位)直接调这条技能, 阶段1 会变成一条**横跨工位的直线**(实测算出来 Δy≈271mm)——
  要么先自己把臂挪到孔边, 要么接受这条未经实测的长斜线。
- `needs_unlock:true` 的阶段**默认拒发**, 请求要带 `"allow_unlocked_retract":true`。
  带的正当理由只有一种: 该阶段是"沿轴退 60mm", 只在**模块已插在孔里**时才危险。**带之前确认工件状态。**
- 服务回执必须**同步看**(`success=False` 的原因只在 message 里)。回执 `success=False` → 中止剩余阶段且**绝不重发**。
- 力控前置: 控制器侧工具/工件坐标系要设好(`setToolset(tool1, wobj0)`), 否则 `code=-50501 工具工件坐标系设置失败`;
  工具负载/质心没标定还会报 `#41447 力矩传感器与模型偏差较大`。

## 二、“插到底”怎么才算完成

**`success=True` = 算法找到了孔并把模块滑进去了, 不等于插到底。** 实测搜索段只走 ~11mm,
比操作员手推到底的深度浅 20~40mm。验收三件套:

1. **TCP 真值 vs 示教插入点**逐位对比(报差值, 不报"完成");
2. **现场目检** —— 工件深度只有操作员的眼是权威, 图/算法都不是;
3. 要更深就**小步续推**: 每次 ~1cm · 慢速(接触段档) · 纯轴向 · 每步读 TCP 真值核对。

深度不够时不要一次给大位移: 模块已在孔内, 斜向推力会憋在孔壁上(位置模式下没有柔性)。
续推保持单轴、小步、慢速, 并**每推一次就让操作员看一次**。

## 三、外出/回退技能 (roundtrip) 的成型结构

现场说"做成一个技能, 从 A 到 B, 再从 B 回 A"时, 要的是**双向**的多阶段条目, 回程不能另开一条点动序列。

```
去程 起点抬到安全高度 → 安全高度横移(拆成 2 条正交腿, 每个拐点都是实测点) → 降到作业高度
     → 接近到位 → [力控/插入原语]
回程 [反向原语] → 沿轴退出 → 抬到安全高度 → 横移回到起点正上方 → 下降到起点(到位即停, 禁下压)
```

- **每个 `to` 都是现场实测位姿**(含安全高度上的中转点)。斜线没测过, 正交腿走的是已实测路径。
- 回程先"沿轴退出"再抬升: 直接从插入位抬升会把模块别在孔里。
- 终点落到示教点时用**位姿回放**(位置+姿态都回示教点), 否则朝向接不上。
- 这一类技能的验收: 去程末端 TCP 与示教插入点吻合 + 回程末端与起点吻合(实测 ≤0.003mm)。

## 四、速度

| 段 | speed | 实测 |
|---|---|---|
| 安全高度抬升/横移 | 150~200 | 15~20 mm/s |
| 接近孔边/插槽口 | 80 | 8 mm/s |
| 接触段(推入/压入) | 30 | 3 mm/s |

- 尺度 `speed ≈ mm/s ÷ 0.0999`(线性, 以长行程实测点为准)。
- **真开关是技能级 `speed_max`**: 改请求里的 `speed` 会被静默压回上限(实测某技能 `speed_max=30` ⇒
  请求 100 仍按 3mm/s 跑, 190mm 下降要 63s)。**新建技能从既有条目深拷贝 ⇒ 继承对方的 `speed_max`, 建完必须提上去。**
- 每条 FIFO 指令有 ~10s 固定开销(守卫+下发+等回执) ⇒ **能合成一条多阶段技能就别发 N 条点动**
  (12 阶段往返 = 1 条请求, 省 ~110s)。

## 五、写入卫生

1. 备份 `registry.json` / `taught_points.json`(带时间戳)。
2. 新条目 **deepcopy 同族条目再改数值** —— schema 天然正确, 手搓字段必漏 `point_locked`/`guard`/`contact_guard`。
   点库是 `{"version","note","frame","points":{…}}`, 键在 `points` 里面。
3. 改完 `json.load` 回读断言。
4. **交叉校验所有 `to` 都在点库里** —— 缺失只在跑到那一阶段时才报。
5. 多路点技能**不要** `point_locked`/`point`(会把每段锁到同一点 ⇒ Δ=0 ⇒ 日志全绿而臂不动);
   这两个键只给"所有阶段去同一点"的技能。往已有条目 `update()` 不删旧键, 重建时要显式 `pop`。
6. 注册表热加载, **代码要重启执行器**。
