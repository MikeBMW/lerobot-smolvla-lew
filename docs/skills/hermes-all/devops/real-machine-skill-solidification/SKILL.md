# 真机技能固化服务 (示教 → 验证 → L2 肌肉记忆 → ROS2 下发)

## When to Use (触发)
- 操作员在真机上**手把手摆出一个动作**(抓/放/插), 说「别每次都让你发指令, 固化成技能」「你自己练习」
- 需要在**没有可信手眼标定**的情况下, 只用图像把末端对准目标
- 要求「指令要从**状态空间工程的 L2** 发出去, 经 **ROS2 节点转发给 Orin**」
- 要把 **L4(场景理解)/L3(流程规划)/L2(执行)** 分层在线作业真正跑在真机数据流上

## 分层职责 (现场实测口径, 别越层)
| 层 | 干什么 | 输出判据 |
|---|---|---|
| **L4** | DeepSeek VL 场景理解 + 安全否决 | 结构化字段: 目标可见/是什么/位置/在夹爪上吗/朝向/画面质量(模糊·过曝·太远·遮挡)/光照/背景线索/建议 |
| **L3** | 规划: 抓哪个 + 分几步 + 每步目标量 | 用**实测增益**把"图像误差 px"换成"基座 mm" |
| **L2** | 执行: 单步原子动作 + 取证 | 每步只发一条; 判完成**只看真值**, 不看 success |

分工的用户口径(2026-09-19): 「用 L4 的 deepseek VL 理解场景, 用 L3 规划流程, 用 L2 功能抓取光模块」——
并且他要**从工程「真机视」里操作**, 不是我这边跑一次性脚本. 固化的技能要挂在真机面板上可点.

## 固化流程 (四步, 缺一步就会"跑完说成功其实没抓到")
1. **示教**: 操作员手动把臂摆到"正好能抓/放"的那一刻 → **立刻读并落盘** `pos + quat`.
   ⚠️ **他手一碰臂, 你之前读的位姿就失效** —— 算目标点前必须重读 (实测按旧位姿算出的目标点=错点).
2. **点名**: 写进 `data/skills/l2_muscle/<名>_v1.json` — `points{命名点位}` + `params{speed, grasp_force…}`
   + `steps[{op:"move"|"gripper", to|args, note}]` + `verify{开度判据}`, `source` 必须写「人机在环示教 + 实测验证」.
3. **干跑**: `--dry-run` 先把每步**完整字节**打给操作员过目 → 他点头才真发.
4. **验收**: 跑 1 轮 → 用**物理判据**判定 → 不合格就请操作员重摆并覆写该点位, **绝不改判据硬说成功**.

## 物理判据 > 视觉判据 (最可靠, 优先用)
- 夹爪**开度**是免费的真值: 空载全合 ≈21 · 夹住细长目标(force=40) ≈185 · 只到 250~311 = 偏松
- **抬升前后开度不变** ⇒ 目标在指间没滑 (实测 100mm 抬升 185→185 ✓)
- 自动跑完开度 ≈**5** ⇒ 空爪(比空载 21 还小=顶死) ⇒ **点位错**(典型: 下降 z 偏高, 两指从目标上方穿过),
  此时**别说成功**, 也别用图像去"证明"它抓住了
- 目标被抓在手里时, 图像里通常"半个被画面边缘切掉/贴脸离镜头几厘米" → 检测器多半检不到,
  **不能用它当抓取验收**; 要修就现场标注这类视角重训(见 `live-camera-detector-adaptation`)

## 视觉伺服 (没有可信手眼时的对准办法, 已跑通)
1. **每轴量一次增益**: 走一个已知 Δ → 量同一目标在画面里的像素位移.
   实测: 基座 -X 50mm → 画面↓52.4px (1.05px/mm) · 基座 +Y 50mm → 画面←56.2px (1.12px/mm).
   **自洽校验**: `fx ÷ (px/mm) ≈ 相机到目标距离` (402 ÷ 1.05 ≈ 375mm ✓ 对上就说明量对了).
2. **方向映射必须实测**, 不能按直觉假设(哪个基座轴对应画面哪一边由装配决定).
3. **目标像素 = "夹爪像素"**, 不是画面中心: 相机与夹爪刚性固连 ⇒ 目标出现在"夹爪像素"时才真在指间;
   该像素可由**成功夹持那一帧反推**(目标被夹住时它的框中心 ≈ 夹爪像素); 不确定就迭代小步逼近.
4. **单轴小步**, 每步 30~100mm, 走完重检重算 (实测 3 步把目标从 (131,142) 收敛到中心附近);
   组合斜线大位移会被判「超出运动范围/奇异点」且**无运动**(安全, 但白跑一趟).
5. 下降 z 是最危险的一维(**碰撞检测常被关掉**): 分 2~3 级下, 每级停一下听声音/看画面, 操作员按急停.

## 操作员侧的两个"约定差" (踩过, 会直接导致方向判断相反)
- **他面板里的图是 180° 翻转的** (我取的是原始帧): 同一目标在我帧"上左"= 他帧"下右".
  报方向一律说「**朝画面中心 / 远离画面中心**」(两视图的共同不变量), 别说左/右/上/下.
- **他说「我接管了」= 正在手拖示教**: 此时**一条指令都不发**(拖动模式下夹爪指令也可能被忽略, 实测下发无效),
  等他说「可以动作」再走三查闸门.

## 调用已注册的 L2 技能 (参数 + 速度 + 多步取证)

- **FIFO 契约**: `echo '{"skill":"L2.lift","d_mm":10,"speed":11}' > ~/zmax_data/l2_cmd.fifo` —— 一行一条 JSON, 延迟 <1s;
daemon 在 `~/zmax_data/l2_daemon.log` 回 `目标 <技能>: pos=(x,y,z) · Δ=(...)mm ↑上升|↓下降|→平动` + `受理: 已下发`。
- **先 dry 再真发**: `{"skill":"...","dry":true}` 只算目标 + 打印将要下发的 `ros2 service call`, **不下发**。
但 dry **只证目标算得对, 不证真机能动** ⇒ 首步必须真发一次、读真值算 Δ 核对(实测 Δz=+10.00mm 逐位吻合),
确认后才发剩余步骤 —— 一上来就跑整串是拿现场赌。
- **两个独立旋钮**: `d_mm` 控距离 · `speed` 控快慢(缺省 **60**, 技能级 `speed_max` 再收口)。
用户说“每秒 N 毫米”时就是调 `speed`。
- ❗ **速度换算是估算, 说出口前必须实测复核**：尺度用 **≈0.0999 mm/s 每单位**
（daemon 注释里的 0.093 偏保守 7%，别拿它换算；那里偏保守是故意的，别去改）。
  实测 19→1.90 · 30→3.00 · 50→4.97 · 100→9.99 mm/s（线性度极好）。
  注：极短行程/极低速（如 speed=11 走 10mm）反推会偏高（≈0.106），那是起步/服务开销被平均进去 —— **尺度用长行程点定**。
  **复核法（一次拿准）**：以话题原生频率采 `/robot/tcp_pose` 约 25s（别手动“每 ~1s 一次”，那算不出瞬时速度），
  逐对相邻帧算 `位移/Δt`，取**运动段（>0.2mm/s）的中位数** = 实测速度；起点终点分开报。
  报告给“命令值 + 实测值”两个数，别只报命令值。
（注: 多阶段“等到位”超时公式里的 0.093 是**故意偏保守**的 —— 那里低估速度=高估时间=安全，别去改它。）
- ⚠️ **多步/循环动作别每步都读一次真值位姿**: 经 Docker tap 读一次 `/robot/tcp_pose` 要 **3~4s**,
8 步读 16 次 ≈ 1 分钟起 ⇒ 会把录像/观察窗口吃光，还可能错过下一步下发时机。
逐步取证改用 **daemon 日志行**(含目标位姿+Δ，足够逐步核对)；真值 TCP 只在**整串的首尾各读一次**核对“回到原点”。
- 🔴 **但 `受理: 已下发` 只证明"进了通道", 不证明臂动了** —— **你自己写的驱动脚本**(连发多条 FIFO)每腿的
  成败判据必须是 **TCP 前后差值**(目标 ±2mm), 不能 grep `受理:`。实测踩过: 通道跑到一半变僵尸(ssh 活着不转发),
  4 条腿全报 "OK" 而 TCP 逐位不变, 据此对外报了"回位完成"; 直到多阶段技能报
  `阶段 1/2 未在 183s 内到位(最近偏差 269.9mm) → 中止剩余阶段` 才暴露。
  (daemon 内部 `run_stages()` 的单阶段"等到位"本来就是读真值判 —— 会漏的只有**脚本层的腿间判据**。)
- **通道僵尸的一步诊断**: 看下发时刻之后日志里有没有 ROS 请求/回执 ——
  `grep -a 'ROS: requester\|ROS: response' ~/zmax_data/l2_daemon.log | tail`。一条都没有 = 通道死;
  有请求无回应 = 服务/驱动侧问题。恢复: 按 argv 精确 kill 执行器 → `bash ~/.hermes/scripts/l2_daemon_keepalive.sh`
  → 见 `✅ ssh 探针通过` + `🔌 命令通道已建立` → **以当前 TCP 真值为起点重发**(别照原参数补发, 通道恢复后会叠动作)。
- 长链(>5 腿)中途任一腿 TCP 不变 → **立即停下诊断**, 别让它把剩下十几条也"完成"掉。
- 清点进程/通道时**别把匹配串写进自己的命令行**: `pgrep -f tools/l2_daemon.py` 会把自己的 shell 数进去
  → 假"2 个在跑"。把匹配串放进脚本文件再跑。
- 汇报纪律: **只说你真启动过的东西** —— 描述过"后台在跑"却没真启动, 现场看到的就是"怎么又停住了"。
步进节奏按实测速度算时长 + 余量(10mm@1.17mm/s → 17s/步，实测到位)。
- **图案运动直接用方向技能拼**(别自己拼 `move_line`): `L2.lift`抬升(+Z) · `L2.lower`下降(-Z) ·
`L2.left`(+Y) · `L2.right`(-Y) · `L2.forward`(+X) · `L2.backward`(-X) —— 全是 `line_rel` + `param.d_mm`(**min 5mm**)。
「抬升→向右→下降→向左」就是边长 `d_mm` 的正方形（**短串/单圈**闭合成原点实测误差 0.01mm）。
🔴 **但 `line_rel` 的“重发整串”只能跑短串**：伺服欠程每步少走 ~0.16mm，下一步以**实际落点**为基准
⇒ 误差滚雪球（实测 40 步累积 −6.6mm（同相位）、80 步 −27.6mm(X)/+19.3mm(Z)）。
⚠️ “每步 Δ 都对” **不等于** “总位姿不漂” —— 两者必须分开取证。
**要循环多圈/长时间，必须换绝对位姿路点（下节）。**

## 把一串动作固化成一条技能（多阶段 steps + 绝对位姿，长循环必用）

用户说「把这个动作作为技能保存」「变成技能 <名字>」时要的是**下次一条命令能重跑**的注册表条目，不是录像。

1. **先算绝对路点**（从当前 TCP 只读采样 6 帧，不靠猜）：
   `tools/make_abs_path.py --d <步长mm> --prefix <前缀>` → 写 `taught_points.json` + 注册 `<前缀>_p1..p4` 的 `line_abs` 技能。
2. **生成多阶段技能**：
   `tools/make_loop_skill.py --prefix <前缀> --d <mm> --cycles <N> --speed <S> --name "<用户叫法>"`
   条目带 `steps[]`：`{stage, to, dz_mm, tol_mm, timeout_s, dwell_s, guard, note}`；执行走 `run_stages()`，
   **逐段真值等到位**（连续两次落进 `tol_mm` 才认停稳）才进下一段；任一段被拒/未到位 → 中止剩余且绝不重发。
   - 🔴 **多路点循环绝不能写 `point_locked`/`point`**：daemon 的 `_point_name()` 里技能级锁点**优先于**阶段 `to`
     ⇒ 所有段被锁到同一个点 ⇒ 臂已经就在那个点 ⇒ **每段 Δ=0**，而日志一路报"✅ 到位 · 真值偏差 0.0mm"
     （**看着在跑，其实没动**）。这两个键只给"所有阶段去同一个点"的技能（如 slot 类）。
     ⚠️ **重建/改边长时必须显式 `pop` 掉这两个键**：往已有技能条目上 `update()` **不删旧键** ——
       上一次留下的锁点会跟着新技能走，又变回"臂一动不动"。生成器要自己保证，别指望复盖。
     ⚠️ **路点基准 = 生成那一刻的 TCP**：换边长或重算路点前先确认臂在起点（安全三查里的 TCP 就是基准），
       否则整圈会以偏移后的位置为原点。生成后务必用 `stages:[1,2,3,4] + dry` 核对 4 个 Δ 是 ±d。
3. **空跑验证（10 秒能拓出两类 bug）**：
   `{"skill":"<id>","speed":<S>,"stages":[1,2,3,4],"dry":true}` → 看 `受理: DRY-RUN(未下发) 4 阶段: 阶段1 Δ=… | 阶段2 Δ=…`
   —— **Δ 必须非零且随段变化**（锁点 bug 会让 4 段指向同一个点；目标算错会直接在 Δ 上暴露）。
4. **交付形态**：一行跑法 + **用户给的叫法原封不动进技能名**：
   ```bash
   echo '{"skill":"L2.loop_fubd100_x10","speed":100}' > ~/zmax_data/l2_cmd.fifo
   ```
   技能名格式：`<用户叫法> (<边长>·<方向序列>×<圈数>·<实测 mm/s>)`。

**长循环验收三件（缺一条不算交付）**：
1. 每段 `✅ 阶段 N/M 到位 · 真值偏差 X mm` **全部 ≤ tol**（实测全 0.00mm）；
2. **目标点分布对称**（如 p1×10 / p2×10 / p3×10 / p4×10）—— 不对称就是序列拼错；
3. **首尾 TCP 总偏差**（走 2000~4000mm 回起点，实测 ≤0.001mm）。
⚠️ 第 3 条**必须在最后一段到位之后取**：轮询退出早或中途取，会把"循环还没跑完"报成几十 mm 的巨大漂移。

**速度换算（实测线性，以此为准）**：`speed ≈ mm/s ÷ 0.0999`；实测 19→1.90 · 30→3.00 · 50→4.97 · 100→9.99 mm/s。
技能级 `speed_max` 会封顶 ⇒ 要跑 speed=100，`speed_max` 必须 ≥100（否则静默压到上限，速度对不上）。

**录像配合**：40 段 ≈ 12 分钟，按“距离/速度”估会短 30%+（每段还含 docker 直读位姿 ~3-7s）⇒
录像上限设大（900s）+ 发现末段到位就 `kill -INT` 录像进程（录制器带 SIGTERM 处理）→ 视频精确收尾。
轮询判完成**不能 grep 全日志**（会匹配到上一次运行的 `40/40` 假完成），要记字节偏移只看新行。

## 🔴 力控插入与"插到底"的验收 (别把算法回执当物理结果)

调用口径: `L2.lissa_insert` 三阶段 = 沿工具 Z 退 60mm 到插槽口 → 直线推进到 `insert_pose` →
`/lissajous_force_search`(frame_type=3 工具系 · plane=0 XY · 6N · 李萨如 6mm/3Hz+4mm/2Hz · 盒 ±10mm/8s ·
`use_current_pose_as_box_origin:true` · `calibrate_force_sensor:true`)。
- **搜索盒以"当前位姿"为原点 ⇒ 臂必须先站到插槽口** —— 前面两阶段就是把它摆到盒原点, 不是装饰。
- 阶段标 `needs_unlock:true` 的**默认拒发**, 要显式带 `"allow_unlocked_retract":true`;
  正当理由只有一种: 该阶段是"沿轴退 60mm", 只在**模块已插在孔里**时才危险, 模块没插时退让无害。**别当万能解锁用。**
- **`success=True` 只代表"找到了孔并滑入", 不代表插到底**: 实测力控搜索只走 ~11mm, 比手推到底浅 20~40mm。
  验收三件: ① 最终 TCP 与示教插入点逐位对比 ② **现场目检**(唯一权威) ③ 要更深就**小步**继续推
  (每次 1cm、慢速、纯轴向、每步核 TCP)。**别把算法回执当"插到底"汇报。**

## 现场人工一次性授权的 scope 匹配坑

授权文件的 `scope` 是拿**动作描述文本**匹配的, 而多阶段技能上报的是**点位名**(`slot1`)不是技能 id(`L2.slot1`)
⇒ 只列技能 id 的授权**匹配不上** → 执行层落回"等慢层 VL 裁决", 干等 300s 才超时(现场看就是"发下去不动")。
⇒ 给多阶段技能开授权时, **技能 id 和它 `steps` 里用到的所有点位名都要写进 `scope`**。
授权最小化: 只列本次要用的动作、限时限次、每笔写审计、**任务一结束立刻收回 `enabled=false`**, 不留放行证。

## 用已示教点推理工件几何 (槽位/料位/排位)

现场常常只教过一排的**两个端点**(或三个点), 却要推出整排/整片工位的坐标。定式:

1. **先判「是不是一条直线的一排」**: 三点做最小二乘空间直线拟合, 报**每点到直线的垂直残差**。
   实测 0.21~0.67mm ⇒ 共线成立; 到毫米级以上 ⇒ 它们不在同一排, 别硬拟。
2. **槽距用最小二乘定, 不要拿两段硬除**: 把点投到主轴方向, 对「槽号 → 沿排弧长」做线性回归(2 自由度、N 点)
   ⇒ 得 pitch 与残差。比「首尾距离 ÷ 格数」稳得多 —— 端点各带一点误差就直接进结果。
   实测 pitch=48.683mm, 三点残差 ≤0.83mm。
3. **逐段间距不一致 ⇒ 先怀疑示教点, 不要先怀疑工件**: 四段算出 45.6/51.2/49.4mm 时, 剔除某点后
   其余两段只差 2.0% ⇒ **那个点就是偏的**(实测偏 5.8mm)。
   ⚠️ 若它原本也是 `point_locked` 的示教值 ⇒ **改它必须先问操作员**, 不许自己改锁点。
4. **图像标尺用机器人真值定, 绝不用零件标称尺寸猜**: 拿「已知两点的基座距离」当尺子(如一排端点 292.4mm)
   去除「这两点在图像上的像素跨度」得 mm/px。用零件标称尺寸(如「模块 40mm」)标定**会错一倍以上**
   (实测差 1.83 倍), 且错误会静默传播到所有由它换算的毫米值。
   ⇒ **像素框仍是对的(像素是直接测的), 错的是所有 mm 数值** —— 发现后必须回头改口径并如实说明。
5. **单位统一, 算完先做量级自检**: 排长(m)÷ 像素 = m/px, 别再 ×1000 又 ÷1000; 同一段代码里混用 m 与 mm
   会差 1000 倍(实测把第二排推到 x=60.5 **米**)。基座工作区量级 0.5~0.8m, 越界立即查单位。
6. **第二排/第二片必须有独立真值锚**: 平行排的「形状」可复制(同 pitch、同朝向), 但**横向绝对位置**靠图像推
   会有 ±13mm 以上偏差(实测与已知插口点差 25.3mm) ⇒ 交付时**逐点标 `anchored` / `uncertainty_mm`**,
   并明说「还缺一个真值锚」; 请操作员在该排随便教一个位即可锁死。
7. **「上/下排」的对应关系是推断不是测量**: 要靠相机姿态或一次观测坐实; 说不准时如实标注, 别把推断当结论报出去。

产物形状(可直接复用): `~/zmax_data/l5_slots/derived_14slots.json` =
`{pitch_mm, rowA:[{slot,x,y,z,anchored}], rowB:[{slot,x,y,z,anchored,uncertainty_mm}]}`。

## 拿「每步核实的 TCP 真值」: 必须有 DDS 之外的通道

「小步移动 + 每步核实真值」这条规矩成立的前提是**真值读得稳**。DDS 话题可能**看着在、却收不到任何帧**:
- **报「Publisher count: 1」的可能是旧 ros2 daemon 的缓存**: 同一条命令 `ros2 topic info /robot/tcp_pose`
  说 1 个发布者, 加 `--no-daemon` 就变成 `Publisher count: 0`, 且 `ros2 node list --no-daemon` 里
  robot_driver / motion 全不见了。⇒ **凡「有发布者但 0 帧」先用 `--no-daemon` 复核再下结论**,
  否则会去修 QoS / 网络 / domain(都不是原因), 白烧几十分钟还把现场拉进排查。
- ⇒ **不要为了拿真值重启机器人栈**(现场栈手工拉起, 重启=打断产线, 红线)。改用**控制器/厂商侧直读**提供真值:
  高频采样脚本落 `<out>/tcp_direct_<date>.jsonl` + **`latest.json`(原子替换)**; 下游要「秒级拿当前值」
  直接读 `latest.json`, 不要为读一次位姿连一次控制器。实测 5Hz × 600s = 3000 样本 · 读失败 0 次 ·
  最大间隔 0.205s; 与控制器的口径与产线话题逐位一致。珞石控制器直读的连法/口径见
  user-owned 技能 `rokae-direct-control`(我无权改, 需 `hermes curator adopt` 才能纳入维护)。
- **判「臂已静止」用多点一致**(如 6 秒内采样逐位相同), 不要拿单点当静止。
- 失效模式要如实告知: 控制器断电/网线断/会话占满 ⇒ 单次读超时; 脚本会重连但**没有本地缓存兜底** ——
  掉线时数据就是断的, **不许拿旧值当实时值**。

## 固化新技能的写入卫生 (schema 用抄的, 不用手搓的)

- 两个文件都先 `shutil.copy` 备份; 改完 **`json.load` 回读**断言新 id 存在、`steps` 长度对。
- 新点 = `deepcopy(points['<现有点>'])` 只换 `pos/quat`; 新技能 = `deepcopy(<同族技能条目>)` 只换 `id/name/steps`。
  ⇒ 手搓字段最容易漏 `point_locked`/`guard`/`contact_guard`。(点库结构是 `{"points": {…}}`, 不是顶层直接点名。)
- ⚠️ **深拷贝会继承对方的 `speed_max`**: 建完必须显式提到你要的速度档, 否则请求里的 `speed` 被静默压回。
- **交叉校验**: 收集 `steps` 里所有 `to`, 逐个断言在点位库里存在 —— 引用不存在的点会在**跑到那一阶段**才失败
  (前面几段照跑), 现场很难看出是定义错误。
- 长链的中间路点(安全高度上的中转点)也必须是**现场实测位姿**: 把斜线拆成两条正交腿走**已实测路径**, 斜线没测过。
- 默认速度就给分级档(现场反复催快): 安全高度抬升/横移 **150~200** · 接近孔边/插槽口 **80** · 接触段压入 **30**。
  改请求里的 `speed` 无效, 真开关是注册表的 `speed_max`。

见 `references/l2-force-insert-and-verification.md`。
