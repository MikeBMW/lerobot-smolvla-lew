# 显示值"旧了"怎么办: 先分清死源/活源, 再换路 —— 不是给它贴个"仅供参考"

现场抱怨形式: 「我在现场，怎么还是 43 小时的数据，赶快更新啊」(某个状态格/三查/位姿/badge 长时间不变)。
**贴"⚠ 旧值"标签不算解决** —— 那只是把问题写在脸上。正确动作是找到**生产端**并把它接到**活路**上;
真的只能降级时, 才诚实降级并同时给出"要修谁"。

## 1. 分三步定位

1. **看消费端读的是哪个文件/字段**: 在承载页面的服务里 grep 该字段名, 找到它的源头路径
   (例: 三查来自 `<scene>/robot_status.json`, 位姿来自 `<sdk>/tcp_out/latest.json`)。
2. **看源头文件的 mtime/帧龄**, 而不是看内容像不像真的: `ls -l --time-style=+%H:%M:%S` 与 `date` 对比。
   帧龄小时级 ⇒ 该文件是死源。
3. **找"现在到底谁在写"**: `grep -rl <文件名> tools/ | head` 找写者; 写者不在跑、或它依赖的上游不见告端点
   ⇒ 死因在上游。

## 2. 典型死法(两种, 都要认出来)

- **上游发布者停更**: 例如 ROS 话题发布者的 DDS 端点已过期 —— 老订阅者(长连录制器)还在收，
  **任何新订阅者 0 帧**。标志: `ros2 topic info <t> --no-daemon` = Publisher count 0; `--once` 拿不到。
  ⇒ 别用"某个老进程还在收到"证明该源可用。
- **写者进程还在、但只是不再写入**: 进程活着(容器 Up N 小时)不代表它在写 —— 判据一律回到**文件帧龄**。

## 3. 改法: 接到"已经证明新鲜"的那条路

选源铁律: **优先复用同设备上已经证明每秒都在刷的那条通道**，而不是再开一条新连接
(直连控制器/设备的 SDK 会话通常是共享/有限资源)。

- 本机实例: 位姿已由常驻采样器(直连控制器, 5Hz)写到 `<sdk>/tcp_out/latest.json`，一直新鲜 ⇒
  把三查(上电/运行/操作模式)**顺手加进同一个采样循环**(每 2s 一次)写到 `state.json`，
  页面优先读它、缓存话题只当兑底。
- 采样循环的写法要点: ①按周期(不每次)读慢接口; ②**局部 try/except**，任一字段读失败写成 `*_err` 字段
  而不是让整循环挂掉; ③先写 `.tmp` 再 `os.replace` 原子落盘; ④常驻参数不要设成有限秒数(设了会在无人注意时
  自己到期退出, 位姿/状态一起静默死掉 —— 要么设 0=一直跑, 要么由保活拉)。
- 页面/服务端的映射要在同一次改动里做完: 源字段 → 页面字段 → 一行状态文案，并**把源名带出来**
  (`src: "<设备> 直读"` vs `src: "topic_cache(… 起停更)"`) —— 现场看一行就知道自己在看什么。
  ⚠️ 字段名要对齐: 读 payload 时用真实键(嵌套的 `xyz/quat` 不是 `x/y/z`)  —— 拿同名键去读会得到 None,
  然后误判"页面又坏了"。

## 4. 报警类真值: 读控制器日志, 不推测

- 上电/运行/模式读状态接口; **急停/碰撞/报警读控制器报警日志**(带编号/时刻/物理量/阈值)。
- 日志是**事件流**，不是当前态 ⇒ 用**时刻年龄**分级: 3 分钟内的当"当前"(参与拦发)，更早的只当历史展示。
- 事件编号会成对出现(物理量超限一条 + 安全停止一条) ⇒ 取到第一条不代表完整，汇报时把两条都带上。
- 历史也要留: 现场要的是"每一次碰撞都记住" ⇒ 页面常驻显示"上次碰撞 HH:MM 关节N(安全停止)"这一行。

## 5. 页面显示契约(与 `user-facing-dashboard-delivery` 一致)

- 状态**一行说完"能不能动 + 为什么"**: `🟢 正常 · 上电 · 无新报警 · 执行器在线` /
  `🔴 不能动：急停按下|碰撞报警|未上电|执行器离线` / `🟡 状态源旧(N 前) · 不能确认现场状态`。
- 不显示原始秒数/pid/技能数这类细节(现场嫌杂); 但**要显示**采集时刻/帧龄、被哪一层拦、最近一次事故时刻。
- 同一句警告不要在页面上出现两遍(多个元素各写一份旧值提示 = 现场看到的是重复噪声) —— 合并成一个元素，
  其余置空但保留 DOM 节点(别删节点: 仍在写它的旧 JS 会让同 try 块后半段一起失效)。
