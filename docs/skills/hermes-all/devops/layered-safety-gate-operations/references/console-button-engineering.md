# 现场手动控制台·按钮工程(加按钮 / 数据驱动状态 / 一行布局 / 「点了没反应」诊断)

适用: 现场说「帮我加个按钮」「这个按钮点了没反应」「有记录的绿、没记录的灰」时。
按钮类需求在本项目反复出现(点动 / 绕轴 / 夹爪 / 回点 / 号位…), 下面是把一次做对的定式。

## 1. 加一个按钮 = 同口径改三处, 缺一就是「未识别 / 被拒 / 超范围」
1. **技能定义**: 幂等注册脚本(不手改 runtime JSON —— `data/` 是 runtime state, 改了等于没存)。
   参数上限、`guard`、`point_locked`、`steps` 都写在这里。
2. **服务端白名单**: 带数字参数的进点动表(元组 `(参数名, 最小, 最大)`), 无数字参数的点位/锁点技能进
   **另一张表**(误塞进点动表 = 直接拒); 漏加 = 点了「不在白名单里」。
   上限必须与技能守卫**同口径**(页面档位 > 守卫上限 = 点了没反应)。
3. **页面**: 按钮 + JS; 同一组按钮**排成一行、等宽均分**(面板 `grid-column:1/-1` 横跨整行 +
   `grid-template-columns:repeat(N,minmax(0,1fr))`), 角标 `small{display:block;white-space:nowrap}`, 字号 ≤17px。
改动后**重启承载接口的那个服务**(白名单在代码里, 不热读); 技能注册表通常是**每条指令前热读**, 不用重启。

## 2. 状态由「服务端判据」驱动, 页面只画不算
例: 「有记录=绿可点 / 没记录=灰不可点」。判据 = 点位库有没有这个点 + 注册表有没有这个技能 + 白名单放行,
三项**全在服务端**算, 一个只读接口把 `ready` 交给页面; 页面自己判会画出"点了却没通道"的**假绿**。
灰按钮要 `disabled` + tooltip 写清**缺哪一样**以及怎么补(录点工具名), 别只置灰不说话。

## 3. 验收取证
- **几何**: 用浏览器控制台取每个按钮的 `getBoundingClientRect` ⇒ y 全同(同一行) + 宽度相等 + 间距相等 +
  首尾贴面板内边距。别用"看着像一排"回话。
- **链路(零动作)**: ①不带真动标志发一条 ⇒ `dry` + 执行器打「目标 Δ / DRY-RUN」; ②带真动标志但**未授权** ⇒
  HTTP 403 且执行器零新增行; ③绕过页面直接写队列 ⇒ 「🛑 被拦(授权)」且 `已下发` 计数 = 0;
  ④页面点一下 ⇒ 结果栏出执行器**原始行**(可复制)。
- **JS**: 页面改动后读一次控制台消息, 要求 `js_errors` 为空(内联 script 语法错 = 整页白屏)。

## 4. 「点了没反应」读日志梯队(每一条都实测过)
0. **读日志一律 `grep -a`**: 执行器日志里混过 NUL 字节, 裸 `grep` 只回 `binary file matches` 什么都不打 ⇒
   会被误判成"日志里没有这条"。取增量固定 `OFF=$(stat -c%s $LOG)` + `tail -c +$((OFF+1)) "$LOG"`。
1. `受理: DRY-RUN(未下发)` / 页面回「演练(未授权真动)」 ⇒ 只是授权/演练档, 链路是通的。
2. `🛑 被拦(真动授权)` ⇒ 授权窗过期, 或签发后被撤销(epoch 作废)。
3. `🛡 <闸门> … ⇒ 拒发` ⇒ 分层闸拦的(fail-closed); 关闸/授权口径见 SKILL.md §3 / §3b。
4. `🛡 阶段 N/M 拒绝: 直线距离 … 超过守卫` / `向下 … > 守卫` / `z_floor` ⇒ **执行器守卫**(见 §5)。
5. **`执行异常: <一行 message>`** ⇒ 异常被外层 `except` 吞了 traceback, 是**数据坏了**(如四元数分量数不对)。
   别猜: import 执行器模块直接调 `dispatch(reg, {"skill":…,"speed":…,"dry":true}, None)` 打完整栈,
   比翻日志快得多(`reg` 就是注册表 JSON 原文, dry 下传 `chan=None` 安全)。
6. `未知技能` / `不在白名单里` / `超出允许范围 [a,b]` ⇒ 注册表没热读 / 白名单漏加 / 页面档位超守卫。

## 5. 守卫分两层: 可用性上限 vs 防撞红线(别混)
- **可用性上限(可就现场要求放开)**: `max_lin_mm` 这类"目标离当前位置多远就不许一步到位"。
  臂停在别处时它会让技能**百分百拒发**, 而现场看到的就是"这个技能坏了/不动"。
  放开方式 = 幂等注册脚本的参数(如 `--max-lin-mm 1500`) + 把改动写进技能 note 留痕 + 留备份;
  先问一句"要不要放开", 别无脑让操作员点动几十次。反例要记住: 拿着"守卫是故意的"当教条, 现场只会反复报同一个故障。
- **防撞红线(任何情况都不放)**: `z_floor_*`(目标 z 绝不低于参考点) · 阶段级下降上限 · 到位即停禁下压 ·
  下降/侧向的接触类守卫。放开距离上限 **≠** 放开撞机保护 —— 汇报时必须把两者分开说。

## 6. 点位/姿态数据的体检(症状常常只是「执行异常」一行)
- **四元数必须是 4 分量(x,y,z,w)**: 演示学习/示教点写入侧丢字段会留下 3 分量的 `quat`,
  而取姿态的代码若直接取 `q[3]` ⇒ `IndexError` 被外层 `except` 吞成一行 `执行异常`,
  单阶段与多阶段**两条路径都干点不动**(dry 也一样)。
- 收口做法: 一个 `_quat4()` 校验函数, 两条路径都过一遍 —— 4 分量归一放行; 3 分量只在
  `x²+y²+z² ≤ 1` 时按单位约束补 `w=+sqrt(1-Σ)`(取正号 = 与同批已记录点同号, 两候选姿态差 ≈ 2·asin|w|,
  通常 ~1°)**并在日志里喊出来 + 建议重录**; 其它分量数一律**拒发**。永远不要拿 `len(q)!=4` 的四元数去拼设备指令。
- 数据侧一次修: 幂等脚本扫描全部点位、补 w、写 `*_repaired_at/note` 留痕、留备份, 且支持 `--dry` 复核。
- 未录入的点/槽位要**干净拒发**(如「点位 X 不在点位库」), 不能崩、也不能瞎走近似点;
  这类拒发文案就是页面上灰按钮 tooltip 的依据。
