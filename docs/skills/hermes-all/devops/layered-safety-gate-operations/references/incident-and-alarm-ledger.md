# 撞后处置 + 事故台账（真机）

## 撞后固定动作（顺序不能换）
1. 跑全停脚本停**执行器**（本机 `tools/agent_all_stop.py --keep-capture`）。关键不只是"停手"：
   未走完的**多段计划后面几段也发不出去了** —— 只发一条"停止"而让实例活着，下一段仍可能被下发。
2. **主动停设备**：`ros2 service call /robot_stop std_srvs/srv/Trigger`。实测回执 `success=True`
   （内部 `rt_stopMove` 子步会回"非实时模式"异常，不影响 stop 生效），模式被切回 `Nrt`。
   已冲击到控制器的动作**不会因为杀进程而停** ⇒ 这一步必须有，不能只靠第 1 步。
3. **撤销真动授权**（本机 `tools/ctl_auth.py` 口径）⇒ 防任何自动/误触重发。
4. **取硬证据**（只读）：控制器报警日志最近的 error/warning 条目，与位姿同一条 SDK 会话读。
5. **落档**：`docs/INCIDENT-<日期>-<一句话>.md`（时间线 · 硬证据原文 · 一句话根因 · 我的设计错误 · 待现场补充）
   + `docs/INCIDENT-INDEX.md` 登记**一行**（一句话根因 + 落成哪条规则）。
6. 撞后控制器常 `power_state=off`（柔顺停止的后果）⇒ **恢复前不下发任何运动**，先让现场目检
   （工具/工件/本体/线缆），并要求他说清三件：撞到什么 · 有无损伤 · 该方向能安全通过的高度上限。

## 报警日志是唯一真值（不是"我觉得撞了"）
- 形如：`#30400 检测到碰撞，关节传动力矩超限！触发柔顺停止。 N轴…测量值为 X Nm, 超过限定力矩 Y Nm`
  + `#13036 RSC检测到关节[N ]碰撞力超限，触发安全停止`。
- **超限关节号本身就是判据**：不同关节 = 不同撞法（低位关节多为"高位横移撞"，腕部关节多为"在空中转身扫掠撞"）。
  复盘必须带：关节号 + 力矩/限定 + 时刻 + 当时位姿。
- 历史条目与当前条目要分开说：3 分钟内的当"当前"（拦得住动作），更早的只当历史，但**不能因为"当前无报警"
  就把历史抹掉** —— 现场要的是每一次都留痕。

## 自动台账口径（宁缺毋编）
- 条目识别：只有上面两个码算事件；±5s 内配对同一次事件，只留带物理量+阈值的那行。
- **位姿只在"事件后 N 秒（例 90s）内首次看到该条目"才采**：事件后设备保护停住 ⇒ 那时位姿 ≈ 事件点。
  更早的历史条目一律写「位姿未采到」，**绝不拿当前位姿冒充过去**（现场会把数字/画面当结果）。
- **去重要写两遍**：写入时 + 返回时（幂等）。只在写入时比对本轮新条目，会漏掉与**已在台账里**的条目
  配对的第二行（实测同一事件的两行报警各占一条）。
- 落盘：单文件 JSON，倒序（最新在最上），`写 .tmp + os.replace` 原子替换。
- **采集点挂在页面已经在轮询的聚合接口里** ⇒ 采集/去重/落盘都在那一次请求里做完，不另起常驻进程。
- 上游缓存（`state.json.recent` 之类）只有最近十几条 ⇒ **滚动会丢**：老事故必须靠落盘文档，不能全指望自动采集。
