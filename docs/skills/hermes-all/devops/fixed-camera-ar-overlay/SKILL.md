# 固定相机 AR/VR 叠加底图 (第二台相机 → 叠加层)

## When to Use
- 用户:「应用 VR/AR 技术把机器人工具中心轨迹可视化出来」「在**笔记本摄像头**这个场景上叠加一条看得见的通道」「场景叠加是为了更好地调试算法」。
- 要给一台**不在机械臂上**的相机(笔记本内置、电视顶摄)画 base 系 3D 内容(管道/框/点)。
- 该相机没有内参/外参, 需要判断「能不能画」或现场标定。

## 铁律: 没外参就不画(宁缺勿假)
- 只有**做过手眼标定**的那台相机能把 base 3D 真投到像素; 固定相机必须**自己解一套**外参, 不能借手眼链。
- 🔴 静态特征(两机都看得到的目标)在 base 系往往**几乎共面** ⇒ 3~5 点解 7 参(`f+rvec+t`)是**欠定**, 硬解只会得到
  "投影对得上、深度方向全靠猜"的假外参。用户拿它调算法, **贴歪比不画更坏** ⇒ 页面应如实写「未标定」+ 给标定入口。
- 同理: **别把仿真坐标/别的相机的外参硬套**上去, 量不出就报缺。

## 没外参也能画「世界水平」辅助线 —— 但必须过消失点
用户口径: 在笔记本摄像头画面上「定位桌子上面、横梁内部的空间位置, 给我画几条辅助水平线」,
随即纠正: 「画的线不是以相机坐标系为轴, 要以世界坐标系为轴, 要平行于横梁, 你好好研究一下投影关系」。

- 🔴 **「世界水平」≠「图像水平」**: 像素 y 恒定的横线 = 拿**相机坐标系**当轴, 是错的。
  3D 中平行的直线在图像里**交于同一消失点(VP)** ⇒ 「平行于实体 X(横梁/台面边)」的辅助线必须是
  **过 VP 的斜线**, 且层越低/越远越斜。用户说"要平行于 X"时: **先解 VP, 再画线** —— 直接画横线会被当成没干活。
- **解 VP 只用该实体自身的两条平行棱**求交(如梁的上棱亮线 × 下棱台阶), 不用"画面里随便两族线":
  实测上棱 −7.4° / 下棱 −3.1°, 斜率差 0.075~0.09、相隔 ~310px ⇒ 条件数可用, VP≈(−440, 210)。
- 🔴 **病态解不许拿来画线**: 近正视视角下平行棱**近乎平行** ⇒ 两族线求交条件数极差, 三种拟合给出
  **144 / 248 / 286** 三个互相矛盾的答案。判据: 两棱**斜率差 <0.02 或相隔 <100px** ⇒ 报"本视角解不出"
  (宁缺勿假)。同理"地平线"的**位置**也是病态的(它必过 VP 这一点是确定的) ⇒ 不拿它当交付。
- ⚠ **VP 会随单帧噪声漂 ⇒ 必须多帧取中位**: 逐帧 RANSAC 初值 + JPEG 噪声会让同一静止画面的 VP x 漂
  ±150px, 逐帧拟合的倾角重复性只有 ±1~3°(同一层连跑两次 11.1°→8.3°)。定式 = 采样 **N=8 帧**分别拟合,
  对 **(斜率, 截距) 取中位**(各层特征线同样取中位) ⇒ 重复性压到 **±0.5°**: 三连跑实测 VP x = −383/−372/−413、
  空间顶 −2.83/−2.78/−2.98、作业层 +10.42/+10.65/+9.76、空间底 +15.38/+15.64/+14.63。
  ⇒ **交付前连跑三遍比数**(工具侧留 `--frames` 参数) —— 这是"稳不稳"的唯一证据, 别只跑一遍就发图。
- **精度边界如实说**: 取了中位后 VP 也只定到 ±20px 级 ⇒ 倾角重复性 **±0.5°**, 仍**是目视参考、不是量具**。
  要度量级精确就回到本技能的标定路线: 用 3+ 已知 base↔像素点
  解**平面单应**(固定相机看近似平面桌面时最省事的路径), 别指望像素台阶能把精度提到毫米。
- **落地要 2D 折线元素**(轴对齐薄盒天然画不出斜线), 且线要**在真值带画完之后补画**:
  底部真值带不透明、从底部往上铺 ~120px ⇒ 落在带里的线**一个像素都没有**; 核验时"某条线 0 像素"先查这一点,
  再怀疑画法。
- **锚点取强实测台阶, 不取弱拟合线**: 单点 Δ 大的台阶(实测 −29 @y=264)就固定用该 y;
  只有 11/30 内点的 RANSAC 会把锚点拉偏 33px; 拟合的 **x 范围必须覆盖该特征真正存在的区间**
  (拿只存在于左侧的台阶去右侧区间拟合, 拟出来的是别的东西)。
- **核验逐条算倾角**, 不是只数像素: 只取"落在该线 ±3px 内"的像素做直线拟合 —— 按 x 窗口取会把相邻线
  混进来, 实测造成"目标 −2.97° 实测 −0.07°"的**假失败**。判据: 每条实测倾角与目标差 <1.5°;
  并把 VP 位置与各层倾角写进图例/规格 —— 倾角就是"为什么说它平行于横梁"的唯一证据。

## 交付形态: 三条一起给(缺一个都会被当成"没做")
1. **VR(不需外参, 立刻可用)**: base 系**软件渲染**三维视图 —— 台面网格 + 轨迹管道 + 实时 TCP 十字, 指针拖动可转。
   不依赖任何 CDN/三方库 ⇒ 标定还没做时用户先有东西看。
2. **AR(需外参)**: 相机画面上叠 3D 管道 —— 逐段按**相机系 z 降序(远的先画)**、线宽 **∝ 1/z**、沿程颜色渐变、
   每 N 点画一个**截面环** ⇒ 才有"走过的通道"的立体感。实测轨迹(绿)与规划航路(蓝)同屏叠, 正好对照
   "算法规划的路"与"实际走出来的路"。
3. **人机在环标定**: 页面四步「进入标定 → 点夹爪尖 → 解算并保存 → 验证对准」, 每步给可核对的回执(点数/RMS/命中率)。

## 标定(人机在环, 最可靠, ~40s)
- 采点: 臂**停稳** → 点画面里**夹爪尖** → 同刻取 TCP 真值(3D)。
  · 采点闸: 点击前先测 **1.2s TCP 漂移**, 还在动就**拒收**(脏点进去会让外参"看着能用")。
  · **≥6 点才开解**(DLT 要 6 点起); 点要**高低/左右都变**; 每次点击把 3D↔2D 对子显示出来便于自查。
- 🔴 **解算器必须 DLT 线性初值 + 内置自检**: 只用"多起点 + LM"会收敛到**退化解** —— 实测 f 真值 520 解成 84.6,
  相机系 z 变 1.4e4 m、RMS 2.4e8 px, **而且它通过了 z>0 的合理性检查、不报错**。
  定式: DLT(Hartley 归一化)求 P → `cv2.RQDecomp3x3` 抽 (f,R,t) 作初值 → `least_squares` 收细,
  并**拒绝任一点 z≤0.02 的解**; 返回体里带自检(见下)。`cv2.RQDecomp3x3` 在本机 OpenCV 返回 **3 个值** `(retval,K,R)`。
- 返回给页面的证据: `rms_px` + 逐点误差 + 点散布 σ/range + `dlt_used` + `solver_selftest`。
- 现成脚本: `scripts/extrinsics_solve_selftest.py`(DLT 初值 + 多起点 + 自检, 自带合成相机自测, 可直接跑)。

## 独立验收(必须, 且和自检分开)
- **自检**只证明**管线**对: 造一个已知相机 → 投已知 3D 点 → 反解, 判 f 复原误差与 RMS(实测 0.36% / 0.46px)。
- **现场验收**才算数: 把 TCP 真值投到"**运动中的机械臂**"掩膜(相邻帧差法出掩膜)里数命中率;
  或者用已知 base 点(如台面/标定板)正投影 vs 图上实检比对。两条都过, 才把管道摊到画面上。
- 跨语言渲染必须同源: 浏览器 `proj()` 与 Python `project()` 用**同一 (f,R,t,主点)**;
  交付前注入一个已知外参、两边投同样 3D 点比对(实测最大差 0.001px), 否则会出现"算得对、画得歪"。
- 渲染器不能只看"没报错": 数**画布像素**(`getImageData` 的 alpha / 非背景计数)+ 段数, 并喂**真实录到的 3D 点**跑一遍。

## 叠加层的开关/清除语义(否则用户会说"数据没了")
- **默认关**(人工开启), 状态存**一个文件**(单一真源), 页面/发布器/服务都读它; 别让每个页面各存一份。
- "清除" = 设**清除线(baseline)**, 只影响画面、不动录制历史 ⇒ 必须同时给 **`显示 / 隐藏 / 清除 / 📜全部历史`**
  四个按钮, 并在状态条写明「**现在画: 实测 N 点 / 航路 M 点 · 已录 K 点**」。
- 发布器是"跑一次就退"的壳每 2s 重拉一次 ⇒ **每轮都要先读开关**再决定"撤掉/发布", 否则关掉后线又被画回来。
- "撤掉"= 从规格**挪到缓存文件**(可原样恢复), 不是删元素。排查"没看到"按链走:
  **开关 → 清除线 → 真源里的点数 → 渲染**, 别先怀疑代码。

## Pitfalls
| 坑 | 症状 | 修法 |
|---|---|---|
| 页面在 A 端口调 B 端口的接口 | 按钮点了**毫无回显**; 后端日志里**根本没有这条请求**(跨源被浏览器静默拦掉) | B 端服务回 `Access-Control-Allow-Origin: *`(+`Allow-Headers/Methods`), 并实现 `do_OPTIONS` 回 204 |
| 在浏览器控制台改页面内部变量 | 设 `window.CALIB` 无效(顶层 `let` 不挂 window) ⇒ 误判"渲染函数坏了" | 给**裸标识符**赋值(`CALIB = {...}`), 测完复原 |
| 只用多起点 + LM 解外参 | 解出物理上不可能的参数却"不报错" | DLT 线性初值 + 拒绝 z≤0 的解 + 内置自检 |
| 拿静态共面锚硬解 7 参 | 投影对得上、深度全靠猜, 管道贴歪 | 先判断能否解; 不能就报缺外参, 请人点 6~8 个不同高度的点 |
| 自测/合成外参留在生产路径 | 假标定被当真值加载, 比没标定更坏 | 自测完**立刻删**该文件并明写"已删" |
| 只断言"段数>0 / 没报错" | 死代码或错口径照样"通过" | 数画布像素 + 跨语言投影比对 + 真实 3D 点 |
| `pkill -f "<脚本名>"` 收尾常驻壳 | **杀掉调用它的那条命令自己**(exit -15) | 用 `[c]<脚本名>` 这类括号式, 或按监听端口找 pid |
| 为改页面去重启正在被看的推流服务 | 掐断用户眼前的 MJPEG | 页面按 mtime 热读; 改动攒批 + 先问, 不要反复重启 |
| 页面里那个格子的 `data-src` 指的是**原始帧**而不是叠加帧 | 叠加层里画什么用户都看不见, 他会说"没有线/没有轨迹" | 改成 `overlay_<cam>.jpg` 后**回读页面 HTML**确认; mtime 热读 ⇒ 不用重启服务 |
| 在固定相机画面上直按"水平线" | 用户:"不是以相机坐标系为轴" | 先解消失点, 画**过 VP 的斜线**; VP 病态就如实报解不出, 不硬编坐标 |
