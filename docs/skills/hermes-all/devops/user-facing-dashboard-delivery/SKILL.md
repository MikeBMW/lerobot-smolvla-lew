# 把真实数据送到「用户真正在看的那个界面」

## When to Use
- 用户说「**APP / 看板 / 界面上看不到 XXX**」（硬件、显存、指标、消息…），而你**看不到他的屏幕**
- 你要给一个**别人的页面/程序**加一块数据展示，且不知道它的数据从哪来
- 已经因为「猜错界面」发过一版或几版，用户回复仍是"还是没有"

## ★★ 第 0 步：先定位 artifact，再动手（血泪，代价 = 4 轮错版本）

本轮我把「APP」连猜三次全错（Web 控制台 → 桌面 exe → 最后才发现是一个 HTML 页面），
每猜一次就改代码 + 发一个版本，用户每次回复都是"还是没有"。

**定位四板斧（几分钟出结果）**：
```bash
# ① 在仓库里搜页面/界面文件（排除 .git 与 site-packages）
find . -name '*.html' -not -path './.git/*' -not -path '*/site-packages/*'
# ② 看页面的数据源 —— 这一行直接告诉你数据从哪来
grep -oE "fetch\([^)]*\)|/api/[a-z_]+|raw\.githubusercontent[^\"']*" <page>.html
# ③ 看页面有没有用户要的字段（没有 = 你要加的就是它）
grep -cE 'gpu|GPU|nvidia|显存|利用率|硬件|<用户提的正关键字>' <page>.html
# ④ 看页脚/署名（谁是采集方、谁是渲染方 → 整条链路一眼清楚）
grep -oE '采集|渲染|collector|powered' <page>.html | head
```
本轮真相：页脚「小芳(Mac)采集 · xspace渲染」+ 数据源
`fetch(.../mac/docs/web/robot-status.json)` + 该页**无任何 GPU/显存字段**
→ 一次性解释全部现象：**页面存在、通道存在、就是缺字段**。

**判据与止损**：
- 界面是「读某个 JSON/接口的页面」→ 要做的是**给页面加卡 + 给数据源喂真值**，
  **不是**发新版 exe（装 exe 需用户手动下载覆盖，每多一环就多一次失败机会）
- 用户**连续 2 次**说"还是没有"→ **立即停止发版本**，转去定位 artifact
- 桌面程序与网页是**两条完全不同的链路**，别把网页的问题当桌面程序修（反之亦然）
- 若对方给了 @某人（如 @web），那多半在说**那个人维护的界面**，不是你手上那个
- **用户说「装不了 / 点不了 / 进不去 / 用不了」时，先查那条路径上有没有入口，再查产物好不好**：
  `grep -nE '<动作词>|<对象>' <他打开的那个页面>` 零命中 ⇒ 真卡点是"路径上没入口"，与产物质量无关
  （实测：交付的安装包六道体检全过、下发字节与产物逐字节一致，而页面里 grep「装|下载|apk」一个字都没有
  —— 把链接发给他也走不通流程）。**修法=把他已经在看的那个面补上引导流程**
  （入口按钮 + 分步设置 + 报错原文→做法对照 + 可自证的校验串），不是重新打包 / 再发一版。
  同族老坑：「还是老样子」= 你改的产物不是他看的产物。
- 卡住时问**报错原文**（他自己屏幕上那句话）—— 一个二分问题胜过再发一版
- **動手写数据前先确认「他打开的是哪个 URL/端口」**: 同一台机器常同时开着控制台页、站点总览页等好几个面,
  甚至**一个进程监听多个端口**(`--port A --station-port B`), 各面路由/页面常量却是同一份。
  你验证通过的可能不是他盯的那个 ⇒ 先 `ss -ltnp | grep <端口>` 认清进程与端口, 再**在他那个端口上**取证。
  本轮实测代价: 在 8791 上折腾三轮, 他看的其实是 8793(同一进程的另一端口)。
- **端口压根没人监听 ⇒ 不是页面问题, 是没人把它拉起来**（常见于重启后）：先 `pgrep -af` 看手工进程/守护, 
  再确认守护有没有真的走到"拉起"那一支（多分支守护写成 `if bad: return` 时，前面的坏分支会吞掉后面的自愈）——
  恢复与治本见 `linux-host-maintenance` §9/§10。
- **定位要分两层: 「面」和「面里那个格」**。真根因常常不在你修的那个面, 而在那个面里某一格的取数地址:
  实测总览页那格写死了取**原图** `/snapshot/<名>.jpg`, 而叠加框画在 `/snapshot/overlay_<名>.jpg`
  ⇒ 服务侧统计全对、图也真画了, 用户那格永远没有框。修法与三步取证见
  `sim-real-scene-overlay` 的「用户那格没有框先查 tile 的 src」(该技能 user-owned, 需
  `hermes curator adopt` 才能自动维护)。
- **「图在动」不等于「上面那层在动」**: 页面每 N 百 ms 换帧(画面是活的), 而标注/框可能来自一份写死坐标的规格文件。
  判活的硬判据: ① 隔 3 秒比规格文件 `md5sum` ② 隔几秒取两张成品图比差异像素数。
  两条都不变 ⇒ 它就是在用活图垫着静态层, **不许报「已实时」** —— 用户一挪相机就会看到标注飘走。

**「还是老样子 / 一点都没变 / 还是小窗口」= 你改的产物不是他看的产物**
一次点击/一个功能往往同时产生**好几个可见产物**（弹出的浏览器窗口 · 会话里画布节点上的画面 ·
浮动面板 · 通知）。用户报"还是老样子"时，先**枚举这次动作会产生哪几个产物**，逐个确认他盯的是哪一个，
**别在同一个产物上继续加码**。实测代价：改了一轮页面布局、又改了一轮窗口尺寸/搬屏，
用户原话仍是"一点都没变" —— 因为"小窗口"指的是**画布节点上贴的那块实时拼图**，尺寸根本没动。
定位手法（不靠猜）：
```bash
wmctrl -lG                 # ① 这次动作到底开没开窗口、落在哪块屏、多大
scrot -o /tmp/now.png      # ② 截图后按窗口几何裁切, 量"画面占窗口宽度的百分比"等硬指标
                           #    (统一黑边上量出 46% vs 100%, 一跟就知是哪个产物)
grep -n "def <回调名>" -A40 <gui文件>.py | grep -nE "Popen|openUrl|setPixmap|start_|show\\("
                           # ③ 代码里搜出这次动作的**全部**可见结果, 逐个列清
```
- 问一个**二分问题**比再发一版便宜：`你看到的是画布上那个小方块，还是新弹出的浏览器窗口？`
  （用户"赶快修"时也要问 —— 第三次猜错的代价远大于一句话）
- 用户"直接打开浏览器 / 别放 X"这类**明说的形态要求就是验收口径**：把不想要的产物**删掉**，
  并让升级后历史残留自动撤掉（在入口处 stop/clear）；不是把它改大、改好看、改清晰。

## ★ 用户说「把这些推到 <端口> 服务」→ 他给的那个端口常常不是他的眼睛落点

实测：用户要「硬件状态 / 模型版本号 / 训练进度都推到 8796 服务，放在窗口左下角」——
我照做：8796 上 `/status/all` 通了、本机 GUI 面板也挂了 ⇒ 他打开手机看
`https://datadrive.world/st/station?k=…` 仍是空的，直接问「**这里怎么没有版本号硬件状态等信息**」。
真因：**8796 只监听 `127.0.0.1`（回环）**，手机走移动网络物理上够不到；他的眼睛落在**公网镜像**那一跳上。
⇒ 只做了**本机那一半**，**公网那一半漏了**。

**定式**：把他要的信息沿这条链补到**最后一跳**，并在最后一跳验收：
```
① 真源采集 → ② 本机聚合端点 → ③ 本机界面(GUI/局域网页) → ④ **公网镜像** → ⑤ 他打开的那个页面
```
- `ss -ltn` 先看监听地址：`127.0.0.1:<port>` = 只有本机能访问 ⇒ 凡"手机/远程要看"的需求，
  **必须再发一份到公网**（本项目现成通道 `ss3d_push.php`：token + **文件名白名单只加不改** + 改前 `.bak_<ts>` + 远端 `php -l`）。
- **本机页与公网页是两份产物**：要么同源同文件，要么写清谁是真源、由谁同步（cron `--if-changed` 幂等）。
- **验收在最后一跳**：`curl` **公网 URL** 的响应体（不是 127.0.0.1），再给用户**带破缓存参数的链接**
  （`?k=…&v=<时间戳>`）—— 他反复说"还是看不到"时，九成是手机浏览器缓存了旧页。
- 用户会**按端口号下指令**，但端口只是实现细节：先确认"**你是在哪个页面 / 哪个 URL 上看**"再决定往哪发，
  他给的端口可以只当"源头"。（同族：他给 `@某人` 时，那条线多半归那个人。）

## ★ 状态条/看板必须有「空态」，否则"没活干"会被读成"功能坏了"

实测：训练一跑完 ⇒ `training.active=false` ⇒ 面板/页面那一条**空着** ⇒ 用户连报两轮
"手机还是看不到训练模型的状态"（功能其实是好的）。
规则：**空态不留白，显示「最近一次」** —— `上次训练: L4 v20261001-r600 ✓ 17:52 完成`，
数据取最新一轮的 summary/产物目录；这样"随时打开都有东西看"。
配套：三态要能分辨 —— **在跑 / 上次跑过 / 从未跑过**，别用同一句话糊过去。

## ★ 条目标识只给「层 + 版本号」= 用户眼里等于没写名字

实测：状态条每层一个 chip 显示 `L2 v1001` / `L4 r200`，用户原话「**L2 L3 L4 的模型名字要显示出来，
现在的 v1001 也不知道是哪个模型**」。版本号是内部批次戳，对用户零信息量；**层 + 版本号 ≠ 标识**。

定式（本条两条硬要求）：
1. **每个条目 = 层 + 短名 + 版本**。短名**从真 `name` 字段提取**（不许手编），规则**自定但要一致**，≤9 字；
   完整名/完整版本/step/eta 全进 tooltip。顺序优先级判定：去括号说明 → 去 `^L\d+ ` 层前缀 →
   取第一个 ASCII 型号词(遇 `+` 截断) → 长词查小别名表 → 带限定词(`LoRA`/`世界模型`)加 `-L`/`-WM` 后缀
   （**同层两个同名族必须靠后缀区分**：`INTACT` vs `INTACT-WM`）→ 全中文名取前 4 汉字。
2. **同一套规则必须同时落在所有显示面**（本页 JS + 控制台 Python 各一份实现）⇒ 否则两处名字不一样，
   用户会再报一次。两份实现都写上"与 xxx 的 yy() 同一套规则"的注释互相指认。

**条数多时按层聚合**（用户原话「13 个模型一行放不下 ⇒ 按层聚合，每层优先在役那个 + 其余计数」）：
每层 1 个主 chip（灯+层标+短名+版本+推理标记+`+N`）+ 该层**另有真版本**的模型各 1 个不带层标的小 chip；
**手机没有 hover ⇒ 点一下整条展开全部明细**（层/短名/完整版本/状态/完整名），别指望 tooltip。

🔴 **`max-width:9ch` 会把 9 字短名截断成 `SmolVL-…`**：`ch` 是 `0` 的宽度，大写字母串比它宽得多。
短名长度限死由**生成函数**兜（≤9 字），CSS **不要再加 `max-width:Nch` + ellipsis**，否则等于白拦。
验收用**像素截图读出来**：截图上必须能同时看到「层 + 短名 + 版本」且无截断/无横向滚动。

## ★ 重启 PyQt 桌面控制台：用已有的 systemd --user unit，别用 setsid 也别重复启动

用户要求「重启用 `bash .../launch_studio.sh`，必须 setsid 脱离，否则会被你的会话带走」——
**先查有没有现成的 user unit**（`systemctl --user list-unit-files | grep <名字>`）：
```bash
systemctl --user reset-failed <unit>; systemctl --user start <unit>; sleep 30; systemctl --user is-active <unit>
```
linger 已开(`loginctl show-user $USER -p Linger` = yes) ⇒ 天然脱离会话，比 setsid 更干净。
三条坑：
- 🔴 **启动脚本里的 `pgrep -f "[g]ui-venv311/bin/python studio.py"` 会匹配到你自己那条命令行**
  （命令文本里含同样字符串）⇒ 走到"已有实例→激活旧窗→exit 0"分支，**33ms 就退出、`is-active`=inactive**。
  ⇒ 启动/重启的那条命令**不要包含那个 pgrep 模式串**，把进程查询放到另一个命令里。
- 重启前用**显式 PID** `kill`（不要 `pkill -f`），等窗口消失再 start。
- 验收要看**真窗口里的样子**：`DISPLAY=:0 scrot -o /tmp/s.png` → 按窗口几何裁切 → 放大 2~4x →
  用视觉读一遍（本机没有 ImageMagick `import`，有 `scrot`），同时保留一份离屏 4x 面板图（`--live-shot --scale 4`）。

## ★ 「这个链接能不能做成 APP」→ 先查现有包是不是 WebView 壳，别急着重打包

- 本项目手机端产物是 **WebView 套壳**（壳加载**远端页面**）⇒ **改页面即生效，不需要重打包/重签名/重分发**
  ⇒ 回答"APP 要不要升级"之前先确认这一点（看 `assets/` 里有没有把 HTML 打进包内；只有真打进去了才需重打）。
- 判断"某个端口有没有手机端 APP"：`grep -c "<端口>" <手机页>` 零命中 + `ss -ltn` 显示回环
  ⇒ **没有、也不可能有**，该端口只是服务端内部件（"给它做个 APP"是伪需求）。
- 出包要求一次说全（否则返工）：壳加载**远端页** · 允许**混合内容 + 文件下载**（画布 PDF 要能下）· 竖屏锁定 ·
  出包放站根并把**直链**发出来；版本号让页面上能自证。
- 打包与端口转发在本项目分工归 **web** 那条线；`@web` 的群提及即转达，不要靠猜的中转接口（猜的路径会 404）。

## ★ 用户说「某按钮点了没反应」→ 先取证后端，再改反馈面（不要去解释）

三步定责（几分钟出结果），**别用"它其实在跑"去说服他**：
```bash
tail -5 <GUI 无条件落盘的日志>              # ① 点击到没到代码（如 /tmp/simulink_log.txt）
pgrep -af "<后台任务脚本名>"                # ② 后台进程真起了吗（配 ps -o lstart）
ls -la / cat <状态文件>.json <产物目录>     # ③ 状态文件 + 产物路径与时间戳
```
- **请求根本没到后端的第一嫌疑是跨源**: 页面在 A 端口/域名、接口在 B 端口/域名 ⇒ 浏览器把请求**静默拦掉**，
  后端访问日志里**一条都没有**，页面也没任何回显（看上去就是"按钮坏了"）。
  判据: 后端日志零命中 + 浏览器 console 有 CORS 报错；修法: B 的服务端回
  `Access-Control-Allow-Origin: *`(+ `Allow-Headers/Methods`) 且**实现 `do_OPTIONS` 回 204**。
  同一站点的**多端口**就是跨源，别以为同机就不算。
- 三处都指向"真跑起来了" ⇒ **缺陷在反馈面，不在功能**。此时唯一有效动作是**把反馈改成看得见的**
  （同族上一课：先确认他盯的是哪个产物，别在同一产物上继续加码）；反复解释只会让他再报一遍"还是没反应"。
- 两种不合格反馈落点，**都等于没有**：① 只写日志文件 / 只写 GUI 底部日志栏 ② 印在密集画布的小节点文字上
  （87 节点里连自己截图都读不出）。合格形态 = **可视区顶部通栏状态条**（viewport 坐标，缩放平移下都停在那）
  或**侧栏固定区块**；状态色 运行中=黄/橙 · 完成=绿 · 失败=红；未运行时不画。
- **"已在运行 ⇒ 不重复启动" 这类静默分支同样要显式显示**（`⏳ 已在运行: <阶段> <进度>`）：
  用户重复点击时它是最常命中的分支，只写日志 ⇒ 在他眼里还是"没反应"。
- **判据必须自己截图判**：启动 → 触发 → 截图 → 自问"一眼能不能读出当前状态 / 进度？" 读不出 = 没过。
- 汇报口径：给"进程 pid + 状态文件 + 产物路径与时间戳"三处实证，不给"已启动/已修复"；
  他判"没反应"时，**一条能打开的图/链接**胜过十行解释（实测：把后台跑出的标注结果图直接推到他的飞书，比文字有用）。
- 🔴 **前端回执分支漏了「服务器明确拒发」这一支 = 现场眼里的「点了没反应」**：只在客户端写
  `denied / pending / ok` 三种分支时，执行器离线 / 白名单 / 守卫 / 闸门拒发会落进**空气** —— 提示永远停在
  "下发中"，按钮旁边的文案一动不动。治本两条：① 每个下发按钮的回执处理必须有「其它/拒发」分支；
  ② 拒发原因用**服务器原文**摆在**被点的那个按钮旁边**（不是"看下面日志/见日志"这种指路）。
  验收：直接调用同一个 handler 塞一个 `{ok:false,msg:'...'}` 的响应，读 DOM 确认原因真的出现了。
- 🔴 **状态条只显示一行，先给判定再给细节**：`🟢 正常 · 上电 · 无新报警 · 执行器在线` /
  `🟡 状态源旧(N 前) · 不能确认现场状态` / `🔴 不能动：<一句话原因>`（离线/急停/碰撞/未上电）。
  用户原话「太复杂，智能显示1行，简单明了」。三条硬规矩：
  ① **同一句旧值提示不得在两处各渲染一遍**（两个元素都打"⚠ 下面是旧值…"，用户会以为页面坏了）；
  ② 字段必须先**合成一句判定**再显示 —— 只摆 "上电 on · 报警 无" 这种原始字段，用户会读成"一切正常"
     （实测那两行是 42 小时前的旧帧，他据此判断，对"点了不动"完全没有预期）；
  ③ **帧龄秒数/pid/技能数这类实现细节不上那一行**，要留就放 tooltip/日志。
- 🔴 **状态必须暴露「真正执行那条链的组件」在不在**：页面只显示设备侧字段（上电/报警）时，即使执行器
  （真正读指令并干活的那个常驻进程）已经死了，整页看起来也一切正常 ⇒ 把执行器在线状态并入**同一行**判定
  （离线 ⇒ 直接写「不能动：执行器离线（按钮点了不会动）」），并给出他要做的那一步恢复动作。
- 🔴 **数据源停更不许只靠小字提示遮着**：某个字段的唯一来源停更后，要么**换到活着的源**
  （实测：话题缓存停了 42 小时，而同一条链路的直连采样文件一直新鲜 —— 换源后帧龄 <2s），
  要么把那一行直接判成「状态源旧· 不能确认现场状态」。**"还是 xx 小时前的数据"就是用户级故障，必须修源。**
  顺带：常驻采样器不能有到期时间（写成永跑参数）且容器给重启策略，否则过期后"进程还在、文件不再更新"，最难查。

## ★ 在「会动东西」的按钮旁加「看结果」按钮 → 只读实现 + 诚实空态

需求长这样: User 指着页面上一个**会真拍/真下发**的按钮说"在它旁边再加一个「最后结果」按钮，最终得有结果啊"。四条规则:
1. **只读口只加在 `do_GET`**, 绝不复用那个会触发硬件动作的口（否则"看结果"会真的去拍产线相机）；并在交付说明里点明这一点。
   服务端代理到数据源(跨机/跨端口都不同源): 页面只 `fetch` **自己 origin** 的 `/api/...`, 由服务端去取 —— 免得被浏览器静默拦 CORS。
2. **返回里必须带时间**: `fetched_at` + 数据源自家的采样时间 + **帧龄 `age_s`**（数字必须标采集时间/数据龄，同上）。
3. **缺数据不能空白、不能报错、不能装死**, 要给**下一步动作**: 空态文案 = "还没有结果 + 先点哪个按钮"。
   三种状态分开: 连不上数据源 / 数据源说还没有(404) / 有结果 —— 三者的文案差很多。
4. **结果卡给全且可自证**: 判决 + 计数 + 序号 + 采样时间/帧龄 + 耗时 + **指向真实产物**的链接
   （"模型实际吃的那张图"与"人看的那张图"各自可点开）+ **可复制的原始 JSON**。
   "模型吃的那张"必须真是**同一份像素**（服务端原样供出来, 带 md5 更好）, 不是长得像的那张。
   ⇒ 这条只读口同时就是调试判据: 用户自己调的程序没产出时，一点就知道是"路不通"还是"还没产出"。

**用户说"停止历史程序，我要重启"时的收尾口径**：按模式逐个停（模式写成 `[x]xxx` 中括号式，避免 `pkill -f` 自匹配自杀）
→ **回读残留计数 = 0** → 报出释放的资源（显存/端口）→ **点明刻意保留的**（推流服务、采集记录器、机器人栈），
否则下一次重启会把他要的东西一起带走。

## ★ 用户说「我看不到 XXX」时先枚举**显示闸门**，别先怀疑数据丢了

实测：用户说「我轨迹已经打开了，也没看到历史轨迹」。读代码/查盘一路正常 —— 真因是**显示闸门**：
他之前按过「清除」，那按钮的语义是把**清除线(baseline)** 设到当前时刻，于是规格里只剩 1 个点，
看起来像历史被删了（历史一条没丢，录制侧还有上万点）。
**定式（按这条链逐层核，每层都能一条命令看出来）**：
```
①功能开关(默认可能是关) → ②显示闸门/清除线/筛选(baseline·deleted 抑制清单·时间窗)
→ ③真源里的条数(规格/接口返回了多少) → ④渲染(页面/画布真的画了吗)
```
- 排查永远**按顺序核到哪一层断**，不要跳层、不要先动代码（改代码去"修"一个只是没打开的开关，会把好好的功能搞坏）。
- **只有"清除"没有"恢复全部"= 一定会被当成数据丢失**。任何"清屏"类按钮都必须配一个反向按钮（全部历史/恢复默认），
  并明写它的作用域是"只影响画面、不动录制"。
- **把数量写在界面上**：状态条写「现在画: 实测 N 点 / 航路 M 点 · 已录 K 点」⇒ 用户自己就能看出是"没开"还是"没数据"，
  省掉一轮"为什么没有"的问答；这也让"我看到 0"变成可复核的事实而不是感觉。
- 反向同理: 用户报"数据是旧的/没动"时，先用**条数+数据龄**自证在动，再谈别的。

## ★ 用户报「屏幕一直闪烁 / 画面在闪」→ 先量数据链, 再动代码

闪烁类投诉**不要先改渲染逻辑**。按顺序量一遍(每步一条命令, 几分钟出结果), 把"机器/相机"先排除掉:
```bash
# ① 源是不是在抖/丢帧: 拆 MJPEG 流的帧, 逐帧算亮度+帧间差(只有噪声 ≈1 就是稳的)
# ② 叠加流的质量: 数帧间隔(中位/max/std) —— 实测中位 98ms 但 max 270ms = 交付抖动, 不是丢帧
# ③ 硬件: dmesg 查 uvcvideo/USB disconnect/i915 翻转错误;  ④ 核数 vs load;  ⑤ ss -tn 数同一路流的消费者
```
- ⑤条全正常 ⇒ **问题在页面, 不在机器**(本轮实测: 三路相机帧龄 0.0x 秒、亮度恒定 124、无 uvc/显示错误、32 核 load 7)。
- 此时按这棵可疑树查**页面自身**: 有没有重设 `img.src`(cache-busting 参数) · 有没有每 1.5s 重建 SVG/DOM ·
  有没有在图像 `load` 回调里做布局。
- 🔴 **头号真因: 在 MJPEG `<img>` 的 `load` 里清画布**。Safari/部分内核对该类 `<img>` **每帧触发 load**,
  而布局里 `canvas.width=...` —— **赋同一个值也会清空画布**(实测 alpha 255→0) ⇒ 叠加层/VR 面板每帧被清一次 ="一直闪"。
  定式: ①布局带**尺寸签名**(尺寸没变直接 return) ②canvas 只在宽高**真变化**时重设 ③重画只在**数据签名变了**时做。
  取证: 手动连发 N 次 `img.load` 事件, 断言"重画 0 次 + 画布标记像素仍在"。
- 改完给用户**一个动作**(硬刷: 手机下拉 / 桌面 Ctrl+Shift+R) + **一个二分问题**(哪一面在闪: 各页面对应的 URL / 整个桌面),
  不要让他描述屏幕 —— 二分问题一轮就能定位。

## ★ 往真页面加一块「实时读数」(HUD): 复用同源 + 拆轻量端点 + 实测布局

需求长这样: 「在这个页面的右上角，实时显示 x y z a b c 的数值」。
🔴 **第一版别做成 `position:fixed` 悬浮角标，尤其当页面有右侧控制栏时**：悬浮层会压在右栏内容上，
用户下一句就是「**与手动控制台互相遮挡了**」。他真正要的形态是：**同栏里的一块独立卡片，宽度与同栏卡片对齐**
（他原话：「做成一个独立的控件…放在手动控制台的上面吧。宽度要对齐」）。十条定式(实测三轮过):
1. **先找页面里已有的同类字段**（本轮 `#tcp` 面板里已经有 xyz+abc）⇒ 数据源、口径、判失效逻辑全都现成，
   **HUD 只做"换位置的重渲染"，不新开数据通道**。给 HUD 另写一套取数 = 必然出现同一页面两处读数不一致。
2. **放法 = 插进同一栏的容器里当第一个子卡**（`aside` 下 `.card` 的第一个兄弟）⇒ 宽度自动与同栏卡一致(宽度对齐)，
   且在文档流里 ⇒ **永远不会遮挡**。**拷用同栏现有卡的原子类**(`.card`/`h2`/`.hint`)，不要自建一套边距。
   💡 重定位时**保留原元素 id**(如 `#posehud`) ⇒ 前端轮询/复制/样式钩子一行 JS 都不用改，只改 CSS 与文档流位置。
3. **多值横排一行不换行**: 外层 `display:flex;flex-wrap:nowrap;justify-content:space-between`，
   每个值 `flex:1 1 0;min-width:0`(平均分配宽度 ⇒ 自动撑满 = 视觉宽度对齐)，`font-variant-numeric:tabular-nums`
   + 等宽字体 ⇒ 数字跳动时不左右抖。**空间不够时缩字号而不是换行**(用户明确要"横向一排")：
   把值里的 `°`/单位符号去掉(单位写到卡片标题里)，一字省出 ~8px。
4. **宽度/溢出必须按"最窄的那个布局"实测**：响应式页面同一卡在不同断点宽度差 3 倍
   (本轮 1280 单列时卡宽 1239px，>1500px 时 `main{grid-template-columns:minmax(0,1fr) 640px}` ⇒ 右栏只有 640px)。
   验法：把 grid 克隆进一个指定宽度的临时容器量 `scrollWidth<=clientWidth`，并给出"需要多少 px / 可用多少 px"。
5. **刷新率要匹配源频率，但别拖累聚合接口**：整页 `/station/status` 是聚合重口(还去查两台工控机 AOI)，
   保持原 1.5s 不动；HUD 单开 `GET /pose` —— 服务端**调用与整页同一个取数函数**(`_rokae_pose()`) ⇒ 同源同口径，
   只读一个 5Hz 小 JSON。**先量端点耗时再定周期**(实测中位 0.9ms ⇒ 250ms 轮询零负担；比"我觉得很轻"硬)。
   前端加 busy 闸 + `document.hidden` 跳过，服务端慢时不叠请求。
6. **数字必须带帧龄 + stale**：`帧龄 0.16s · 5Hz · base_link`；源停 >10s 红框 + 写「上面是最后一帧, 勿当实时」。
   这是老倪的铁律(他会把画面当结果)，卡片越小越容易漏，越要显式。
7. **可复制**：数字全部 DOM 文本(0 canvas)；点一下复制全部。⚠️ **http:// 源下 `navigator.clipboard` 是 undefined**
   (非安全上下文) ⇒ 用隐藏 textarea + `document.execCommand('copy')` 兜底，失败再退化成"选中文本"。
8. **改完的服务端代码要重启推流服务**；**HTML 是热读的**(`curl <页> | grep -c <新id>` 立刻能看到) ⇒ 不用重启，
   但**用户浏览器里跑的是旧 JS ⇒ 交付话术必须给"刷新一次(F5)"这一步**，否则他看到的还是老页面。
9. **单位必须照抄"操作员现场那台机器上看到的那个单位"**（他原话：「我看机器人的状态监控，单位是 mm，而你是 m，
   你也要将单位改成 mm」）。数字对、单位不对，他照样判不可用。做法: ①换算只在**显示层**（×1000），真源文件单位不动；
   ②**小数位数按源分辨率折算**，别"看起来更精确"就多加位（m 4 位小数 = mm 1 位 = 0.1mm，加第 2 位就是虚报）；
   ③**同一页所有该量的读数一起改**（含复制文本/标题/tooltip），否则同一页两种单位混着看更乱。
10. **一个量只显示一处；加了新读数就把旧的连同它的 JS 一起删**（用户下一句就是「已经显示了 X Y Z A B C，
   显示重复了，将下面的显示先删掉吧」）。页面里**已有的同名读数（包括它在别的卡片里的那份）在加新卡时就要一并规划**：
   要么合并，要么先问一句。⇒ 删显示必须**连它的 JS 写入一起删**：元素没了还写 `$('#id')` ⇒ `null` 抛错，
   会打断**同一个 `try` 块里后面所有字段**的更新（残留比重复更坏，且症状是"别的字段也不动了"）；
   合并时**诚实口径（帧龄/stale）必须活着**——把它挪到留下的那一处，别顺手把"判失效"删掉。

11. **列表/台账型卡片（事件流、告警、碰撞点）—— 与实时读数卡不同的四条**：
    需求长这样：「记录所有 X，显示在 <某卡> 下面**紧挨着**，红色字体，小窗口，**高度与 <那张卡> 一样**，
    可以拖动，最上面显示最新的」。
    - **位置**：插成那张参照卡在**同一栏里的紧邻兄弟**（写在它 `</div>` 之后 / `refCard.insertAdjacentElement('afterend', card)`），
      不是"同栏第一张"。原子类照第 2 条复用。（"某卡下面"默认= 物理上紧邻，不是"同一栏里随便找个位置"）
    - **"高度一样"用 JS 对齐，别写死 px**：每次渲染 `card.style.height = refCard.offsetHeight + 'px'`，
      内层列表 `overflow-y:auto` 承担滚动 ⇒ 参照卡以后变高它跟着变。验收比 `offsetHeight`（实测 101 = 101 ✓）。
    - **"可以拖动"= 列表可滚动**：`overflow-y:auto` + `-webkit-overflow-scrolling:touch` + 触屏拖动，
      **不是**做成可拖拽悬浮窗（这个页面上悬浮层已被用户明确否过，见本节开头）。
    - **红字要连标题一起**：`#<id> h2{color:#f85149!important}` —— 通用 `.card h2` 规则会盖掉卡自己的标题色，
      只写 `#<id> h2{color:...}` 实测**不生效** ⇒ 加 `!important`（或提高选择器权重）。内容是 DOM 文本，别画 canvas。
    - 其余形态：**倒序**（最新在最上）+ 标题写计数（`共 N 次`）+ 点一条复制全文（可导出）。
    - 🔴 **台账行只放"能与参照卡逐列对上的那几个量，其余全进 tooltip**：用户原话「要显示 x y z a b c，与实时位姿对应；
      放在右上角就是要用眼睛看、对比的，你显示那么多没必要」。第一版把关节号/力矩/限定值/错误码一起铺在行里 ⇒ 被否。
      定式 = 每行 **时间 + 与参照卡同单位、同小数位、同列宽的那几个量**（六轴就六个），其余字段挪进 `title`；
      这样眼睛能沿列上下对齐地比，才叫"看得见"。同理：缺项画 `—`，别用 0 或 "未知" 糊过去。
    - 🔴 **回填历史条目的字段前，先比一次「当前读数 vs 最近一条历史读数」**：两者不一致 ⇒ 该量事后被动过，
      此时用当前值补历史条目就是编（实测姿态 85.72°→87.02° = 期间被移动过 ⇒ 该字段只能写「未采到」）。
      自查办法：想回填某字段时先问"这个量从事件到现在动过没有"，动过就空着。
12. **写入型/枚举型数据挂在已有的聚合接口上**：页面本来就在轮询 `/station/status` ⇒ 把它并进那个 payload
    （`<区块>.<字段>`）就自动获得了"定时采集"；采集/去重/落盘都在**服务端那一次请求里**做完（低频、幂等）。
    不用新开端点，更不用另起常驻进程。第 5 条那种**高频数字**才另开端点。
13. **事件台账的去重必须做在"读时"，而且幂等**：只在"写入时"比对本轮新条目会漏掉 —— 与**已在台账里**的条目
    配对的第二行照样会作为"新条目"被追进去（实测同一事件的两行报警各占一条）。修法：**返回前再滤一遍**
    （同事件 ±N 秒配对，只留信息量大的那条）。写时 + 读时都去重，才不怕任何一条路径重复投喂。
14. **事后无法还原的量，如实写"未采到"，绝不用当前值顶替**：事件当时的位姿/温度这类量，只有落在
    "事件后 N 秒内首次看到该事件"这个窗口内采到的才算数（设备触发保护后会**停住** ⇒ 那时读数 ≈ 事件点）；
    更早的历史条目采不到 ⇒ 写「未采到」，**宁可空着也不拿现在的位置冒充过去**（同下面「宁缺毋编」）。
    同理：上游缓存只有最近十几条 ⇒ 滚动会丢，老事件要靠落盘的文档留档，不能全指望自动采集。
    - **事件源必须用设备/控制器的原生报警码，不要自己判"出事了"**（实测 `#30400 力矩超限` / `#13036 RSC 碰撞力超限`）——
      这样台账每一条都能被原始日志复核；同一事件常同时产生两行（带数值的那行 + 保护动作那行）⇒ 按 ±N 秒配对只留带数值的那条。
    - **采集窗口宁宽勿窄，卡窄了会静默丢真记录**：实测设 90s ⇒ 一条真实事件只写进「未采到」；
      放宽到 300s 并在文末写清"为什么是空的"（超窗/源不新鲜），比留白更可核。窗口宽度本身也要和用户对一次。

**验收三条（都要做）**：① 与参照物比几何：本卡 `width/left` vs 同栏控制台卡 
   (`Math.abs(diff)<=1`) + 上下不重叠(`a.b<=b.t` 或 `a.t>=b.b`，**不能**用重叠判定那套反向逻辑)；
   ② 横排不溢出 + 所有值都在卡内(`scrollWidth<=clientWidth` 且每个 `.v` 的 left/right 落在卡边界内)；
   ③ 连续采样(每 200ms 读一次 `帧龄` 文本)证明刷新率 —— 帧龄在变就说明真在刷。
   ④ **单位与位数**核对一遍（与现场机器同单位；每位数不超出源分辨率）；
   ⑤ **重复读数零命中**：全页搜那个量只应命中一处，且被删元素的 id/写它的 JS 在源码里零命中
   (`grep -c "id=\"<旧id>\""` + `grep -c "'#<旧id>'"` 都应为 0)，并确认删除后**其余字段仍在更新**(证明没打断 try 块)。
   ⑥ **卡片顺序/兄弟关系别用 `compareDocumentPosition` 的位标志手算**（PRECEDING/FOLLOWING 极易判反，实测判反过一次，
   白报一条假警报）：直接 `[...parent.children].map(x => x.id || x.querySelector('h2')?.textContent)` 打印真实顺序。
   🔴 **坑**：设备**正在动**时，两次读数天然有差(实测 Δ=0.38mm、abc 差 0.16°)，
   别把它误判成"数据源错了"—— 那只是采样时刻不同；要判数据源对不对，必须在**静止**时比，
   或直接比"DOM vs 同一刻接口"而不是"DOM vs 几秒前的文件"。

## ★ 用户说「这里看不到数值 / 只有静态变量，给我高亮」→ 先找值的真源，再问那块面板有没有「值列」

实测：用户要「trace 里实时显示数值，不是静态的变量，是动态的数据，在哪里？给我高亮显示出来」——
那块面板**根本没有值列**（列全是 Time/Name/Type/判定/概率/发送方…），而值一直躺在总线落盘文件里
（`live.json` → `topics.<key>.fields`）。**"看不到"不等于"没有"。** 四步定式：
1. **先定位值的真源，再动界面**：逐话题的实时值快照（`fields`）+ 健康量（hz/count/lamp/判定）。
   核你要的量在不在里面 ⇒ 在 = 只差渲染；不在 = 上游确实没发（诚实说明，别在前端补数）。
2. **面板有没有承载它的那一列**：没有就加一列，**放在第 2 列紧跟时间** —— 放最后一列在长表里会被挤到视野外，
   等于没加。值压成一行；长序列（几百个数的轨迹/路径）折成 `键=[首3个数 …(N)]`，不要把几百个数铺进单元格。
3. **"动态 vs 静态"必须用颜色自证**：本次刷新**值有变 → 高亮**，与上帧相同 → 灰。他要的就是"一眼看见它在变"；
   只把值印上去、永远一个颜色，下一句还是"看不出在动"。
4. **搜完"置顶"= 提上去但不隐藏**：他说"搜索之后就在窗口里置顶" ⇒ 命中项排最上面**同时保留其它帧**。
   做成过滤器会丢掉他要对照的其它行；要隐藏就另给一个明确叫"过滤"的开关。

🔴 **别用业务约定去格式化"载荷数值"**：本仓把 `-1` 约定为"该字段缺测"，于是复用一个带该语义的
`_num()` 会把 `-0.233`（合法坐标）显示成 `—`。**缺测约定只属于规则/校验层**，载荷数值一律纯格式化。
这类 bug **只有拿真实数据渲染才会暴露** —— 拿手造数据测必然漏（所以验收必须用真源文件）。

🔴 **跨命名空间搜不到不是 bug，是词表没对齐**：用户搜的是 A 系统的关键词，界面里只有 B 系统的镜像
（实测：ROS 的 action 话题不在 DDS 总线上，搜 `move_action` 零命中）。**先给他能命中的那个词**，
并明说"A 不在这个界面上、要看它得用另一条命令"，否则他会以为搜索坏了。

🔴 **截断的落盘记录不要 `json.loads`**：总线/追踪文件里的 payload 常是**截断存储**的，`loads` 直接抛。
用正则抠 `"键": 数值` 对并跳过约定为缺测的哨兵值；一个可用值都抠不到时**显式写"全缺测"**，
既不留白也不补 0。

🔴 **别用截断的键清单下结论**：`list(d.keys())[:14]` 打印后断言"没有这个字段"—— 实测那个字段就在第 15 个。
核字段一律按名字查（`k in d`）或打印**全部**键，绝不看前 N 个。

⚠️ **与上面「点击反馈必须可见」不冲突，两类文字待遇相反**：
- **点击反馈**（他点完要看回应）= 必须摆在被点的那个控件旁边，可见、原文。
- **常驻状态文字**（系统自己在跑的读数/进度）= 用户会嫌它糊在界面上难看，正解是**画面上不写字**
  （只留边框/状态色这类一眼可辨的信号），文案挪到下方终端/日志，并且**只在内容变化时输出一行** ——
  否则 1s 轮询会把终端刷爆，等于还是坏体验。
判据一句话：这条文字是"我点完要看到的回应"，还是"系统一直在跑的读数"？前者贴近控件，后者进日志、变化才写。

## ★ 零安装交付路径（刷新即见效，首选）

页面读 `raw.githubusercontent.com/<owner>/<repo>/<branch>/<path>.json` 时：
```
改该 <branch> 上的 ① 那个 JSON（加字段） ② 那个 HTML（加渲染） → 用户刷新即见，不装任何东西
```
- 写 JSON 用**读-改-写**合并（模板：`tools/hw_to_robot_status.py`）：
  读现有 → 只加/覆盖自己的键 → 写回。**绝不整份覆盖**（会抹掉采集方的数据）
  ```python
  d = json.load(open(F, encoding="utf-8"))      # 保留他人字段
  d["hardware"] = collect()                     # 只加自己的段
  json.dump(d, open(F, "w", encoding="utf-8"), ensure_ascii=False, indent=1)
  ```
- 要**可 cron 化**：脚本支持 `--push --watch N`，再挂一个 `no_agent` 定时任务（每 2 分钟）保新鲜
- 字段命名带单位（`vram_used_mb` / `gpu_util_pct`），前端只做展示不做换算
- 未采集到的量给 **null**（前端渲染成「—」），**不要给 0**（0 是合法实测值，会误导）

## ★ 别动别人的数据分支（worktree 叠加，绝不强推）

```bash
git fetch origin mac
git worktree add -f --detach /tmp/wt origin/mac        # 隔离作业，不动主工作区分支
# 跨分支文件不共享：把需要的页面/工具从 main 显式取过去
git show main:docs/web/robot-monitor.html > /tmp/wt/docs/web/robot-monitor.html
git show main:tools/hardware_view.py      > /tmp/wt/tools/hardware_view.py
# 合并（读-改-写）→ 提交 → 在 origin/mac 之上推送（天然 fast-forward）
git -C /tmp/wt push origin HEAD:mac
git worktree remove -f /tmp/wt
```
- 推送被拒（分叉）时**不要 `--force`**：那会毁掉对方的数据。改成"在其之上叠加"
- ⚠️ **别用 `git stash -u` 包自己的新脚本**：脚本中途失败就不会 `pop`，
  你自己的新脚本会"消失"在 stash 里（本轮踩过，靠 `git stash list` 找回）
- 跨分支跑的 venv 可能是**对方平台**的（如 mac 分支上的 `gui-venv311/bin/python` 指向
  `/Users/xxx/.venv/bin/python`）→ 跨分支跑脚本优先用**系统 python3**

## ★ 生产数据完整性（信任底线，最重要）

**自测/合成数据绝不允许出现在生产视图里。**
本轮我往真实通道发过一个测试节点（`MacTEST(自测)`），它**在数据文件里留了 1.7 小时** ——
用户此时打开页面就会看到"Apple M2 Pro"这种**编造硬件**，而我一直在强调"全是真实数据"。
**三条防护缺一不可**：
1. **命名**：自测数据的 `node`/`key` 必须带 `TEST` / `自测`，一眼可辨
2. **入口过滤**：采集/桥接端拒收（`if "TEST" in key.upper() or "自测" in key: continue`）
3. **自动过期**：超 N 秒（如 120s）未更新的节点**从视图移除**，不留僵尸节点
   （否则旧值被当成实时值 —— 比没数据更糟）
加完防护还要**清理历史残留**（把文件里已有的测试节点删掉）并复验。

**交付物上的自证信息（版本号 / 哈希 / 体积 / 时间）必须由产物自动生成**：手填的会在下次重打包后
变成假信息。做法=构建脚本用占位符（`__APK_SHA256__` / `__APK_SIZE__`）把新值写回页面，
写完断言占位符零残留；页面上的校验串因此与产物强一致，用户能自证、你也无法说谎。

**给不出就说给不出**：
```
宁可显示「—（未上报）+ 一条怎么上报的命令」，
也不要显示一个编造的值。
```
如 Mac 的硬件**物理上只有那台机器跑一次采集才会存在** —— 明确写出来，
用户才知道该让谁去做，而不是继续怀疑界面坏了。

## 验证纪律（别信自己的成功提示）

- **文件改动必须回读确认**：一次 `c.replace(锚点, ...)` 锚点没匹配 → 静默 no-op，
  但脚本照样打了"✅ 已补" → 结果程序直接崩（`threading` 未定义）。
  **铁律：改完 `grep`/`sed` 打印实际内容复核，不能信自己打的成功日志。**
- **JS/HTML 改动**：抽出 `<script>` 用 `node --check` 验语法，再用真实 API 响应**复刻渲染**
  跑出「用户实际会看到什么」，别只交付"我认为对"的代码
- **GUI 改动**：`QT_QPA_PLATFORM=offscreen` 离屏构造 + **读控件文本**验收；
  常量名写错、局部 import 这类错**只在构造时才炸**，语法检查发现不了
  （本轮踩过：`C_TEXT`/`C_SUB` 不存在 → 应为 `C_WHITE`/`C_GRAY`；
   `shutil` 只在该文件方法内局部 import，模块级没有 → 卡片里必须自己 import）
- **验收断言必须跟着口径改**：用户否掉某个产物后，旧断言还在断言那个产物
  （如"画布节点已出画面"）⇒ 自动化继续报全绿而用户仍看不到。改行为的同时改 `verify_*.py`，
  并加**反面断言**（断言用户不要的那个产物**不存在**：`video_pixmap isNone/Null` + 后台线程已停）
- **PyQt 工作线程里绝不碰 Qt GUI API**（含 `QDesktopServices.openUrl`/控件读写/建 QPixmap）：
  实测后果是整个 GUI 进程 `QThread: Destroyed while thread is still running` +
  `Fatal Python error: Aborted`（窗口全没）。后台线程只能给纯进程调用（subprocess/gio/xdg-open），
  Qt 侧一律发信号回主线程执行；此错只在真点按钮时炸, 语法检查与离屏构造都发现不了
- **打包类交付**：先确认 **CI 打的入口就是你改的那个文件**；用**产物体积差**自证依赖打进去了
  （本轮 `+4MB` = DDS 运行时确实进包）；让用户在界面上能**自证版本号**（标题栏/菜单栏/首页小字）
- **窗口类产物要让几何自己说话（别信"已打开/已最大化"的日志）**: 开浏览器/新建窗口后
  **读回** `wmctrl -lG` 把实测尺寸+落屏坐标写进日志与汇报 —— 新窗常落在**另一块显示器**，
  `--start-maximized` 在 GNOME 下也可能不生效（要补一刀 wmctrl），而**认窗不能只靠标题**
  （标题要等页面加载完才更新）：启动前记下窗口 id，按"**新出现的 id**"认窗，等足 20~25s，
  搬屏+最大化+激活各做 2 轮再说成功。
- **Web 页上"图看着小"多半是信箱黑边，不是窗口小**: 4:3 画面在宽屏上 `object-fit:contain` 只能占
  窗口宽 ~46%（两侧各几百像素纯黑）。修法是**用满宽度**（默认多格并排）或给一个"铺满/全屏"按钮，
  不是去改窗口尺寸；判据用截图逐列平均亮度量黑边像素数，不靠感觉。
  本轮靠"锚点必须在写盘前校验"拦住了 → 用**精确显示串**匹配（如 `Z-MAX vX.Y.Z`），
  只改显示位 + 在旧块**之前**插入新块

## 交付话术（用户视角）
- 给**可直接点击/打开的链接**，而不是"我改好了"（用户要眼见为实）
- 说明**他自己只需做的一步**（如"点 🔄 立即刷新"）
- 若还看不到，**问一个能二分定位的问题**（如"有没有出现这张卡？"——
  有卡无数据 / 完全无卡 是两条完全不同的排查路），别让他描述整个屏幕
- 报告"改了什么"时要点名**产物**（"弹出的浏览器页在控制台那块屏最大化 3068×1862 / 画布上不再出现小方块"），
  配一条自己能量化的硬指标（占屏宽度 %、黑边像素、窗口几何），别只说"已修复"
- 数字必须标**采集时间/数据龄**（用户会把画面当结果，陈旧值会被当成实时值）
