# 把真实数据送到「用户真正在看的那个界面」

## When to Use
- 用户说「**APP / 看板 / 界面上看不到 XXX**」（硬件、显存、指标、消息…），而你**看不到他的屏幕**
- 你要给一个**别人的页面/程序**加一块数据展示，且不知道它的数据从哪来
- 已经因为「猜错界面」发过一版或几版，用户回复仍是"还是没有"

## ★★ 第 0 步：先定位 artifact，再动手（血泪，代价 = 4 轮错版本）

本轮我把「APP」连猜三次全错（Web 控制台 → 桌面 exe → 最后才发现是一个 HTML 页面），
每猜一次就改代码 + 发一个版本，用户每次回复都是"还是没有"。

**定位四板斧（几分钟出结果）**：
```bash
# ① 在仓库里搜页面/界面文件（排除 .git 与 site-packages）
find . -name '*.html' -not -path './.git/*' -not -path '*/site-packages/*'
# ② 看页面的数据源 —— 这一行直接告诉你数据从哪来
grep -oE "fetch\([^)]*\)|/api/[a-z_]+|raw\.githubusercontent[^\"']*" <page>.html
# ③ 看页面有没有用户要的字段（没有 = 你要加的就是它）
grep -cE 'gpu|GPU|nvidia|显存|利用率|硬件|<用户提的正关键字>' <page>.html
# ④ 看页脚/署名（谁是采集方、谁是渲染方 → 整条链路一眼清楚）
grep -oE '采集|渲染|collector|powered' <page>.html | head
```
本轮真相：页脚「小芳(Mac)采集 · xspace渲染」+ 数据源
`fetch(.../mac/docs/web/robot-status.json)` + 该页**无任何 GPU/显存字段**
→ 一次性解释全部现象：**页面存在、通道存在、就是缺字段**。

**判据与止损**：
- 界面是「读某个 JSON/接口的页面」→ 要做的是**给页面加卡 + 给数据源喂真值**，
  **不是**发新版 exe（装 exe 需用户手动下载覆盖，每多一环就多一次失败机会）
- 用户**连续 2 次**说"还是没有"→ **立即停止发版本**，转去定位 artifact
- 桌面程序与网页是**两条完全不同的链路**，别把网页的问题当桌面程序修（反之亦然）
- 若对方给了 @某人（如 @web），那多半在说**那个人维护的界面**，不是你手上那个
- **用户说「装不了 / 点不了 / 进不去 / 用不了」时，先查那条路径上有没有入口，再查产物好不好**：
  `grep -nE '<动作词>|<对象>' <他打开的那个页面>` 零命中 ⇒ 真卡点是"路径上没入口"，与产物质量无关
  （实测：交付的安装包六道体检全过、下发字节与产物逐字节一致，而页面里 grep「装|下载|apk」一个字都没有
  —— 把链接发给他也走不通流程）。**修法=把他已经在看的那个面补上引导流程**
  （入口按钮 + 分步设置 + 报错原文→做法对照 + 可自证的校验串），不是重新打包 / 再发一版。
  同族老坑：「还是老样子」= 你改的产物不是他看的产物。
- 卡住时问**报错原文**（他自己屏幕上那句话）—— 一个二分问题胜过再发一版
- **動手写数据前先确认「他打开的是哪个 URL/端口」**: 同一台机器常同时开着控制台页、站点总览页等好几个面,
  甚至**一个进程监听多个端口**(`--port A --station-port B`), 各面路由/页面常量却是同一份。
  你验证通过的可能不是他盯的那个 ⇒ 先 `ss -ltnp | grep <端口>` 认清进程与端口, 再**在他那个端口上**取证。
  本轮实测代价: 在 8791 上折腾三轮, 他看的其实是 8793(同一进程的另一端口)。
- **端口压根没人监听 ⇒ 不是页面问题, 是没人把它拉起来**（常见于重启后）：先 `pgrep -af` 看手工进程/守护, 
  再确认守护有没有真的走到"拉起"那一支（多分支守护写成 `if bad: return` 时，前面的坏分支会吞掉后面的自愈）——
  恢复与治本见 `linux-host-maintenance` §9/§10。
- **定位要分两层: 「面」和「面里那个格」**。真根因常常不在你修的那个面, 而在那个面里某一格的取数地址:
  实测总览页那格写死了取**原图** `/snapshot/<名>.jpg`, 而叠加框画在 `/snapshot/overlay_<名>.jpg`
  ⇒ 服务侧统计全对、图也真画了, 用户那格永远没有框。修法与三步取证见
  `sim-real-scene-overlay` 的「用户那格没有框先查 tile 的 src」(该技能 user-owned, 需
  `hermes curator adopt` 才能自动维护)。
- **「图在动」不等于「上面那层在动」**: 页面每 N 百 ms 换帧(画面是活的), 而标注/框可能来自一份写死坐标的规格文件。
  判活的硬判据: ① 隔 3 秒比规格文件 `md5sum` ② 隔几秒取两张成品图比差异像素数。
  两条都不变 ⇒ 它就是在用活图垫着静态层, **不许报「已实时」** —— 用户一挪相机就会看到标注飘走。

**「还是老样子 / 一点都没变 / 还是小窗口」= 你改的产物不是他看的产物**
一次点击/一个功能往往同时产生**好几个可见产物**（弹出的浏览器窗口 · 会话里画布节点上的画面 ·
浮动面板 · 通知）。用户报"还是老样子"时，先**枚举这次动作会产生哪几个产物**，逐个确认他盯的是哪一个，
**别在同一个产物上继续加码**。实测代价：改了一轮页面布局、又改了一轮窗口尺寸/搬屏，
用户原话仍是"一点都没变" —— 因为"小窗口"指的是**画布节点上贴的那块实时拼图**，尺寸根本没动。
定位手法（不靠猜）：
```bash
wmctrl -lG                 # ① 这次动作到底开没开窗口、落在哪块屏、多大
scrot -o /tmp/now.png      # ② 截图后按窗口几何裁切, 量"画面占窗口宽度的百分比"等硬指标
                           #    (统一黑边上量出 46% vs 100%, 一跟就知是哪个产物)
grep -n "def <回调名>" -A40 <gui文件>.py | grep -nE "Popen|openUrl|setPixmap|start_|show\\("
                           # ③ 代码里搜出这次动作的**全部**可见结果, 逐个列清
```
- 问一个**二分问题**比再发一版便宜：`你看到的是画布上那个小方块，还是新弹出的浏览器窗口？`
  （用户"赶快修"时也要问 —— 第三次猜错的代价远大于一句话）
- 用户"直接打开浏览器 / 别放 X"这类**明说的形态要求就是验收口径**：把不想要的产物**删掉**，
  并让升级后历史残留自动撤掉（在入口处 stop/clear）；不是把它改大、改好看、改清晰。

## ★ 用户说「某按钮点了没反应」→ 先取证后端，再改反馈面（不要去解释）

三步定责（几分钟出结果），**别用"它其实在跑"去说服他**：
```bash
tail -5 <GUI 无条件落盘的日志>              # ① 点击到没到代码（如 /tmp/simulink_log.txt）
pgrep -af "<后台任务脚本名>"                # ② 后台进程真起了吗（配 ps -o lstart）
ls -la / cat <状态文件>.json <产物目录>     # ③ 状态文件 + 产物路径与时间戳
```
- **请求根本没到后端的第一嫌疑是跨源**: 页面在 A 端口/域名、接口在 B 端口/域名 ⇒ 浏览器把请求**静默拦掉**，
  后端访问日志里**一条都没有**，页面也没任何回显（看上去就是"按钮坏了"）。
  判据: 后端日志零命中 + 浏览器 console 有 CORS 报错；修法: B 的服务端回
  `Access-Control-Allow-Origin: *`(+ `Allow-Headers/Methods`) 且**实现 `do_OPTIONS` 回 204**。
  同一站点的**多端口**就是跨源，别以为同机就不算。
- 三处都指向"真跑起来了" ⇒ **缺陷在反馈面，不在功能**。此时唯一有效动作是**把反馈改成看得见的**
  （同族上一课：先确认他盯的是哪个产物，别在同一产物上继续加码）；反复解释只会让他再报一遍"还是没反应"。
- 两种不合格反馈落点，**都等于没有**：① 只写日志文件 / 只写 GUI 底部日志栏 ② 印在密集画布的小节点文字上
  （87 节点里连自己截图都读不出）。合格形态 = **可视区顶部通栏状态条**（viewport 坐标，缩放平移下都停在那）
  或**侧栏固定区块**；状态色 运行中=黄/橙 · 完成=绿 · 失败=红；未运行时不画。
- **"已在运行 ⇒ 不重复启动" 这类静默分支同样要显式显示**（`⏳ 已在运行: <阶段> <进度>`）：
  用户重复点击时它是最常命中的分支，只写日志 ⇒ 在他眼里还是"没反应"。
- **判据必须自己截图判**：启动 → 触发 → 截图 → 自问"一眼能不能读出当前状态 / 进度？" 读不出 = 没过。
- 汇报口径：给"进程 pid + 状态文件 + 产物路径与时间戳"三处实证，不给"已启动/已修复"；
  他判"没反应"时，**一条能打开的图/链接**胜过十行解释（实测：把后台跑出的标注结果图直接推到他的飞书，比文字有用）。

## ★ 在「会动东西」的按钮旁加「看结果」按钮 → 只读实现 + 诚实空态

需求长这样: User 指着页面上一个**会真拍/真下发**的按钮说"在它旁边再加一个「最后结果」按钮，最终得有结果啊"。四条规则:
1. **只读口只加在 `do_GET`**, 绝不复用那个会触发硬件动作的口（否则"看结果"会真的去拍产线相机）；并在交付说明里点明这一点。
   服务端代理到数据源(跨机/跨端口都不同源): 页面只 `fetch` **自己 origin** 的 `/api/...`, 由服务端去取 —— 免得被浏览器静默拦 CORS。
2. **返回里必须带时间**: `fetched_at` + 数据源自家的采样时间 + **帧龄 `age_s`**（数字必须标采集时间/数据龄，同上）。
3. **缺数据不能空白、不能报错、不能装死**, 要给**下一步动作**: 空态文案 = "还没有结果 + 先点哪个按钮"。
   三种状态分开: 连不上数据源 / 数据源说还没有(404) / 有结果 —— 三者的文案差很多。
4. **结果卡给全且可自证**: 判决 + 计数 + 序号 + 采样时间/帧龄 + 耗时 + **指向真实产物**的链接
   （"模型实际吃的那张图"与"人看的那张图"各自可点开）+ **可复制的原始 JSON**。
   "模型吃的那张"必须真是**同一份像素**（服务端原样供出来, 带 md5 更好）, 不是长得像的那张。
   ⇒ 这条只读口同时就是调试判据: 用户自己调的程序没产出时，一点就知道是"路不通"还是"还没产出"。

**用户说"停止历史程序，我要重启"时的收尾口径**：按模式逐个停（模式写成 `[x]xxx` 中括号式，避免 `pkill -f` 自匹配自杀）
→ **回读残留计数 = 0** → 报出释放的资源（显存/端口）→ **点明刻意保留的**（推流服务、采集记录器、机器人栈），
否则下一次重启会把他要的东西一起带走。

## ★ 用户说「我看不到 XXX」时先枚举**显示闸门**，别先怀疑数据丢了

实测：用户说「我轨迹已经打开了，也没看到历史轨迹」。读代码/查盘一路正常 —— 真因是**显示闸门**：
他之前按过「清除」，那按钮的语义是把**清除线(baseline)** 设到当前时刻，于是规格里只剩 1 个点，
看起来像历史被删了（历史一条没丢，录制侧还有上万点）。
**定式（按这条链逐层核，每层都能一条命令看出来）**：
```
①功能开关(默认可能是关) → ②显示闸门/清除线/筛选(baseline·deleted 抑制清单·时间窗)
→ ③真源里的条数(规格/接口返回了多少) → ④渲染(页面/画布真的画了吗)
```
- 排查永远**按顺序核到哪一层断**，不要跳层、不要先动代码（改代码去"修"一个只是没打开的开关，会把好好的功能搞坏）。
- **只有"清除"没有"恢复全部"= 一定会被当成数据丢失**。任何"清屏"类按钮都必须配一个反向按钮（全部历史/恢复默认），
  并明写它的作用域是"只影响画面、不动录制"。
- **把数量写在界面上**：状态条写「现在画: 实测 N 点 / 航路 M 点 · 已录 K 点」⇒ 用户自己就能看出是"没开"还是"没数据"，
  省掉一轮"为什么没有"的问答；这也让"我看到 0"变成可复核的事实而不是感觉。
- 反向同理: 用户报"数据是旧的/没动"时，先用**条数+数据龄**自证在动，再谈别的。

## ★ 用户报「屏幕一直闪烁 / 画面在闪」→ 先量数据链, 再动代码

闪烁类投诉**不要先改渲染逻辑**。按顺序量一遍(每步一条命令, 几分钟出结果), 把"机器/相机"先排除掉:
```bash
# ① 源是不是在抖/丢帧: 拆 MJPEG 流的帧, 逐帧算亮度+帧间差(只有噪声 ≈1 就是稳的)
# ② 叠加流的质量: 数帧间隔(中位/max/std) —— 实测中位 98ms 但 max 270ms = 交付抖动, 不是丢帧
# ③ 硬件: dmesg 查 uvcvideo/USB disconnect/i915 翻转错误;  ④ 核数 vs load;  ⑤ ss -tn 数同一路流的消费者
```
- ⑤条全正常 ⇒ **问题在页面, 不在机器**(本轮实测: 三路相机帧龄 0.0x 秒、亮度恒定 124、无 uvc/显示错误、32 核 load 7)。
- 此时按这棵可疑树查**页面自身**: 有没有重设 `img.src`(cache-busting 参数) · 有没有每 1.5s 重建 SVG/DOM ·
  有没有在图像 `load` 回调里做布局。
- 🔴 **头号真因: 在 MJPEG `<img>` 的 `load` 里清画布**。Safari/部分内核对该类 `<img>` **每帧触发 load**,
  而布局里 `canvas.width=...` —— **赋同一个值也会清空画布**(实测 alpha 255→0) ⇒ 叠加层/VR 面板每帧被清一次 ="一直闪"。
  定式: ①布局带**尺寸签名**(尺寸没变直接 return) ②canvas 只在宽高**真变化**时重设 ③重画只在**数据签名变了**时做。
  取证: 手动连发 N 次 `img.load` 事件, 断言"重画 0 次 + 画布标记像素仍在"。
- 改完给用户**一个动作**(硬刷: 手机下拉 / 桌面 Ctrl+Shift+R) + **一个二分问题**(哪一面在闪: 各页面对应的 URL / 整个桌面),
  不要让他描述屏幕 —— 二分问题一轮就能定位。

## ★ 零安装交付路径（刷新即见效，首选）

页面读 `raw.githubusercontent.com/<owner>/<repo>/<branch>/<path>.json` 时：
```
改该 <branch> 上的 ① 那个 JSON（加字段） ② 那个 HTML（加渲染） → 用户刷新即见，不装任何东西
```
- 写 JSON 用**读-改-写**合并（模板：`tools/hw_to_robot_status.py`）：
  读现有 → 只加/覆盖自己的键 → 写回。**绝不整份覆盖**（会抹掉采集方的数据）
  ```python
  d = json.load(open(F, encoding="utf-8"))      # 保留他人字段
  d["hardware"] = collect()                     # 只加自己的段
  json.dump(d, open(F, "w", encoding="utf-8"), ensure_ascii=False, indent=1)
  ```
- 要**可 cron 化**：脚本支持 `--push --watch N`，再挂一个 `no_agent` 定时任务（每 2 分钟）保新鲜
- 字段命名带单位（`vram_used_mb` / `gpu_util_pct`），前端只做展示不做换算
- 未采集到的量给 **null**（前端渲染成「—」），**不要给 0**（0 是合法实测值，会误导）

## ★ 别动别人的数据分支（worktree 叠加，绝不强推）

```bash
git fetch origin mac
git worktree add -f --detach /tmp/wt origin/mac        # 隔离作业，不动主工作区分支
# 跨分支文件不共享：把需要的页面/工具从 main 显式取过去
git show main:docs/web/robot-monitor.html > /tmp/wt/docs/web/robot-monitor.html
git show main:tools/hardware_view.py      > /tmp/wt/tools/hardware_view.py
# 合并（读-改-写）→ 提交 → 在 origin/mac 之上推送（天然 fast-forward）
git -C /tmp/wt push origin HEAD:mac
git worktree remove -f /tmp/wt
```
- 推送被拒（分叉）时**不要 `--force`**：那会毁掉对方的数据。改成"在其之上叠加"
- ⚠️ **别用 `git stash -u` 包自己的新脚本**：脚本中途失败就不会 `pop`，
  你自己的新脚本会"消失"在 stash 里（本轮踩过，靠 `git stash list` 找回）
- 跨分支跑的 venv 可能是**对方平台**的（如 mac 分支上的 `gui-venv311/bin/python` 指向
  `/Users/xxx/.venv/bin/python`）→ 跨分支跑脚本优先用**系统 python3**

## ★ 生产数据完整性（信任底线，最重要）

**自测/合成数据绝不允许出现在生产视图里。**
本轮我往真实通道发过一个测试节点（`MacTEST(自测)`），它**在数据文件里留了 1.7 小时** ——
用户此时打开页面就会看到"Apple M2 Pro"这种**编造硬件**，而我一直在强调"全是真实数据"。
**三条防护缺一不可**：
1. **命名**：自测数据的 `node`/`key` 必须带 `TEST` / `自测`，一眼可辨
2. **入口过滤**：采集/桥接端拒收（`if "TEST" in key.upper() or "自测" in key: continue`）
3. **自动过期**：超 N 秒（如 120s）未更新的节点**从视图移除**，不留僵尸节点
   （否则旧值被当成实时值 —— 比没数据更糟）
加完防护还要**清理历史残留**（把文件里已有的测试节点删掉）并复验。

**交付物上的自证信息（版本号 / 哈希 / 体积 / 时间）必须由产物自动生成**：手填的会在下次重打包后
变成假信息。做法=构建脚本用占位符（`__APK_SHA256__` / `__APK_SIZE__`）把新值写回页面，
写完断言占位符零残留；页面上的校验串因此与产物强一致，用户能自证、你也无法说谎。

**给不出就说给不出**：
```
宁可显示「—（未上报）+ 一条怎么上报的命令」，
也不要显示一个编造的值。
```
如 Mac 的硬件**物理上只有那台机器跑一次采集才会存在** —— 明确写出来，
用户才知道该让谁去做，而不是继续怀疑界面坏了。

## 验证纪律（别信自己的成功提示）

- **文件改动必须回读确认**：一次 `c.replace(锚点, ...)` 锚点没匹配 → 静默 no-op，
  但脚本照样打了"✅ 已补" → 结果程序直接崩（`threading` 未定义）。
  **铁律：改完 `grep`/`sed` 打印实际内容复核，不能信自己打的成功日志。**
- **JS/HTML 改动**：抽出 `<script>` 用 `node --check` 验语法，再用真实 API 响应**复刻渲染**
  跑出「用户实际会看到什么」，别只交付"我认为对"的代码
- **GUI 改动**：`QT_QPA_PLATFORM=offscreen` 离屏构造 + **读控件文本**验收；
  常量名写错、局部 import 这类错**只在构造时才炸**，语法检查发现不了
  （本轮踩过：`C_TEXT`/`C_SUB` 不存在 → 应为 `C_WHITE`/`C_GRAY`；
   `shutil` 只在该文件方法内局部 import，模块级没有 → 卡片里必须自己 import）
- **验收断言必须跟着口径改**：用户否掉某个产物后，旧断言还在断言那个产物
  （如"画布节点已出画面"）⇒ 自动化继续报全绿而用户仍看不到。改行为的同时改 `verify_*.py`，
  并加**反面断言**（断言用户不要的那个产物**不存在**：`video_pixmap isNone/Null` + 后台线程已停）
- **PyQt 工作线程里绝不碰 Qt GUI API**（含 `QDesktopServices.openUrl`/控件读写/建 QPixmap）：
  实测后果是整个 GUI 进程 `QThread: Destroyed while thread is still running` +
  `Fatal Python error: Aborted`（窗口全没）。后台线程只能给纯进程调用（subprocess/gio/xdg-open），
  Qt 侧一律发信号回主线程执行；此错只在真点按钮时炸, 语法检查与离屏构造都发现不了
- **打包类交付**：先确认 **CI 打的入口就是你改的那个文件**；用**产物体积差**自证依赖打进去了
  （本轮 `+4MB` = DDS 运行时确实进包）；让用户在界面上能**自证版本号**（标题栏/菜单栏/首页小字）
- **窗口类产物要让几何自己说话（别信"已打开/已最大化"的日志）**: 开浏览器/新建窗口后
  **读回** `wmctrl -lG` 把实测尺寸+落屏坐标写进日志与汇报 —— 新窗常落在**另一块显示器**，
  `--start-maximized` 在 GNOME 下也可能不生效（要补一刀 wmctrl），而**认窗不能只靠标题**
  （标题要等页面加载完才更新）：启动前记下窗口 id，按"**新出现的 id**"认窗，等足 20~25s，
  搬屏+最大化+激活各做 2 轮再说成功。
- **Web 页上"图看着小"多半是信箱黑边，不是窗口小**: 4:3 画面在宽屏上 `object-fit:contain` 只能占
  窗口宽 ~46%（两侧各几百像素纯黑）。修法是**用满宽度**（默认多格并排）或给一个"铺满/全屏"按钮，
  不是去改窗口尺寸；判据用截图逐列平均亮度量黑边像素数，不靠感觉。
  本轮靠"锚点必须在写盘前校验"拦住了 → 用**精确显示串**匹配（如 `Z-MAX vX.Y.Z`），
  只改显示位 + 在旧块**之前**插入新块

## 交付话术（用户视角）
- 给**可直接点击/打开的链接**，而不是"我改好了"（用户要眼见为实）
- 说明**他自己只需做的一步**（如"点 🔄 立即刷新"）
- 若还看不到，**问一个能二分定位的问题**（如"有没有出现这张卡？"——
  有卡无数据 / 完全无卡 是两条完全不同的排查路），别让他描述整个屏幕
- 报告"改了什么"时要点名**产物**（"弹出的浏览器页在控制台那块屏最大化 3068×1862 / 画布上不再出现小方块"），
  配一条自己能量化的硬指标（占屏宽度 %、黑边像素、窗口几何），别只说"已修复"
- 数字必须标**采集时间/数据龄**（用户会把画面当结果，陈旧值会被当成实时值）
