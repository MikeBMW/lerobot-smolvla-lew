# 无手眼相机的 AR 叠加: 外参标定 → 投影 → 渲染 → 验收

## When to Use
- 用户要在**第三路固定相机**(笔记本内置 / USB / 电视顶摄)画面上叠 base 系 3D 内容:
  工具中心轨迹管道、3D 边界框、规划航路。
- 用户说「应用 VR/AR 技术把轨迹可视化出来」「要有明显的 3D 渲染, 能清晰感觉出已经走过的通道」。
- 某路相机**没有手眼外参**(也可能没有出厂内参), 但你要把 base 系的东西投到它的像素上。

## 第 0 步: 先判有没有现成外参, 不要重新标
- **只有做过手眼标定的那一路**(臂上 D405)可以直接投; 固定相机**没有**手眼, 通常也拿不到出厂 K(UVC)。
  臂上那套 `base→TCP→cam→px` 的链**不能顺过来用**。
- 没有外参时的选择顺序: ①现场标定(本技能) ②如实拒绝并说清缺哪一步。**不存在"先凑一个"**。

## 第 1 步: 收集 3D↔2D 对应点 (人点优先, 别先去写自动标定)
- **主人点夹爪尖**: 臂停稳 → 在页面上点画面里的夹爪尖 → 同刻取 TCP 真值。6~8 下、40 秒就能完事,
  精度比任何自动方式高一截 ⇒ **先把这条做成按钮**, 自动配准是后续优化不是第一版。
- **停稳判据放服务端**: 采 1.2s TCP, 报 max 漂移 mm; 还在动就不收点(否则记脏数据), 页面显示原因。
- **要求空间散布**: 至少 6 点(线性初值需要 6), 且**高低/左右都要变**。落盘时同时报
  逐点误差 + 散布 σ + 三轴范围 —— 点全挤在一处等于没标, 数字一摆就看得出来。
- 自动化备选(散布更好但更重): 运动中的已知物(固定视角里"在动的那一个"做身份)
  × 臂上深度测得的同物 3D; 或臂上深度点云↔固定视角边缘配准。
- 🔴 **近似共面的静态特征解不出可靠外参**: 实测几个绿拉环在 base 系 z 只差 2cm 量级 ⇒
  3 点解 7 参欠定, 硬解能得到"投影对得上、沿视线深度全靠猜"的结果 ⇒ 管道贴歪。
  **用户拿这个画面调算法, 贴歪比不画更坏 ⇒ 不够 6 个散布点就如实不画。**

## 第 2 步: 解算器定式 = DLT 线性初值 + RQ 分解 + 非线性收细
```
① Hartley 归一化(3D/2D 各自) → ② 12 参投影矩阵 DLT(每对点 2 行, SVD 取最小奇异向量)
→ ③ 反归一化 P=inv(T2)@Pn@T3 → ④ 分解 cv2.RQDecomp3x3(P[:,:3]) 取 K,R, f=(K00+K11)/2, t=inv(K)@P[:,3]
→ ⑤ least_squares(method='trf', x_scale='jac') 收细 7 参 f+rvec+t, 主点固定图像中心
```
- 🔴 **只用"多起点 + LM"会收敛到退化解**: 自检实测 f 真值 520 解成 84.6、相机系 z=1.4e4 m、
  RMS 2.4e8 px —— 而且**通过了 `z>0` 的弱检查**(z 全是巨大的正数)。没有 DLT 初值就不要相信结果。
- 🔴 **自检相机必须物理合理**: 用 look-at 构造(`zc=normalize(tgt-C)`、`xc=normalize(cross([0,0,1],zc))`、
  `yc=cross(zc,xc)`、行=相机三轴、`t=-R@C`), 并断言所有点 z>0。第一版自检的"真值相机"把点放到了相机背后
  (z 全负) ⇒ DLT **精确拟合了垃圾**(误差 0.00px), 看着像"解算器完美"。修好后实测 f 误差 0.36%、RMS 0.46px。
- ⚠️ `cv2.RQDecomp3x3` 在该版本返回 **3 个值** `(retval,K,R)`, 写 `K,R=...` 直接 ValueError。
- 解算器**自带 `selftest()` 并把结果写进接口响应**(页面显示"解算器自检=通过"), 否则后人改坏参数没人发现。

## 第 3 步: 独立验收 (两条都不能省)
1. **与标定过程无关的判据**: 把 TCP 真值投到"运动中的手臂掩膜"(帧差法)上, 报命中样本/总样本
   + 到最近运动像素的距离。只有这条过了才敢说外参可用。
2. **两侧投影同口径**: 页面(JS)与后端(Python)各算同一点比最大差(实测 0.001px)。
   省掉这步的后果是"算得对、画得歪", 从日志上看不出来。

## 第 4 步: 渲染成"能感觉出的通道"(不是一条细线)
- 每段粗线 `lineWidth ∝ baseW·ref/z`(远的细+暗、近的粗+亮), 按深度**远的先画**
- 沿程渐变(按路径进度取色) + **中心亮线**(≈0.3×线宽)读出中轴
- 每 N 点画**截面椭圆环** ⇒ 立体管道感(纯粗线只是一条带)
- 起点/终点标记 + 当前 TCP 十字
- 固定视角上同时摊**实测轨迹**(暖色)与**规划航路**(冷色、更细更淡) ⇒ 直接看出规划与实走的差
- VR 侧(纯 3D 软件渲染, 不依赖 CDN): 台面网格 + 基座竖轴 + 同一管道 + 拖动旋转;
  **不需要标定 ⇒ 先给用户看它**, 别让"AR 要标定"把可看的东西卡住

## 第 5 步: 显示语义 (轨迹这类"会越攒越乱"的叠加)
- 轨迹**默认关**, 人工开启(用户明确要求时按他说的做)。
- 🔴 **只有"清除"一定会被当成数据丢失**: 清除类按钮必须同时给"全部历史"(把清除线归 0),
  状态条写"正在画 N 点 / 录制侧已录 M 点"。清除只影响画面、不动录制数据, 要在按钮说明里写明。

## Pitfalls
| 坑 | 症状 | 修法 |
|---|---|---|
| 拿臂上那套投影去投固定相机 | 管道/框整体贴歪 | 固定相机没手眼 ⇒ 先标定(第 1~2 步), 标不出如实不画 |
| 只用多起点+LM 解外参 | 结果"看起来收敛"但相机系 z 上千米 | 先 DLT 线性解出 P 再分解做初值; 加自检闸门 |
| 自检相机把点放在相机背后 | 解算器误差 0.00px 的假完美 | 自检相机用 look-at 并断言所有点 z>0 |
| `cv2.RQDecomp3x3` 拆包 | ValueError: too many values | 它可能返回 `(retval,K,R)`, 按长度取 |
| 3 个近似共面点就想解 7 参 | 投影对得上、深度全靠猜 | ≥6 个空间散布点 + 报散布 σ/范围; 不够不落盘 |
| 只在日志里说"已验证" | 无法自证 | 报掩膜命中率 + JS/Python 同口径差 |
| 清除类按钮没配"全部历史" | 用户当历史丢了 | 配对反向按钮 + 状态条写清正在画多少点 |
| 自测用的假外参写完不删 | 系统里留下假标定 | 接口自测后立刻删掉 calib 文件并复核不存在 |

## 页面侧的三个真坑 (渲染/调试)
- 🔴 **在 MJPEG `<img>` 的 `load` 回调里做布局会清画布**: Safari/部分内核对 multipart/x-mixed-replace 的
  `<img>` **每帧触发 load**, 而 `canvas.width=...` **赋同一个值也会清空画布**(实测 alpha 255→0) ⇒ 叠加层/VR 面板
  每帧清一次 = 屏幕一直闪。定式: 布局带**尺寸签名**(没变直接 return) + canvas 只在宽高真变化时重设 + 只在**数据签名变了**才重画。
- **顶层 `let X` 不是 `window.X`**: 在自动化浏览器里注入测试状态(如假外参)必须直接给裸名赋值(`CALIB={...}`),
  `window.CALIB=...` 不影响脚本闭包, 后续 `proj()` 仍读不到 ⇒ 会误判成"函数坏了"。
- 跨端口调接口(页面在 A 端口、轨迹台在 B 端口)= 跨源 ⇒ 服务端要回 `Access-Control-Allow-Origin: *`
  + 实现 `do_OPTIONS` 回 204, 否则浏览器静默拦掉, 表现为"按钮点了没反应"。
