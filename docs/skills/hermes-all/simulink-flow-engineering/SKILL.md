## Flow JSON 格式（load_flow_file 解析）
```
{format:"hermes-flow", version:1, name, sim, nodes[], links[]}
```
- node: `{id, type, name, x, y, w, icon, color, params{}, inputs[in1], outputs[out1], actions[]}`
- link: `{id, f, t, f_port:"out1", t_port:"in1", label?}` — 连线字段是 **f/t**（不是 src/dst）
- **type 必须 ∈ NODE_TYPES**（condition/data/model/action/system/hardware/switch/train_gate/yolo_gate/coord_overlay/row_bg/pdf_report/skill/scene），否则 add_node KeyError 中断加载
- id 任意字符串；加载时 id_map 重映射为新 id → 校验悬空连线要用原始 flow 的 f/t ∈ 原始 nids
- row_bg 节点: params`{bg, model, desc}` + 额外 `h:214`

## 生成器模式（推荐，勿手写 JSON）
- 写 `tools/gui/gen_xxx_flow.py`（幂等可重跑），产物 `flows/xxx.json`（仓库根，不是 tools/flows）
- 布局常量: BASE_X=140, BASE_Y=80, COL_W=240, ROW_H=230, BG_H=214
- row_bg: x = BASE_X−160, y = 行y−20；背景名 ≤8字（不含🎨）；节点 x ≥ bg_x+160；行内节点 x 间距 ≥150
- 参考产物: `flows/dual_brain_peg.json`（22节点21连线, left_right 工程对齐 policy=left_right, 含交付行▶视频/📄PDF）、`flows/hardware_toolbox.json`（37硬件+5row_bg+42节点32连线）、`flows/transfer_adaptive.json`（18节点17连线, 元数据带 commit 字段）

+ 验证脚本走 `mktemp -t hermes-verify-XXXXXX.py` 路径运行（系统要求 hermes-verify- 前缀 + tempfile 路径），跑完清理 /tmp 残留；输出过滤 `grep -v "Unknown property|libEGL|MESA|requestActivate"`。

## 单步执行（仿 Simulink，2026-08-12 老倪要求：每次执行高亮一个节点 + 终端看到当前节点输出）
- 原实现 step_sim 一次 `_exec_topological()` 跑完全部节点 → 改为**每步只执行 1 个节点**（拓扑序推进）
- 状态: `self._step_order` / `self._step_idx`（__init__ 初始化 None/0）
- step_sim 逻辑: `if self._step_order is None:` 才重建拓扑（**排除 row_bg 背景行** — `[nid for nid in self._topo_sort() if self._by_id(nid).get("type") != "row_bg"]`，否则背景行先被执行）；⚠️ **完毕分支必须独立 if**（`if self._step_idx >= len(order): log("✅ 单步执行完毕") + order=None + idx=0 + return`）— 若和"order is None 重建"用 `or` 合并，idx 被重置成 0 完毕分支变死代码（踩过，日志永远不出"单步执行完毕"）
- 高亮: `node["status"]="step_active"` → paint 加 `elif status=="step_active": color=#ffd700` + `pen = QPen(color, 2.8 if status=="step_active" else 1.6)`（金色粗框）
- 推进: 每步先扫 `status=="step_active"` 的旧节点置 success(绿)+update；当前节点置 step_active + `_sim_node(n, keep_active=True)`；`_sim_node` 加 `keep_active` 参数（默认 False 老行为；True 时执行完保持 step_active 金色 — **最后一步高亮保留**，用户能看到最后执行的节点，19/20 变绿是正常设计）
- start_sim 运行模式互斥: 清 _step_order/_step_idx + step_active→idle
