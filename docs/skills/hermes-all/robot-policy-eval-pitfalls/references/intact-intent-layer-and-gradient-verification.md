## 一、更正 SKILL.md ⑬: 螺旋搜索已实施, 但**未能提升成功率**

⑬ 原文把螺旋搜索写成"正确解法(未实施, 下一步)"。**已实施并实测, 收益为零**, 记录以免后人再加码:

- **实现**: 遇阻时 peg 头在孔口平面走半径 `SPIRAL_R0→SPIRAL_RMAX` 递增螺旋 (相位 `SPIRAL_OMEGA`/帧),
  "先搜后撤" = 螺旋优先, 期间**撤销**回撤/回退安排; `SS_SPIRAL` 默认开, 只在遇阻时生效 (成功路径零影响)。
- **实测 (5 seed, mode=insert)**:
  - seed7 / seed9 / seed104: 螺旋 **0 次触发**, 零回退, 343/346/355 步与基线逐帧一致;
  - seed11: 螺旋 3 次 (上限用完) 后仍遇阻回退 24 次;
  - **seed12: 螺旋 0 次、遇阻回退 0 次** —— 它压根没走到插入段 (卡在"对位 465 / 下降 469"。
    属抓取滑脱问题, 见 SKILL.md ⑫)。
- ⇒ **对孔精度缺口 (3~5mm vs 需求 1~2mm) 不是靠搜索能补的**; 两个难组失败各有别的原因:
  seed11 的 peg 摆放 x 偏 6cm = **布局问题**; seed12 与几何完全相同的 seed7 走向相反 = **抓取物理临界**。
  **别再在"插入搜索/对孔阈值"上加码。**

### 同批的另一个止血点: 基元重放**不能**驱动插入段
首版把"共享运动基元"当插入前馈 → 用**多 seed 平均模板**做毫米级精插 → **0/5 全败**;
给螺旋加上"仅孔口 XY 搜索"的限制后才不破坏成功组。
⇒ 重申 ⑨: **插入段恒走解析伺服**, 记忆/基元只作冷启动或前段引导。
(教训: 这条规则早在 ⑨ 写过, 实现时仍会漏 —— 动"前馈槽位"前先回读 ⑨ 的分段约束。)

## 二、把 INTACT 二态意图落到流形上 (物理量的精确对应)

既有流形已经把两种意图的**物理形式**准备好了, 不需要新造:

| INTACT | 本仓库流形上的物理量 | 来源 |
|---|---|---|
| `m_local = z_{t+1} − z_t` | `−e_par` (接触流形**切向**推进) | `ContactManifold.decompose()` |
| `m_goal  = sg(z_g) − z_t` | `−∇V_p = −W·d` (性能流形负梯度, 指向 η=1 完成态) | `PerformanceManifold.evaluate()` |

共享语法 = 两者都是 `Δz ∈ R³` 意图向量 → 同一个算子消费; 流形提供**物理接地**(约束/风险边界),
意图层提供**规划能力**(往哪走) —— 二者正交互补, **保留流形、在其之上叠加**, 不替换。

### ⚠️ 坑 1: 接触流形的误差符号约定**因段而异**, 必须统一
```python
# ContactManifold._error() 原设计 (不是 bug):
#   插入/完成段: e = peg_head − hole_pos   (当前位置−目标) → 推进方向 = −e
#   自由空间段:  e = target   − hand        (目标−当前位置) → 推进方向 = +e
```
意图层若一律取 `−e_par`, 自由空间段方向会**整体反向**
(实测转移段 `m_local` 与 `m_goal` 的 cos = **−1.000**, 统一成"指向阶段目标的单位向量"后 = **+1.000**)。
⇒ 意图层的第一件事就是**把两态统一到同一语义**, 这本身就是 INTACT 说的"共享特征语法"的落地。

## 三、验证 "非对称梯度" 只能看梯度, 不能看前向

`m_goal.detach()` **只影响反向** ⇒ 两个变体(all / 去 detach)的**评估 NLL 必然一字不差**。
本会话就曾以此误判"两者没差异"。

**正解: 测 `∂L/∂m` 的范数**:
```
∂L/∂m 实测:  局部意图 0.3379  ·  目标意图(停梯度) 0.0000  ·  目标意图(不停) 0.26246
```
- 局部路径梯度畅通("绳", attached, 塑造物理认知); 目标路径被完全切断("锚");
- 第三个量是**对照** —— 证明 `0.0000` 是 detach 造成的, 不是数值巧合。
**通用规则: 任何"梯度层面的机制"(detach / stop-grad / 冻结 / 梯度缩放) 都必须用梯度量核验,
用前向指标核验等于没验。**

### ⚠️ 坑 2: stop-gradient 的语义
**前向照常产生动作, 反向截断**。写成"把 m_goal 置零"是错的 —— 那样目标意图就不产生动作了。

## 四、另外三个"消融/似然"侧的静默坑

1. **`@torch.no_grad()` 用在被 loss 消费的 helper = 零梯度, 静默失效。**
   首版 `behavior_align_loss` 用 `@torch.no_grad()` 的采样统计 → 对齐项完全没有梯度, 形同虚设,
   **签名 = 相关消融结果一字不差** (实测 `xy_align` 与 `no_align` 完全相同), 且只剩别的损失项在使劲
   (主指标异常变差)。改用**解析式可微统计** (混合高斯: mean=Σπ_kμ_k, var=Σπ_k(σ_k²+μ_k²)−mean²)。
2. **消融对照必须在"有区分度"的量上做。** 意图向量若已**归一化成单位向量**,
   "坐标 L2 对齐 vs 行为对齐"就失去区分度 → 两者结果相同 = **对照无效**。
   要证明"行为对齐优于坐标对齐", 必须用**非归一化的原始位移量**重做对照。
3. **混合高斯 NLL 可以为负** (σ 可增大 ⇒ 密度 > 1) ⇒ **不能拿 "NLL > 0" 当健康判据**;
   报数要同时给 NLL 与 σ 量级, 并声明这一点, 否则容易被后续会话当成"模型学坏了"。
