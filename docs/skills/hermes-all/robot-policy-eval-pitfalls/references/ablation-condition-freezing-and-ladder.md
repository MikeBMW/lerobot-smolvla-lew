# 消融阶梯的实验条件冻结 + 门闸空过 (2026-09-14, 记忆层集成阶梯 30 格实测定稿)

## 触发
- 要跑**多层消融/逐层打开**的对照 (关 / +L2 / +L3 / +L4 / +仲裁), 并要敢说"哪一层带来了提升"。
- 出现"同 seed / 同权重 / 同代码, 两次跑结果不一样" 或 "某两层数字**一模一样**"。
- 要在**带扰动**的条件下评估鲁棒性 (先确认扰动真的被注入了)。

## ① 可变状态文件 = 实验条件的一部分 (本次抓到的真 bug)
**症状**: 同 seed、同 cap、同权重、同代码, 解析链结果从 `65.26mm(done)` 漂到 `58.02mm(not done)`;
而**纯模型路径逐位复现** (649.33mm / 667.13mm 两次完全一致)。
→ 复现性差异**只出现在读记忆的那条路上** = 定位到"被 run 写入的状态文件"。
**根因**: `data/muscle_memory.json`(标杆/冠军轨迹)、`assembly_memory.json`(台账)、`shared_memory.json`
由引擎**逐局写入** (成功即固化)。它们既不在 manifest 里、也不在格与格之间复位
⇒ 后跑的格看到的"记忆"与前格不同 ⇒ **同口径被悄悄破坏**。
**修法 (四条一起做才有意义)**:
1. 把可变状态文件 + 辅助权重 (`models/*.pt` 这类引擎/模型会读的资产) **全部 sha256 纳入 manifest**。
2. 每 manifest 建一份**状态快照目录**; **每格开跑前把状态复位到快照** (所有格起点一致)。
3. 跑完把该格产生的状态**另存为 artifact** (`state_after/<tag>__<file>`) — 证据不丢, 还能看"记忆真在长"。
4. **续跑要用快照的 sha 算 manifest hash** (不是 live 文件的 sha), 否则 live 漂移会让 manifest 每跑一次都变
   → 断点续跑失效。做法: 先算"不含状态"的 core hash → 用它做快照目录名 → 快照不存在就现场建 →
   把快照 sha 并进 manifest 重算最终 hash。
**通用判据**: 任何**运行过程会写**的文件 (记忆库/台账/缓存/索引/warm-start 缓冲) 都是实验条件。
没进 manifest + 没逐格复位 = 这批对照不成立。

## ② manifest 该冻什么 (阶梯台的最小集合)
```
权重: policy 名 + 文件 sha256 + 字节数 + epoch
数据口径: 反归一化 stats 文件 sha256 + action_space 字段 (逐维 mean/std 来源必须唯一)
代码: 引擎/桥/势场/仲裁 文件的 sha256 + git rev (改一行代码 = 另一批历史行)
开关: 逐层开关快照 (data/<layers>.json)
状态: ① 里的可变状态文件 + 辅助权重 sha256
口径: seeds / max_steps / mode / device
```
manifest 变了 = 新一批历史行, **不和旧的混着比**; 结果 append 到 `runs.jsonl` + 汇总表 append 到
`ladder_history.csv` → 换权重/换配方后同一格直接对比 = "能力怎么变的"可追溯。

## ③ 门闸空过 (vacuous pass) — 最容易被当成成绩
阶梯闸常写成"后一臂 ≥ 前一臂"。当**所有臂都全 0**时, `0 ≥ 0` **天然成立** → 闸"通过"但什么都没证明。
本次实测: 5 臂 × 2 干扰档全 0/30, 闸表里 N2/N3/N4 全 ✅ —— 报告里必须写明
**"✅ 空过 (全 0 相等于全 0)"**, 不能算作通过。判据: **先看绝对水平 (成功率/深度是否接近成功线),
绝对水平不达标时, 相对闸的 ✅ 一律标注为空过。**

## ④ 相邻臂数字完全相同 = 该层零贡献 (别当提升)
`L23` 与 `L234` 与 `assy` 三行**数字逐位相同** (610.8 / 605.9 std 也相同) ⇒
后加的层在**当前状态下没有可测贡献**。这不是"稳定", 是"没生效"。要查两处:
1. **该层是否真的进了动作** (介入步数/权重 w 是否为 0 或恒定下限);
2. **权限是否被写死成下限**: 本次 `w = w_max·max(conf, w_floor)` 中现场 `conf ≡ 0` (离最近轨迹管 207mm)
   ⇒ `w = 0.5×0.2 = 0.1` 恒定 → **层每步都介入, 但只出力 10%**, 扳不动 600mm 的误差。
   修法 = **增益调度**: `far = clip((d_perp−d_near)/(d_far−d_near),0,1)`;
   `w = max(w_max·max(conf, w_floor),  w_far·far)`;
   **管内维持原公式 (不回退), 出管 (模型跑飞) 才让记忆场主导**。参数 (w_far/d_near/d_far) 写进逐步诊断,
   便于同口径对比。

## ⑤ 带扰动评估: 先证"扰动真的注入了"
本次最贵的发现: 桥调 `sim.run(max_steps=…)` **没传能力档**, 而引擎里干扰只在 `cap=='l4'` 分支打开
(`_jitter_on=True`) ⇒ **历史上所有"L4 链"跑法其实都是无干扰的**, 抗鲁棒性从来没被测过。
**协议**: ① 把能力档/扰动开关**透传**到引擎; ② 每格结果里**记录真实扰动元数据**
(dx/dy/dz/yaw/shell90 这类由注入函数产出的字段); ③ 报告里贴一条真实样本, 证明扰动不是纸面配置。
**另注语义**: 引擎在扰动轮会**主动旁路**某些"按场景固化"的记忆层 (布局变了标杆失效 → 正确降级)
⇒ 扰动档里该层的介入下降是**预期行为**, 不是回退; 报告要说明, 不能当卖点也不能当故障。
