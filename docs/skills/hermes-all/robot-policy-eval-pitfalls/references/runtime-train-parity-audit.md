# 训练/运行时口径对齐四查 (2026-09-14 实录, Z-MAX L4 INTACT)

## 触发场景
判闸/离线评估连续多轮 ❌, 症状固定为两条合体:
- `pred_std / teacher_std ≈ 0.08` (报"预测塌缩")
- 模型 xyz MAE 0.042 > 常数基线 0.0325 (**打不过"直接预测教师均值"**)
**且训练轮数从 1 轮到 4 轮都一样**。

判别口诀: *去掉整体偏置后 MAE ≈ 常数基线* ⇒ 模型在该口径下对教师动作**零信息量**
⇒ 先查口径 (输入/变换/统计来源), 不要加训练量、不要调超参。

---

## §1 零初始化死锁 (0×0 乘积, 梯度恒 0)

**症状**: 新加的条件分支训多少轮都不动; 判闸 `skill=on` 与 `skill=zero` 输出**逐位相同**。

**实例**: `IntentActionActor` 新增 `skill_enc` (24→32, SiLU, LayerNorm, 32→32), 末层零初始化
(为了暖启动与老模型逐位等价); 同时 `train.py` 把入口层 `net.0.weight` 的**新列也置零**
(为了让部分加载后老列不受污染)。两边同时为 0 ⇒
`E(s) = 新列(0) × 末层输出(0) = 0`, 且 `∂L/∂(新列) = δ ⊗ 末层输出ᵀ = 0`,
`∂L/∂(末层) = (新列ᵀδ) ⊗ 输入 = 0` ⇒ **谁也不会先离开 0**。

**取证** (真权重 + 真数据, 全打印, 无手写数字):
```
$ cd /home/ubuntu/INTACT-JEPA && ./.venv/bin/python tools/skill_deadlock_evidence.py
[体检] |skill_enc[-1].weight|max   = 0.000e+00      ← 训满 3 轮仍全零
[体检] |net.0.weight[:, -32:]|max  = 0.000e+00      ← 入口层新列也全零
① skill=on 与 skill=zero 输出逐位相同 = True
   ∂L/∂(skill_enc 末层) = 0.000e+00
   ∂L/∂(入口层新列)     = 0.000e+00   ← 0x0 死锁
   ∂L/∂(入口层老列)     = 9.222e-01   ← 对照: 老能力一直在学, 只有新通道死了
② 解冻后 (末层仍零初始化): 输出与解冻前逐位相同 = True (暖启动零回退不破)
   ∂L/∂(skill_enc 末层) = 1.165e-01   ← 梯度通了
③ 优化 5 步: |skill_enc[-1].weight|max 0 → 0.002758
```

**修法**: 只允许**一端**零初始化。
- 入口层新列改小随机 `U(±1/√in_dim)`; 末层保持零初始化 ⇒ 暖启动输出仍**逐位不变** (0 向量乘任意权重恒 0), 但 `∂L/∂(末层) ≠ 0`。
- 另加无条件体检函数 (本次 `_break_skill_deadlock(model)`): 若"末层与新列同时全零"就在 init 后解冻 ⇒ **续训也能自愈** (续训会把死锁状态从旧 ckpt 带过来)。

**推广**: 任何"零回退 (warm-start 逐位等价)"设计都要检查这条 —— 门控/残差/新增投影若两端都是零初始化, 通道就是死的, 而且前向形状对、诊断 `used=1.0` 全都"看起来接上了"。

## §2 图像预处理口径 (尺度差 ~100×)

**取证** (拿训练侧真取值, 别猜):
```python
# 训练侧 (train.py build_dataset → get_img_preprocessor)
ds = swm.data.load_dataset(name, transform=None, cache_dir=..., **dataset_cfg)
r  = ds[0]["pixels"]                    # → torch.uint8  [8,3,224,224]
tr = get_img_preprocessor("pixels","pixels",img_size=224)
p  = tr({"pixels": r.copy()})["pixels"] # → float32, min/max/mean = -2.118 / 2.429 / 0.280
```
判据: `ToImage(scale=True)` = `ToDtype(float32, scale=True)` + ImageNet Normalize。
**关键**: `scale=True` 只在 **uint8→float** 时做 /255; 数据集若把像素存成 **float 0~255**,
loader 会先转 uint8 (本例如此) 才 /255 —— 所以真正的口径是 **/255 + ImageNet**。

运行时若直接喂 h5 里的 float 0~255 (min 0 / max 255 / mean 130.7) ⇒ ViT 输入被放大 ~100 倍且带巨大正偏移
⇒ 编码器退化 ⇒ 动作头输出**恒定且带偏移** ⇒ "std 比 0.08" + "打不过常数基线"。

**修法**: 修在**唯一入口** (桥 `tools/intact_worker.py::_prep_images`), 所有运行时 (判闸回放/引擎直驱/
direct_rollout) 同时生效。自动判量级, 防重复归一化:
- `max > 2.0` ⇒ 视为 0~255: `(x/255 − mean)/std`
- `[0,1]` (min ≥ −0.01 且 max ≤ 1.01) ⇒ 只补 ImageNet
- 其它 ⇒ 视为已归一化, 原样
并把 `img_prep` 写进每次推理的诊断 (逐帧可查, 不是"写了没接")。

**实测 (同一 ckpt 同一批 120 帧)**:
| | 修前 | 修后 |
|---|---|---|
| pred/teacher std 比 (dx/dy/dz) | 0.08 / 0.09 / 0.06 | 0.76 / 0.74 / 0.61 |
| 预测偏置 (dx/dy/dz) | +0.025 / +0.004 / +0.041 | −0.005 / +0.005 / −0.006 |
| raw 输出 std | 0.004~0.07 (近恒定) | 0.62~0.70 |

**连带**: 这条 bug 会同时污染**所有**运行时 (评测与真机闭环), 所以"离线判闸差"与"引擎直驱差"会一起出现 —— 别当成两个问题分开查。

## §3 反归一化统计来源 (必须与 ckpt 训练数据集同源)

**取证**: 比对 `stats.json` 的 `source` 与 ckpt `train_config.yaml` 的 `data.dataset.name`。
```
zmax_action_stats.json      : source=zmax_insert.h5           n=18635   dx std 0.1531  grip mean 0.1203
optical_insert_v5_action_stats.json : source=optical_insert_v5_disturb.h5 n=149100  dx std 0.0740  grip mean 0.8275
```
用错那一个 ⇒ dx 指令放大 2.1 倍、grip 偏移完全不同 ⇒ 数字全废 (本例还叠加了"原数据集文件已被删, 只剩残留 json")。

**修法 (做成红线, 不靠自觉)**: 在工具里加 `audit_stats(s_meta, policy)`: 从 ckpt 的 `train_config.yaml`
读训练数据集名, 与 stats 来源比对, **不一致直接 SystemExit**; 确需做对照才允许显式 `--allow-stats-mismatch`。
效果: 从"白跑 25 分钟后拿到假数"变成"2 秒失败并说明原因"。

## §4 判闸/哨兵的去重键 (按 epoch 号 = 续训后永久静默)

**症状**: 脚本手动跑**零输出、exit 0** (no_agent cron 的静默语义), 怎么看都像"没新 ckpt"。

**根因**: 标记名写成 `v6_epoch_{n}.json` 且"文件存在就跳过" ⇒ 续训/换轮次 (v6r2 → v6r5) 的 ep1/ep2
被**上一代**同名标记顶掉 ⇒ 新轮次永远判不出。

**修法**: 去重键改成 `{family}_epoch{n}.json` (family = 训练输出目录名), 同时继续写一份老名字的
**兼容别名** (飞书进度报/人工看的老路径不受影响); 别名覆盖不会造成假跳过, 因为去重只看 family 名。
另外: 短跑时代取消"只判 1/2 与偶数轮"的限流 (每轮都判)。

**同类坑**: 报尾 f-string 写 `f"...{on,zero}..."` → `NameError` (打印时崩, 标记已写但 exit 1)。
凡"脚本正常但退出码非 0/无输出", 先把尾部 print 检查一遍。

## 证伪纪律 (别急着改口径)
本次怀疑过"goal 口径": 判闸把所有帧的 goal 都设成第 0 回合末帧 (帧却横跨所有回合)。
用 `--goal-mode own` (每帧用**自己回合**的末帧) 对照 → `dz raw mean +0.8914 → +0.9055`、MAE 几乎不变
⇒ **猜想被证伪**, 真因是 §2 的图像尺度。**对照实验要留档** (证伪也是结论)。

## 作废与留证
口径修好前的一切评测数字 (判闸 ❌、"越训越塌"、直驱 92.2mm) **一律作废**:
改名留证 (`*__prefix_imgfix.json` / `*_v6r2_deadlock.json`), 清掉会挡住重判的标记, 让同一套哨兵重跑。
**修后同一 ckpt 的对照**才是唯一可比口径:
```
v6r2 ep3 (死通道): on == zero 逐位相同 (0.039963994175195694 双方一致) · std 比 0.10 → 0.51
v6r5 ep1 (活通道): on 0.0402 / zero 0.0389 (Δ=-0.00134)            · std 比 0.08 → 0.71
```
这张表同时反证了**判闸本身没坏**: 死通道给"逐位相同", 活通道给"有差"。
两臂都仍输常数基线 ⇒ 结论只能是"**口径修好, 但无提升证据**", 不许写成有提升。

## 排期提示
口径类 bug 修复的成本极低 (单点改 + 前后对照), 而"加训练量"的成本极高 (小时级 GPU)。
遇到"多轮训练结论一致地差"时, **先花 10 分钟做口径四查**, 再决定要不要训。
