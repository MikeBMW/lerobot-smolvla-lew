## 一、UI 尺寸最终基线 (v3.0.3, 老倪原话"太大了, 同比例缩小")

| 元素 | 太小(原始) | 过大(被否) | ✅ 最终基线 |
|---|---|---|---|
| 工具栏按钮高 | 35px | 66px | **52px** |
| 工具栏字号 | 11pt (22px) | 15pt (30px) | **12pt (24px)** |

## 二、画布节点框: 加高优先, 加宽前必须先量行内间隙 (v3.0.3)
老倪:「画布的方框有些小, 方框里面的字太挤, 你来**重新排布**一下」
先量 (`tools/probe_canvas_nodes.py`, 复刻 `SimNodeItem.paint` 同一套排版算法):
- 原 **240×84**, 最长名字「🛡 安全执行边界 (饱和限幅)」需要 204px, 可用宽正好 204px (w−36)
  ⇒ **零余量**, 只能两行硬塞 → 视觉上"挤"
- 横向相邻节点**最小间隙 0px (紧贴)** ← 直接加宽必然重叠
- 纵向行距 190~280px 却只放 84px 高的框 ⇒ 空间全浪费在纵向

改法三件套:
1. `DH 84→110` + 新增 `DW=280` (可用宽 204→228); 把 5 处写死的默认 `240` 全换成 `DW`
   (`SimNodeItem.__init__` / row_bg 分支 / `add_node_at_center` / spec 兜底两处)
2. 标题排版: 右留白 36→**52px** (字不贴状态徽章) + 允许拆到**三行** (原最多两行) +
   绘制区四周留白 `QRectF(14, 10, w-56, h-26)`
3. `_relayout_row_gaps(min_gap=56)`: 按 y 分行 (`round(y/60)`), 行首 x 不动, 逐个把后节点推到
   `前一个右边界 + 56px`; 顺带把旧 JSON 里遗留的 240×84 升级到 DW×DH。**只整理横向, 纵向不动**;
   挂在内置画布生成之后 (`open_state_space` 末尾), 不动用户手工保存的布局。
   ⚠️ 内部刷新用 `self._sync()` — 本工程**没有** `_sync_links()`; 写错会被 except 吞掉只留一行警告。
实测状态空间 22 节点: 280×110, 行内最小间隙 **0→56px**, 标题全部单行 12pt 零溢出, 左右余量 0→14px。

## 三、状态估计器"输出很乱"= 两个真问题 (v3.0.8)
老倪:「自适应状态估计的输出, 为什么这么乱?」— 先量化再改, 结论不是画法问题。

### 量化 (读同源 trace, 别凭感觉)
| 量 | 实测 |
|---|---|
| 观测噪声 z_k−真值 | 每轴 **5.0 mm** std (PhysicalWorld.observe noise=0.005) |
| 末端真实每步位移 | **0.29 mm/步** (ctrl_dt 12.5ms) |
| x̂ 每步抖动 | **2.17 mm/步** ⇒ **= 真实运动的 7.4 倍** ← 画成线就是乱麻 |
| x̂ 与真值误差 | 均值 4.73 mm / 峰值 13.0 mm |

### 真 bug: 卡尔曼预测的控制输入用错了
`est.predict(latent, act4)` 里 `act4` 取的是 **u_ff (前馈加速器的建议)**, 而系统真正下发执行的是
**u_exec** (= 动作调制器融合 0.3·u_ff+0.7·u_fb 再过安全限幅)。实测两者**模长差 3.12 倍**
⇒ 预测拿"根本没执行的动作"外推位置, 白送一份预测误差。
**铁律: 卡尔曼/任何预测器的控制输入必须是上一步真正作用于系统的量** (`self.u_prev = u_exec`)。
两处都要改: `tools/gui/state_space_sim.py` 与 `tools/gen_ss_metaworld_episode.py` (后者复制了同样的逻辑)。

### 增益标定: 用离线重放扫参, 不拍脑袋
观测噪声(5mm) 比每步位移(0.32mm) 大一个数量级 → K=0.5 等于一半直接跟噪声走。
离线重放 (用 trace 里的 z_k/u 序列重跑估计器, 不用重训不用重跑仿真) 扫 K:
| K | 误差 | 抖动 |
|---|---|---|
| 0.5 (原) | 3.01 mm | 2.19 mm/步 |
| 0.3 | 2.30 mm | 1.31 mm/步 |
| 0.15 | 1.68 mm | 0.71 mm/步 |
取 **K=0.2** 折中 (保留跟随性)。改完实测: 误差 4.73→**2.62 mm** (−45%), 抖动 2.17→**0.89 mm/步** (−59%),
抖动/真实位移 7.4→**2.8 倍**, 八阶段仍全通终态完成。
> 剩余 2.8 倍抖动是**物理设定**(5mm 传感器噪声 vs 0.32mm/步位移), 不是 bug。别继续压 K 或加多帧滤波:
> **残差本身就是接触检测的信号源**, 过度平滑会把"撞到孔沿"这个信息滤掉 (插入段残差 0.213 vs 抬起 0.014)。

### 可视化配套
- 估计轨迹窗口 60→30 帧 (噪声下窗口越长越乱)
- 数值面板加 **"x̂ 抖动 mm/步"** — 把"乱"变成可读数字, 不靠感觉吵架

## 四、方法论 (这一天 9 个版本反复验证有效)
1. **先量后改**: 每次老倪说"太小/太大/太乱/看不懂", 先写探针读**真实控件几何或真实 trace**,
   把数字摆出来再改; 汇报时给"改前 → 改后"两列数字。
2. **参数类改动用离线重放扫参**: 有 trace 就能重放, 不必重跑仿真/重训。
3. **改完必须重启 studio + 报窗口标题版本号** (老倪会主动质疑"你没重启")。
4. **每轮一个 patch 版本号 + tag** (v3.0.1…v3.0.9), 版本号七处同步 + `integrity_check.py` 绿。
