# 共享状态文件: 条目"消失"的取证 + 清理工具的安全设计

## When to Use
- 用户问 **"X 怎么没有了 / 昨天下了怎么看不到"** —— 而 X 的模型/服务/代码都在, 只是画面上/列表里不出现。
- 要写或改**清理、重置、清层、按类别删除**的工具/端点。
- 一个多写者共享的 JSON(规格/画布/注册表/缓存)被多个常驻进程与服务同时读写。
- 要判断"这个条目是不是我弄没的" —— 需要证据而不是感觉。

## 铁律一: "没有"有四种, 先分清是哪一种
按顺序查, **不要**一上来重下权重/重装/重启服务:
1. **实物在不在** —— 给路径 + 字节数 + 服务状态, 别用"应该没有"发誓。
   注意"看起来空"的权威来源可能只是**引用桩**: 缓存目录几十 KB 而真权重在数据盘的镜像目录(逐文件复制而不是快照下载) ⇒ 桩是正常的。
2. **条目被抑制** —— 这类文件常带**抑制清单**(`deleted[...]` / 黑名单), 条目被删过就不再出现, 且常被当"负项"传给下一轮生成 ⇒ **只恢复显示而不清抑制项, 它永远不再生成; 只清抑制项而不管错值, 恢复的是错值** ⇒ 两件事一起做。
3. **注册表在但无实体** —— "来源/类别"注册表里有这个名字, 但当前这一轮没有它的实例。注册表存在 ≠ 数据存在。
4. **文件被别的写者整体重写** —— 最常见也最容易被误判成"生成器坏了"。下一个铁律处理它。

## 铁律二: 清点写者 + 用备份链定罪 (不靠"感觉是谁写的")
1. **列写者**: `grep -rIl <文件名> <代码根> | sort`, 然后分两类——
   · **整体重写型**: 命中 `json.dump(..., open(path,'w'))` / 写 tmp 再 `os.replace` ⇒ 它能一次抹掉所有没被它显式保留的东西。
   · **按类别合并型**: 只拿掉自己那一类再加回自己的(`kept = [x for x in old if key(x) != MINE]`) ⇒ 安全。
   速筛: `grep -cE "json\.dump|open\([^)]*<file>[^)]*,\s*[\"']w" <每个文件>`。
2. **常驻者优先怀疑**: `ps -eo pid,etime,cmd | grep <脚本名>`; 进程刚起而文件 mtime 很新 ⇒ 它就是最后写者。cron 也要看一眼(`crontab -l`)。
3. **备份链定罪**: 这类文件通常被工具自己留了 `.bak*`/`bak_<原因>_<时刻>.json`/批次归档 ⇒ 把它们按 mtime 排成时间线,
   逐个统计**同一通道各类别的条目数** ⇒ 一眼看出"什么时候没的"。
   🔴 **先证自己清白**: 在怀疑自己/自己刚做的改动之前, 先把动手前的备份拿出来看 —— 目标本来就为空 ⇒ 不是这一步删的(本类事故里最常见的一次冤枉)。
4. **定罪靠代码 + 备份, 不靠"猜哪个脚本像凶手"**。两个看起来可疑的(名字带 clear/rebuild 的)常常都是安全的;
   真正的凶手往往是**设计上不算错**的那一个(白名单语义), 见下。

## 铁律三: 清理工具必须黑名单语义 (默认保留, 只删点名的)
```python
# ✗ 白名单: 任何没被枚举过的新类别静默消失, 且每次运行再杀一次
kept = [x for x in items if category(x) in KEEP]      # KEEP = ("meas",)

# ✓ 黑名单: 新上线的能力默认免疫
kept = [x for x in items if category(x) not in CLEAR]  # CLEAR = ("vlm","det","plan",...)
```
**为什么**: 白名单把"保留=必须被记得"当成了前提, 而新能力上线时没人会回来改那张名单 ——
于是新类别被删得干干净净, 而且**下一次清理还会再删一次**, 表现为"这东西怎么老是没了"。
- 工具的 docstring 里写明: 保护清单是什么、"新增类别默认免疫"这条语义。
- 删除前**归档 before 快照**(`cp` 到按时刻命名的目录), 并在回复里给出归档路径。
- 同一守则适用于一切"按类别保留"的删除: 配置清理、缓存回收、标注/数据集过滤、注册表裁剪。
- ⚠ 反向的"用户可见动作"也要直接落盘: 用户点"清除"时必须在**服务/工具侧立刻改文件**,
  不能把可见结果托给下游某一轮发布 —— 下游一死, 用户看到的就是"点了没用"。

## 铁律四: 这类工具必须能演练 + 真跑验证
- 给 **`--spec <副本>`**(或等价的路径开关) + **`--dry-run`**, 才能在**不动在役文件**的前提下验证语义。
- **验过 = 在副本上真跑一遍并断言**, 不是读一遍代码、也不是只过语法检查:
  造一个含**三类**条目的合成副本 —— 受保护类 · 点名要清的类 · **未登记的新类** —— 跑完断言:
  受保护类在 · 未登记新类**也**在 · 点名的被清。把断言结果写进回复。
- 改在役文件前 `cp` 备份, 改后**回读计数**。

## 自伤坑
| 坑 | 症状 | 修法 |
|---|---|---|
| 同一文件连打多个 patch, 两条锚点落在**同一行** | 第二次把第一次刚写进去的内容换成占位/空, 而语法检查仍然过 ⇒ 功能静默失效(该落盘的不落盘) | 同一行只打一次; 改完**回读该区间逐行确认**, 别用语法检查当验过 |
| 用"最新快照/几分钟前读到的值"推理现状 | 与用户/别的进程当前看到的对不上, 结论全错 | 下结论前重读真值文件; 用户可能正在同时改它 |
| 把"注册表里有名字"当成"数据在" | 断言"功能是通的"而实例数为 0 | 分别断言: 注册表命中数 **且** 实体数 |
| 在共享卡/共享服务忙时跑验证 | 失败被归因到被测对象 | 跑前后报出**整机资源占用**(显存/进程表), 说明是独占还是共用 |

## 回报口径 (用户问"为什么没有了"时)
三段, 先给物证再给结论:
1. **实物在不在**: 路径 + 大小 + 服务状态(带能自己核对的一行命令)。
2. **"没有"的到底是哪一层**: 模型/服务/注册表/图层, 指名。
3. **根因 + 改动 + 真跑验证**: 附上备份链那一条决定性证据; 若自己有关系, 先讲清哪一步是自己做的、用证据说明,**不要猜**。
