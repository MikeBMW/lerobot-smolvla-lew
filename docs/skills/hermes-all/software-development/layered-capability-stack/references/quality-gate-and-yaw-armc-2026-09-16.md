# 放权前的质量闸 + 上层通道的失败取证 (2026-09-16 下半场)

承接 `adaptive-gain-and-lie-intent-2026-09-16.md`。上篇把增益结构做出来了, 但 600 步 11 臂 A/B
结论是"抬增益无收益" ⇒ 前置条件是**先判上层在本场景是否真的比下层对**。本篇是那个前置条件的
实现 + 另外三步 (DiT 真消费 / 横向归因 / yaw 出口) 的实测。

## 一、质量闸 (放权判据): "上层提案是否优于下层" —— 可抄的构造

判据必须**只用真值样本 + 留一预测**, 不许偷看引擎内部计数 (内部计数只证"跑了", 不证"对"):

```
任务几何梯度   g = unit(孔口 − 末端)            # 减少接触势的物理"对"方向
上层提案方向   ξ̂_v = Φ_se3(Δz) 的平移部分, **LOSO 预测** (留一 seed, 不在拟合集上评估)
下层参考方向   ẋ_hand (真实执行速度 = 下层收口后的实际结果)
cos_L4 = cos(ξ̂_v, g)   cos_L2 = cos(ẋ_hand, g)
判定: cos_L4 > cos_L2 + margin(0.05) → 该阶段允许放权 (K>0); 否则 K 强制 0 只记录
```

- 逐阶段判 (别全局判): 全局 +0.182 看着过关, 但拆开是 下降 +0.607 / 抬起 +0.191 / 接近 +0.174 /
  对位 +0.070 / **转移 −0.191 (下层更对 → 否决)**。
- 落盘 `models/<name>_quality_gate.json`, 引擎按阶段读; 未过闸的阶段 K 硬置 0 并在 trace 里写原因。
- 在线取证要对得上: `quality_summary.allowed_frames == gain.applied` (120 步实测 62 == 62)。
- ⚠️ **判据自身的诚实边界 (必须一起说)**: 本版用"孔口"当**唯一**吸引子, 对**还没抓件**的阶段
  (接近/抬起/转移) 那个梯度根本不是任务正确的方向 ⇒ 这几行的 cos **绝对值不可当结论**,
  只有同帧相对比较 (L4 与 L2 用同一梯度) 有意义; 正解 = 逐阶段各自的吸引子 (接近→工件, 插入→孔)。
  写进文档, 别让下一个会话把 0.661/0.852 当成功力指标。

## 二、上层通道"接上了但不等于有用": 三个数字 + 一个失败

### ① DiT 真消费几何 token — 有条件通过
同 seed 同步数 2 臂 40 步 (CPU):

| 臂 | cond_dim | act_norm | delta 均 | trace_hash |
|---|---|---|---|---|
| 关 | 214 | 0.1766 | 0.3502 | bab44571… |
| 开 | **223** (=214+ξ6+ω3) | **0.1625** | 0.3553 | c2ccd9ba… |

⇒ token 真进了 DiT 输入且输出随之变化, 但**响应很小**: ‖ξ‖≈0.023 / ‖ω‖≈0.012, cond_norm 只从
1.76305 动到 1.76256 (小数第 4 位)。**教训: 往既有条件向量里 append 小尺度 token ≈ 被淹** ——
接完通道的下一步是**按各 token 的经验尺度归一**, 不是宣布接通。只证"消费+响应", 不证"更好"。

### ② 横向分量归因: 先纠正读数, 再排除两个假设
`per_dim_loso=[0.14, 0.226, 0.817, 0.438, 0.056, 0.511]` 对应 `[ω_x, ω_y, ω_z, v_x, v_y, v_z]`
⇒ 最弱是 **v_y 0.056**, 而 v_x = 0.438 (**别把第 5 位读成横向 x** —— 本次先犯了这个错, 汇报要纠正)。
逐维 LOO R² (352 对样本, 含 null 对照):

| 口径 | ω_z | v_x | v_y | v_z |
|---|---|---|---|---|
| Δz_pred (线性) | 0.817 | 0.438 | 0.056 | 0.511 |
| Δz_pred + 二次特征 | 0.842 | 0.428 | **−0.042** | 0.577 |
| Δz_goal (线性) | 0.606 | 0.513 | 0.125 | 0.588 |
| **pred ⊕ goal** | 0.820 | **0.569** | **0.202** | **0.703** |
| null (打乱 Y) | −0.085 | −0.143 | −0.073 | −0.121 |

判定链 (可复用): ① 真值幅度够不够 (σ: v_x 10.9mm/帧, v_y 4.0mm ⇒ 不是信息缺失);
② 是不是非线性 (二次特征不抬升、v_y 反而更差 ⇒ 线性可读, 排除); ③ 剩下是**口径 + 阶段混合**
(双路意图 pred⊕goal 抬 v_x/v_y/v_z; 逐阶段更高: 下降段 v_x 0.751 / v_z 0.802)。
⇒ 采信建议: 意图向量用 pred⊕goal, 且**逐阶段标定/逐阶段增益**。
⚠️ 逐阶段 n 小 (42~103) 时 32 维 PCA 会过拟合出**负 R²**, 那是假象, 别当结论。

### ③ yaw/姿态通道并进唯一出口 — 接线完成, **本轮失败证据** (不许写成通过)

前提先查清: **动作里没有旋转维** (u=dx,dy,dz,grip; 姿态走 `env._grip_yaw`), 全仓 `_grip_yaw`
只被演示链用 ⇒ "让 SU(2) 参与控制"的唯一真实出口 = 演示链 yaw 段, 不是引擎 u。

- 三臂 (seed 0, yaw 段): script 89.38° / 流形头 **−45.33°** (与几何需求差 135°) / SU(2) 臂 **90.00°**,
  K 均 **0.0** ⇒ 熟场景零增益闸生效, **逐位退回脚本参考** ✓ (这是设计行为, 不是失败)。
- 全链 A/B: 基线 **⑤ 插入成功 49.4mm/50mm**; 开 SU(2) 臂后 **夹持验证失败** (模块随动 Δz=0.7mm
  / 指令 12mm), 根本没走到插入。
- 根因 (可推广到任何物理仿真 A/B): **指令等价 ≠ 轨迹等价** —— 两臂 yaw 指令在 K=0 时几乎相同
  (90.00° vs 89.38°), 但**步数不同** (54 步 vs 脚本 100+ 步) ⇒ 治具/闭夹的物理时序被推移 ⇒ 抓取姿态失效。
  所以 A/B 的"同口径"不止是**同一个数**, 还包括**同样的步数/时序/相位**; 要 A/B 一个控制律,
  先把它对齐成**同步数 + 同停止条件**。
- 另一个几何教训: **② 段夹爪是空的, twist 由转台决定, 夹爪转不动它** ⇒ 那里几何残差**不是可控目标**
  (这才是 K 归 0 的原因); SU(2) 残差真正可控的段是**夹持之后** (插入前对准), 已在那里接闭环
  (残差 <0.5° 才放行, 不收敛由既有姿态预检拦截) —— 但本轮上游已失败, **未跑到 = 未验证**。
  **通用规则: 用几何残差做闭环前, 先确认这个残差随你的执行量变化 (可控性检查)**。
