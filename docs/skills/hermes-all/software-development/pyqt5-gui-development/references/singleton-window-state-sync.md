# 单例窗口 + 外部状态开关: 必须同步, 只 raise_() 就是状态漂移 (2026-09-17 实测)

**类级规则 (先看这条)**: 一个"单例复用窗口" (`Cls._cur`) 被"从菜单/双击打开的入口"驱动时,
**入口参数必须在打开时现读应用状态, 且复用分支必须比对状态并同步** —— 两处少一处, 用户改了状态
却看到旧状态画面, 而且看起来像"功能坏了"(窗口照常显示, 不报错)。

## 实例 (老倪: 「我调到仿真模式了, 右键打开输入图像还是显示现场的视频, 应该是仿真的视频啊」)

两个根因, 都常见, 排查时一起看:
1. **入口写死**: `open_input_viewer(self, module=..., source="real")` —— 从不读画布当前数据源状态。
2. **复用不比对**: `win = getattr(Cls, "_cur", None)` 命中后只 `show()/raise_()/activateWindow()` 就 return
   ⇒ 上次开的是"真机源"窗口, 这次状态已是"仿真"仍显示旧源画面。

## 修法三处 (缺一不可)

- **(a) 入口现读状态**: 收敛成一个读取函数 (`_canvas_src_state(module)`), 菜单项标签写明会开哪一路
  (「打开输入图像 (🧪 仿真 metaworld) / (🎥 真机 RealSense)」) —— 用户一眼可见, 不用猜。
- **(b) 复用窗口时对齐状态**: `win.cb.setCurrentIndex(want)` **触发控件既有 change 逻辑**
  (停旧源 → 起新源 → 依赖它的数据根/类别表一起切), 别在复用分支另写一套切换代码。
- **(c) 状态开关变更时推送**: 开关 handler 末尾同步"已开着的窗口", 免得用户忘记手动切。

## 通病化 (比本次修复更重要)

- **"单例窗口 + 外部有状态开关"** 组合必须 (b)+(c)。同族坑: 3D 视图复用窗口不换轨迹源、
  pyqtgraph GL 窗口复用不重建 scene、GL 句柄跨上下文失效 —— 复用分支一律"比对状态 → 需要就同步"。
- **从菜单/双击/快捷键打开的功能, 参数必须打开时现读, 不许在调用点写死**
  (同族: 画布档位 L2/L3/L4、数据源、图像尺寸/归一化口径)。写死 = 用户改了状态你看不到, 会被当场抓出。
- 状态源要**唯一**: 一个权威字段 (+ 只读副本), 别让多处各自推。

## 验证 (两层, 都要)

1. **状态读取 + 复用对齐** = 真函数体 + **假窗口对象** (`FakeWin/FakeCb`, 记录 `setCurrentIndex` 调用次数):
   覆盖"旧源≠新状态 → 必须切"两种方向 + "两边一致 → 不许乱切"。
   ⚠️ 桩绑定 `@staticmethod` 必须包 `staticmethod(...)`, 否则被当实例方法绑 self → TypeError 被
   `except Exception: pass` 吞掉 → **"不许动"的 case 全部假 PASS** (详见 `multiscreen-window-clamp.md`)。
2. **替代数据源是否真出帧单独测** —— 别只测"窗口不报错"。本机做法: 直接起真 `_SimGrabber(q, False)`,
   40s 内收 ≥3 帧, 断言 `shape=(480,480,3)` / `src=sim:metaworld corner2` / `device=mujoco 渲染(非真机相机)`
   (同族教训: 引擎"影子臂 calls>0 实为空转" —— 计数/无报错都不能当"真接入"证据)。
