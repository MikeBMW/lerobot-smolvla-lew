# 看不了图时怎么"读"图 (无眼判读 / 目检代理)

场景: 任务对象是图像(截取/几何/对准/缺陷), 但你没有视觉能力, 而**用户是靠眼睛验收的**。
此时唯一靠得住的做法: 把图变成**数字与字符**去读, 再用"给眼睛看的证据"让用户拍板。

## 一、两个基本工具

### 1. ASCII 降采样图 —— 一眼看清"东西在哪"
```python
s = cv2.resize(gray.astype(np.float32), (cols, rows), interpolation=cv2.INTER_AREA)
RAMP = " .:-=+*#%@"
# 每行左边印真实 y 坐标, 顶部印 x 坐标刻度 → 图上任何结构都能回溯到像素坐标
```
- 亮度图看整体布局(物体/背景/高光), **二值掩膜图**看目标结构(把阈值以上的像素画出来)
- 分辨率按需: 判"上下有几段结构"用 100x40; 判"焊盘是不是离散"要把窗口放大到 ~110 列/视场

### 2. 逐行 / 逐列剖面 —— 定量定边界
对全宽做逐行统计(每行: 覆盖率%、亮度均值、p95、|gx| 均值), 逐行打印。这是**定上下边界**的根据,
比任何"最大轮廓/minAreaRect"稳: 核大小一变, minAreaRect 的尺寸就跳(实测 (61,5)→1559x164 vs (41,5)→1455x98)。

## 二、把"一片糊在一起的目标"拆成结构

当掩膜把多个特征连成一坨时, 用**行密度分 run** 拆:
1. 取主列段(最大连通域的 x 范围, **不要横向搭桥**, 否则把邻区连进来)
2. 行密度 `d(y)`; 阈值 `max(25, 0.05*dmax)`; 相邻 dense 行空隙 ≤ `gap` 行合并成一个 run
3. 对每个 run 算三个判别量: **高度**、**金/目标覆盖率**(run 内均值)、**横向边缘密度 |gx|**
4. 用"边缘密度"区分**离散结构**(焊盘排 |gx| 大) 与 **实心结构**(镀金面 |gx| 小)

实测(产线金手指相机, 同一张参考图):
| 区域 | 行范围 | 高 | 覆盖率 | \|gx\| | 结论 |
|---|---|---|---|---|---|
| 焊盘排 | y[1097,1162] | 66 | 29.8% | 28.6 | **金手指本身**(离散) |
| 缝 | y[1163,1179] | 17 | — | — | 空的 |
| 实心金带 | y[1180,1265] | 86 | 64.3% | 8.3 | 镀金边, **不是**金手指 |
| 塑料本体亮边沿 | y ≥1258 | — | 0%(非金) | 高 | 亮度冲到 255, 必须切掉 |

选"哪一段是用户说的目标"不要靠猜: 用 |gx| + 高度做候选, **取最上面那个合格 run**(固定相机的物体总是同序出现),
同时把两个候选版都出图让用户挑。

## 三、跨帧一致性 = 真值检验

同一台固定相机连拍 N 张, 目标的行/列范围必须**稳定**(实测 5 张: 1454~1462 x 70~72, 倾角 0.8~1.0°)。
某一张抖 90px 就是测量方法不稳: 例: 焊盘两端在某几帧金像素稀疏, 用 run 自己的列剖面会抖 ±90px,
**改用最大连通域的 x 范围**就稳了。别把"抖"当成物体在动。

## 四、度量口径的坑(踩过)

- **斜率类指标必须在"未拉伸"的画布里算**: 画布纵向拉伸 13 倍喂 YOLO 时, 同一个残余倾角在拉伸图上
  被放大 13 倍(0.1° → 2 px/1000 → 判据误报)。输出拉伸版 + 另存原比例版, 指标只算原比例版。
- **"顶边"比"质心线"脆**: 顶边残差 ~11px(焊盘本身有台阶); 每列取目标像素质心行再拟合, 残差 ~5px、斜率亚像素。
- **只在目标核心行上拟合**: 用整块 ROI 算斜率会被相邻结构带偏(实测 −5~+2 px/1000); 限"行密度 ≥95% 峰值 ±3 行"
  后三套掩膜口径一致 ≈0。
- **颜色掩膜不可靠时别当主定位手段**: 宽 HSV 阈值把无关黄色区域也选进来(目标只占 1/2), 严格阈值只剩 10 px。
- **平坦模板会给出假高分**: NCC 处处 ≈0.99, 出现"score 0.988 但裁剪里一个目标像素都没有"的假成功
  → 终判据必须是**裁剪内的实质指标**(覆盖率/质心线有效性), 不能只看 score。
- **`cv2.getAffineTransform`/`getPerspectiveTransform` 的方向**: 配 `warpAffine/warpPerspective` 不带
  `WARP_INVERSE_MAP` 时, 矩阵必须是 **src→dst**(传反了 = 双重反变换 → 裁出空图/黑图)。

## 五、给用户(眼睛)的证据包 —— 这是验收方式, 不是可选项

用户的验收动作是**看一眼图**, 所以要交付**带标注的拼图**, 而不是一串数字:
1. 原图 + 识别框(醒目色描出认定的区域, 角点画点)
2. 规范化输出(真正喂下游模型的那张)
3. 原比例输出(不拉伸, 便于判断边界对不对)
每张上方用 **文字标签**写清"这是什么"和关键数值(score/角度/尺寸); 拼成一张竖直三联图传到用户能打开的共享目录,
然后明确请他确认。**一次只改一个变量, 一次给 1~3 张同格式图**; 不要用文字列一堆方案让用户挑
(用户明确说过"别选那么多")。
用户会一眼指出"上面少一截 / 下面多一条厚边沿 / 纵向太短"这种**他看得见你看不见**的问题 —— 收到这种反馈后,
回到底层**逐行量数据**定位是哪一段结构, 再改; 不要凭猜测改参数。
