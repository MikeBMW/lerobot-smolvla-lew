# 接管式集成的诚实取证: 零采纳 / done 标志 / 几何量复核 (2026-09-12 实测)

本文件补充 SKILL.md「假接入的常见形态」第 8/9 条 (本轮 SKILL.md 正文写入被 read-before-write 守卫拦截,
先落这里; 下次补进正文)。适用: **模型 + 原控制器兜底** 的接管式集成 (任何"不回退"要求的接入)。

## 形态 8: 守卫式接管里模型零采纳 = 成功率漂亮但模型是摆设

实测: 一致性守卫配置得出 **成功率 10/10 = 100%**, 但明细是
```
actor 采纳 0 次 · 引擎兜底 3705 次
```
⇒ 模型一次都没真正出动作, 等于**把原控制器重跑一遍**。这类"漂亮成功率"若不做采纳率取证,
会直接变成假交付。

**判据 (写进报告模板)**
- 必须给 **`actor 采纳次数 : 引擎兜底次数`**, 最好再给**按 seed 的采纳率** (能看出个别 seed 是否滑向全模型)。
- **采纳 0 次或 <5% ⇒ 一律写"未接管"** (允许写"接口已通但模型未参与"), 不许只报成功率。
- 反向也要防: 采纳率 **>50% 时成功率会崩** (实测 TOL=0.3 → 86% 采纳 / 0% 成功; TOL=0.6 → 100% 采纳 / 0% 成功)。
  所以合格区间是**两端都报**: 成功率 + 采纳率 + 用的 TOL。
- **硬 CAP 限流会造成同类假象**: 实测按累计采纳率压到 35% 上限后, 采纳率塌到 **7%** 且成功率回到 100%
  —— 看着"两全", 其实是限流把模型压成摆设。限流参数也要一起报。

## 形态 9: `done=True` / 完成阶段 ≠ 物理上真做到

实测: 引擎完成判据 `insert_depth`(件头到终点距离) 阈值 **6mm** 过松, 于是
```
done=True · 插入了 · 用时 106s   ← 日志/面板口径
但残余 4.5~5.0 mm, 用户目检视频: "光模块没有插进去"   ← 物理真相
```
收紧阈值到 **2mm** 后才视觉真插入, 代价是成功率 **~100% → 73%** —— **收紧后的数字才是真数字**,
交付时应当报后者。

**复核铁律: 用引擎/物理自己的量, 不许用日志里的列**
- 正确: `peg_head()` 到 `_goal_p()` 的范数 (引擎判据同口径)。
- 反例(实测): 脚本里取了 `tr["peg"]` —— 它存的是 `obs[4:7] = **速度**`
  (布局 `cur = [x3, grip1, v3, _pc3, goal_p3, …]`, 位置在 `[7:10]`),
  于是算出"离孔 **135 mm**"的假结论, 差点当成"引擎判据有 bug"上报。
  ⇒ 拿日志列做几何判断前, **先回源码确认那一列存的是什么**; 一轮内同一个索引坑踩了两次, 记牢。
- 老倪式验收本就要求"交付前用几何量自检真插入 (done 标志不可信)" —— 这条是其实测版本。

## 附: 接管式集成的合格汇报骨架

```
① 架构: 原控制器 = 安全基线 (其自带域外兜底必须保留, 不要整体替换控制器对象)
② 成功率: X/N (写明进程数 / seed 数 / 是否跨进程重复)
③ 模型参与: actor 采纳 a 次 : 引擎兜底 g 次 (a/(a+g) = z%), 按 seed 分解
④ 关键参数: TOL / CAP / 阈值 (如 insert_depth) 的实际取值
⑤ 物理自检: 用引擎几何量复核 (如残余深度 mm), 不用 done 标志
⑥ 证据: 视频帧数 + 来源 (哪条管线截的), 并写清"视频是代表性片段, 成功率以 json 为准"
```
