# 退化型假接入: 计数在涨, 执行却没变 (2026-09-15 实测)

孤岛是"没接上"; 这一类更隐蔽 —— **接上了但等价于没接**, 甚至"接上后把环境改坏"。
审计时若只查"注册/连线/ran 计数", 这两种形态都会漏掉。

## 形态 ① 组件在调用中改写了正在运行的场景

- 症状: 同 seed 两臂 `act` 逐位相同、step 前 `qpos` 逐位相同, **step 后状态不同**;
  某臂场景在第 1 帧就"瞬移" (实测 peg Δ=[+1.2mm, −17mm, 0]); 同 seed 多次运行结果漂移/翻转。
- 根因: 组件内部**又新建了一个 env/引擎实例**去采样几何/状态, 而底层仿真器的 model/data 是
  **进程内共享**的 → 正在跑的回路被改写。
- **判定手法 (可复用两段)**:
  1. **帧 0 同一性测试**: 包住 `env.step`, 两臂各存逐帧 `act / qpos_pre / qpos_post / site_xpos`。
     第 0 帧全同 + 第 1 帧分叉 ⇒ 是**外部改写**, 不是控制律/协议差异。
     (实测数据: 第 0 帧逐位相同; 第 1 帧 peg qpos 0.53944 → 0.52237 而对照臂不动)
  2. **调用隔离探针**: 同一 reset 后**逐个调用**嫌疑函数, 每步比较 `env.data.qpos` 是否变化:
     ```python
     sim._reset(seed); q0 = env.data.qpos.copy()
     for tag, fn in (("render", sim._render_frame),
                     ("skill_ctx", lambda: sim._l4_skill_ctx("接近")),
                     ("l2_proc", sim._l4_l2_proc),
                     ("model_step", lambda: node.step(fr, skill_ctx=sk))):
         fn(); print(tag, "Δqpos =", np.abs(env.data.qpos - q0).max())
     ```
     一次即可定位到具体函数 (本例 `skill_ctx → 势场构建 → from_engine → 新建引擎 + reset`)。
- 修法: 传**现成**的几何/状态进去, 不新建第二个实例 (只读不写)。修后应满足"逐帧复现对照臂"。
- 影响面: 该批所有 A/B 结论作废 (两臂跑的不是同一个场景) —— **必须回滚结论并重测**。

## 形态 ② 提案 100% 被执行端否决 (ran/applied 在涨, 执行却由下层主导)

- 症状: 计数漂亮 (`ran=74` 帧推理 / `applied=592` 帧融合), 执行端有收口闸, 实测**否决率 38~98%**
  ⇒ u 实际来自下层解析链。"任务完成了"是**下层的功劳**, 不能记在上层接入头上。
- 判定: 逐帧记录 `提案 vs 下层参考` 的 **方向 cos** 与 **幅度比**, 加否决计数;
  再用 **逐帧 stage 直方图 + 末端真位移** 验证是否真推进 —— 计数完全不能证明推进。
- 合格证据形态 (两种, 都实测过):
  - **"有闸 ≡ 解析链"逐帧一致** (本例 7/8 seed 阶段序列逐帧相同) = 接入等价且不越权 ✓
  - **"闸关 8/8 卡死"** = 闸是**必需项**而非优化项 ✓
  - 反例: "解禁阶段白名单能提升" → 实测 `stage_counts` 显示**从未到过该阶段**, 加白名单是**空操作**。

## 汇报口径 (声称接入生效时逐条给)

① 推进证据 (stage 直方图 / 末端真位移) ② 与对照的逐帧差异或一致性 ③ 零回退证明 (成功样本逐位不变)
④ 若有闸: 否决率 + 明确写出"此刻谁在主导执行"。只报 `ran/applied` = 不合格。
