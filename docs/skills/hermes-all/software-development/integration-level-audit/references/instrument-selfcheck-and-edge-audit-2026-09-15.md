# 证据仪器自检 + 画布逐边审计 (2026-09-15 续录)

接 `references/evidence-tool-integrity-2026-09-15.md` (铁律 1-3: 行号/名称运行时定位、探针不许吞日志、
必须有正对照且门控参数可控)。本篇是同一轮里**又踩到**的三条, 以及"每条边是否真有数据"的审计范式。

## 铁律 4: 逐位比对 (bit-compare) 前必须先证"仪器本身确定"

- 场景: 要证明"新代码不改 L2/L3" → 同 seed 每臂独立进程跑两遍比对 trace hash。
- 实测结果: **L2 档逐位相同 (真通过)**; **L3 档同配置两臂 hash 也不同** —— 625M 模型 CPU bf16
  路径有 FP 级归约顺序非确定, 且策略推理本身含随机噪声采样。
  · 播种 (`np.random.seed` + `torch.manual_seed`) 后**仍会不同** (复现 3 次, 其中一次相同纯属巧合);
  · 单线程化 (`torch.set_num_threads(1)` + `OMP_NUM_THREADS=1`) 没救回来, 反而慢到超时。
- 判据 (必做): **先跑"同配置两臂"当对照**。
  ```bash
  # 两臂参数完全相同 (都不设新开关) → hash 应相同; 不同 ⇒ 仪器不确定, 禁用 hash 判据
  ```
- 仪器不确定时的**结构性判据** (本次采用并写进报告):
  1. 新代码在两臂的进入计数都为 0 (`L4calls=0 / fiber.frames=0`) ⇒ 该档根本没走新路径;
  2. 唯一执行出口未动 (`sched.decide` + `safety.saturate` 调用点仍是那一处);
  3. 确定性档 (L2) 逐位相同。
- 报告口径: 写"L3 用结构性判据, hash 仅参考", **不要**拿不确定的 hash 硬凑一个 ✅。
  仪器自身的缺陷也要如实写进交付 (老倪认这个, 比一个假的绿灯值钱)。

## 铁律 5: 采数/标定不能依赖"已就绪" (否则死锁)

- 症状: 把"采标定样本"写在"标定过闸之后" ⇒ 没标定 → 不采数 → 永远标不出来 → 通道永远不注入。
- 修法: 未过闸也**照跑照采** (记录 `z/真值` 对), 只把**注入权重设 0** (诚实拒绝 + 计数 + 来源标注)。
- 本次落地顺序: 先加"未过闸只采数"分支 → 8 seed × 900 步采到 582 条真实样本 → 标定过闸 (R²_loso 0.471)
  → 再开注入。**采数与注入解耦**是这类通道能闭环的关键。

## 铁律 6: 导出侧新增字段, 必须核对消费侧的白名单/拷贝

- 症状: 子进程 worker 已经把新键 (`z_pred`) 写进输出 npz, 但桥 (`runtime/model_adapter.py`) 读回时是
  `{k: v for k in ("z_t","z_goal","delta")}` 白名单 ⇒ 新字段在**桥这一层被丢掉**, 下游永远收到 None。
  表面现象是"导出有了却不生效", 极易误判成"模型没这个能力"。
- 修法 (通用): 改导出**先看消费侧** —— `grep -n "for k in (\\|np.load(\\|\\.get(" <bridge>` 找白名单/拷贝/字段筛选,
  把它一起改; 并在诊断里回显 `latent_keys` / `*_keys` 让"收到哪些键"可核对。

## 画布逐边数据流审计 (回答"每条线都要有实际数据")

范式: **边 → 运行时计数/逐帧列** 的映射表, 每条边给一个判决桶, 不认"画布上有一条线"。

```
┌ 每条边: 从 flows/*.json 取 (id, f, t, label)
│ 判决桶: ✅ 有数据   (计数>0 且逐帧列非零)   ← 唯一算"有数据"的桶
│         ⚠️ 通道在跑未接管 (真前向但 w=0 / 未过闸)
│         ❌ 死线      (找不到任何运行时消费者 → 直说)
│         ❓ 未登记    (审计表没写 → 视为未审计, 不许算通过)
└ 计数来源优先级: 引擎侧 stats dict > 逐帧 trace 列 > 节点/桥计数 > (不要用返回值形状当证据)
```

实操要点 (本次 19 条 L4 边 → 13 有数据 / 6 死线 的全部经验):
1. **先框定"行"**: 用节点 y 坐标把同一行的节点挑出来 (L4 行 5 个节点 → 19 条相关边),
   不要用"名字含 L4"瞎捞 (会把 L2 的边全带进来, 噪声淹没结论)。
2. **逐帧列必须看 `n_nonzero`**, 不看 `n`: 很多列"有值"但恒 0 (例: 自由空间里 `mani_eta`/`mani_risk`
   恒 0 是**物理事实**不是缺陷) —— 报告里要把"物理为零"和"没接上"分开写。
3. **运行模式要标注**: 引擎档 (`SS_L4_INTACT`) 与直驱档 (`install_direct_act`) 覆盖的边不同;
   某条边在本轮模式里没被覆盖, 要写"需 X 模式跑", 不能写"死线"。
4. **死线要配下一步**: 每条死线给"为什么 + 怎么补" (例: VLM 960 口径未接 → 需按 960 口径重训预测器),
   否则审计表只是坏消息清单。
5. 工具落点: `tools/audit_l4_edges.py` (映射表 + 判决桶 + 打印合计), 数据源 = 探针产出的审计 json。
