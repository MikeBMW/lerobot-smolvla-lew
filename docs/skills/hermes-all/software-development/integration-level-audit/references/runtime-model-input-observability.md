# 输入级取证: 「模型/节点实际吃的是哪份数据」

适用: 一个组件确实被链路每帧调用了(L2/L3 已过), 但还要回答**它吃的是哪张图/哪份数据, 返回什么** ——
或者自己要在交付里声明"模型输入没变"。现场问法通常是「代码哪里调用模型, 我看看实际输入给模型的图片, 和返回值」。

## 1. 回答形状 (给全四样, 别只描述)

1. **代码位置**: 绝对路径 + **行号** —— 实例化那一行、真正 `detect()/forward()` 那一行、返回值落台账那一行。
   调用点通常在后**后台 worker 线程**, 不在 HTTP 路由里, 要说清(否则"接口秒回 200"会被当成"检测完了")。
2. **能点开的图 URL**: 不是本地路径。经用户能访问的那台机器转发一个口(手机/浏览器直接开)。
3. **返回值原样**: 抄真实一帧的 JSON, 不加工, 后面逐字段一行解释(count/defects/verdict/ms/对照口径)。
4. **同源硬证据**: 取回图的**像素 md5** 与台账里记的 md5 一致 —— 不说"看起来像"。

## 2. 可观测口怎么造

- 在"数据真的会被喂进模型"的那条路径上, 把**同一份像素/张量**留在内存, 配一份 meta:
  `n`(来源帧号) / `hw`或`shape` / `md5`(原始字节: `md5(np.ascontiguousarray(img).tobytes())`) / `src`(怎么派生的) / `fed_to`(喂给谁)。
- 出图口用**无损编码**(PNG), 响应头带上 md5/hw/n ⇒ 肉眼对账 + 脚本断言都能做; 解码后的像素与喂进去的逐位相同。
- 台账(结果接口)里同时给: 模型吃的路径 + 一句话 `*_kind` 说明 + `*_md5` + **给人看的那张** + 对照口径结果。
- 宿主侧加一个转发路由, 让用户点得到。

## 3. 同源闸 (可重跑)

`scripts/verify_model_input_same_source.py`: 拉取图口的图 → 算像素 md5 → 要求等于台账 md5。
- ⚠️ **先用只读调用确认两边的 n 是同一个计数器**, 再拿它当 join key。实测踩过: 台账的 `n` 是"检测序号"(每次检测+1),
  而帧号是"拍照序号"(每次抓帧+1) ⇒ 拿它们对齐永远对不上(14 次尝试全废), 白白浪费一轮。
- 在线系统一直在动 ⇒ **按帧号对齐才下结论**; 对不齐就如实写"未能对齐, 不作结论", 不硬凑一帧。

## 4. 临时产物生命周期 (会直接变成现场事故)

- **只在会入队干活的那条路径上写临时文件**。把写操作放进"抓帧"函数 ⇒ 连用户只是"看一眼"的请求也会写,
  实测 9 分钟泄漏 2180 张(而只看一眼那条根本不需要临时文件)。
- 清理残留时 **必须跳过仍在待处理队列里的那些文件** —— 清掉它们等于让模型去读一个不存在的路径。
- 待处理队列**设上限**, 积压时丢最旧的(顺手删它的临时文件) —— 否则用户手动触发的那次会排在几十个自动请求后面, 表现就是"点了没结果"。
- 喂模型之前**先判路径/张量存在**, 不存在就跳过并打印, 别把已清掉的路径硬喂进去。
- 干完立即删; 磁盘上只留给人看的产物。

## 5. 两个接口里的同一个字段

- 同一事实出现在两个接口 ⇒ 在**唯一收口点**写, 别在两处各算一次; 廉价/旁路分支**沿用上次真值**, 不得覆盖成空。
- 一致性块**别用 `except: pass`**: 吞掉异常后现象只是"字段空的", 会把排查带偏。
- 改了"模型吃什么"之后, 把旧字段**全部**同步。实测踩过: 主口径已改回 960 方图, 而另一个接口里还写着旧的那张图 ⇒
  两个接口自己打架, 用户一眼就看出来了。

## 6. 改这类组件前必做

1. 先跑**离线桩测试**(桩传感器喂真实原始数据 + 桩模型**记录它被喂了哪个文件**) —— 桩能硬证"模型输入没变", 比肉眼看图硬;
   实测也靠它抓到过"新加的打印用了未定义变量"这种一部署就每次请求 500 的低级错。
2. 桩环境与真环境有差异时, 断言要写成"用真相源量出来的值", 否则桩自测的指标会与现场不一致。
3. 升级走现有部署器(带备份/回滚/验收), 验收判据只看被改的那一路。
