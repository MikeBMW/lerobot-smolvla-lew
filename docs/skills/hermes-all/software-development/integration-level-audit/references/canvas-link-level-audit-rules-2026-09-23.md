## 四条铁律 (逐条都踩过, 少一条就会得出相反结论)

1. **JSON 里的 x/y 只是输入, 不是位置。** 加载时画布自己重排: 普通节点被强制 ≥280×110;
   `_relayout_row_gaps(min_gap=56)` 按 `round(y/60)` 分桶, 把桶内后一个节点推到“前一个右缘+56”。
   ⇒ 断言/取证必须用**真画布几何** (QT offscreen → `load_flow_file` → `_relayout_row_gaps`)。
   实测: 同一节点 JSON x=2456 → 真位置 x=2798。
2. **加载会重映射 node id (`id_map`)** → 一律按**节点名**匹配。按 JSON id 查会全部 miss,
   得出“节点不存在”的假结论 (实测第一次跑就这样白跑一轮)。
3. **行带 (row_bg) 矩形是整行宽** (x≈-126, w 6000~11500) → “节点落在哪一层”**只由 y 判定**。
   这正是“它怎么在这层”的直接来源, 也解释了为什么“层带归属”与“能力档归属”会打架。
4. **端口 label 是被删边的铁证 (不必读代码猜)。** 消费者端口仍写着来源名、而来源节点出边 0 条
   ⇒ 这条边是**被删的**, 不是设计没接。实例: `🧭动作调制器 in8 = "contact+残差 (状态校正器)"`,
   而 `状态校正器` 出边 0 条。逐版本查出边数即可精确定位删除 commit。

## 断头/孤立/悬空 三分类 (先分类, 再判 bug)

| 类 | 判据 | 处置 |
|---|---|---|
| 断头 | 入>0 且 出=0 | 真 bug 或**合法终端** (3D视图/波形/直方图/操作视频/Test 用例/Feature 清单/任务指令·MES) |
| 孤立 | 入=0 且 出=0 | 必是 bug (画布铁律: 不许孤立) |
| 悬空 | 出>0 且 入=0 | **合法源头** (数据源/真机信号/工程记忆) vs **消费型节点缺入边** (如技能库——其 desc 写“由 L3 序列调用”却没有 L3→库 的线) |

汇报时**分清单独列**: 数字要连同“哪些是合法终端”一起给, 否则老倪会以为 13 条断头全是坏的。

## 头号根因: “剔除右→左连线”的自动 purge

`tools/gui/post_layout_fix.py` 为实现要求③「画布不能出现右侧输出连左侧输入」, 会删除**所有
`f.x >= t.x` 的边**并把它们 dump 到 `docs/design/feedback-edges-v510.json`。
- 节点一旦被重排到消费者右侧 (或坐标系重新生成), 原本正向的语义关键边突然“变反向” → 被删 → 断头。
- ⚠️ **原脚本顺序是「先 RESTORE 后 purge」** ⇒ 删掉之后**重跑也补不回来**;
  更糟: 每轮重跑都会用当轮结果**覆盖 feedback dump** → 历史语义记录彻底丢失。
- **修法 (已验证 durable)**: 把 RESTORE 移到 purge **之后**, 关键边写进 RESTORE 表并带 `t_port`;
  复跑时会打印 `↩ 复跑保边: <f> → <t>` —— 这条打印就是“不会再掉”的证据。

## 别把“零反向线”当 KPI

纯反馈/回流边**必然**右→左, 且是设计允许的 (实例: `物理世界→状态校正器 ↩观测反馈`、
`引擎→渲染源 ↩渲染回流`)。老倪的真实口径是“**尽量不要**右→左”, 不是“必须为零”。
强行清零只会砍出断头 (把能力删掉换来的干净)。

## 改完必复跑体检, 代价照实报, 取舍交老倪

移节点 / 补边前后**必须**复跑审计并逐项对比: 节点数 · 连线数 · 断头 · 孤立 · 悬空 · 反向线数。
实测 (state_space_obs.json): 恢复「状态校正器→动作调制器(in8)」→ 断头 14→13、该节点 判定=连通(入3出1),
但反向线 18→19 (2510px, 因为校正器仍在调制器右侧)。若改为把校正器左移: 断头同样修好, 却会把
「物理世界→状态校正器」(原本前向) 变成 2908px 反向线 —— **反向线总数不变, 代价只是换个位置**。
⇒ 这是**架构取舍**, 明确说“需要你定”, 不要自己默默选; 也别把任一方案说成“零代价”。
