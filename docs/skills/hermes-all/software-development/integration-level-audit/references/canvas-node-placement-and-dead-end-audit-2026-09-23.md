# 画布节点"放错层/断头/悬空"取证 (2026-09-23 老倪三问)

老倪问法 = 「X 节点为什么在 Y 层?」「Z 节点为什么没有输出连线?」——他要的是**根因 + 证据**,
不是"我看看"。以下四类判据全部可查, 照抄即可复现。

## 0. 取证工具与铁律 (先看这条, 省一轮)

```bash
# 真画布几何审计 (QT offscreen + load_flow_file + _relayout_row_gaps 复现用户视角)
QT_QPA_PLATFORM=offscreen gui-venv311/bin/python tools/canvas_node_audit.py \
    flows/state_space_obs.json <节点名子串...>
# → 行带清单(真几何) / 关注节点真位置+所属带 / 入出边数 / 反向线清单 /
#   断头·孤立·悬空全画布清单 / 端口 slot
```
- **画布加载会重映射 node id (id_map)** → 关注节点必须按**节点名子串**匹配。按 id 查会全部
  miss (实测第一次跑: 按 id 传 ssllm/n_l2_muscle/ssinnov → 输出"不存在", 白跑一轮)。
- **row_bg 行带矩形是整行宽** (x=-126, w=6000~11500) → "节点落在哪条带" **只看 y 区间**, x 不参与。
  所以 y 落进哪条带, 视觉上就是那一层的节点 —— 这正是老倪"它怎么在这层"的来源。
- JSON 里的 x/y 只是输入: 普通节点被强制 ≥280×110, `_relayout_row_gaps(min_gap=56)` 按
  round(y/60) 分桶把桶内后一个推到"前一个右缘+56" → **必须按真画布几何判定, 别读 JSON 推算**
  (实测 ssinnov JSON x=2456 → 真位置 x=2798)。

## 1. 断头 / 孤立 / 悬空 —— 三分类, 先分类再判 bug

| 类 | 判据 | 备注 |
|---|---|---|
| 断头 | 有入无出 | 可能是 bug, 也可能是**合法终端** |
| 孤立 | 无入无出 | 必是 bug (画布铁律: 不许孤立) |
| 悬空 | 有出无入 | 源头/库类节点合法; 消费型节点 = 缺入边 |

**合法终端** (别当 bug 报): 3D 视图/波形/直方图/操作视频/Test 用例执行/Feature 功能清单/
任务指令·MES/数据源。**合法源头**: 📦metaworld 数据源 / 🖥Z700 真机信号 / 📚工程记忆 /
💪L2 肌肉记忆技能库 / SK02-08 段落。
实测口径 (state_space_obs.json): 节点 83 · 连线 JSON 132 / 画布渲染 128 (画布按名去重了 4 对
重复边) · 断头 13 (多数是上述终端) · 孤立 0 · 悬空 11。

## 2. 断头根因模式 (本仓实锤, 高频复现)

`tools/gui/post_layout_fix.py` 为实现老倪要求"画布不能出现右侧输出连左侧输入", 把
**所有 `f.x >= t.x` 的边**从画布剔除, 并 dump 到 `docs/design/feedback-edges-v510.json`。
→ 节点一旦被重排到消费者**右侧**, 它的出边就会被静默删掉 → 断头。

**铁证法 (不必读代码猜)**: 看消费者节点的输入端口 **label**。端口语义还在等这条线 = 边是被删的,
不是设计没接。实测: 🧭动作调制器 `in8` label = 「contact+残差 (状态校正器)」, 而状态校正器出边 0 条。

**精确定位删除commit**: 逐版本查该节点的出边数
```bash
for c in $(git log --format=%h -30 -- flows/state_space_obs.json); do
  git show $c:flows/state_space_obs.json | python3 -c "
import json,sys; d=json.load(sys.stdin)
print([l['t'] for l in d['links'] if l['f']=='ssinnov'])"; done
```
实测: 出边在 adc464b7 (09-19 v5.10) 前一直是 `['sssched']`, 从 13632919 (09-19 「剔除22条右→左连线」)
起变 0 → 根因锁定。

**⚠️ 最深的坑**: 原脚本顺序是「先 RESTORE 后 purge」→ 被剔除的关键边**重跑也补不回来**
(且下一次重跑会把 feedback dump 覆盖成当轮结果, 历史语义记录彻底丢失)。
**修法: RESTORE 移到 purge 之后**; 改好后复跑会打印 `↩ 复跑保边: <f> → <t>`, 即可证 durable。

## 3. 归层冲突 —— 权威归属看登记表, 不看行带名

画布有**两套分组体系**, 会打架:
- 行带名 (视觉分组, 语义如「大模型层 · 任务/编排/记忆中枢 (回路外慢决策)」) —— 由
  `gen_ss_obs_layout2.py` 的行定义 + `post_layout_fix.py` 的 `PIN` 坐标钉死。
- 能力档位 (权威归属) = `src/lerobot/verification/capability_levels.py::CAPABILITY_LEVELS`
  (L2/L3/L4 + funcs 的 fid/name/groups)。另有老倪现场定稿的分层职责表 (见
  `zmax-state-space-architecture/references/layer-responsibilities-and-real-machine-chain-2026-09-19.md`)。

实测冲突: 「🧠 L3 长程序列规划器 (场景理解驱动)」= planner.py `TaskPlanner`, 在
capability_levels 里是 **L3-B02 任务规划**、按 09-19 定稿 L3=长程序列规划 / LLM层=场景理解,
但它被 PIN 在 (1460,952) → 落在大模型层带 (与 🧿DeepSeek-VL / 👁VLM / 🔍异常推理器 同行)。
**答老倪: 这不是设计, 是"回路外慢决策"功能分组与能力档位两套体系的历史错位**, 并同时给出
`params.layer` / capability_levels 的权威归属证据 + 指出节点名里自己写着 L3。

同类: 「💪 L2 肌肉记忆技能库」`params.layer=L2` (归属 L2-A08/肌肉记忆), 却被放在 (800,1400)
= L4 记忆带 (L2 记忆行在 y=2900); 且**入边 0 条** (它的 desc 写"由 L3 序列调用", 但没有任何
L3→技能库 的线) → 悬空。

## 4. 处置纪律 (改完必复跑体检, 如实报代价)

移节点/补边后**必须**复跑 §0 的审计并对比: 节点数、连线数、断头/孤立/悬空数、反向线数。
实测代价 (照实报): 恢复「状态校正器→动作调制器(in8)」后 断头 14→13、校正器 判定=连通(入3出1),
但该边是回流边 → **反向线 18→19** (2510px), 因为校正器仍在调制器右侧。若把校正器左移, 断头同样
修好但会把「物理世界→状态校正器」(原本前向) 变成 2908px 反向线 —— 反向线总数**一样是代价,
选哪条只是把代价放在哪** (v5.5.42 的设计位是校正器在调制器左侧、接受"物理世界→校正器 ↩观测反馈"
为回流边)。这属于架构取舍 → 交给老倪定, 不要自己默默选。
