## 判据速查: 症状 → 根因 (别互相混淆)

| 症状 | 根因 | 一眼判据 |
|---|---|---|
| 断点不进 **且** 目标内部计数恒 0 **且** 调用侧计数满格 | 函数身份被换掉 (装配期实例覆盖) | `'forward' in obj.__dict__` = True; `obj.forward.__name__` = 被换过去的那个 |
| 断点不进, 调用侧计数也是 0 | 不在执行路径上 (只读分支 / 别档位 / 结构节点) | grep 调用点 + 正对照场景 (`micro`/`L3`/`L4line`) |
| 断点不进, 但探针/可视化有数据 | 另有**诊断前向**直接调内部函数 (绕过守卫) | 查 `obj._ff(...)` 这类直调; 探针非空 ≠ 主路径在跑 |
| 内部计数涨的是**守卫**计数 | 真的被域判定/守卫拦截 | 打出判据真值 (`d_guard` vs 门; 归一化 `max|xn|` vs σ 门) |
| 进了, 但动作不是它决定的 | 执行权在别处参考量 (直驱档的执行参考是引擎本帧 `u`) | 读装配器 (`install_direct_act` 一类) 的融合/否决分支 |

## 铁律 (本轮新增, 下一步应并入 SKILL.md)

- **先证身份, 再谈调用链**: 被问"这段代码怎么没进"时, 第一个动作不是插断点, 而是打印
  "这个名字现在指向谁" (`__dict__` 覆盖 + `__name__` + 类真身文件行号)。
- **两层包装计数**: 包类方法 = 真身进入次数 (实例已覆盖时恒 0, 这个 0 本身就是结论);
  再包实例属性 = 调用侧次数。**不要**在被换过去的目标 (`analytic_forward`) 上计数 ——
  赋值时捕获的是原 bound method, 事后包类方法无效 (实测不生效)。
- **孤儿开关**: 某个 env 变量只在目标文件里被读、调用侧 grep 不到任何人设置它
  ⇒ 生产口径下该分支恒不生效。这类"开关存在但没人拨"是假接入高发形态, 静态 grep 5 秒可查。
- **"进了"必须追问"它决定动作么"**: 汇报里分开写"每帧被调用 (次数)"与"输出参与执行 (权重/融合/否决)",
  二者混为一谈就是把演示当交付。
