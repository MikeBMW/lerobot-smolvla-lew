## 一、事故: 「注入零影响 ⇒ 新 LoRA inert」是错的

**当时怎么写的** (进过交接单, 差点当结论交付): L4 LoRA 注入臂的 `u_ff` 轨迹 hash 与解析链**逐位相同**
⇒ 判定"注入对指令零影响 = 新 LoRA inert", 据此"不切在役指针"。

**复检后真因**: 引擎 L4→u 的**对齐层** (`src/lerobot/manifold/l4_align.py`; 标定文件
`models/l4_align_map.json`, LOO cos −0.325→0.931 · ready=True) **只在 `SS_L4_ALIGN=1` 时才施加**;
而所有 A/B 与诊断都没设这个开关 ⇒ 原始提案 (cos 中位 **−0.605** · 幅度比中位 **5.8×**) 逐帧撞
L2 收口闸 (`SS_L4_INTACT_GATE` 默认开: cos<0 或 幅度>1.5× → 否决) ⇒ 通过率 0% ⇒ 输出与解析链逐位相同。

**开开关后的同口径实测** (`SS_L4_ALIGN=1` · 在役 `intact_l4_current` · 90 步 direct 臂):
闸门 `{1.0: 90}` **全过** · blend **90/90** (原 0) · cos 中位 −0.605→**0.963** / 0.603→**0.900** ·
幅度比中位 **0.864 / 0.848** (>1.5× 帧数 0/90, 原 89/90)。

**闭环 A/B (3 seed × 4 臂 · 450 步; 同 seed 解析锚逐位一致 ⇒ 口径可比)**: 对齐 ON ⇒ **回退被消除**
(seed1 direct 插入末端 13.6→27.7mm, 与解析锚 30.9 同级), 但**未证明提升** (成功数与解析链同 1/3)
⇒ 按门槛不进默认档。报告 `docs/design/lora_align_ab_20260924.md`。

**可复用判据 (下任何评测结论前)**:
1. "零影响 / 无变化 / inert" 结论必须带**逐级计数**: 提案 → 闸门 (pass / 方向否决 / 幅值否决) →
   融合 blend → 输出逐位比对; **缺级则结论无效** (本次就是跳过闸门这一级)。
2. 评测前把这条链上**所有开关的默认值**列出来并写进报告 —— Z-MAX L4 链:
   `SS_L4_INTACT`(默认关) · `SS_L4_ALIGN`(**默认关, 本次事故主角**) · `SS_L4_INTACT_GATE`(默认开) ·
   `SS_L4_INTENT_LINE`/`_W`(默认关) · `SS_INTACT`(默认关); 完整表见
   `zmax-state-space-architecture` 的「引擎 L4 注入开关盘点」。
3. 工具: `tools/diag_lora_du.py` (逐帧 Δu vs 解析链 + 闸门内部量; `--arms analytic,direct,line_w1`)。

## 二、工具: 逐连线运行时对账 (静态有连线 ≠ 每帧有数据)

`tools/canvas_link_reconcile.py` (仓库内, 可复跑; 产物 `reports/canvas_link_reconcile_<ts>.json`)

```bash
cd <repo> && ./gui-venv311/bin/python tools/canvas_link_reconcile.py
```

做法: 真跑一次引擎 (`RealStateSpaceSim(seed=104, vision=False, mode="insert")`, 120 步) → 取逐帧
`tr["io_trace"]` (每步 append `(t, {画布节点名: {...}})`), 汇总运行时通道集合 → 节点 / 连线分级 → 落盘 JSON。

### 节点分级 (老倪认的"分级回答"口径)

| 级 | 含义 | 判定 |
|---|---|---|
| R1 | 引擎**每帧真发 io** 的通道 | 通道集合里有对应 key (含数据源) |
| R2 | **真模型 / 真算子**, 但只在**档位链 / 双击自检**时执行 (默认档不每帧) | 有真源码 + 已注册, 不在运行时通道里 |
| R3 | **语义容器 / 标注** (记忆 / 编排 / 图谱 / 字典 / 档位 / 大模型层) | 设计上不产运行时 io |
| R4 | **合法可视化终端** (波形 / 视频 / 3D / Feature / Test / 直方图 / 旁路) | 天生有入无出 |
| R5 | **待建节点** (待办任务做成的功能节点) | params 带 status / todo |

连线三类: **双端 R1** (真数据流) / **单端 R1** / **双端非 R1** (设计语义 或 待接入)。

## 三、踩过的坑

1. **行带背景 (`type=row_bg`) 不是节点**: 第一版把 16 条行带当节点分级 → 数字全废, 还凭空多出 15 个"待接入"。
   遍历画布节点一律 `if n.get("type") != "row_bg"`。
2. **画布加载会重映射 node id** → 分级 / 匹配一律按**节点名**; 名字对照表在
   `tools/gui/simulink_module.py` 的 `SS_MODULE_TO_NAME` (键 = 引擎 last_io 模块名, 值 = 画布节点 name;
   引擎侧 `🛡 安全限幅` / `🤖 执行器` 与画布 `🛡 安全执行边界` / `🤖 机器人执行器` 有前缀差异)。
3. **分级结果依赖引擎启动开关**: 默认档 (不设 `SS_L4_INTACT` / `SS_INTACT`) 的 R1 = 18 通道;
   开 L4 直驱 / 直连线后 INTACT 相关通道才出现 ⇒ 报告必须写明"分级基于哪组开关", 否则不可比。
4. R2 ≠ 假接入: 它们是**真模型真算子**, 只是默认档不每帧跑 —— 表述成"档位级验收清单", 不要写成"没用"。

## 四、可复用的"待办任务 → 功能节点"落地三件套 (2026-09-24 老倪要求)

老倪: 「代办任务也要面向节点功能…作为一个功能节点」「节点要是进不了系统则删掉该节点, 要保证节点的完备性」。
一个新节点要真"进得了系统", 必须**同时**做三件事 (缺任一 = 画上去但进不了系统):

1. `tools/gui/node_logic.py`: `_reg("<key>", [名关键词…], "<说明>", node_<key>)` —— 节点函数要读**磁盘实况**
   (ckpt 大小 / mtime / 报告数字), 缺就报缺, **不写死数值**;
2. 同文件 `_EXTERNAL_LOC["<key>"] = (真源码文件, 行号, "符号")` —— 右键"看源码"指向真实现, 不指向胶水函数;
3. `src/lerobot/verification/capability_levels.py` 的对应档位 `funcs` 里加 `{fid, name, desc, groups}`
   —— 否则档位/能力清单里查不到它 (L2 摊平审计第 ④ 步)。

配套: 画布 JSON 里给节点写 `params.desc / source / source_symbol / status / todo`, 并用真连线接进上下游
(孤岛=没接); 完备性终检脚本 `tools/canvas_completeness_check.py` (孤岛 0 · 断头⊆合法终端 · 悬空⊆数据源)。
