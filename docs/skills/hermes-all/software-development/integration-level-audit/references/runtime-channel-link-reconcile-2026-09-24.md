# 运行时通道对账 + "上游开关默认关" 反向误判 (2026-09-24 实锤)

两个本子放在一起: 一个是**新工具/判据** (逐连线运行时对账), 一个是**一次被自己写错误结论的事故**
(把"上游开关没开"写成了"模型无效")。

## 一、事故: 「注入零影响 ⇒ 新 LoRA inert」是错的

**当时怎么写的** (进过交接单): L4 LoRA 注入臂的 `u_ff` 轨迹 hash 与解析链**逐位相同** ⇒ 判定
"注入对指令零影响 = 新 LoRA inert", 并据此"不切在役指针"。

**复检后真因**: 引擎的 L4→u **对齐层** (`src/lerobot/manifold/l4_align.py`, 标定文件
`models/l4_align_map.json`, LOO cos −0.325→0.931 · ready=True) **只在 `SS_L4_ALIGN=1` 时才施加**;
而所有 A/B 与诊断都没设这个开关 ⇒ 原始提案 (cos 中位 **−0.605** · 幅度比中位 **5.8×**) 逐帧撞
L2 收口闸 (`SS_L4_INTACT_GATE` 默认开: cos<0 或 幅度>1.5× 即否决) ⇒ 0% 通过 ⇒ 输出与解析链逐位相同。

**开开关后的同口径实测** (`SS_L4_ALIGN=1` · 在役 `intact_l4_current` · 90 步 direct 臂):
闸门 `{1.0: 90}` 全过 · blend 90/90 (原 0) · cos 中位 −0.605→**0.963** / 0.603→**0.900** ·
幅度比中位 **0.864 / 0.848** (>1.5× 帧数 0/90, 原 89/90)。

**闭环 A/B (3 seed × 4 臂 · 450 步)**: 对齐 ON ⇒ **回退被消除** (seed1 direct 插入末端 13.6→27.7mm,
与解析锚 30.9 同级), 但**未证明提升** (成功数与解析链相同 1/3) ⇒ 按门槛不进默认档。

**可复用的判据**:
1. "零影响 / 无变化 / inert" 结论必须带**逐级计数**: 提案 → 闸门 (pass/方向否决/幅值否决) → 融合 blend →
   输出逐位比对; 缺级则结论无效。
2. 评测前把这条链上**所有开关的默认值**列出来 (Z-MAX L4 链: `SS_L4_INTACT` / `SS_L4_ALIGN` /
   `SS_L4_INTACT_GATE` / `SS_L4_INTENT_LINE(_W)` / `SS_INTACT`) —— 清单表在
   `zmax-state-space-architecture` 的「引擎 L4 注入开关盘点」。
3. 工具: `tools/diag_lora_du.py` (逐帧 Δu vs 解析链 + 闸门内部量; 参数 `--arms analytic,direct,line_w1`)。

## 三、踩过的坑

1. **行带背景 (`type=row_bg`) 不是节点**: 第一版对账把 16 条行带当节点分级, 数字全废。
   遍历画布节点一律 `if n.get("type") != "row_bg"`。
2. **画布加载会重映射 node id** → 分级/匹配一律按**节点名**; 名字对照表在
   `tools/gui/simulink_module.py` 的 `SS_MODULE_TO_NAME` (键=引擎 last_io 模块名, 值=画布节点 name;
   引擎里 `🛡 安全限幅`/`🤖 执行器` 与画布 `🛡 安全执行边界`/`🤖 机器人执行器` 有前缀差异)。
3. **分级结果依赖引擎启动开关**: 默认档 (不设 `SS_L4_INTACT`/`SS_INTACT`) 的 R1 集合 = 18 个通道;
   开了 L4 直驱/直连线后 INTACT 相关通道才出现 ⇒ 报告里必须写明"分级基于哪个开关组合", 否则不可比。
4. R2 不是"假接入": 它们是**真模型真算子**, 只是默认档不每帧跑 (档位链/双击自检时才执行) ——
   交付口径是"**档位级验收清单**", 不是"没用"。
