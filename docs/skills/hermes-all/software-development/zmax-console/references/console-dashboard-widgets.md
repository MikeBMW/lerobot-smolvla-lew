# 仪表盘控件与图形化表达 (圆环 · 状态条 · 指示灯)

## 老倪口径 (always-on)
- 硬件/资源/状态类卡片**少堆文字**: 数值用 圆环(百分比) + 状态条(比例) + 指示灯(通断) 表达;
  原始文字行退到 tooltip + 「📋 复制参数」按钮 —— 他要的是"可复制可导出的纯文本", 不是把信息删掉。
- 卡片必须真实: 缺测一律 "—" + 空环/空槽, 不编数、不拿 0 充数; **数据源不通要点红/灰灯, 不能灯还是绿的**(假健康=会被抓)。
- 位置由语义定: 主设备(本机 4060)永远排灯带最右; 硬件卡沉到页面最底。
- 版式纪律: 字号要有阶梯(标题 > 数值 > 副标题 > 小字); 同一行按钮高度与字号必须一致; 卡片与页面栅格左右边缘对齐、上下间距均匀。
- 视觉判断外包 vision 子代理做逐像素描述(坐标/占比/对比度), 自己不做主观评价。

## 三控件规格 (tools/gui/hw_widgets.py: Ring / StatBar / Lamp)
- Ring 弧**必须 Qt.FlatCap**: 圆头端帽让弧看起来比数值多 ≈9° (34% 视觉像 36%)。
- Ring 内中文与数字混排要统一 font family/size, 否则中文 21px / 数字 14px、基线差 5px, 四环明显不齐; 副标题写清 used/total (11/31GB), 只写总量会被读成百分比。
- StatBar 必须有**可见底槽**(100% 量程参照), 槽色与卡底拉开(卡底 #161b22 → 槽 #2b3340); 同色时空条看起来像"漏画"。
- StatBar 无数据/无额定值时只画空槽 + 数值 "—", 不画假条。
- Lamp 设备名/型号用省略号截断(`…`), 不要硬切(`name[:16]` 会出现半截词)。
- 灯带**左对齐**, 别用 `addStretch()` 推到右边(否则卡片左半 30% 全空); 多个圆环用等 stretch 铺满整宽。

## 阈值与配色 (dark 主题)
- 显存/CPU/内存 <80 绿 · 80–92 黄 · >92 红; 磁盘 <80 绿 · 80–90 黄 · >90 红; 温度 <70 绿 · 70–82 黄 · >82 红。
- GPU 利用率: 训练中 <50% 判黄(沿用掉载口径), 空闲灰。
- 绿 #3FB950 / 黄 #D29922 / 红 #F85149; 表头文字别用 #8B949E (对比 5.1:1) → #B6C2CF。

## CANoe 三窗格范式 (tools/gui/dds_canoe.py = 「全局数据空间」页)
- 布局 = 顶部测量条(⚡Start 黄 / ⬢Stop 灰 + 设备灯带 + 刷新龄) + 上排左 Data 表 (Name/Value/Unit/Last Value Time[s]/Bar) + 中 Trace **整宽 9 列** (Time/Name/Object Type/Classification/Probability/Sender/Sender Id/Tracking Id/Group) + 上排右详情 + 底部页签(数据闭环/质量告警)。
  旧的多 Tab 堆叠一律收进「🗂 经典视图」一键切换(入口零丢失)。
- 顶栏中间不留死区: 拿真实读数填(如 `Trace 500 行 · 过滤 关 · Δt 关 · 帧龄 1.7s · 闭环 5/9`)。
- Bar 列 = **实测/设计** 比值, 不是绝对值 → 表头必须写明并给底轨, 否则读者按条长读绝对量级(0.5Hz/设计10Hz 的 5% 短条会被当成画错)。
- 详情面板首刷自动选中第一行, 否则空面板 78% 空白会被判"没做完"。
- 表头与内容一律左对齐(整列错位 30–40px 一眼可见)。
- 取值键要对齐: live.json 用短名(heartbeat)、trace.jsonl 用全路径(zmax/heartbeat) → 查表必须两种键都建, 否则整列 "—" (看起来像功能没做)。

## 独立窗口多视图 (跑 L5 画布时同时看数据空间 topic)
- `dds_canoe.build_view(main_win=None, standalone=True)` → 顶层非模态窗口, 可拖到副屏与主窗口并排看。
- 窗口句柄存模块级变量复用: 关掉再点开的是同一个窗口, 不重建不重复采集。
- standalone 下隐藏「🗂 经典视图」(依赖主窗口切换回调), 其余控件照用。
- 入口放画布页顶部工具栏, 与 🧩场景叠加 / 🛰工位总览 并列; 顺手在命令通道加 `ds_win` token 便于自动化验证。

## 192 DPI 自绘/取证
- 自绘控件验收要**两路截图**: 离屏出图证画法, 现场 x11grab 证真机没崩; 再用像素统计确认关键色真落到屏上(环轨/绿灯计数非 0)。
- 现场口径: 客户区 `-video_size 3068x1862 -i :0.0+132,212`, 整屏 `3200x2000`; 逻辑坐标 = 原图像素 ÷2。
- 真机字体渲染的 ClearType 子像素彩边是渲染现象, 不是缺陷, 别去"修"。

## 工具栏「空白」诊断 (不是缺控件, 而是控件看不见)
- 报「中间一大块空白」时**先量像素再改布局**: 取那块矩形统计 **亮度>90 的像素数**。为 0 = 该区没有任何亮元素 ⇒ 控件在那里但**读不出来**; 别急着把邻居按钮拉宽/加分隔线。
- Qt 默认给 `QCheckBox`/`QRadioButton` 的**字色是黑**: 画在深色工具条 (#0d1117) 上对比度 ≈1.1:1, 肉眼上就是"空档"。全局深色 QSS 覆盖 QPushButton 的底色,**不保证**覆盖 QCheckBox 的字色 ⇒ 自己写的浅色按钮配方(浅底+彩字)在现场可能只剩彩字(底仍深), 而勾选框整块黑。
- 修法: 每个勾选框**显式**给深色 pill 样式(`background:#14181f; color:#c9d1d9; border:1px solid #30363d; radius 5`; `:checked` 绿字 #7ee787 + 绿块指示器 #3fb950), **padding 与同排按钮一致**才等高。
- 复测判据: 该区亮像素数(实测 0 → 17258)、绿色(勾选态)像素数 > 0、重排后无重叠; 再交 vision 逐像素质检读文字是否可读。

## 高频刷新表格 (机制详见 references/data-bus-canoe-trace.md)
- 每秒级重建的表**禁用 ResizeToContents**: 单元格一变就逐格量文字重算列宽, 且开销在事件循环里(不在 fill 函数内), 逐函数计时完全看不出来 → 现场满核"卡住"。改显式列宽 + 只留名字列 Stretch。
