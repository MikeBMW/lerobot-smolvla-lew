# 派生画面 vs 定时刷新 + UI 口径 + 验证纪律 (2026-09-24 实测)

老倪这一天连着抓到三类问题 (画面"闪一下变回坏图"、"图片怎么不动了"、按钮被截断/字挤)，
下面每条都是**实测根因 + 修法 + 回归断言**，同一类 GUI 任务直接照抄。

## 1. 派生画面 vs 定时刷新 (最贵的一个 BUG)

**症状 (老倪原话)**:
- 「选择框选拉伸后, 为什么刚开始显示被圈选的图片, 然后**立刻变成原始的拉伸坏了的图片**」
- 「拉伸后**还是一片白**」(同一根因, 我一开始误判成"旧窗口没刷新")

**根因**: 窗口里 500ms 的 `_tick()` 每次都把**原始帧** `self._opt_rgb` 重新 `set_frame_rgb()` 到面板 →
把**派生判据图**(裁剪/过曝切除/框选拉伸的产物)直接冲掉。画面"闪一下"就是 500ms 后那一跳。

**纪律**:
- **定时器只做两件**: ①为新数据源取新帧(真实流) ②刷状态文字(链路/帧龄/耗时)。
  **已显示的派生画面绝不在定时器里重设**。
- 派生管线 (原始图 → 裁切/切除 → 拉伸 → 推理) 每次都在**显式动作处整条重跑**:
  点按钮 / 切源 / 改参数(倍率/开关) / 自动刷新 tick / 拖框。
- 改完别走另一个极端: 一旦画面只在显式动作时更新, 用户马上会说
  「**图片怎么不动了? 也无法更新, 都不知道是什么时候拍照的**」→ 必须同时补齐:
  ① 一键"立即取图/拍照"按钮  ② 自动刷新(默认关, 间隔 3/5/10s, 模式 真拍/只取图) 
  ③ **时间戳标签**: `拍照 17:10:33 (3.2s 前) · 真拍 | 取图 16ms · HTTP 200 · 713KB · [960,960,3] · 判据图饱和 5.8%`
  (时间取对端快照时间戳 `t`, 另给帧龄/耗时/HTTP码/字节/尺寸/处理后的饱和)

**回归断言 (逐位比对, 必须加)**:
```python
snap = w._last_rgb.copy()
for _ in range(3):
    w._tick(); app.processEvents(); time.sleep(0.15)
assert np.array_equal(snap, w._last_rgb)      # 跨 3 跳派生画面逐位不变
```

## 2. 按钮被截断 / 字挤 (192DPI 下实测三回)

- `setMinimumWidth(b.sizeHint().width())` **构造时算不准**: QSS 与字体 (Noto Sans CJK SC) 的解析
  **晚于** sizeHint → 真实需要 148px 却被钉成 140px → 运行期被布局压窄就截字。
  **修**: `_fix_min_widths()` 在 ①`_build()` 末尾 ②`showEvent()` 里各钉一遍:
  ```python
  def _fix_min_widths(self):
      for b in self.findChildren(QtWidgets.QPushButton):
          w = b.sizeHint().width()
          if w > b.minimumWidth(): b.setMinimumWidth(w)
  ```
- **更根本: 别把一堆控件塞进窄面板**。左侧画面条只有 ~540px, 塞 6 个控件必截断 →
  把「画面裁切/标定基准」这类成组控件搬到**整宽独立行**。
- **自动取证**: 真桌面脚本对**所有** QPushButton 断言 `b.width() >= b.sizeHint().width()`,
  并把清单列成 dict(每加一个按钮就补一行) —— 这次它连抓两个回归。

## 3. 老倪 UI 口径 (多轮反馈汇总, 一律照做)

1. **文案极简**: 按钮 ≤6 字 (`📸 立即拍照` / `📍记住此点`), 长解释一律进 tooltip; 一行一个功能。
2. **不许挤 / 不许截断 / 不许显示不全**: 统一字体族 + 标题 9pt / 表 8pt + 行高 24 +
   `elidedText` 省略号 + tooltip 全文; 窗口最小尺寸给足 (例 1200×700)。
3. **不许乱**: 右面板多表格 → `QTabWidget` 分页 (判决 / 检测 / 终端 / 标定·训练); 状态收敛成一行。
4. **最大化必须真能用** (不是禁用): QDialog 换 `Qt.Window` 类型, 见 `references/qdialog-maximize-2026-08-28.md`。
5. **每个技能按钮点一下就要出结果** (判决表 / JSON / 图), 禁占位按钮; 失败也要如实显示原因。
6. **数据必须带时间与新鲜度** —— 老倪会直接问「都不知道是什么时候拍照的」。
7. **命令要能复制去终端执行**: 显示**同源生成**的等价命令 (别手写, 会与真实请求漂移),
   一键复制命令 / 复制反馈 / 复制两者。
8. **图片要能右键复制** (复制图片 / 复制路径 / 另存为 PNG), 可粘贴到别的程序。
9. **重构 UI 时保留老属性名**: 验证脚本按属性名 `.click()` → 移行/改名要给旧脚本留 `btn_xxx` 别名兜底。
10. **接口即按钮**: 用户会要求"那几个 http://… 接口做成技能按钮, 点一下就能用" →
    每个端点一个按钮 (含只读), 按钮 tooltip 写清方法+路径+是否真拍。

## 4. 验证脚本两条纪律

- **UI 级断言不要依赖外部服务/真机在线**: 服务端口一关, 十几项判据同时变红, 分不清代码还是环境。
  把「按钮可达 / 点了有结果(失败也算如实记录) / 标签口径 / 开关可控」做成**不依赖服务**的独立块,
  服务相关判据单独成组, 结论里注明"因对端服务不在线"。
- **统计"是否新增真动作"要按 action 过滤**: 审计流水里同样会记**失败** (http 000) →
  只数 `action in ("capture_detect","fetch_grab") and http == "200"`,
  否则失败记录也会让计数变化, 把"没真拍"误判成"真拍了"。

## 5. Qt 剪贴板/绘图两个坑 (已在正文提及, 这里给可抄代码)

```python
# 图片进剪贴板: 必须一次性 setMimeData — 先 setImage 再 setText 会把图片冲掉 (实测剪贴板 0x0)
md = QtCore.QMimeData(); md.setImageData(img.copy())
if self._path: md.setText(self._path)      # 粘到文本处=路径, 粘到图处=图片
QtWidgets.QApplication.clipboard().setMimeData(md)
```
- offscreen 后端的 `clipboard.image()` **恒 0×0** → 剪贴板类断言必须放真桌面 (`DISPLAY=:0`)。
- `DISPLAY=:0` 下**先 import cv2 再 import PyQt5** 会抢走 xcb 插件 (报 "Could not load the Qt platform
  plugin xcb") → 测试脚本里 PyQt5 必须最先导入。
