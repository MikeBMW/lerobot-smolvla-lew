# 用户第二次坚持"画面/结果就是不对"时的第四步 (2026-09-17 Z-MAX 实战)

> 前情: `references/screen-misread-triage-and-self-labeling-2026-09-17.md` 讲了"先确认他在看哪一帧"。
> 本次又往前推了一步: 用户第二次坚持时, **别再拿"我自己复现的结果"当答案** (第一轮已经量过了),
> 要量**他自己那一轮**的数字, 并把"控制错误"与"口径/规格不同"分开。

## 一、让"用户那轮"留下可查的终局快照 (前置条件, 要提前建)

- 异步/长跑任务 (引擎、仿真、训练) 的生产者应把关键量**节流落盘**成一个状态文件, 例如
  `/tmp/ss_live_frame.json`: `{t, step, stage, depth_mm, lateral_mm, grasped, viewer_consumed}`。
- **节流 1Hz 的坑**: 短轮 (<1s, 如 R0 快跑) 整个生命周期只够写一次 → 文件里只有**首帧样本**。
  修法 = 任务收尾**强制写一次终局快照** (`_ss_write_status(force=True)`), 否则"用户那轮"的数据等于丢了。
- 附带价值: 文件里放一个**消费计数** (`viewer_consumed`), 就能证明"窗口真的在放这些帧",
  比截图/OCR 可靠 (进程内外都能核对)。

## 二、拿到他那轮数字后, 先归类再动作

本次实测: 用户质疑"插销没插到插槽里, 横向有偏差", 拉出**他自己那轮**的收尾快照 =
`阶段=完成 · depth=64.3mm(孔深 66) · lateral=2.5mm · grasped=true` ⇒ 与他描述**对不上**, 不是控制偏。

于是问题变成两个可能的归类, 必须区分后再动代码:

| 归类 | 判据 | 动作 |
|---|---|---|
| 控制错误 (真 bug) | 站点/几何真值显示深度不足或横向明显偏 | 查控制链、判据、目标点 |
| **口径/规格不同** | 站点距离达标, 但**几何体**只进去一小部分 | 讲清口径, 让用户拍板, 别自己改 |

- 本次的口径差异写实: 官方任务判据 = 长杆**头部**到孔底 ≤7cm 即成功
  (`metaworld/envs/sawyer_peg_insertion_side_v3.py:115` `success = obj_to_target <= 0.07`,
  且 `obj_head = site("pegHead")`), 而用户按**产线语义**认为"光模块体要坐进插槽"。
  24cm 的杆只进了 6~7cm、其余横在盒外 ⇒ 在他看来就是"没插进去、横向差一段"。
- **"长物体只进去一小部分 ⇒ 视觉上判定失败"是一类典型假警报**: 先把口径差异讲清, 给两个明确选项 —
  ① 改终点定义 (座入深度, 会牵动 L2/L3/L4 共用段与完成判据, 必须同口径 A/B 对照)
  ② 只改善可视化 (在画面上叠加孔中心线/深度刻度, 让"头在孔里、杆体在外"一眼可辨)。
- 一句话判据: **站点距离达标 + 几何体只进 1/4 ⇒ 不是控制偏, 是终点定义问题。**

## 三、可复用的收尾话术 (用户要的是结论, 不是过程)

- 先给"你自己那轮"的一行数字 (时间戳 + 阶段 + 关键 mm + 布尔), 再说"因此它不是 X, 而是 Y"。
- 明确区分"我已验证的"与"还没确定的", 需要用户拍板的地方**只问一句** (给推荐项 + 另一选项),
  不要罗列一堆选项 (老倪: 「别选那么多」)。
- 交付话术别用"无法确定/建议进一步检查"这类空话: 要么给数字, 要么给一个可执行的下一步。
