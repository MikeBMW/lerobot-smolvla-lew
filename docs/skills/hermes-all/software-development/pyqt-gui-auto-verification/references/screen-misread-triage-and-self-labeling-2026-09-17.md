# 用户拿「画面」质疑结果时的定界与取证 (2026-09-17 Z-MAX 仿真窗口实战)

> 同一族提问连问三次 (「仿真渲染里光模块没插进槽 / 与插槽横向有偏差 / 点了运行图像不动」),
> 两次的正确答案是**"你看的那一帧不是运行结果"**, 不是 bug。GUI 取证的重心应该先放在"他在看什么"。

## 定界三连 (先做这个, 再谈代码)

1. **哪面窗口在开着**: `DISPLAY=:0 wmctrl -l` (本次只有「📺 输入图像」开着 ⇒ 不是 3D 分层视图窗口)。
2. **引擎在不在跑**: 现成的 1Hz 状态文件 (`/tmp/ss_live_frame.json`) 的 `t` 与当前时间差;
   加 `grep -c mujoco /proc/<gui-pid>/maps` 作旁证 (引擎加载了 mujoco)。
3. **哪一档/哪种模式**: 画布 `flows/*.json` 的 `cap_switch/cap_level`、引擎 meta 的 `mode`(insert/full)。

## 取证手法 (替代"再截一张图")

- **双口径真值量**: ①站点坐标 (`site_xpos`) = 引擎自己以为的位置; ②**几何体**世界位姿
  (`geom_xpos`/`geom_xmat` → 长轴/两端/中心) = 用户眼睛看到的东西。两者都要打, 差多少一目了然。
- **按物理量分解**: 沿孔轴分解成 `depth`(进多深) 与 `lateral`(横向偏差), 给 mm 级数字; 落逐帧 CSV 供事后复核。
- **静止帧也要量**: "没数据时的画面"本身就是一个可测对象 (本次量出: 初始布局里光模块中心离插槽孔口
  **水平 358mm**、低 110mm ⇒ 用户描述"横向差一段距离"完全对得上, 但那是初始布局)。
- **反面断言必须有**: 「有实况 → 用实况」+「无实况/帧过期 → 不许上屏」; 判据用像素/字节
  (idle 帧 top band 均值 < 其余 ×0.6 且含橙字; 实况帧 `np.array_equal` 原样)。

## 显示面必须自证 (本次落地)

- 无数据/占位画面**自己带结论**: 画面上压横幅 (顶部条带压暗 ×0.25 + `cv2.putText` 橙字
  「⚠️ 引擎未运行 · 静态初始帧 — 这幅画面没有在跑仿真」) + 状态栏写帧龄/来源。
- 只靠状态栏小字不够 —— 用户看画面不读小字, 本次就是因此连问两次。
- 长跑/异步画面上屏的帧要带**可核对的标识** (step/帧龄/来源 tag), 让"显示的是什么"可被程序断言。

## 测试写法坑 (本次踩的)

- **stub 测真实方法体时 `@staticmethod` 必须显式包一层**:
  `Stub._visible_ratio = staticmethod(真实类._visible_ratio)`,
  直接赋值会被当实例方法绑上 self → 方法内异常被 `except` 吞掉 → 断言**假 PASS** (第一版 3 例误报)。
- 用真实窗口类跑也要隔离外部副作用: 打桩外部链路 (`classmethod(lambda cls: ...)`)、
  环境变量指向临时目录、**别把被测方法本身换成 lambda** (那样清屏/重置代码根本不执行, 断言假过)。
- 1Hz 节流的落盘文件: 断言"写的就是最新值"要先睡过节流窗口; 短跑 (<1s) 的长任务要在收尾
  强制落一次终局快照, 否则文件里只有首帧样本。

## 通用原则

**"用户说画面里 X 不对" ⇒ 第一步是确认他看的是哪一帧、哪一路、有没有真的在跑; 第二步用真值数字回答,
第三步才动代码。** 只截新图/只改几何常量 = 可能白改一轮 (本次三次提问, 两次都不是代码问题)。
