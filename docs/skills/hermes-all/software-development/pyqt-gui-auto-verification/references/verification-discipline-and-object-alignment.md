# 取证纪律：改完的要自证，用户跑的要先对齐对象

> 2026-09-25 实战教训（桌面 APP 加硬件卡，连发 5 个 patch 版本用户仍"没看到"）。
> 适用于任何"改 GUI → 交付给用户在别处运行"的活。

## 1. ★ `str.replace` 静默 no-op + 自报成功 = 最坏的组合
给 `studio.py` 加新类时，我用
```python
c = c.replace("\nimport time\n", "\nimport threading\nimport time\n", 1)
print("  ① threading 已补")        # ← 这行是谎话
```
锚点没匹配（真实那行是 `import time  # 硬件工具箱日志时间戳`，带注释），**静默什么都没改**，
而我的日志照样打了"✅已补" → 结果 APP 一构造就崩：`name 'threading' is not defined`。

**铁律**
- 改完必须**回读文件确认**：`sed -n '18,22p' file` / `grep -n 'import threading' file`，
  打印**实际行内容**，不是再打一遍自己的意图。
- 用**精确锚点**（带足够上下文/注释）而不是 `"\nimport x\n"` 这种易失配的模式。
- 批量替换前先**数匹配数**并断言（`assert old in c`）；本轮另一个事故是
  `v5.14.0` 有 5 处（3 个显示位 + 2 个历史变更块），盲目全替换会**篡改变更历史** ——
  靠 `assert` 才拦下。

## 2. ★ 语法通过 ≠ 能构造（GUI 专属）
只在运行时才炸的三类错，静态检查全查不出来：
| 错 | 症状 | 预防 |
|---|---|---|
| 猜颜色/常量名 | 写 `C_TEXT`，宿主只有 `C_WHITE` → NameError | 先 `grep -nE '^[A-Z_]+\s*=' <宿主>` |
| 宿主只有局部 import | `shutil` 模块级没有 → 异常被 `try/except` 吞 → 那行永远 "—" | 新代码自己 import；警惕自家 except 吞错 |
| `import threading` 非模块级 | 新类用到 → 进程崩溃 | 补进模块级 import 区 |

**最低验收**（两步都要）：
```bash
python3 -c "import ast;ast.parse(open('<file>').read())"            # ① 语法
QT_QPA_PLATFORM=offscreen <venv>/bin/python -c "                    # ② 构造 + 读文本
  w = <被测控件>(); w.refresh(); print(w.lb_x.text())"
```
② 比截图+PIL 像素占比**更快也更定位**（"哪一行没填上"一目了然）。
图表窗口用像素断言，新加的文本/面板用**控件文本断言**，两者互补。

## 3. ★ 用户说"你这是没做"时，先分清是哪种"没有"
```
① 真没做               → 去做
② 做了但用户拿不到     → 旧版本/网络不通（单文件 exe 必须换文件才生效）
③ 你看的不是同一个东西 → ★ 最难发现：我改 Web 控制台, 用户指的却是 PyQt5 桌面 studio.py
⇒ 本轮白做两轮就是 ③。**先要两个信息**：
     · "你 APP 里版本号显示多少"        → 判断他手上是哪个构建
     · "关键诊断行显示什么"（如"数据源:"）→ 判断哪一步断了
```
- **一件事只发一次版本**：连发 v5.15.1→.5 而用户仍"没看到"，说明瓶颈不在功能实现。
- 每次发布要让用户能**自证版本**：版本号显示位（标题栏+菜单栏+首页小字）同步升，并点名让他核对。
- 打包**体积变化**可作"依赖已打进"的证据（本轮 +4MB = cyclonedds 打包成功）。

## 4. 客户端可能跑在"别的机器"上（数据类界面必查）
用户在自己电脑上打开 APP，那台机器**没有目标硬件** → "本机"行永远为空。
凡是展示"某台特定机器"数据的界面，必须：
1. **远端拉取优先**（本机数据只作补充行，并标注"本机=运行 APP 的这台机器"）
2. **数据源自动发现**（配置 → 本机 → 已知 LAN IP，命中即缓存）+「🔄 刷新数据源」按钮
3. **界面显示当前数据源**（这就是第 3 节说的"关键诊断行"）

完整配方（含 studio.py 具体代码）见技能 `zmax-console` 的 `references/hardware-card.md`。
