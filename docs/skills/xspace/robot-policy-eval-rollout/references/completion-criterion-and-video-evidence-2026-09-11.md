# 完成判据 · 模型参与率 · 视频取证铁律 (2026-09-11 实锤, 老倪肉眼抓出假成功)

背景: 在 L4 层接入外部世界模型 (INTACT-JEPA) 后给出"插入成功 100% + 视频", 老倪看完视频直接说
**"光模块没有插入"** —— 查证后他对: 引擎判定"完成"时 peg_head 距孔底还有 4.5-5mm, 视频里就是
没插进去。以下把这次教训固化成评估/取证铁律。

## 1. `done=True` ≠ 任务成功 — 必须按引擎自己的物理量复核
- `done` 只表示状态机进了"完成"段; 真判据是引擎内部的量, 例:
  `_insert_depth() = ‖peg_head − _goal_p()‖ < insert_depth`, `done = sched.stage()=="完成"`。
- 阈值 6mm 时**残余 4.5-5mm 就算完成** → 视频肉眼可判"没插到底"。
- **对外给成功率/视频前, 按引擎口径复算物理残余**(本例 4.5-5.0mm), 不要只看布尔 done。
- 判据阈值是**真实性旋钮**: 6mm→2mm 后成功率 100% → **73% (11/15)**, 但"完成"才等于真做完。
  宁要低而真, 不要高而假; 口径变化时前后两个数一起报。

## 2. 测量量必须与引擎同源 — 否则得出假结论
- 本例引擎 `tr["peg"]` 存的是 `o[4:7]` = **速度**, 不是位置。用它算"到孔距离"得到 135mm,
  差点据此把"假成功"外归因成别的 bug。
- 复核几何一律用引擎自己的接口 (`sim.peg_head()` / `sim._goal_p()` / `sched.stage()`);
  评估脚本与引擎判据**同源同量**才构成证据。
- 同理: obs 切片口径要逐个确认 (本例 `obs[4:7]`=v, `obs[7:10]`=_pc, `obs[10:13]`=goal_p,
  `obs[36:39]`=阶段目标)。同一个索引错可以连踩两次, 记进脚本注释。

## 3. 跨进程布局漂移 = 假稳定
- metaworld 每进程布局不同: **同进程内重复 N 次结果完全一致**(看起来极稳), 换进程就变。
- 真泛化必须**每 seed 独立进程**; 报告 "M/N 成功 + 每 seed 的关键量", 不要把同进程重复当可靠性。
- 本会话: 同进程 3 次完全相同 (1024/2773 采纳/兜底) → 每 seed 独立进程 6/6 成功 (各自 21-34% 参与)
  才算真证据。

## 4. 模型接管评估必须同时报「成功率 + 模型参与率」
- 只报成功率 = 可能全程引擎兜底 (模型零参与, 拿基线冒功)。
- 一致性守卫 (只在模型与引擎建议一致时采纳模型) 的 TOL 扫描实绩 (10 seed):

  | TOL | 模型参与 | 成功率 |
  |---|---|---|
  | 0.05 | 0% | 100% (退化为纯引擎, 无意义) |
  | **0.15** | **21-34%** | **100%** |
  | 0.3 | 86% | 0/10 |
  | ≥0.6 | 100% | 0/10 |

- 结论: 模型是**辅助**(≤30% 安全), 主导(>50%)必崩 — 因为引擎是有状态调度器
  (`u = w_ff·u_ff + (1−w_ff)·u_fb` + 阶段状态机), 内部状态不在 obs 里, 纯模仿无法复现。
- 另一条: **latent 预测误差监控检测不到"卡住"** — 世界模型 held-out MSE 6e-5 极准, 但 guard
  触发 0/599 次, 因为停滞状态同样可预测。要守卫停滞须用**任务进展量**(到孔距离单调性)。

## 5. 录闭环视频的正确姿势
- 帧捕获用引擎的**只读钩子** (本例 `sim._frame_sink`), 或 sitecustomize patch 记录
  `info_dict["pixels"]` 末帧。
- **绝不要在 wrapper.forward 内部渲染**: 会改变控制流 → 实测采纳率 27%→77% 且全部崩;
  录出来的帧和评估结果就不是同一件事了 (同时也解释了"为什么同代码不同结果"的假象)。
- 帧**只在成功时落盘**: 循环多 seed 时后一个失败 seed 会覆盖前面的成功帧, 视频与数据对不上。
- 合成用 `ffmpeg -framerate N -i f%04d.png -c:v libx264 -pix_fmt yuv420p`
  (imageio 常缺编码器; PNG 序列 + ffmpeg 最稳)。
- 逐帧标注 `[阶段] src=模型/引擎 · dist=xx mm · step`, 让观看者直接判断哪些帧是模型在控。
- 视频"慢"先分解再解释: 本例模型前向 **0.13 ms/步** (免搜索, 不是瓶颈), 引擎+渲染 26 ms/步,
  视频是 8fps 慢放 (实际 ~39fps) → 慢在渲染与播放帧率, 不在模型。

## 6. 排查脚本模式 (可复用)
```python
class W:                                  # 包装 accel: 记录 obs/返回动作/来源计数
    def forward(self, obs): ...
    def analytic_forward(self, obs): return self.forward(obs)   # ★ 两个入口都要包
sim.accel = W()
```
- 输出: stage 序列 + 到孔距离 + actor/guard 计数 + `s.sched.stage()` 字符串集合
  (引擎阶段名: 接近/对位/下降/抓取/抬起/转移/插入, 带推进后缀如 "下降 · 接触")。
- 采集训练数据时同样要包装 accel 捕获**它实际收到的 obs** (用 `tr["obs"]` 会不同源:
  前 12 维一致但后段不同 → 同输入输出差 3 倍)。
