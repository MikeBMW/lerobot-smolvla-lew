# 决策头的泛化验收: 留一"工况" + 操作性判据 + 假泛化排除 (2026-09-11 实测)

配套阅读: `references/decision-head-and-anisotropic-part.md` (第 0-8 步: 证伪监督信号存在 →
造各向异性几何 → 真实物理判据 → 探针数据集 → 条件决策头 act_dim 4→5 → 接线 → A/B)。
本文件是它的**续集**: 要求形态 = "把 <工况> 随机化 (例: ① 来料转台角 60~120°), 验证决策头在
**没见过的工况**上仍能选出可用的选项"。适用于任何"让模型在候选里选一个"的任务。

## 1. 先把工况参数化 (否则扫不了)
- `stage_turntable90(target_deg=None)` → 读 env `SS_L4_TT_DEG` (默认 90); CLI 加 `--tt-deg`;
  探针加 `--tts "60,75,90,105,120"` 一次覆盖多工况。
- 改完**先跑一个工况回归** (默认 90°) 确认旧行为不变, 再扫。
- 演示链的**默认路径**也要能覆盖新工况下的正确解: 决策器候选搜索的 span/中心要放开
  (本轮 span 从 ±45° 放到 ±90°), 否则头再准也够不到正确解。

## 2. 多工况数据集 (真实试验)
- 5 工况 × 13 候选 × 2 布局 = **130 次真实试抓, 45/130 成功** (约 3 分钟)。
- 结论: **正确选项随工况移动** —
  tt=60° 成功区 -90~-15° · tt=75° -60~-30° 与 +60~75° · tt=90~105° -60~0° ·
  tt=120° -60~0° · **φ=+90° (脚本固定角) 在所有工况恒败**。
  工况不动而正确解动 ⇒ 固定值必然在某些工况失效 (这正是"必须决策"的证据)。

## 3. 留一工况交叉验证 (判据选择是关键)
- `tools/train_yaw_head.py --group-key tt` (分组键: seed / tt / tt_seed), 留出 1 个来料角:
  实测 ok_acc 0.54~0.96, 但"预测 argmax == 实测 argmax" 只有 **1/5**。
- **"精确命中实测最优值"过严, 会把可用结果判死** (例: 预测 -45° 而实测最优 -60°, 两者都能夹住)
  → 必须同时看操作性判据 (下条), 别只报命中率。

## 4. 操作性判据 = 真验收口径
- 判据: 预测决策值在**实测里是否真能成功** (Δz > 探针成功阈值)。
- 实测对比 (同一批留一工况):
  | 裁决规则 | 落在"实测能成功"的工况数 |
  |---|---|
  | argmax 预测 Δz (回归点估计) | **3/5** (tt=60/75 选错) |
  | **argmax P(成功)** (分类头) | **5/5 ✅** |
- ⇒ **执行器裁决规则改为「P(成功) 为主 + 0.25·预测回归值」** (原 `-dz - 0.25*p` → `-p - 0.25*dz`)。
  原因: 回归头是点估计, 跨工况会漂; 成功概率更稳。**本条是本轮唯一必要的执行器修改**。
- 端到端未见工况 (训练网格之外): tt=72°/108° → 决策 -45.3° (27 决策 / 351 次前向 / 权重 v2) →
  真实夹持 Δz≈12mm → ③④⑤⑥⑦⑧ 全绿 **success=True ×2**。

## 5. 🚨 必做: "假泛化"排除 (否则结论不成立)
- 检查**是否存在一个固定候选值能通过全部测试工况** —— 本轮 φ=-45° 在全部 **12 个**测试来料角
  下都可行, 而训练出的头在这几个工况下恰好**恒输出 -45.3°** ⇒
  **实验区分不出"学到自适应"与"学到万能角"**。
- 因此报告只能写"**未证实自适应**", 并给出下一步验证条件: 制造该固定值**不可行**的工况
  (更极端长宽比 60×10 / 工况+位置组合偏移 / 把决策移到其它相位如插入段)。
- 通用规则: 跨工况验证里只要有一个固定候选值全过, 该验证就不能作为"模型学会适应"的证据。
- 附带产出: `tools/eval_yaw_head_ops.py` 逐留一工况打印 (预测 argmax 的实测 Δz / 实测可成功集合 /
  实测最优值) — 可复跑, 别现场手算。

## 6. 本轮踩坑
1. **argparse 传负数列表**: `--phis -45,-30,...` 被当作选项 →
   `error: argument --phis: expected one argument`, 且被 grep 过滤后表现为"脚本无输出"
   (看起来像脚本崩了) → 用等号形式 `--phis=-45,-30,...`。
2. **改函数签名要清残留引用**: 探针函数去掉 `log` 参数、函数体仍留 `log = log or ...` → 运行即
   `NameError`; 改签名后全函数扫一遍。
3. **权重版本切换要同步 CI 断言**: 重训出新权重文件名 (v1→v2) → CI 的下载 URL/md5/`--add-data`/
   构建后校验计数**四处**一起改 (本轮用脚本批量替换 `_v1.pt`→`_v2.pt` + md5, 改后打印替换次数核对)。
4. **旧结论作废要跟着改**: "打分退化/无信息" 的旧记录在监督补齐后失效 — 技能/版本记录同步更新,
   否则后续会话会拿旧结论否定新结果。
