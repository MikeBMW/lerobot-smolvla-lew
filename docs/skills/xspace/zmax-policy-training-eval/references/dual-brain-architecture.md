# 双脑架构调试全路径 (2026-08-10, MLP 左脑 + 世界模型右脑判断)

`tools/train_dual_brain.py` — 从 0/8 到 5/8 抓起的完整迭代记录。每个版本的行为差异
（d_hp/peg_z 轨迹）是判断"哪一环在起作用"的关键证据。

## 架构终版

```
左脑 LeftBrainMLP(39→512→512→512→4): 动作回归 (800 epoch, seed 42)
右脑 RightBrainWM(39+4→256→256):  pred_next(39) + contact_head(1, sigmoid)
训练 loss: 左脑 MSE + 右脑 (next MSE + 0.5×BCE)
评估融合: contact_p>0.5 且 d_hp<0.06 → act[3]=0.6 (夹持) + act[:3]*0.1 (锁定)
          else → act[3]=-1.0 (张开)
接近偏置: d_hp>0.10 → act[:3] = act[:3]*0.3 + clip((peg-hand)*2.0, -1, 1)
```

## grab_effort 探针 (metaworld 夹爪控制真相)

```python
# 官方专家 SawyerPegInsertionSideV3Policy._grab_effort:
#   xy 距离 > 0.04 或 z 差 > 0.15 → 返回 -1.0 (张开)
#   否则 → 返回 0.6 (夹持力)
# 结论: grab_effort 正值 = 夹持, 负值 = 张开 — 与直觉相反!
# 验证夹爪是否真的动: 看 env.data.qpos[-2] 变化, 或看 peg 是否跟随手 (peg_z 升高)。
# 动作[3] 是增量位置控制, 不会直接改 qpos 快照。
```

## 训练稳定性 (为什么固定 seed + 800 epoch)

- 400 epoch 训练两次: loss 0.1586 / 0.1076 — 接近质量漂移, 同评估逻辑 0/8 vs 5/8。
- 800 epoch: loss 0.0895-0.1076 稳定, 3/8 复现。
- `torch.manual_seed(42) + np.random.seed(42)` 在 main() 开头, 数据采集和权重初始化都固定。
- ⚠️ 每次重跑脚本会重新训练并**覆盖** dual_brain.pt — 好模型会被坏模型覆盖, 迭代时先备份
  或加 --eval-only (只加载评估)。

**⚠️ 别过度固定 seed (2026-08-10 实测, 老倪要求\"训练也加seed固定连env数据采集\" → 变差)**:
- 在 collect_data 里给每 ep 加 `np.random.seed(base_seed+ep)` + `torch.manual_seed(...)` +
  `env = make_env(base_seed+ep)` → **左脑 loss 0.0857→0.1575, 评估 8/8+7/8 → 7/8+4/8**。
- 根因: 全局 np seed 固定改变 metaworld 内部随机 (专家动作/物体初始分布) → 训练数据分布
  变化 → 模型质量下降。**env 数据采集的自然多样性 (make_env(ep) 用 ep 种子) 是泛化来源,
  固定它反而损害**。
- main() 里的 torch.manual_seed(42)+np.random.seed(42) 已足够保证训练确定性 (重跑 loss
  逐位一致); **别再动 env 采集种子**。回滚 (git checkout tools/train_full_pipeline.py)
  后立即复现 8/8+7/8 — 且老倪在 VSCode 终端自己跑同一脚本也是 8/8+7/8 (loss 0.0857),
  跨用户可复现, 无需 seed 增强。

## 插入控制器为什么破坏抓取 (v7 教训)

grasped 标志在 `contact_p>0.5 且 d_hp<0.06` 时置 True — 但这个时刻 peg 可能还没真被夹起
(夹爪 0.6 需要几帧才抓住)。插入控制器 `grasped and peg_z-peg_z0>0.02` 的条件看似安全,
但**夹持未成功的帧** (d_hp 贴住但 peg 没跟随) 会走插入分支把把手拉向 hole → peg 掉回桌面
→ 阶段判定回落 → 循环失败。**结论: 抓取 (5/8) 和插入 (状态机) 分两个独立迭代, 别合并。**

## 双脑+状态机融合 (train_full_pipeline.py, 抓起 8/8)

**方法论: 状态机逻辑与动作质量分开验证。** 三组对照一次跑清差距在哪层:

| 组合 | 抓起 | 插入 | 说明 |
|---|---|---|---|
| 官方专家独立 (对照组) | 7/8 | 7/8 | 专家自身 85% 基准 |
| 状态机 + 专家动作 | 8/8 | 7/8 | 状态机转移逻辑全对 (接近→抓取→抬起→转移→插入→完成) |
| 状态机 + 学习模型 | 0/8 | 0/8 | 差距全在动作层 (抓取/转移控制器质量) |
| 双脑抓取 + 状态机插入 (终版) | **8/8** | 0/8 | 双脑宽松抓取条件 + 状态机接管抬/转/插 |

状态机转移条件迭代 (每改一处涨一截):
- LIFT→TRANSFER 用 `peg_z > hole_z + 0.03` → **永远不满足** (专家插入完成时 peg_z≈hole_z,
  从不抬到孔上方 3cm; 专家路径是抬一点→水平移→下降插)。改 `peg_z > peg_z0 + 0.05` → 7/8 插入。
- GRASP 条件用严格 `xy<0.04 且 z_err<0.01` → 0/8 (peg 被手推走, z 永远贴不住; 且 ALIGN/
  DESCEND 分阶段下降太慢 dz*3.0 100 步才 10cm, 满速 -0.6 又压 peg)。**换回双脑宽松条件
  (d_hp<0.06 + contact_p>0.5) → 8/8 抓起** — 单阶段偏置接近 (act*0.3+delta*2.0) 优于
  分阶段对位/下降控制器。
- 转移卡死 (插入 0 根因): TRANSFER 动作生效 (act=[-0.6,0,0], peg 在动) 但 d_xy 卡 0.15,
  peg_z 0.09~0.115 接近台面 → **抬起高度不够, peg 蹭台面水平移不动**。修: 抬起
  peg_z0+0.08+ 再转移, 或真机力控夹爪绕开。

**状态机动作执行 (终版, 每状态一个控制器)**:
```
APPROACH: act[:3]*0.3 + clip((peg-hand)*2.0) ; act[3]=-1.0     # 双脑偏置接近
GRASP:    contact_p>0.5 且 d_hp<0.06 → act[3]=0.6, act[:3]*=0.1 # 夹持+锁定
LIFT:     [0,0,0.5], act[3]=0.6                                  # 垂直抬起
TRANSFER: (hole-peg)xy 方向归一×0.6, act[3]=0.6                  # 水平转移
INSERT:   [0,0,(hole_z-peg_z)*2.0 clamp ±0.6], act[3]=0.6        # 下降插入
```
状态转移只判物理量 (d_hp/d_ph/peg_z), 动作由状态选控制器 — 与层级策略"决策器+阶段MLP"
同构, 但控制器是规则/双脑而非阶段 MLP (阶段 MLP 反归一化动作爆炸 + 抓取学不会夹起,
见 SKILL.md 层级策略节)。

**教训**: 状态机+学习模型 0/8 时别怀疑状态机 — 先跑"状态机+专家动作"对照, 逻辑对错
一测便知; 差距在动作层时回头用已验证的组件 (双脑宽松抓取), 别重造轮子。
