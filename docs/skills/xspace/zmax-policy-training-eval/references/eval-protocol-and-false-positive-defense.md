# 评估协议 + 假突破防御 (2026-09-10 实测, 血泪教训)

**触发**: 任何要汇报"模型变好了 / 追平了 / 有提升了"的时刻; 或对比两个执行者 (模型 vs 解析链) 时。

姊妹文件: `l3-official-inference-and-insert-fixes-20260910.md` (官方处理器管道 + 插入修复)、
`l34-joint-baseline-lessons.md` (32.1% 基线 + 失败模式分类)。本文补的是**评估方法论**。

---

## 1. 🚨 核心事件: 单次 5/6 → 多重复复核 0/15 (差点上报假突破)

一次 6 seed 单跑里, L3 模型 (SmolVLA-Lew) 闭环 **5/6 成功**, 步数 343-390, 与解析链同 seed 集
的 5/6 一模一样 → 一度按"模型首次追平解析链"上报, 还录了视频、写了版本里程碑。

随即做了多重复复核 (**5 seed × 3 重复**, 同一脚本同一口径):

| 执行者 | 结果 | 步数特征 |
|---|---|---|
| L3 模型 | **0/15** | 全部 600 步超时 |
| 解析链 (对照) | **15/15** | 385/385/385、390/390/390、346/346/346 — **逐次完全相同** |

→ 之前那个 5/6 是**特定进程布局下的单次侥幸**。同 seed 在新进程里换一个布局就全败。

**两条结论**:
- 解析链在**同一进程内是确定性的** (3 次重复步数逐位一致) — 所以对照组的"稳定"不是偶然;
- 模型成败**强烈依赖进程布局** (metaworld 每进程布局漂移, 同 seed 跨进程不同) — 所以模型这边
  单次结果毫无统计意义。

**协议 (报"提升"前必须全做)**:
1. 每 seed **≥3 次重复** (不是每 seed 跑一次凑够 seed 数);
2. **对照组 (解析链 / 旧模型) 在同一脚本、同一口径、同一批 seed 下跑** — 换脚本、换 seed 集、
   换 max_steps 的对比一律作废;
3. 用**逐 seed 分布** (wins/reps) 汇报, 不是只报总数百分比;
4. 拿不到对照组就先别下结论 — "模型 5/6" 单独看毫无意义, 和解析链 5/6 并排看才有信息。

**这次的自我检查点**: 同一个 session 内我先得到 5/6、后得到 0/15。**如果只发前者, 就是误导**。
一旦出现"比预期好得多"的结果, 第一反应必须是"多重复 + 对照组", 而不是发喜报。

## 2. 可复用评估脚本

见 `scripts/eval_reliable.py` (本 skill 内)。用法:

```bash
# 模型 (xyz 由模型输出, gripper 仍由状态机管)
MUJOCO_GL=egl SS_MUSCLE=0 EVAL_MODE=model EVAL_SEEDS="104,0,6,101,7" EVAL_REPS=3 \
  SS_L3=1 SS_L3_CK="outputs/train/<dir>/checkpoints/last/pretrained_model" \
  gui-venv311/bin/python -u scripts/eval_reliable.py
# 对照: 解析链 (同一脚本, 去掉 SS_L3)
MUJOCO_GL=egl SS_MUSCLE=0 EVAL_MODE=analytic EVAL_SEEDS="104,0,6,101,7" EVAL_REPS=3 \
  gui-venv311/bin/python -u scripts/eval_reliable.py
```

要点: 每次 `run()` 都**新建 sim 实例** (= 新布局, 这才是"多次尝试"); 逐 seed 打印
`wins/reps` + 成功步数; `EVAL_MODE=analytic` 时 `os.environ.pop("SS_L3")`。

## 3. 推理图像尺寸 = 训练尺寸 (smolvla_lew 是 **128**, 不是 480/64)

- 训练数据采集时图像被 **PIL LANCZOS 缩放到 128×128** 后编码 → 推理必须**同样 resize(128,128)**。
- ❌ 直接喂 `env.render()` 的 480 原图 → 输入分布与训练不一致 → 模型表现得"完全不会"
  (这是 0/6、0/15 那批失败的头号真凶之一, 修之前三轮训练全部白跑)。
- ⚠️ 本 skill 的「评估管道铁律」第 2 条写的是 **SmolVLA 64×64 / ACT 128** — 那是**另一批
  (旧 smolvla/ACT) 的 config**。**smolvla_lew (v8/v8_d1/v10) 走 128**。判别: 直接看训练数据
  `videos/observation.image/*.mp4` 的帧尺寸 + 采集脚本里的 resize 值, 别照抄铁律表。
- **语言指令必须读数据集 `meta/tasks.parquet` 的原串** (动态读), 硬编码任务串易错;
  留 `SS_L3_TASK` 环境变量覆盖 (将来接 L4 自然语言指令)。

## 4. 规则修复的收益递减 → 判断物理上限

| 版本 | 28 seed 结果 |
|---|---|
| 三项修复 (步数上限 500→1000 / 插入深处夹持误判 / 滑移量选回退目标) | **13/28 = 46.4%** |
| 再加「夹持态回退守卫」(已夹持禁回对位, 防追漂移目标死循环) | **12/28 = 42.9%** ❌ 无提升 |

- 守卫本身修的 bug 是真的 (seed80 夹爪匀速漂走 0.3m、629 帧不动、水平距离恒 94.5mm — 因为
  对位目标是 `pg(实时光模块位置)+悬停高`, 夹持时 pg 随夹爪动 = 追不上的目标), 但**总体不涨**。
- 剩余失败 seed 的根因是**物理**: 早前实测「R0 site 真值对齐也插不进 (peg 头横向偏孔口
  15.6mm vs 孔间隙 2mm, 无倒角刚体)」→ 47% 这条线不是算法没调够, 是**无倒角 + 2mm 间隙的硬约束**。
- **判断规则**: 当连续 2-3 个"合理"的规则修复都换不来总体提升, 而逐 seed 分析显示失败集中在
  接触/几何极限上 → 停手, 别再刷规则。仿真里的 ~43-46% 视为**物理下限**, 真机 (倒角 + 力控柔顺)
  才是提升方向。

## 5. "L3+L4 联合"的三种形态 — 全部实测无增益 (别再重走)

| 形态 | 实测结果 | 失败原因 |
|---|---|---|
| 纯流形 6D → 动作 decoder | val loss 反升; gripper MAE 0.16 | 流形是几何导出量, 动作→流形的映射病态, 单帧流形不含"该往哪走" |
| **共享编码器 + 流形辅助头 (多任务)** | 仅动作 MAE **0.00828** vs 联合 **0.00878** | 流形是 obs 几何的**确定性函数** → 辅助任务信息冗余, 还分散编码器容量 |
| DAgger / 残差 (专家 = 解析链) | 闭环仍 0; 残差标签 Δu≈0 无料可学 | **没有比解析链更优的专家信号** → 模仿的天花板 = 老师 (解析链), 闭环里还追不上 |

- 第 2 行就是本 session 的 A/B 消融: `obs(43D) → 共享编码器 → [动作头, 流形头]`,
  loss = `action_MSE + 0.3·manifold_MSE`, 3705 帧 14 个成功 seed 轨迹 (held-out 布局验证)。
- **关键区分**: 离线动作 MAE 0.008 (归一化空间, 学得会) **≠ 闭环可用** (仍 0/15)。
  瓶颈是 **闭环分布偏移 + 布局泛化**, 不是"离线数据不够 / 辅助任务不够 / 步数不够"。
- 要突破只有两条真路: **RL 闭环训练** 或 **真机数据**(真机演示才有比解析链更优的专家信号)。

## 6. 附带: 多会话抢 GPU 的开工前检查

同机多会话共享仓库 + 同一块 GPU。**启动训练/采集前先查占用进程**:
```bash
ps -eo pid,etime,args | awk '/lerobot_train/ && !/awk/'
nvidia-smi --query-compute-apps=pid,used_memory --format=csv
```
本次重复启动同配置训练 → 两个进程抢卡 → `torch.OutOfMemoryError` (896MB 申请失败, 另一个进程
已占 5.35GB) → 我的训练直接崩。**发现别人已在跑同一任务时, 不要重复启动**; 要停就先确认
那不是自己的进程、且确认对方任务已无价值 (本例 R2 训练基于"0% 模型的 rollout", DAgger 无法自举,
已证无效, 才停)。
