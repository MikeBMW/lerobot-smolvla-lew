## 一、★ 根因: 两套数据的 obs 同名不同义

```
v5/v6 h5 的 obs 来源 (tools/intact_domain_dataset.py:96 原文):
    "observation": "env 原生 o[:39] (与引擎/L3 同源口径)"
→ 存的是 metaworld **env 原生观测**

L5 造数据写的 obs:
    引擎 tr["obs"]（引擎内部状态向量, cur18+prev18+target3）
→ 两者都叫 39 维, 但内容完全不同

实测逐维对比 (各 3000 帧):
    dims 7/8 : v6 std 0.000/0.000      vs  L5 0.077/0.067
    dim 10   : v6 mean 0.999(近似常数) vs  L5 mean -0.276
    39 维均值最大差 **1.275**
→ 拿它们做留出集 = 拿两种语义的数据比对
   ⇒ 指标劣化里混的是"数据不匹配", 不是"模型不行"
```

### 铁律（这几条比任何超参都重要）
```
① **跨数据集比对前先跑逐维口径校验**:
      np.abs(mean_a - mean_b).max()      # 量级 >> 0 ⇒ 不同源 ⇒ 评估直接作废
   维度同名/形状相同都不算同源 —— **必须验数值分布**。
② 造数据前先找**训练集的实际生成脚本**并照抄它的 obs/action 约定:
      grep -rn '"observation"' tools/*dataset*.py     # 注释里"同源口径"指什么
③ 引擎 `tr` **不记录** env 原生 obs（run() 没存）→ 要造同源数据必须
   先给引擎加记录（或从 `sim.env` 直取）。**别想当然拿 `tr["obs"]` 顶替**。
④ 结论被证据推翻时**当场撤回并在汇报里说明**，别留着 —— 本次撤回后用
   同源留出集重做，才拿到可信结论（§三）。
```

## 二、L5 造数据的两处必修（否则整批报废）

### 1. `--vision 1` 必须开，否则 pixels 全零（本次 75k 帧报废）
```
引擎 `_key_frames` **只在 vision 开启时采集**（在 perception refresh 内,
且需 `_kf_cnt >= 6` 同阶段连续帧才开始记）
→ vision=False 造出的 pixels 全是 0

验证真渲染: 非零率 > 0.99 且均值 ~130
            (全零 / 均值 0 → 废数据, 重造)

诚实标注: pixels = "该阶段的关键帧按阶段复用", 不是每步独立渲染。
```
obs/action 即使 vision=False 也是真值（非零率 74% / 88%）→ 可用于动作/世界模型，
但 L2 感知通道需要真渲染。

## 三、同源留出集才拿到了可信结论

**做法**：v6 自身切 train/holdout（同 convention, env 原生 o[:39]）。

### 三组实验，同一结论（同源留出）
| 配置 | 留出 L4观测MAE (step1 → 250/500) | 判定 |
|---|---|---|
| 全参微调 | 18.1 → **45.2**（2.5× 差） | 过拟合 |
| 冻结基座 + 强正则 (lr 3e-4, wd 1e-2) | 11.9 → **402.7**（34× 差） | 过拟合（更糟） |
| ~~L5 变体当留出~~ | ~~13 → 441~~ | **作废**（obs 源不同, §一） |

```
→ **三组一致崩坏 ⇒ 可排除 超参 / 冻结 / 限幅 三个因素**
→ 关键线索: 训练 loss 在 **<14% epoch**（~500 步 × batch128 / 227k 帧）内压到
   1e-3 ⇒ 训练目标里有"捷径", 不是学到规律
→ 真瓶颈: **数据多样性 / 训练目标的可泛化性**
   → 该动的是数据与任务定义, 不是继续调超参
→ 未证明提升 ⇒ **不进默认档**（用户门槛）
```

## 四、留出集评估硬纪律（补齐）

### 1. 先排除"切分方式"的影响
```
顺序切最后 10%  → 可能引入时序/采集顺序泄漏
改用**随机切分**: perm = rng.permutation(N); ho = np.sort(perm[:n_ho])
   (h5py 帧索引必须升序)
```

### 2. 平凡基线必测（否则不知道该跟谁比）
```
留出集上算:
   动作恒输出 0        的 MAE
   观测恒输出训练均值  的 MAE
模型训完若**比平凡基线还差** ⇒ 训练在**破坏**而非学习
```

### 3. 动作输出必须结构限幅
```
动作合法域 [-1,1]; 不限幅时 OOD 上 L1 可达 **2.703**（超出合法域上界 35%）
   ⇒ 输出无界不可控 ⇒ 产物不可部署
修: u = torch.tanh(u)        # 结构上保证有界
实测: 留出 MAE 2.703 → 0.845（立刻优于随机基线 1.06）
```

### 4. best-by-holdout 保存（"训到最后" ≠ "最好"）
```python
每 --stats 步评一次留出 → 只在改善时 save_ckpt
本次 best ckpt ≈ **step 1**（即训练没带来任何泛化收益）—— 这个事实本身就是结论
```

### 5. 三个工程坑（各浪费一轮）
```
① h5 拷贝必须保压缩: v6 是压缩存的(4.1GB), create_dataset 不压 → 11.3GB（3× 膨胀）
   修: create_dataset(..., compression="lzf")（或照抄源数据集 d.compression）
② 内联 `python -c` / `bash -c` 多层嵌套引号会崩:
   bash: unexpected EOF while looking for matching `"'
   修: 复杂脚本写成 .py 文件再跑，别在 -c 里塞多层引号
③ `ep_len` 这类"按 episode"的 1 维键不能按帧切
   修: 只切 ndim>=2 且 shape[0]==N 的按帧键（action/observation/pixels/skill_ctx）
```
