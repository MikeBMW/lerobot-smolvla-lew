## 一、🚨 obs 口径: 引擎里有**两个都叫 39 维**的向量

```
tr["obs"]         = fuse_sensors(concat([cur18, prev18, target3]), force, tactile4)[:39]
                    ← 引擎内部 fused 观测（我一开始误用的就是这个）
env._get_obs()[:39] = metaworld env 原生观测
                    ← **v5/v6 训练数据集用的是这个**
                      (tools/intact_domain_dataset.py 原文:
                       "observation": "env 原生 o[:39] (与引擎/L3 同源口径)")
```

**实测辨明**（逐维比对 3000 帧均值）：

```
平均逐维均值差:  tr['obs'] = 0.1793   ·   env._get_obs()[:39] = 0.0273
关键维度证据:
  idx 7,8 : 参考 = 0.000±0.000  ←→  env = 0.000±0.000 ✓   tr = 0.011/0.485 ✗
  idx 10  : 参考 = +0.999       ←→  env = +1.000      ✓   tr = -0.243      ✗
→ **同源口径 = env._get_obs()[:39]**
```

**代价**：误用 tr["obs"] 造的数据既不能训练、也不能当留出集；我曾据此得出
"联合训练过拟合/表征被冲垮"的结论 —— **该结论因口径不一致而作废并撤回**
（撤回过程见 `references/joint-training-holdout-eval-corrections.md`）。

### 非侵入式修复（不改引擎文件）
引擎 `run()` 的 tr 里**不记录** env 原生 obs，但可以挂运行时钩子：

```python
rec = []
orig_fuse = sim.perception.fuse_sensors          # ★ 每步恰好调 1 次 → 1:1 对齐轨迹步
def patched_fuse(visual39, force, tactile4):
    rec.append(np.asarray(sim.env._get_obs(), dtype=np.float64).ravel()[:39].copy())
    return orig_fuse(visual39, force, tactile4)
sim.perception.fuse_sensors = patched_fuse       # 必须在 sim.run() 之前装
tr = sim.run(max_steps=steps)
```

**钩子位置是关键**：挂 `env._get_obs` 会每步收到约 2 条（实测 340 步 → 683 条）
→ 与轨迹步对不齐；挂 `fuse_sensors` 才严格 1:1。

修复后核验：逐维均值差 **0.1793 → 0.0286** ✓ · 像素非零率 0.998 ✓
（idx 3 仍差属正常：那是工件高度维，变体高度本来就不同）

## 二、跨域 A/B：测"造数据有没有用"的唯一正确实验

```
臂 A: 训练 = 仅 v6_train_rand (78,435 帧)                → 留出 = **L5 未见变体** (15,000 帧)
臂 B: 训练 = v6_train_rand + l5_train (30,000 帧, 按变体切) → 留出 = **同一 L5 留出**
控制: 同 batch / 同步数 / 同 seed / 同留出集
判据: B 显著优于 A ⇒ 造数据真有增量; 持平 ⇒ 诚实报"当前变体多样性不足以带来增量"

⚠️ 反面教训（我先犯过）: 用"同域留出(v6 自身)"测 L5 数据 → 指标持平 → **测不出增量**。
   留出集必须落在**被测数据的域**上, 否则实验设计本身无效。
⚠️ 切分方式: L5 是 150 变体 × 300 步的连续块 → 前 100 变体训练 / 后 50 变体留出
   （按**变体**切, 不按帧切 —— 相邻帧高度相关, 按帧切会泄漏）。
```

同域对照（统一主干，batch 256，800 步）：

| 训练数据 | 留出 L4 认知预测 | 留出 动作 |
|---|---|---|
| 仅 v6 (78,435 帧) | 0.011 | 0.048 |
| v6 + L5 (123,435 帧) | 0.011 | 0.051 |
→ 同域留出上**无差异**（可预期）；L5 的增量必须在 **L5 域留出** 上测（见上设计）。

## 三、本技能自带的可复用脚本

- **`scripts/identify_obs_convention.py`** — 跨数据集比对前**必跑**。
  同一步采两个候选向量 → 与参考 h5 逐维比对 → 直接判定哪个同源。
  实现同本文 §一 的非侵入钩子（挂 `fuse_sensors`）。
- **`scripts/h5_rand_split_with_baselines.py`** — 随机切分 + **打印平凡基线**（判据本体）。
  ```
  动作恒定输出 0        : MAE 0.2362
  动作恒定输出训练均值   : MAE 0.0947
  观测恒定输出训练均值   : MAE 0.0366   ← 认知预测的及格线
  ```
  两个设计点: ①**随机**切分（"最后 10%" 有采集顺序泄漏风险）
             ②写盘 **lzf 压缩**（不加 → 4.1GB 写成 11.3GB, 2.7×膨胀）
               + **chunk ≤ 256**（chunk 512 → 随机取 1 帧要解压 75MB → 训练饿 GPU）

## 四、一条贯穿性教训

```
**跨数据集比对前, 先验 obs/action 口径; 评估前, 先算平凡基线。**

这两件事都不是"优化", 是**让数字有意义**的前提 ——
省掉它们会得到一整套自洽但完全错误的结论（并浪费数轮实验）。
```
