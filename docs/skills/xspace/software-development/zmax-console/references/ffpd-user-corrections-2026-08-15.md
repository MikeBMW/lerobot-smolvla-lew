## ⑤ 性能指标时间列 = 工程节拍预算, 不是特征根 Ts

Ts=4/(ζωₙ)×1.2 在低增益阶段算出 24.37s 远超 15s — 数学一致但工程错
(节拍由轨迹规划决定, 不是特征根)。
改: 每阶段预算时间 接近3.5/抓取0.5/抬起1.5/转移2.5/插入2.0s,
总节拍 = 动作 10.0s + 待机/完成 1.0s + **扫码/AOI 预留 2.5s** (用户要求默认 2~3s)
= 13.5s < 15s ✅ (余量 1.5s)。
速度/加速度/能量按预算时间算; 特征根 Ts 降级为稳定性参考。
三处同步: PerformanceWidget.refresh_metrics / RunSummaryWidget.refresh_summary /
EngineeringReqWidget.export_pdf — 改一处必须三处一起改。

## ⑨ 数学分析 = Z700 模块级数据分析 (用户: "这是你的技术框架")

"数学分析, 要从实际的Z700 前馈, 双脑, 状态机, 动作等模块, 给出完整的数据分析过程"。
报告第五章必须逐模块 (与画布节点一一对应):
数据流链路: 视觉/触觉 → 感知链(观测) → 双脑(预测) → 状态机(决策) → 动作(执行) → 末端
① 感知链 — 观测模型 y=C·x, K_obs=1.0 (39D状态→位姿)
② 双脑 — 前馈预测, 左脑MLP(u_ff 4D) + 右脑WM(next_obs+contact), K_ff
③ 状态机 — 比例决策, Kp (6阶段增益调度)
④ 动作 — 微分执行, Kd (限幅±0.6=饱和阻尼)
⑤ 被控对象 — m·ẍ+b·ẋ+k·x=F(t), m/b/k
组合: 前馈通道 F_ff=K_obs×K_ff (回路外) + 反馈通道 C(s)=Kp+Kd·s (回路内)
→ 拉普拉斯 → 闭环传函 → 特征方程 → 特征解/ωₙ/ζ → 增益调度表。
