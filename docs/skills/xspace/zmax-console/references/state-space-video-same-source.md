# 状态空间 3D 视图 与 操作视频「同源」架构 (v3.0.0, 2026-08-25)

老倪三连反馈驱动的重构:
1. 「3D空间视图，与操作视频的视角不一样」→ 先按视频相机换算了角度 (v2.8.2)
2. 「没有从初始位置到抓取插销的过程」→ 状态空间仿真补八阶段 + 插销独立 (v2.9.0)
3. 「角度还是不一样，而且动作、轨迹都不一样」→ **根因不是参数, 是数据源**

## 根因 (必须先认这一条)
- 操作视频 = **metaworld MuJoCo** + 策略的真实 episode (gen_insert_video.py / 双脑)
- 3D 视图 = **state_space_sim.py 纯 numpy 引擎**自己的轨迹, 且旧 obs 里 `peg 位置 = 末端`
  (等于开局手里已握着销 → 永远没有"去抓销"的过程)
- 两套物理 + 两套控制器 + 两套随机化 ⇒ **调参数永远对不上**。角度能对齐, 轨迹不可能。

## 真解: 同源 episode (唯一正确做法)
`tools/gen_ss_metaworld_episode.py` — 状态空间六层**真实源码**直接驱动 metaworld:
```
obs (env 真实状态) → perception.fuse_sensors → parallel.FeedforwardAccelerator(u_ff)
  ‖ AdaptiveStateEstimator → dynamics.PriorDynamicsPredictor → cognition.state_correction
  → cognition.ActionModulator.decide (八阶段+否决) → safety.saturate → execution.RobotExecutor
  → action[:3] = u·ctrl_dt/action_scale → env.step()
```
一次运行同时产出:
- `reports/ss_episode_latest.npz` — 每步 hand/peg/销头/孔位 + 八阶段 + **全部处理层向量**
  (u_ff/u_fb/u_fuse/u_limit/u_exec/latent/corrected/residual/z_k/v) + meta(相机外参/几何)
- `reports/ss_episode_latest.mp4` — 同一条 episode 的 corner2 画面 (= 操作视频)
→ 3D 视图读 npz, 视频是同一条 episode ⇒ 轨迹/动作/视角三项天然一致。
GUI: `open_ss_3d()` 优先读同源 trace, 找不到才退回 numpy 引擎 (并在终端明说不同源);
`_start_video_export()` 也改调这个生成器。

## 相机精确对齐 (不是估算)
- metaworld corner2 实测: `cam_pos(1.3,-0.2,1.1)`, 视线 `(-0.746,0.458,-0.484)`, fovy 60
- 视频里 `np.rot90(k=2)` ⇒ 等效基底 = (**-right, -up**), 视线不变
- pyqtgraph 侧: `GLViewWidget(rotationMethod='quaternion')` +
  `setCameraPosition(rotation=camera_quaternion(fwd, right, up))`
  (R 的行 = [right, up, -fwd]; viewMatrix = T(0,0,-d)·R·T(-center))
- center = 相机轴上锚点投影, distance = 该投影距离 ⇒ 位置也一致
- ⚠️ **pyqtgraph `opts['fov']` 是水平视场**, metaworld `fovy` 是垂直 (源码 `r=near·tan(fov/2); t=r·h/w`)
  → 必须 `fov_h = 2·atan(tan(fovy/2)·w/h)` 换算, 且窗口 resize 要重算;
  不换算时非正方形窗口下物体投影**偏 60px** (实测)。
- 投影只保留唯一实现 `ss_dreamview.project_world(view, p)`, 探针复用 (防口径分裂)。
  离屏无 GL 时不能调 `view.projectionMatrix()` (本版需 region/viewport 参数 + 抛 OpenGL 版本异常)。

## 八阶段认知状态机 (cognition.ActionModulator, 6→8)
`接近 → 对位 → 下降 → 抓取 → 抬起 → 转移 → 插入 → 完成` (与 gen_insert_video 真机状态机同构)
推进证据: 手-销水平距离<0.06 / <0.02 → 力觉接触**或**到达抓握位姿 → 夹持建立(gripper>grasp_th)
→ 提起>0.08m → 销头对准孔口<0.02 → 插入深度<0.004
- `gripper_cmd()` 夹持**锁存**: 抓取阶段起恒 1.0。听前馈层"近距即闭合"会在对位/下降就夹上
  → 抓取阶段 1 帧跳过, 3D 视图看不到"张开→夹紧"。
- `grasp_th` 必须按被夹物体标定: 实测 metaworld 夹住 0.03m 插销闭合度**饱和在 0.70**,
  写死 `>0.8` 永远等不到 → 卡抓取 (1733 帧原地不动)。
- 下降→抓取 双证据 (力觉 **或** 几何到位): 张开的夹爪下到销两侧可能零接触。

## 物理层语义 bug (状态空间 numpy 引擎, 2026-08-25 修)
六层里 u 是**速度指令** (前馈 `Kp·(target−pos)` 限幅 ±0.5 m/s; 估计器 `predict` 用 `B=dt` 按速度积分),
但物理曾按**加速度**积分 `v += u·dt` → 双积分无阻尼: 位置比例控制**必然过冲发散**
(实测末端冲过孔位 0.13m 停不下), 还给估计器制造假残差。
正确: 一阶速度伺服 `v ← v + (u − v)·dt/τ`, τ=0.08s (真实执行器惯性)。

## 阶段子目标进 obs (感知层职责)
`obs[36:39]` = **当前阶段子目标** (不是固定孔位) — 前馈层就是按它比例引导:
接近(销上方0.10) → 对位(0.055) → 下降/抓取(抓握位姿0.022) → 抬起(台面+0.16)
→ 转移(孔口 − **真实夹持偏移** + 0.03) → 插入(goal − 真实夹持偏移)
⚠️ 转移/插入必须用**真实夹持偏移** `peg_head − hand`, 不能用名义 `PEG_HEAD_OFF`:
抓取锁存发生在"手比抓握点高 12mm"时, 用名义值会残留 12mm → 永远差最后 4mm 判不了完成。

## 接触力必须分两路 (v3.0.1, 2026-08-25 实测踩坑)
症状: 抬起/转移/插入 三段 **接触概率恒 1.00、残差模恒 1.0001** → 调度器收到的是常量,
「接触」信号彻底失去区分度 (夹住插销后就永远"接触中")。
根因 (两层):
1. 夹爪 body 清单**漏了真正夹住插销的指垫** `rightpad` / `leftpad`
   (metaworld Sawyer 夹爪 body: `hand` / `rightclaw` / `leftclaw` / **`rightpad`** / **`leftpad`** /
    `right_hand` / `right_wrist`) → peg↔指垫的夹持力被归类成"环境接触" → f_env 饱和
2. 夹爪各连杆之间的**自碰撞**也被算成环境接触
正确做法 (`contact_forces()`):
```python
pair = {b1, b2}
if pair & peg_ids and pair & hand_ids:  f_grasp += mag   # 夹持 (判夹住没有)
elif pair <= hand_ids:                  continue         # 自碰撞 → 丢弃
else:                                   f_env  += mag    # 环境 (判碰孔沿/插进去)
```
进 obs 触觉 + 残差的只能是 **f_env**; f_grasp 单独一路做夹持证据。
修后实测 (才算有物理意义):
| 阶段 | 环境接触 | 夹持力 | 接触概率 | 残差模 |
|---|---|---|---|---|
| 接近/对位/下降 | 0.039 | 0.000 | 0.58 | 0.041 |
| 抓取 | 0.058 | 0.071 | 0.60 | 0.059 |
| 抬起 (悬空) | **0.004** | 1.000 | 0.53 | **0.014** |
| 转移 | 0.032 | 1.000 | 0.55 | 0.043 |
| 插入 (顶孔沿) | **0.206** | 1.000 | **0.62** | **0.213** |
诊断工具: `MUJOCO_GL=egl gui-venv311/bin/python tools/probe_contacts.py`
(把夹着销之后的**真实接触对按 body 名字 + 累计力**打出来 — 别猜 body 名)

## 状态估计层的画法 (老倪: "为什么显示一堆点")
`latent_vec` = 卡尔曼后验 x̂ (4D: 位置3 + 预测接触力)。原来每帧画一个散点 → 看着是点云,
看不出是轨迹。改成 **紫线(最近 60 帧估计轨迹) + 当前帧大球**。
实测 x̂ 与真实末端偏差: 均值 5.75mm / 中位 4.99mm / 峰值 17.4mm (峰值在"转移"加速段, 预测滞后);
分阶段 接近 8.31 / 对位 4.86 / 下降 3.73 / 抓取 2.53 / 抬起 6.23 / 转移 6.88 / 插入 3.42mm。
解释口径 (给老倪讲这层是干嘛的): ①观测有 ~5mm 噪声 → 估计值提供平滑可用位置;
②x̂ 与观测之差(残差) = "撞到/被挡"的唯一线索, 不靠力传感器也能感知; ③残差超阈值 → 调度器否决减速。

## 「看得懂」比「像素级对齐」更重要 (v3.0.2, 老倪: "还是一堆点不知道啥意思")
⚠️ 严格 1:1 复刻视频机位 = **画面太远**: metaworld corner2 是大远景, 926x764 画布上实测
**96.8% 是空背景**, 插销只有 51px / 夹爪 458px / 末端轨迹 5px → 每个元素都成了"小点"。
对齐了角度 ≠ 用户看得懂。
修法 (三件套, 缺一不可):
1. **自动取景** (默认档): 朝向保持视频机位 (角差仍 0.00°), 只按**实际投影**迭代收紧
   center/distance — `_fit_camera_to_points()`: 每轮投影点云 → 把包围框拉到画面中心
   (沿相机 right/up 平移世界 center) → 按占屏比缩放 distance, 14 轮收敛到占屏 0.72。
   实测 作业区占屏 15%×9% → **71%×45%**, 中心 (0.50,0.50), 零出画; 背景 96.8%→71.8%。
   另留 🎥视频同框 / ⬇俯视 两档按钮 (对比视频 / 看水平对位)。
2. **数据层 additive 穿透遮挡**: 末端轨迹恰好走在机械臂/夹爪实体位置 → 默认深度测试下
   被完全挡住 (只剩 5px)。traj / 四层动作箭头 / YOLO 框 / 估计线 / 接触球 全部
   `setGLOptions("additive")`, 线宽 2→3.5。修后蓝色轨迹 3685~5891px。
3. **文字标签 + 实时数值面板**: `gl.GLTextItem(pos, text, color, font=QFont(...))` 5 个标签
   (末端/插销/孔口/终点/x̂, hand/peg/x̂ 逐帧跟随) + 侧栏 17 行数值 (坐标/x̂偏差mm/夹爪/
   销头→孔/环境接触/夹持力/残差/接触概率/三层 u 模长), 逐帧滚动。
   老倪原话"不知道啥意思"= 缺自解释信息, 光改几何形状没用。
⚠️ 像素校验掩码必须考虑 additive 混色: 叠加后颜色被背景/台面抬亮 (89,166,255)→(130,212,255),
窄容差 (±40) 会漏判成"只有 5px" → 用相对判据 (b>r+55 且 b>g+30 且 b>120) 而不是绝对色距。

## 可视化信噪比铁律 (v3.0.9~v3.1.5, 老倪连问"为什么这么乱/没规律"逼出来的)
⚠️ **画一个量之前先算它的信噪比**: 观测噪声 5mm/轴 vs 末端每步位移 0.35mm → 噪声比信号大
一个数量级, 直接画瞬时值必然"乱且没规律"。实测三个例子 (同源 trace):

| 量 | 瞬时信噪比 | 相邻帧方向变化 | 正确画法 |
|---|---|---|---|
| 后验 x̂ (估计器) | 抖动 0.89mm/步 vs 位移 0.32mm (2.8×) | — | 短窗口(30帧)连线+当前点 |
| 先验 x̂⁻ (预测器) | 确定性增量 0.359 vs 继承抖动 0.901 (**62% 噪声**) | — | **弃用轨迹**, 画「三点两线」: 增量向量(放大30×并标注倍数)+先验点+残差连线 |
| 残差方向 (校正器) | **96% 噪声** | **88.5°** (纯随机 90°) | 主箭头画 **20 帧滑动平均系统性偏差** + 瞬时降级为细半透明线; 标注给**系统占比%** (下降33%→插入45%, 升高=真碰到东西) |

配套原则:
1. **放大必须标注倍数** — 0.36mm 的量按原尺寸看不见, 放大 30× 但标注写真实值 (老倪零容忍糊弄)
2. **动态范围要撑满** — 接触球原用被噪声垫高的 cp (0.58~1.0) 驱动 → 直径只差 10px;
   改用真实力 + **平方根映射** → 8~54px + 102px 脉冲外环 (弱接触 0.07 力也有 20px)
3. **信号要按物理来源分路** — 夹持力(peg↔指垫) vs 环境接触(销头↔孔沿) 各一个球, 别混
4. **排除物理无关基线** — 插销静置台面的自重支撑 1N 被算成"环境接触" → 自由段恒 0.039 底噪; 排除后归零

## 融合律陷阱: 凸组合遇上量级差 = 悄悄砍速度 (v3.1.5, 真架构错)
老倪问"为什么动作调制器速度总是慢一些/方向不如前馈稳" → 挖出控制架构错:
```
原: u = w·u_ff + (1−w)·u_fb      (w=0.3, 力控 0.85)
实测 |u_ff| 0.0903 m/s vs |u_fb| 0.0043 m/s → **量级差 21 倍**
⇒ 凸组合退化成"把前馈砍到 w": |u_fuse|/|u_ff| 恒 29%, 慢通道只贡献 10% 速度,
  却把 0.7 权重的噪声灌进方向 (方向抖动 4.77°→11.28°)
```
正规做法 (三件套一起改, 缺一不可):
1. **前馈+反馈相加**: `u = u_ff + k_fb·u_fb` — 反馈只修正, 不缩放主项
2. **减速用显式阶段限速** `STAGE_V_CAP` (等比缩放保方向): 接近0.35/对位0.12/下降0.05/
   抓取0.04/抬起0.25/转移0.35/插入0.06/完成0.02 m/s — 原来的减速是凸组合意外砍出来的
3. **反馈前滤波** 残差 EMA α=0.15 — 否则等于把 96% 的观测噪声注入指令

实测收益: 方向抖动 11.28°→**5.20°** (追平前馈 4.88°), 速度比 29%→**91~97%**,
episode **1742→647 步**, 八阶段仍全通/插入残距 3.8mm。
⚠️ 附带 bug: 否决路径原返回标量 `0.0` → 下游 `u[3]=…` 会 IndexError (残差从未超阈值所以没炸)。

## 状态机审计与定版 (v3.2.0, 老倪"全局检查算法 + 我要看到你预测的阶段 + 定版")
「状态」= **动作调制器 ActionModulator 内部八阶段状态机**, 证据驱动 (非时间驱动):
| 切换 | 证据 | 阈值 |
|---|---|---|
| 接近→对位 | 手-销水平距离 d_xy | <0.06 |
| 对位→下降 | d_xy 精对位 | <0.02 |
| 下降→抓取 | 接触概率 **或** 到达抓握位姿(几何) | >0.6 / — |
| 抓取→抬起 | 夹持度 gripper | >0.6 (metaworld 饱和 0.70) |
| 抬起→转移 | 提升高度 lifted | >0.08m |
| 转移→插入 | 销头-孔口水平 dist_h | <0.02 |
| 插入→完成 | 销头-终点残距 depth | <0.004 |

**审计工具** `tools/audit_state_machine.py` (逐状态: 时长/证据/阈值/阈值带滞留/限速触顶率/
夹持稳定性/插销回撤/安全层介入/性能分布)。⚠️ 写审计指标本身也会错, 实测踩过 3 个假警报:
1. **触发瞬间的"余量"必然≈0** — 状态机就是在证据刚跨阈值那帧切换 ⇒ 不是风险指标,
   改测"证据在阈值±10% 带内滞留帧数" (滞留久才需要滞回)
2. **插销回撤 >15mm 不等于滑落** — 插入阶段本就要把销压进孔 (实测回撤 21mm 而夹持力
   0 帧丢失) ⇒ 必须"夹持丢失 **且** 回撤"同时成立
3. **统计起点错** — 从"抓取阶段起点"算会把夹爪还没合上的十几帧算成夹持丢失 ⇒ 应从
   夹持真正建立后 (进入抬起) 起算

**审计驱动的算法修正** (三条, 都有实测收益):
- 连续确认防抖 `confirm_n=2` (单帧噪声不能推动状态机; 证据中断则计数清零)

  新增 `STAGE_V_MIN` 最小趋近速度 (接近0.12/对位0.04/抬起0.10/转移0.12) 治末端磨蹭
