# 自绘控件 / 仪表盘 / 数据表的视觉质检缺陷类

用法: 任何 GUI 页(尤其自绘控件页、仪表盘、多列表格)做完, 先离屏出图 → 派 vision 子代理**逐像素**描述(只许报看到的坐标/占比/色值, 不许评价) → 按本表归类 → 修 → 同口径复检 → 重启后现场抽检。
判据一律是**可量的**: 像素数 / 弧长角度 / 对齐 x / 对比度比值 / 行数。

| 质检看到的症状 | 机制(为什么会这样) | 修法 |
|---|---|---|
| 表格一半行"褪色" | 用**前景色**做隔行斑马纹(偶行设灰) ⇒ 与"黄色 warn"同类同亮度, 严重度读不出来 | 隔行改**浅底**(如 #12171e), 文字一律亮色 |
| 列头比内容右移几十 px | Qt 列头默认**居中**而单元格左对齐 | `header().setDefaultAlignment(Qt.AlignLeft\\|Qt.AlignVCenter)` (树 + 每张表) |
| `key: value` 的值列不共线 | 等宽对齐用 `%-14s` 补空格, 而**中文是 2 列宽** | 自写 `_pad(label, w)`: 按 `ord(ch) > 0x2E80` 计 2 宽再补空格 |
| 某列 100% 是 `—`(占位列) | 两路数据**键不同源**: 一路用短名(`heartbeat`)、一路用全路径(`zmax/heartbeat`) ⇒ join 永远落空, 看着像"没数据" | 登记两侧键(全路径 + `split('/')[-1]`); **任何"整列空"先怀疑 join, 不先怀疑上游没数据** |
| 状态条 4 条只看到 2 条 | 空条的**底槽**与面板底色几乎同色 ⇒ 空 = 视觉上"没画" | 底槽用明显区别于面板底色的色(如 #2b3340 vs #161b22); 空条也要能读成"无量程/无数据" |
| 圆环 34% 看着像 36% | `Qt.RoundCap` 两端圆帽各占 ≈4.5° | `Qt.FlatCap`, 弧长严格等比例 |
| 环内小字忽大忽小/基线不齐 | 中文与数字字形高不同(实测 21px vs 14px) | 统一**等宽字体单一字号**, 副标放环内下半部固定位置 |
| 条形长度读不出含义 | 没写分母(条=实测/设计, 而设计 10Hz 的通道 0.5Hz 只占 5%), 也无满格刻度 | 表头写明 `Bar 实测/设计`; 加底槽; 值旁边写百分比; 分母真实量(额定值/限值), 拿不到就别画条 |
| 名称/小字被硬裁 | 按**字数**截断(`[:16]`)而非按**实测字宽** | 量 `QFontMetrics.width` 递减到放得下 + 补 `…`; 全串进 tooltip |
| 卡片左侧一大片空白 | 布局开头一个 `addStretch()` 把内容推到右端, 或控件固定宽不参与分配 | 去掉前导 stretch; 让主体控件 `addWidget(w, stretch=1)` 铺满 |
| 详情/侧栏面板 78% 空白 | 面板等用户点选才填, 首屏没有任何默认选择 | 首刷**自动选中第一行**, 面板立刻有内容 |
| 一排按钮三档高度/字号, 底边错位 | 每个按钮各自写死 `padding/font-size` | 抽一个按钮 QSS 常量(`_BTN_CSS`)统一; 同类表行高也统一 |
| 有的行只有小三角/没有文字 | 父子层级**缩进**造成的错觉(内容列被 indent 占掉) | 先程序化遍历断言"空文本行=0"再改, 别按截图猜缺失 |
| 告警/清单出现完全重复行 | 多规则/多来源产生同文本, 渲染前没去重 | 渲染前按 `(级别, 对象, 文本)` 三元组去重 |
| 表头文字最暗、看不清 | 表头色用了正文的次要灰(在表头底色上仅 ~5:1) | 表头单独一个更亮色(如 #b6c2cf), 正文仍用灰 |
| 暗灰元素几乎不可见 | 次要灰(#484f58)在深底上对比度仅 ~2.3:1 | 提到 ≥3:1(如 #6e7681), 状态点/占位符都要过这关 |
| 自绘控件顺序偶发不对 | 增删控件时只 `insert` **新**控件, 已存在的留在原位 | 每次刷新对**所有**控件按目标序号 `insertWidget(i, w)`(Qt 会移动已有控件) |
| 同一实体出现两条/两盏 | 本机指标与节点列表是两份来源, 未按身份合并 | 按可认出的身份键(如设备名)合并成一条, 并声明合并口径 |
| 顶部通栏中部一大段死区 | 布局用单个 `addStretch()` 顶开, 中间无内容 | 填**真实读数**(行数/过滤状态/帧龄/阶段计数)或收窄; 死区 ≥20% 宽算缺陷 |
| 图上出现孤立 `—`/重复分隔线 | 文本拼接时多了一个空行/多画一条分隔线 | 逐行打印详情文本核对(行数 + 值列起始位置集合是单值) |

## 复检口径(避免"看着好了")
- 同一支离屏探针重跑, 断言: 空文本行 0 · 目标列有值行数 > 0 · 变灰列数 0 · 重复行 0 · 页面宽 == 视口宽 · 横条 max 0。
- 现场再抽一次: 窗口标题带新版本号 + 抓图 + PIL 数**控件特征色像素**(>0 才算画上屏)。
- 探针脚本要先 `_timer.stop()`(自刷新定时器会让探针表现得像卡死), 且 `sys.stdout.flush()` 后再 `os._exit(0)`。
