## 一、本班做完 (已 commit + push + tag **v5.16.13**)

1. **控制台主界面 UI —— 从「看着不对」挖到真根因** (老倪: 「主机面的功能模块太宽了, 不协调」
   → 「不好看, 不要下面的横向拉条。修改, 不要那么宽」)
   - **真根因(实测定量, 不是猜)**: `HardwareCard` 的 `lb_remote/lb_gpu/lb_nodes/lb_src` 是 **24~28px 富文本
     且没开 `wordWrap`** —— 文本一变长就把**整个首页 page 的最小宽撑到 5542px**
     (单个 `lb_remote`「📡 DDS 两端硬件…」`minimumSizeHint=5428px`; `lb_gpu`=1804 · `lb_nodes`=1051)。
     `QScrollArea(widgetResizable)` 于是把 page 拉宽到 5542 (= **1.82× 视口**) ⇒
     ①底部**必然出现横向滚动条**(实测手柄 1459px / 轨 2812px, y1732~1748)
     ②功能模块网格按 page 宽等分 ⇒ 每张卡被拉成 **1752~1795px**(设计最小 260), 卡内文字只占左侧 ~320px。
   - **修法**: ①那几个标签 `setWordWrap(True)` + `setMinimumWidth(1)`(布局不再被 sizeHint 绑架)
     ②`ReflowCardRow` 加**卡宽上限 `max_card_w=470`**(超上限按上限给宽 + 整行居中留白) +
     清历史列的拉伸/最小宽 ③4 个分组框自己也是自适应的(宽屏 **2 列并排** / 中等 1 列 3 卡 / 窄屏 3→2→1)。
   - **实测(离屏 `QT_FONT_DPI=192` = 现场 `Xft.dpi=192` 同口径)**: **页面宽 2796 == 视口 2796** ·
     页面最小宽 2459 ≤ 2796 · **横向条 max=0 = 默认不再需要横拉条** · 卡宽集合 [428] · 分组行 2 列 ·
     卡行 4×3 列 · 整窗冒烟(含侧栏)11 页切换**异常 0**; 修前那条 hbar(手柄 1459px)所在行段已**干净**。
   - 顺手修一个真 bug: **badge 绿底** —— `f"{color}55"` 是 `#RRGGBBAA`, 而 **Qt 的 8 位 hex 是 `#AARRGGBB`**
     ⇒ `#58a6ff55` 被解析成 alpha=0x58 + 黄绿。新增 `rgba_of()` 显式转 `rgba()`。
     实测: 修前角像素 `#a4ff54`(黄绿) → 修后 `#304e76` = 0.33×#58a6ff+0.67×卡底 的理论值(逐层色同样吻合)。
   - 视觉口径铁律(本班实测): **验收 UI 宽度必须看 `页面宽 == 视口宽` + `横向条 max==0`**,
     不能只看窗口/卡宽 —— 这次就是 page 被撑宽 1.82× 才出的一连串"不协调"。
