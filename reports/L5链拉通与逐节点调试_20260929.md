## 4. 三种调试入口 (查哪个节点用哪个, 别混)

**A. 单节点真执行 (查"这个节点的函数到底会不会被调")**
- 右键该节点 →「打开 VSCode 调试」(工程已带 `.vscode/launch.json`); 或设环境变量 `ZMAX_DEBUG_BREAK=<节点名子串>` (如 `metaworld`)。
- 然后 ▶运行 / ⏭单步: `execute_node_logic()` 在真正调用该节点函数**之前**会 `debugpy.breakpoint()` 停住 (只在调试器已连接时生效), 再 F11 进函数真身。
- 注意: `ZMAX_DEBUG_BREAK` 默认**不**注入 (避免"没设断点却停了"); 要停就显式加, 或在 launch.json 的 `env` 里加。

**B. 逐帧引擎链 (查"每帧的数据真的从这过吗")**
- ▶运行 (不要勾「⚡引擎快演」) = **真实化流程**: metaworld 物理 + 每帧渲染 → YOLO detect_3d, 引擎 `tools/gui/state_space_sim_real.py` 每步真跑, 断点每步可进。
- 勾了「▶运行播放演示」路径时, 大多数节点走 `_demo_node_output` (读引擎帧数值展示, **不重跑节点函数**) —— 在节点函数里下断点不会停, 这是设计如此, 不是断点没绑上。

**C. L5 编排 / 训练子进程 (查"标注→训练的数据流")**
- 编排器和训练都是**独立进程** (`subprocess.Popen`) ⇒ GUI 进程里的断点**进不去**。要调试就单独起:
  - 编排: VSCode 里打开 `tools/l5_annotate_train_loop.py` → 直接 F5 (launch 配置 "工具脚本" 用 `lerobot-venv`, 或自建一条指向 `gui-venv311/bin/python` 的配置) → 在 `stage_annotate` / `stage_supervision` / `stage_L2` / `stage_LoRA` / `stage_merge` 里下断点。
  - 训练子进程: `tools/joint_train_all.py --only L3 --lora-l3` / `--only L4 --lora-l4`, `tools/yolo_annot_train.py`, `tools/merge_lora_ckpt.py` 各自单独 F5。

## 5. "数据真的流过每个节点" 的判据 (别用感觉)

1. **函数真被调**: 断点命中 / 日志 `🧠 … 真身执行 #N` / 探针计数 (`tools/probe_l4_callchain.py` 报 `l3_calls`, `_intact_stats`, `_l4_stats`)。
2. **数据不是零/常量**: 该节点 out 的范数/维度非 0 且逐帧变化 (引擎 `io_trace` / `tr['<列>']` 逐帧真值), 例: `mani_pred` 每帧真调、`z7_vec` 维度对得上。
3. **上下游一致**: 上游 out == 下游 in (同帧同源, 不是各算各的)。
4. **同源对照**: 关掉该层 (zero/消融) 后结果应变化; 逐位 hash 对比 (`u_ff_vec/u_exec_vec` 等列) 是零回退判据。
