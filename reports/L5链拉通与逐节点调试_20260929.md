## 4. 三种调试入口 (查什么用哪个, 别混)

**A. 单节点真执行** (查"这个节点的函数到底会不会被调")
- 右键该节点 →「打开 VSCode 调试」(工程自带 `.vscode/launch.json`); 或设 `ZMAX_DEBUG_BREAK=<节点名子串>` (如 `metaworld`), 默认**不注入**。
- ▶运行 / ⏭单步 时 `execute_node_logic()` 在真正调用该节点函数**之前** `debugpy.breakpoint()` 停住 (仅调试器已连接时生效), 再 F11 进函数真身。

**B. 逐帧引擎链** (查"每帧的数据真的从这过吗")
- ▶运行 (不勾「⚡引擎快演」) = **真实化流程**: metaworld 物理 + 每帧渲染 → YOLO detect_3d, 引擎 `tools/gui/state_space_sim_real.py` 每步真跑, 断点每步可进。
- 走 `_demo_node_output` 的演示播放路径**不重跑节点函数** (读引擎帧数值), 节点函数里的断点不会停 —— 设计如此。

**C. L5 编排 / 训练子进程** (查"标注→训练的数据流")
- 编排与训练都是**独立进程** (`Popen`) ⇒ GUI 进程的断点进不去。单独起: 打开 `tools/l5_annotate_train_loop.py` 直接 F5 (在 `stage_annotate/stage_supervision/stage_L2/stage_LoRA/stage_merge` 下断点); 训练侧各自 F5 `tools/joint_train_all.py --only L3 --lora-l3` / `--only L4 --lora-l4`, `tools/yolo_annot_train.py`, `tools/merge_lora_ckpt.py`。

## 5. "数据真的流过每个节点" 的四条判据 (别用感觉)

1. **函数真被调**: 断点命中 / 日志 `🧠 … 真身执行 #N` / 探针计数 (`tools/probe_l4_callchain.py` 的 `l3_calls`, `_intact_stats`, `_l4_stats`)。
2. **数据非零非常量**: 该节点 out 的范数/维度非 0 且逐帧变化 (引擎 `io_trace` / `tr['<列>']` 逐帧真值)。
3. **上下游一致**: 上游 out == 下游 in (同帧同源)。
4. **同源对照**: 关掉该层 (zero/消融) 结果应变化; 逐位 hash (`u_ff_vec/u_exec_vec` 等列) 即零回退判据。
