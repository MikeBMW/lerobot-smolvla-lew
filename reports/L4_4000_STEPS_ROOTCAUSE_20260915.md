# L4 档「跑满 4000 步不出插拔成功」— 根因与修复 (2026-09-15 静静)

> 老倪问：为什么 3D 视频要走 4000 步，还没成功显示插拔成功的视频？
> 结论：**不是慢，是直驱动作把机器人推离光模块 + 推理异常被吞成"零动作"**。
> 两者都会让状态机永远停在「接近」，而 L4 档预算 = full 2000×2 = **4000 步** → 正好烧满、无插入/拔出/AOI。
> 本页所有数字都是本机真跑（gui-venv311 + INTACT 子进程，seed=104，mode=full，cap=l4，与老倪 GUI 同配置）。

## 1. 复现（同 seed / 同干扰 / 同起点）

| 臂 | 结果 | 步数 | 插入 | AOI |
|---|---|---|---|---|
| 解析链（对照） | **done=True** | 868 | 全链 13 段（含拔出 165 步） | **ok** |
| 模型直驱 v6r11 ep2（原样，无闸） | done=False | 600 跑满仍在「接近」 | 从未插入 | 无 |
| 模型直驱 + L2 收口闸（本修） | **done=True** | 879 | 全链 13 段 | **ok** |

起点完全相同（x0=[0.0046,0.6014,0.1951]，peg0=[0.0542,0.5469,0.0342]）。

## 2. 根因 A（主因）：直驱动作与执行层参考**反向** + 幅度塌缩 → 手朝远离光模块方向漂

同状态逐步对照（`tools/diag_l4_stall.py`）：

```
步  教师(解析链) act                  模型(直驱 v6r11 ep2) act           cos
 1  [ 0.119, -0.130, -0.170, -1.0]   [-0.046, -0.013, -0.012, -1.0]   -0.142   ← 方向反
 2  [ 0.119, -0.129, -0.175, -1.0]   [-0.074, -0.011, -0.089, -1.0]   +0.282
 10 [ 0.114, -0.116, -0.177, -1.0]   [-0.044, -0.026, -0.046, -1.0]   +0.362
120 [ 0.060,  0.015, -0.041, -1.0]   [-0.044, -0.002, -0.008, -1.0]   -0.702   ← 又反
前 130 步 std: 教师 [0.055, 0.052, 0.055]   模型 [0.009, 0.007, 0.023]  ← 幅度只有 17%~42%（塌缩）
```

后果（实测轨迹）：
- 教师 130 步内已推进 接近→对位→下降→抓取（首次抓取 136 步）；
- 模型 130/130 步停在「接近」、`grasped=False`，手从 |x−peg| **0.177m 漂到 0.259m（远离 82mm）**；
- 600 步（乃至 4000 步预算）都到不了「下降」，所以**永远没有插入 → 没有拔出 → 没有 AOI**。

这复现了老倪 GUI 里看到的原话形态：`[900~1075/4000] 阶段=接近 grasped=False 残差恒定`。

## 3. 根因 B（放大器）：直驱推理异常被**静默写成零动作** → 手完全不动，日志只显示「接近」

`tools/intact_direct_rollout.py::install_direct_act` 旧实现：

```python
except Exception as e:            # 模型/渲染失败 → 记错并停直驱
    state["err"] = ...
    s._dact_cache = np.zeros(4)   # ← 零动作 = 手冻住, 且阶段机不动
```

实测复现（`tools/diag_intzero_act.py` 同类路径）：只要每步推理抛异常（例：外部传入残缺 `rec` dict → 每步 `KeyError: 'raw'`），
**60/600 步下发动作全是 [0,0,0,0]**，而引擎日志只有 `阶段=接近 grasped=False` —— 用户看到的"模型不动/卡死"其实是异常被吞。
⇒ 任何单点异常都会伪装成"模型能力不行 + 跑满预算没结果"，排查成本极高。

## 4. 修复（都在本提交里）

1. **L2 收口闸扩展到直驱路径**（与引擎既有 `SS_L4_INTACT` 闸同一纪律：上层只给意图，执行由下层收口，每层只能收窄可行域）：
   - 阶段白名单 `SS_DIRECT_STAGES`（默认 `接近,对位,转移`；下降/抓取/插入/拔出/AOI 由执行层收口 —— 实测注入会
     把「抓取点↔头」偏移出 129~132mm 成功域 → 每次抓取后滑脱 33mm → 回退重抓死循环）；
   - 一致度门槛 `SS_DIRECT_COS_MIN`（默认 **0.9**；实测 0.5~0.85 已经会滑脱）；
   - 方向反相 / 零动作 / 幅度 >1.5× 参考 → 否决；方向一致 → 按 w=cos 融合，且**融合后幅值不得超过参考**（收窄不放大）；
   - 否决的步骤**不写 `_direct_act`** → 引擎用自己刚算出的 u 下发（与解析链逐位同源）；夹爪维持"状态机说了算"。
   - 计数全部留证：`state["gate"] = {n, stage_out, veto_dir, veto_mag, blend, applied, clamped, cos_sum}`；
     `SS_DIRECT_GATE=0` 可复现旧行为（A/B 用）。
2. **异常不再静默变零动作**：记 `state["err"]/err_steps` + **显式打印一次** 异常与堆栈，本步交回执行层；后续步继续重试真推理。
3. **GUI 侧同一收口**（`simulink_module.py` L4 档）：直驱装配成功后 `os.environ.pop("SS_INTACT")` ——
   模型只保留一条通道（直驱 + 收口闸），避免被闸否决的步骤仍从 u_ff 槽位二次注入（同样造成滑脱）。
4. 新工具：`tools/diag_l4_stall.py`（L4 档单臂真跑 + 逐步 jsonl + 可选 480² 标注视频）·`tools/diag_intact_zero_act.py`（直驱内部产物微诊断）。

## 6. 诚实缺口（未解决的部分，不吹）

- 闸门今天是**全否决**（`blend=0`）：模型在有干扰的 L4 布局下，闭环提案与执行层参考的一致度**一次都没到 0.9**
  （前 130 步 cos −0.70~+0.44，见 §2）。离线判闸（MAE on 0.036 < zero 0.133 < const 0.083）说明它学到了**训练分布上**的动作，
  但闭环里（自己的动作历史 + 有干扰布局）不足以直接放权。
- 因此当前形态 = **模型每帧真推理（879 次真调用 + 证据落盘）+ 提案留档，执行由 L2 收口**；任务能成功，但"模型独立干完"还不成立。
- 下一步（可疑口径，优先验证）：
  1. **意图口径**：训练 `train.py::construct_intents` 的 goal = 窗口**末帧 embedding**（≈+k 帧前瞻），
     而运行时喂的是 `reports/intact_goal_frame*.npy` = **整段末态**（‖δ‖≈25）。判据实验：同帧用"+k 帧前瞻目标"vs"末态目标"
     喂模型，看动作是否回到教师方向 —— 若回到 ⇒ 属口径 bug（可修），不是能力上限。
  2. **动作历史口径**：`node.action_hist` 滚动的是**归一化 chunk**，训练侧喂的是数据动作列；需逐键对齐确认（contracts.py 注"raw"）。
  3. 闭环数据再训（DAgger 式：用本闸记录的被否决样本 + 执行层动作做纠正标签），按 `cos` 分布**自动放权**（闸门已按一致度连续可调，模型变好即自动接管，无需改代码）。
